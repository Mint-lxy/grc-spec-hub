| 规则 | 说明 |
| --- | --- |

| 不使用 **Access** 指代订阅授权 | 统一写"订阅"或"使用授权" |
| **密钥库** 指本平台模块，**Key Vault** 指企业底层存储服务 | 正文只说密钥库；Key Vault 仅在描述集成关系时出现 |
| **使用条款** 不简写为 Terms | 全文写"使用条款"；资产级使用条款与平台级用户协议是两个文档 |
| 不使用 **应急隐藏**、**应急停用** | 平台只有一个撤下动作：**下架**，由 Owner 或 Deputy 执行 |
| 不使用 **草稿轨道** 指代待发布配置 | 统一写「未发布修订」；草稿是资产的数据属性，不是状态机节点 |

## 2. 问题陈述

奔驰中国各业务团队（合规、风控、法务、人力资源等）正在大量自建 AI Agent 与 MCP 工具，但缺乏统一的企业级入口与治理体系，存在五个问题：

1. **资产难以发现**：员工无法得知公司内已有哪些可用的 Agent 与 MCP，导致重复建设。
2. **使用授权无留痕**：缺少统一的订阅授权、使用条款确认与调用审计。在数据出境、反洗钱、合同审查等敏感场景下存在合规风险。
3. **质量与安全无基线**：资产上线前缺少统一的安全测评（提示词注入、意图偏离、内容安全），上线后缺少内容护栏防护。
4. **调用凭据分散**：调用外部 Agent、MCP 与模型所需的 API Key 与令牌分散在员工个人手中，无统一托管、无最小化授权、无轮换机制。
5. **知识检索无统一入口**：企业知识库分散在各处，对话时无法便捷挂载可信的知识来源。

## 3. 解决方案

**产品定位**：本平台是企业内部的智能体统一上架平台。各智能体的安全与质量由其所属业务场景方自行负责；平台提供测评工具、基础通用的内容防护能力，以及统一的授权、凭据与审计底座（依据 `docs/adr/0004`）。

平台由六个部分组成：

1. **Marketplace**：全平台 Agent 与 MCP 的统一上架、发现与订阅入口。订阅即授权，授权全程留痕。
2. **对话工作台**：统一的对话入口，支持流式输出与中止生成。默认会话对象是**平台 Chat agent-runtime**（界面展示名 Chat）：平台自有的知识问答智能体，可挂载知识库检索（回答附带引用证据与图片、插图）、调用平台原生工具；它不调用任何资产。试用已订阅的资产 Agent 经其详情页「去使用」进入透传会话（不可挂载知识库）。一切经平台流转的对话统一经过平台网关的护栏检测（依据 `docs/adr/0015`）。
3. **自助上架流水线**：资产创建 → 质量门控（硬阻断，按资产类型参数化）→ 发布准入测评（仅 Agent 必须执行；MCP 免跑，其工具描述与返回内容的安全由运行时输出侧护栏覆盖。未通过时是否阻断由平台管理员开关决定，默认不阻断）→ 自助上架。
4. **安全底座**：密钥库（入站统一为 PAT；出站分两层——资产级服务凭据为默认形态，个人出站凭据仅用于按人鉴权资产与知识导入通道；鉴权声明属版本类配置而密钥值属热改类，依据 `docs/adr/0014`）与护栏策略模板（平台管理员维护，Owner 强制绑定，平台网关统一执行）。
5. **知识中枢**：企业知识目录树（公共目录与我的目录），知识库四阶段构建管线与参数治理；目录与知识库相关角色由平台调用 Alice 接口发起创建，授权以 Alice 为唯一权威。
6. **管理后台**：模型设置、准入测评模板与护栏策略模板维护、测评阻断开关、推荐位管理、角色到功能点的映射配置、公共目录一级节点冷启动、平台资源凭据维护、**平台原生工具维护**、治理中心（资产总览、出站调用停用、孤儿资产补员）。平台管理员不改变任何资产的状态（依据 `docs/adr/0009`）。

## 4. 用户角色

| 角色 | 来源 | 主要能力 |
| --- | --- | --- |
| 普通用户 | 全员默认，账号由 SSO 开通 | 使用对话工作台、在 Marketplace 浏览与订阅资产、在订阅者中心跟踪与退订、在密钥库配置个人出站凭据与 PAT、检索有权限的知识库、**创建资产**（全员默认可创建，创建即成为该资产首位 Owner） |
| Owner（资产负责人） | 创建资产后自动成为首位 Owner；一个资产允许多个 Owner | 创建 Agent 与 MCP、维护负责人名单（增删共同 Owner 与 Deputy）、**配置资产级服务凭据**、配置订阅申请表单与使用条款、配置审批人链、执行发布准入测评、自助上架、发布新版本并申报强治理变更、**中止发布**、审批订阅申请、取消他人订阅（必填理由）、**下架、重新上架与删除资产** |
| 订阅审批人 | 由 Owner 在审批人链中指定，可以不是资产负责人 | 在创作者中心「我审批的资产」分区进入该资产控制台的审批人视图，通过或驳回待其审批的订阅申请（须填写驳回理由）；无发布、热改、下架、删除与凭据配置权限 |
| Deputy | 由 Owner 在资产控制台或创建向导中设置，与 Owner 同权限 | 资产的共同负责人，覆盖 Owner 离职与休假场景；发布资产时若 Owner 仅一人，必须至少增设一名 Deputy 方可上架 |
| 平台管理员 | 由 Alice 授予；同时具备普通用户的全部基线权限（§5.3） | 维护发布准入测评模板（含三类阈值）与护栏策略模板、指定平台默认护栏策略模板、配置测评阻断开关、管理推荐位、模型设置、公共目录一级节点冷启动并指定一级目录角色、配置角色到功能点与可用模型的映射、**维护平台资源凭据**、**维护平台原生工具**、**按资产维度停用出站调用（必填原因）**、**孤儿资产补员**（为负责人全部失效的资产指定新 Owner，留痕并通知）。不改变任何资产的状态 |
| 知识侧角色（五种） | 角色由平台调用 Alice 接口创建于 Alice 中，授予与回收由上级目录控制角色审批 | 目录控制角色（管理目录结构及其全部子级）、知识库创建角色（在目录下建库）、知识库 Owner（管理整个知识库）、知识库 Contributor（增删库内文档、执行导入）、知识库 Consumer（检索使用知识库）。**我的目录不存在角色概念**，上述动作均由创建者本人执行 |

**§8 用户故事中的岗位视角与本表的对应**：「知识维护员」指持有知识库 Owner 或知识库 Contributor 角色的普通用户；「测评人员」「合规审核员」是 P1 阶段的岗位视角，不构成独立权限主体（其 P0 相关能力分别归入 Owner 与平台管理员）。

**权限模型**（依据 `docs/adr/0001` 与 `docs/adr/0006`）：

- **Alice 是唯一授权权威**。账号、角色、知识目录与知识库授权全部由 Alice 存储与决策。平台同步展示授权结果并提供申请跳转入口，不自行审批，也不保留账号紧急停用能力。平台不自建账号密码体系。
- **平台是角色创建的发起方**。知识目录与知识库相关角色由平台在相应对象创建时调用 Alice 接口发起创建；Alice 是存储与真相来源。
- **平台保留三项权限职能**：一是角色到功能点与可用模型的映射配置（功能点清单见 §5.3）；二是订阅授权（Owner 对自己资产的消费方进行审批）；三是平台自有对象的运行控制（出站调用停用、平台原生工具启停用）。资产的上下架完全归 Owner，平台管理员不干预（依据 `docs/adr/0009`）。
- **创建资产不设门槛**。全员默认可创建 Agent 与 MCP，质量由质量门控与发布准入测评把关，不设资格前置审批。
- **认证不等于授权**。PAT 与出站凭据只是认证方式，不能扩张持有人已有的授权范围。

## 6. 用户旅程

### J1 普通用户：发现资产 → 订阅 → 使用

1. 进入 Marketplace 的 Agent 或 MCP 频道，通过推荐位、热门榜、全部列表或搜索查找资产。搜索按资产名称、业务标签与简介模糊匹配。列表只展示状态为「已发布」且质量门控全部通过的资产。
2. 打开资产详情页。Agent 详情含四个页签：基本信息、接入配置、测评信息、发布记录。MCP 详情含四个页签：基本信息、接入配置、工具能力、凭据状态。页签按订阅状态分层：未订阅时可见订阅决策所需的信息（Agent 的基本信息、测评信息与发布记录；MCP 的基本信息），服务地址、接口清单与凭据状态等细节订阅后可见（见 M2-5、M2-6）。
3. 点击「订阅」，进入单页订阅申请：顶部为资产说明摘要（默认折叠，详情已在详情页看过）；中部填写申请信息（业务系统、使用场景，以及该资产 Owner 自定义的表单字段）；底部为带版本号的使用条款全文（可展开）与多级审批人链预览，勾选同意后一次提交——提交前一屏看全自己承诺的内容与审批路径。
4. 在订阅者中心跟踪申请状态。页面提供四个状态统计卡（已通过、待审批、被驳回、已取消）用于筛选，鼠标悬停状态可查看各级审批进展。被驳回或已取消时可查看理由并一键重新申请。
5. 审批通过后：Agent 详情页出现「去使用」，点击进入该 Agent 的对话页（平台网关代理透传）。MCP 不是对话对象、无「去使用」——其消费方式为资产 Agent 服务端自行接入，或外部系统经 PAT 调用（此时平台充当 MCP 网关）；**对话工作台内不可调用资产 MCP**（依据 `docs/adr/0015`）。**绝大多数资产无需订阅者配置任何凭据**——平台以该资产的资产级服务凭据发起调用（依据 `docs/adr/0014`）。仅当资产在鉴权配置中声明为「按人鉴权」时，订阅者须在密钥库配置本人的个人出站凭据；未配置时页面明确提示并提供跳转入口，调用失败且**不回落至任何共享身份**。
6. 对话能力按会话类型分两类：与 Chat（平台 Chat agent-runtime）的会话可挂载知识库（检索证据、图片与插图内嵌）、调用平台原生工具、开启深度分析、查看思考过程；资产 Agent 会话为透传会话，能力以该资产返回的内容为准。两类会话的回答均在通过输出侧护栏检测后按段回放，可随时中止生成（中止时已生成部分同样先检测后展示）；命中护栏时回答被拦截，并告知命中的护栏类型。
7. 不再需要某资产时，在订阅者中心主动退订，订阅状态转为「已取消」，使用授权立即失效。以下事件订阅者均收到站内通知：订阅被 Owner 取消、资产被 Owner 下架（附下架原因）、资产重新上架、资产发布新版本（申报为强治理变更时附影响说明与迁移指引，未申报时为轻量通知）、资产使用条款升版。

### J2 Owner：创建高代码 Agent 并自助上架

1. 在创作者中心点击「创建 Agent」，选择高代码方式。前置条件：该 Agent 服务已对外暴露符合 A2A 协议的 Agent Card。
2. 完成六步创建向导：基础信息（含**资产负责人**：创建者默认为首位 Owner，可增加共同 Owner 与 Deputy）→ 接入配置（服务地址、Health Check 开关与一键探测、超时与重试）→ 鉴权配置（声明鉴权模式（静态凭据或动态凭据）、鉴权方式与参数名；**声明该资产是服务间鉴权还是按人鉴权**——服务间鉴权资产须在此配置**资产级服务凭据**并可一键探测，按人鉴权资产由各订阅者自行配置个人出站凭据）→ 能力声明（拉取 Agent Card、声明输入输出结构）→ 订阅配置（上传 YAML 表单定义文件并实时预览；使用条款为独立必填文本，自带版本号；可视化编辑并行多级审批人链）→ **护栏策略模板（从启用状态的模板中选择恰好一个，必选）与发布说明**。
3. 提交后系统运行质量门控。Agent 的七项检查（基础信息完整、Health Check 探测成功、Agent Card 可拉取且格式合法、鉴权方式已声明且服务间鉴权资产的资产级服务凭据已配置并探测可用、订阅申请表单与使用条款已配置、**负责人冗余：多于一位 Owner 或已设 Deputy**、**所绑护栏策略模板当前处于启用状态**）全部通过方可进入下一步；任一项未通过则阻断，修改后需重新运行。
4. 执行发布准入测评。被测对象锁定为本资产，测评模板锁定为平台管理员维护的发布准入测评模板。
5. 测评结束后上架。测评通过则直接上架；测评未通过时按平台管理员配置的阻断开关处理（默认关闭）：开关开启则不可上架（可改进后重测），开关关闭则可上架但资产详情页标注「准入测评未通过」。详情页测评信息页签展示测评执行时间，并明确测评结果仅代表执行时点的快照。
6. 上架后资产状态为「已发布」，可见范围为「全平台可浏览，使用需订阅」，进入 Marketplace 列表。
7. 在该资产的资产控制台处理订阅审批（通过或驳回并填写理由）、查看申请详情（含使用条款确认记录）、查看每个订阅者的请求历史统计、取消他人订阅，并可即时热改以下配置（不进入版本流程、不重跑门控）：负责人名单、订阅申请表单、订阅审批人链（仅对新申请生效）、护栏策略模板改绑、基础信息（名称、业务标签、简介、能力标签、适用场景）、超时与重试。
8. 变更版本类配置（服务地址、Health Check、鉴权声明、能力声明）或修改使用条款时，编辑内容进入该资产的**未发布修订**——修订是资产的一份可选待发布配置，与在架版本并存，**期间在架版本持续对外服务**（依据 `docs/adr/0012`）。发布修订时：纯使用条款修订走**轻发布**（条款版本递增、通知存量订阅者、豁免质量门控与发布准入测评、不要求重新确认）；含版本类字段的修订重跑质量门控与发布准入测评，通过后新版本瞬间整体替换在架版本，版本号递增并写入发布记录，全体订阅者自动跟随，订阅不绑定版本。Owner 在发布时显式申报是否为强治理变更；若是，须同时填写影响说明与迁移指引，平台在版本替换的同一时刻向全部订阅者发出通知（附申报内容）并留痕——**通知与替换同时发生，订阅者无缓冲窗口**，迁移指引是唯一的补偿手段；未申报强治理变更的版本替换同样向全部订阅者发出轻量通知。
9. 需要撤下资产时（含安全事件等应急场景），由 Owner 或 Deputy 在资产控制台执行**下架**：弹窗二次确认并必填下架原因，资产转入「已下架」。下架后全部「已通过」订阅失效、全部「待审批」订阅申请自动转为「已取消」（审批人待办同步清除），受影响方均收到附下架原因的站内通知；平台运行时即时感知，一切经平台流向该资产的调用（资产会话透传与 PAT 开放接口调用）失败并返回「该资产已被下架」，其「去使用」入口与抽屉条目同步置灰。**下架不触碰未发布修订**：Owner 可在「已下架」状态下继续编辑修订以修复问题（含服务地址、鉴权声明等版本类配置）。重新上架即发布该修订的一次新版本发布，重走质量门控与发布准入测评，版本号递增并留痕；重新上架**不恢复**订阅——平台向下架时刻的存量订阅者与待审批申请人发送「资产重新上架」通知，原申请人需自行重新申请（新建记录、审批链重新执行），PAT 集成需在密钥库重新勾选资产范围。

### J3 Owner：创建低代码 Agent（P1）

选择有创建权限的 Dify 工作区 → 跳转 Dify 完成编排 → 平台周期性同步该应用元数据（同步结果落入该资产的未发布修订，由 Owner 确认后发布生效，不绕过版本流程）→ 在平台补录治理字段（平台展示名称、业务归属、简介、建议可见范围）→ 质量门控 → 发布准入测评 → 自助上架。**Dify 侧发布仅表示该应用在 Dify 中可运行，不等同于在本平台上架。**

### J4 知识维护员：建库 → 构建 → 开放

1. 在目录树中选择一个叶子目录进入三步建库向导：基础信息（存放路径、名称、可见范围、描述、标签；可见范围仅控制**卡片可发现性**：公开——知识库卡片对全员可见，无权限者点击展示 Alice 权限 ID 与申请入口；不公开——卡片仅对已有权限者可见，其他用户需经 Alice 申请权限。公共目录建库默认公开，访问权限始终由 Alice 唯一决定；我的目录的知识库仅本人可见，不适用该字段）→ 构建管线配置（默认使用推荐配置：Docling 解析、语义切片、摘要与关键词增强、BGE-M3 向量化、Milvus 存储）→ 确认创建。新建知识库初始状态为「草稿」。**在公共目录下建库需具备该目录的知识库创建角色，建库时平台调用 Alice 接口创建该知识库的三个角色并将知识库 Owner 角色授予创建者；在我的目录下建库无需任何授权，不调用 Alice，创建者是其唯一使用者，不存在角色概念。** 知识库创建后不可在既有目录之间移动、不可复制。
2. 通过四个通道导入文档：本地上传（单文件不超过 40 MB，支持 ZIP 压缩包展开预览）、Confluence、SharePoint 与 OneDrive、S3 与 Azure Blob 对象存储。外部通道导入使用操作人在密钥库配置的个人出站凭据（未配置时引导配置）；**导入即代表建库方确认该内容可被本库全体知识库 Consumer 检索**。导入预览中不支持的文件格式自动置灰且不可勾选。导入后文件初始状态为「未解析」。
3. 勾选文件后一键构建（四阶段自动执行），或切换手动模式按阶段单独执行（用于调试单节点参数或分批重跑）。构建失败时立即弹窗说明原因，失败文件在列表中置顶。**库内首份文档完成向量化时，知识库自动从「草稿」转为「可用」**，此后才可被挂载进对话与被开放接口检索。
4. 在文件详情中审阅构建结果：源文件分页预览、解析后的 Markdown 内容、切片列表的搜索与逐条编辑（编辑保存后触发该文档重新增强与向量化）、文档摘要与关键词、解析信息。
5. 调整构建参数。库级参数为该库所有文档的默认值，保存后触发全库重建；文档级参数可覆盖库级默认，但仅限解析器、切片策略与内容增强三类，向量化模型与向量数据库锁定在库级。
6. 对外开放知识库能力：三个接口（读取知识库元数据、检索知识库、更新知识库内容），外部系统统一使用密钥库签发的 PAT 认证；其中更新知识库内容接口要求 PAT 持有人具备该知识库的知识库 Owner 或知识库 Contributor 权限（我的目录的知识库无角色概念，三个接口均仅限创建者本人调用）。
7. 无权限用户点击受限目录或知识库时，页面展示对应的 Alice 权限 ID（可一键复制）与申请跳转入口；知识库与目录的权限申请为**单级审批**，由上级目录控制角色持有人处理。目录的日常维护（重命名、新建子目录、在知识库上层增加层级并将知识库迁入）由该目录的目录控制角色持有人在平台内直接操作，即时生效，平台负责同步至 Alice。知识库 Owner 可手动停用知识库（转「已停用」，**对新会话生效**——不再出现在挂载列表、不再被新会话检索；进行中的会话按会话级快照继续到结束，见 §9.6）并可重新启用。

### J5 平台管理员：模板化与开关式治理

1. **维护发布准入测评模板**：更新三类测评问题集（提示词注入、意图偏离、内容安全）并发布。
2. **维护护栏策略模板**：配置护栏组合、各护栏的灵敏度与作用侧，启用或停用模板；指定全局唯一的平台默认护栏策略模板。
3. **配置测评阻断开关**：决定发布准入测评未通过时是否阻断上架，默认关闭。
4. **停用出站调用**：这是平台管理员对他人资产唯一的运行控制手段——按资产维度停用后，该资产的全部出站凭据解析（资产级服务凭据与全部个人出站凭据）被禁用，平台网关不再为该资产发起出站调用，无论调用使用何种凭据主体。**停用必填原因**，原因随通知发给全体负责人，并与停用时间一并在该资产的资产控制台常驻可见。管理员不改变资产状态，撤下与删除资产一律由 Owner 侧执行（依据 `docs/adr/0009`）。**出站调用停用与资产状态正交**：资产被下架又重新上架后，未解除的出站调用停用继续生效（资产显示为「已发布」但调用仍失败），恢复需管理员手动解除。
5. **维护平台资源凭据**：平台自有资源（如 Nexus 模型令牌、平台原生工具在对话场景使用的平台内置统一凭据）的凭据由平台管理员统一维护。该凭据不作为用户资产调用的兜底（依据 `docs/adr/0014`）。
5b. **维护平台原生工具**：维护三个原生工具（Confluence MCP、SharePoint/OneDrive MCP、OSS（S3/Blob）MCP）的服务地址、鉴权配置与启停用。原生工具不上 Marketplace、免订阅、无 Owner、不适用质量门控与准入测评。
6. **管理推荐位**：人工置顶 Marketplace 推荐频道展示的资产。被下架的资产自动退出推荐位；重新上架后不自动恢复，需管理员重新置顶。
7. **治理中心**：全平台资产（Agent 与 MCP）的名称、类型、状态、出站调用停用标记与负责人；负责人全部失效的孤儿资产显著标记，可为其指定新 Owner（补员须满足有效冗余，留痕并通知新 Owner；提交时实时复核孤儿性）。
8. **身份与权限**：查看从 Alice 同步的用户只读视图；配置 Alice 角色到平台功能点与可用模型的映射。
9. **公共目录冷启动**：创建一级目录，指定一级目录控制角色与一级目录知识库创建角色的持有人；之后各层级的角色授予与目录维护由上级目录控制角色负责。
10. **平台配置**：维护模型清单（新增、编辑、启停用、设置默认模型）。

### J6 发布准入测评执行

Owner 在发布流程中触发（**仅 Agent**；MCP 不执行发布准入测评，质量门控通过即可上架）：被测对象锁定为待上架资产，测评模板锁定为发布准入测评模板。Owner 可在发布流程页内查看执行进度、样本明细与各项指标得分。测评执行失败（基础设施原因）视同未通过，按阻断开关处理，可重测。测评结束后结果回写至该资产的发布状态，资产详情页展示执行时间并标注快照语义。纯使用条款修订的轻发布豁免准入测评（行为与接入配置均未变，无检测对象）。**P0 的测评仅为发布时的基础准入测评，不设独立的测评中心导航入口**；自助测评模板、数据集管理、对比报告与独立入口均为 P1，相关需求待 P1 规划时展开。

### J7 护栏配置与运行时生效

平台管理员配置护栏策略模板（护栏组合、各护栏灵敏度与作用侧、启用状态）并指定平台默认护栏策略模板 → Owner 创建 Agent 时从启用模板中选择恰好一个 → 运行时由平台网关对一切经平台流转的对话执行检测：资产 Agent 会话适用该 Agent 绑定的模板，平台 Chat agent-runtime（平台自有的知识问答智能体，见 `docs/adr/0015`）的会话适用平台默认护栏策略模板，任一会话恰好适用一个模板。命中即拦截：输入侧命中直接拒答，输出侧命中以「已拦截」占位文本替代原输出，响应中回传命中的护栏类型。输出侧检测针对完整回答执行：网关缓冲全文、检测通过后按段回放，命中则全文不下发。模板修改对已绑定 Agent 即时生效；模板停用只影响新绑定，存量 Agent 继续按该模板运行直到 Owner 改绑，但**下一次质量门控重跑（发布新版本或重新上架）时会强制校验所绑模板处于启用状态**，未启用则阻断并引导改绑。外部接入的 MCP 不单独绑定护栏，其返回内容进入对话上下文后由输出侧检测覆盖。护栏运营看板与命中记录查询为 P1。

### J8 密钥库：配置调用凭据

1. **出站凭据两层模型**（依据 `docs/adr/0014`）：
   - **资产级服务凭据**（默认形态）：每个资产一份，由该资产 Owner 在创建向导的鉴权配置步或资产控制台配置，密钥库托管，该资产的全体调用共用。鉴权声明变更时 Owner 只需更新此一处，订阅者零感知、零操作。密文字段默认掩码显示，可切换明文。
   - **个人出站凭据**（收缩场景）：仅用于两类情形——资产在鉴权配置中声明为「按人鉴权」时由订阅者配置，以及知识库的三个外部导入通道使用操作人个人凭据。**单页配置**：资源类型二选一（按人鉴权资产，目标限已订阅者；平台原生工具，全员可选），认证表单按目标声明的鉴权方式动态生成、已声明字段只读；带参跳转进入时资源选择器折叠为只读摘要。按人鉴权资产未配置个人凭据时调用失败并引导至密钥库，**不回落至任何共享身份**（共享身份会击穿目标服务的按人授权）。
   - **平台资源凭据**：平台自有资源（Nexus 模型令牌、平台原生工具在对话场景使用的平台内置统一凭据等）由平台管理员统一维护，不作为用户资产调用的兜底。
   - 每次调用记录实际使用的凭据主体（资产级服务凭据 / 个人出站凭据 / 平台资源凭据）。
2. **入站 PAT**（外部系统调用本平台开放接口的唯一入站凭据）：创建时填写名称、有效期（默认 90 天，自创建时刻起算）与权限范围。权限范围只能勾选持有人已获授权的对象（已订阅的资产、有权限的知识库），勾选时联动校验。令牌明文仅在创建成功时完整显示一次。重新生成会使原令牌立即失效。停用与删除需二次确认。知识库开放接口与资产调用开放接口均使用 PAT 认证。PAT 调用服务间鉴权资产时由平台以资产级服务凭据发起出站调用，持有人无需逐资产配置凭据；调用按人鉴权资产时仍需持有人本人已配置个人出站凭据。
3. 从 MCP 详情页、订阅者中心、Agent 详情页均可跳转至凭据配置（Owner 跳转至该资产的服务凭据配置，订阅者跳转至个人凭据配置），并带入目标资产信息，保存后自动返回来源页面。

## 9. 业务规则与状态机

### 9.1 资产生命周期

状态流转（MCP 不执行发布准入测评，质量门控全部通过后直接转「已发布」，其余与 Agent 相同）：

```
草稿 → 待发布 →（质量门控全部通过）→ 待测评 →（发布准入测评执行完毕）→ 已发布
待测评 →（版本类配置变更，门控须重跑）→ 待发布
已发布 →（Owner 或 Deputy 下架）→ 已下架
已下架 →（重新上架：发布未发布修订，重走质量门控与发布准入测评）→ 已发布
草稿 / 待发布 / 待测评 / 已下架 →（Owner 或 Deputy 删除，二次确认）→ 已删除（终态）
```

| 状态 | 含义 | 可见范围 |
| --- | --- | --- |
| 草稿 | 创建向导未提交 | 仅 Owner 与 Deputy |
| 待发布 | 已提交，质量门控未全部通过 | 仅 Owner 与 Deputy |
| 待测评 | 质量门控全部通过，等待或正在执行发布准入测评 | 仅 Owner 与 Deputy |
| 已发布 | 已上架 Marketplace | 全平台可浏览，使用需订阅 |
| 已下架 | 由 Owner 或 Deputy 下架 | 见下方「已下架的界面语义」；全部订阅停止生效 |
| 已删除 | 由 Owner 或 Deputy 删除（软删除，终态） | 对**全部用户**不可见（含负责人与平台管理员），退出创作者中心、治理中心与已下架占位页 |

**已下架的界面语义**（「不可浏览」的精确定义）：

| 界面 | 表现 |
| --- | --- |
| Marketplace 列表与搜索 | 不出现（列表可见性规则的自然结果） |
| 资产详情页直连 | 非负责人看到占位页：资产名称、「已下架」状态、下架原因；不展示接入配置与能力声明等细节。负责人进入完整资产控制台 |
| 资产收藏 | 保留条目，置灰并标注「已下架」 |
| 历史会话 | 可打开只读回看（会话内容属用户自有数据）；发送新消息被拒并提示「该资产已被下架」 |
| 对话工作台「我的资产」抽屉 | 保留条目并置灰；Agent 条目不可进入对话页，MCP 与收藏条目仅可进入已下架占位页 |

补充规则：

- 发布准入测评未通过时：阻断开关开启则停留在「待测评」；阻断开关关闭（默认）则可转「已发布」，且详情页标注「准入测评未通过」与测评执行时间（测评仅针对 Agent；MCP 不执行准入测评，质量门控全部通过即可上架）。测评执行失败（被测服务不可达、超时等基础设施原因）视同未通过处理，Owner 可重测。
- **下架是平台上唯一的撤下动作，只有 Owner 与 Deputy 可执行**，应急场景同样如此。平台管理员不改变资产状态，其对他人资产唯一的运行控制手段是按资产维度停用该资产的出站调用（依据 `docs/adr/0009`；管理员对平台自有对象另有原生工具启停用等权限）。
- **下架的保护与留痕**：执行下架需弹窗二次确认（轻量提醒，不引入审批或他人环节）并必填下架原因；原因随业务记录永久留痕，并随下架通知发给受影响方、随重新上架通知发给存量订阅者。
- **下架的连带处置**：全部「已通过」订阅转「已取消」；全部「待审批」订阅申请转「已取消」并通知申请人，审批人待办同步清除。
- **下架的运行时效力**：平台运行时即时感知下架状态——一切经平台流向该资产的调用（资产会话透传与 PAT 开放接口调用）失败并返回「该资产已被下架」；平台不做意图路由（依据 `docs/adr/0015`），下架资产的「去使用」入口与抽屉条目同步置灰拦截。
- **下架与出站调用停用正交**：二者是两个独立开关，可同时成立。资产下架后重新上架，未解除的出站调用停用继续生效（资产显示为「已发布」但调用仍失败），恢复需平台管理员手动解除。
- **下架与推荐位**：被下架的资产自动退出推荐位；重新上架后不自动恢复，需平台管理员重新置顶。
- **资产删除（软删除，终态）**：Owner 或 Deputy 可删除处于「草稿」「待发布」「待测评」「已下架」的资产，需弹窗二次确认。「已发布」资产**须先下架**方可删除（与知识库「可用态须先停用方可删除」同构）。删除为**系统软删除**：资产对全部用户不可见（含负责人与平台管理员），退出创作者中心、治理中心与已下架占位页；删除动作及操作人永久留痕；同时清理该资产的资产级服务凭据，各 PAT 对该资产的访问随之失效（§9.3 对象侧失效）。业务记录（订阅记录、条款确认、审批留痕、发布记录、下架原因）按 §9.8 继续永久保留——留痕的是记录，不是资产条目。
- **发布互斥（发布优先）**：资产处于发布进行中（质量门控与发布准入测评执行期间）时，下架与删除动作被阻断并提示「该资产正在发布，请先中止发布」；**任一 Owner 或 Deputy 均可执行「中止发布」**，中止后修订保留并通知发起人——应急路径因此不被发布流程堵死。
- **出站调用停用的 Owner 侧可见性**：平台管理员停用某资产的出站调用时**必填原因**；该停用状态与原因、停用时间在该资产的资产控制台顶部**常驻可见**（具体样式不在本文档约束），并在创作者中心列表与治理中心列表以标记呈现——避免负责人面对全绿的控制台盲排查。
- 强治理变更由 Owner 在发布新版本时显式申报，申报时必填影响说明与迁移指引；平台在版本替换的同一时刻通知全部订阅者（附申报内容）并留痕，订阅者无缓冲窗口；平台不自行检测（依据 `docs/adr/0011`）。未申报强治理变更的版本替换同样发出轻量通知。
- **接受的风险**：Owner 与 Deputy 同时不可达时，平台可停用该资产的出站调用以阻断一切经平台流向该资产的调用，但无权改变资产状态（资产仍显示为「已发布」），也无法阻断订阅者与 Owner 侧服务之间不经平台的直连（若存在）。该风险由强制负责人冗余（ADR-0007）缓解，已向合规方明示。

### 9.1.1 版本模型与配置变更

- **任一时刻只有一个活版本对外服务**，订阅记录不绑定版本（依据 `docs/adr/0012`）。
- **未发布修订**是资产的可选数据属性，不是状态机节点：「已发布」与「已下架」状态均可携带一份修订。修订与在架版本并存，**修订存在期间在架版本持续对外服务**，全部流量仍走在架版本。
- **修订载荷仅限版本类配置与使用条款**。热改类配置只能经资产控制台即时通道生效，不进入修订——一个字段恰有一条变更通道。**鉴权的粒度划分**：鉴权声明（模式、方式与参数名、鉴权主体类型、动态模式的授权申请接口地址与令牌回写字段）进入调用契约，属版本类；资产级服务凭据的**密钥值本身**不是契约、只是同一契约下的凭证，属热改类——密钥轮换与泄露处置因此无需经发布流程（依据 `docs/adr/0014`）。
- **发布修订的两种形态**：
  - **轻发布**（修订仅含使用条款）：条款版本递增、通知全部存量订阅者（附新版条款）、写入发布记录；**豁免质量门控与发布准入测评**（行为与接入配置均未变，无检测对象）；不阻断存量订阅者继续使用、不要求重新确认；新订阅按当前版本签署。
  - **版本发布**（修订含任一版本类字段）：重跑质量门控与发布准入测评（MCP 仅质量门控），通过后新版本瞬间整体替换在架版本，**全体订阅者自动跟随**，资产版本号递增并写入发布记录。平台不做多版本共存托管。
- **重新上架 = 一次版本发布**：已下架资产可编辑未发布修订（含服务地址、鉴权声明等版本类配置）以修复问题，发布即重新上架，重走质量门控与发布准入测评，版本号递增并留痕。下架不触碰未发布修订。**修订为空时的重新上架**按当前在架配置发起一次空载荷版本发布（版本号仍递增并留痕，门控与测评照常重跑）。
- **发布语义按完成时刻的资产状态判定**：一次发布是「版本发布」还是「重新上架」，以**发布完成时刻**的资产状态为准——从「已发布」完成的走版本发布语义（通知全部订阅者）；从「已下架」完成的走重新上架语义（通知下架时刻的存量订阅者与待审批申请人）。配合「发布优先」的互斥规则（§9.1），不会出现向已被清空的订阅者集合发通知的空转。
- **一切版本替换均通知全部订阅者**：申报为强治理变更的附影响说明与迁移指引（通知与替换同时发生，无缓冲窗口）；未申报的发轻量通知。
- 发布记录保留完整版本历史、各版本的发布说明、测评结果快照、强治理变更申报、使用条款版本历史与下架及重新上架记录（含下架原因）。
- **配置变更两分**（分类原则：字段是否进入调用契约或需要门控／测评验证）：

| 类别 | 字段 | 生效方式 |
| --- | --- | --- |
| 热改类 | 订阅申请表单、订阅审批人链、负责人名单、护栏策略模板改绑、基础信息（资产名称、业务标签、简介、能力标签、适用场景）、超时与重试、**资产级服务凭据的密钥值**（静态模式的固定密钥、动态模式用于换取令牌的密钥） | 资产控制台即时生效，不进入修订，变更审计留痕、不通知订阅者。密钥值保存前强制探测可用；热改类的写入需版本校验（见 §9.1.2） |
| 版本类 | 服务地址、Health Check、**鉴权声明**（鉴权模式即静态凭据或动态凭据、鉴权方式与参数名、鉴权主体类型、动态模式的授权申请接口地址与令牌回写字段）、能力声明、MCP 托管方式 | 仅能经未发布修订以新版本发布变更，重跑质量门控与发布准入测评 |
| 轻发布 | 使用条款 | 经未发布修订发布后生效，通知存量订阅者，豁免门控与测评 |

- 质量门控与发布准入测评的结果均为**上架时点快照**（与 `docs/adr/0011` 的测评快照语义一致）：Marketplace 列表条件中的「质量门控全部通过」指上架时点的结果，上架后的热改类配置变更与纯条款轻发布不影响在架可见性；M3-4 的「任一配置字段变更后需重新运行」仅适用于发布流程与含版本类字段的修订。
- **能力声明无运行时白名单效力**：能力声明是上架时点的契约记录，平台网关不按声明清单约束实际调用；声明与服务实际能力的持续一致性责任归 Owner，运行时内容安全由输出侧护栏覆盖（依据 `docs/adr/0011`、`docs/adr/0008`）。
- Owner 与 Deputy 全部账号被 Alice 停用时，平台不做任何自动处置（资产保持运行）；此时平台管理员可在治理中心为该资产**补员**（指定新 Owner），操作留痕并通知新指定的 Owner，补员后一切 Owner 职能与订阅入口恢复。负责人名单可由资产控制台随时维护。

### 9.1.2 负责人规则

- 创建者自动成为资产的首位 Owner；一个资产允许多个 Owner，Owner 与 Deputy 权限等同。
- 发布前质量门控校验负责人冗余：必须多于一位 Owner，或已设至少一名 Deputy。**冗余口径为「账号有效的负责人数」**——被 Alice 停用的账号不计入，避免停用账号构成的假冗余。
- **热改类写入的并发保护**：负责人名单等热改类配置（§9.1.1）的写入需版本校验——提交时携带读取时的版本，不匹配则拒绝并提示「配置已被他人修改，请刷新后重试」。否则两位 Owner 并发互相移除时，两次冗余校验都基于各自的读取快照通过，资产可退化为零有效 Owner。
- **孤儿资产补员须满足有效冗余**：管理员补员时须使补员后的**有效**负责人满足冗余（一次指定两位有效 Owner，或一位 Owner 加一位 Deputy），否则补员后新 Owner 会被冗余校验卡在无法清理僵尸账号的死结里。原负责人账号被 Alice 恢复后，其负责人身份**自动恢复**（补员从未移除他）；孤儿标记随之解除，并通知该资产全体有效负责人。
- **负责人冗余对已发布资产是持续约束**：任何负责人移除操作若会使「已发布」资产不再满足冗余，阻断并提示；其余状态不受限——已下架期间允许收缩（整改期可能需要人员重组），重新上架时质量门控重新校验。
- 全部 Owner 与 Deputy 账号均被 Alice 停用的资产为**孤儿资产**：订阅入口关闭（§9.2），治理中心只读总览对其显著标记，平台管理员可补员新 Owner（留痕并通知新 Owner）；补员前平台不做任何自动处置，资产保持运行。
- 负责人名单在创建向导「基础信息」步与资产控制台均可维护。

### 9.2 订阅状态机

```
待审批 →（各级均已至少一人通过）→ 已通过
待审批 →（任一审批人驳回）→ 被驳回（终态）
待审批 →（资产被下架 / 资产被删除 / 申请人账号被 Alice 停用）→ 已取消
已通过 →（Owner 取消 / 订阅者退订 / 资产被下架 / 资产被删除 / 订阅者账号被 Alice 停用）→ 已取消
```

- **「重新申请」一律新建记录**，不是原地流转：「被驳回」与「已取消」均为终态，重新申请是**以原申请内容预填的新建动作**，原记录连同其驳回理由、驳回人与时间永久保留（§9.8 审批留痕）。订阅者中心对同一资产的多次申请折叠为时间线展示；「被驳回」统计卡按历史累计计数。

- 「已通过」是唯一可使用资产的状态；「已取消」后使用授权立即失效。不设「已挂起」中间态。
- **「已取消」记录取消来源**（记录属性，不新增状态节点）：主动退订 / Owner 取消 / 资产被下架 / 资产被删除 / 账号失效。订阅者中心与资产控制台的列表行内标注来源；**Owner 取消订阅须必填理由**（与下架必填原因同构）并随通知发给被取消方。取消来源不限制重新申请。
- **主体侧失效**：订阅者或申请人的账号被 Alice 停用时，其「待审批」申请转「已取消」（审批人待办同步清除，复用下架的清除机制）、其「已通过」订阅转「已取消」（来源＝账号失效），并从热门榜的「已通过订阅数」统计中排除。其名下 PAT 与个人出站凭据同时失效（§9.3）。
- 「已取消」是**终态**：资产重新上架**不恢复**订阅，订阅者需重新提交申请（新建记录）并重新走审批链；PAT 集成场景还需在密钥库重新勾选该资产范围。平台在资产重新上架时通知下架时刻的存量订阅者与待审批申请人（不附一键重新申请入口，申请人自行从资产详情页发起）。
- **资产下架时的在途申请**：该资产全部「待审批」申请自动转「已取消」，申请人收到的下架通知中一并告知其申请已取消（不单发独立通知），审批人待办同步清除。
- **审批链为并行多级结构**：申请提交后**全部级同时收到待办，级与级之间没有先后依赖**；每级至少一人通过即该级通过，全部级通过则申请通过。任一审批人驳回即整单驳回。
- **死锁兜底**：某级已无任何有效审批人（离职或账号被 Alice 停用）时，该级自动回落由任一 Owner 或 Deputy 审批，审批记录中标注回落。审批人有效性在申请提交时与每次审批动作时实时校验（账号被 Alice 停用即视为无效），级内全部失效即刻触发回落。
- **孤儿资产订阅入口关闭**：提交申请时校验该资产至少有一名有效 Owner 或 Deputy；全部失效时订阅入口禁用并提示「该资产负责人暂不可用，暂不接受订阅申请」，直至平台管理员补员（§9.1.2）。
- **在途申请锁定快照**：申请提交时快照当时的审批链，按该快照走完；Owner 修改审批链仅对新申请生效。
- 使用条款的版本号、确认人、确认时间随订阅记录持久化。条款升版经轻发布生效并**通知存量订阅者与该资产的待审批申请人**，但不阻断其继续使用、不要求重新确认；版本历史留痕可溯。**在途申请的条款版本以审批通过生效时刻的现行版本为准**——若审批期间条款升版，该申请生效时适用新版；升版通知同时发给待审批申请人，使其在获批前知情（该口径的合规影响见 §13.9 待确认清单）。
- 平台管理员不参与常规订阅审批。
- Owner 关闭审批链时，订阅申请直接进入全体 Owner 与 Deputy 的待办队列，任一处理即可，不会自动通过。
- Owner 取消订阅、资产被下架时，受影响方收到站内通知。

### 9.2.1 知识授权审批

知识库与目录的权限申请为**单级审批**，由上级目录控制角色持有人处理，不适用上述并行多级结构。

### 9.3 凭据规则

- **出站凭据两层模型**（依据 `docs/adr/0014`）：
  - **资产级服务凭据**是默认形态：每资产一份，由 Owner 配置、密钥库托管，该资产的全体调用共用。资产在鉴权配置中声明为「服务间鉴权」时适用。鉴权声明变更时 Owner 更新此一处，订阅者零感知、零操作。**鉴权声明属版本类配置、密钥值属热改类**（§9.1.1）：密钥轮换与泄露处置即时生效，不经发布流程。
  - **个人出站凭据**仅适用两类情形：资产声明为「按人鉴权」时由各订阅者配置；知识库的三个外部导入通道使用操作人个人凭据（目标为对应的平台原生工具）。
  - **平台资源凭据**由平台管理员维护，仅用于平台自有资源（Nexus 模型令牌、平台原生工具在对话场景使用的平台内置统一凭据等）。
  - **平台原生工具的凭据主体按内容去向划分**：对话中经平台 Chat agent-runtime 调用，结果仅回提问者本人，用平台内置统一凭据；知识库导入的内容沉淀进共享库并被全体知识库 Consumer 检索，用操作人个人凭据——「操作人只能导入其在来源系统中有权阅读的内容」这条权限防线保留在导入侧。**P0 不开放经 PAT 调用平台原生工具**（依据 `docs/adr/0015`）。
- **按人鉴权资产不设兜底**：调用者未配置、凭据已过期或调用失败时，调用失败并引导至密钥库配置，**不回落至任何共享身份**——共享身份会击穿目标服务的按人授权。
- **质量门控保障可用性**：服务间鉴权资产的「资产级服务凭据已配置且探测可用」是质量门控项，在架资产因此开箱可调，无需运行时兜底。
- **审计**：每次调用记录实际使用的凭据主体（资产级服务凭据 / 个人出站凭据 / 平台资源凭据）。
- **管理员停用优先于一切解析**：平台管理员按资产维度停用某资产的出站调用后，该资产的资产级服务凭据与全部个人出站凭据的解析一并禁用，平台网关不再为该资产发起出站调用，任何调用方（含持 PAT 的外部系统）均调用失败并收到明确提示；恢复需平台管理员手动解除（依据 `docs/adr/0009`）。
- **PAT 唯一入站**：PAT 是外部系统调用本平台全部开放接口（资产调用、知识库三接口）的唯一入站认证凭据，统一在密钥库签发与吊销。PAT 调用服务间鉴权资产时由平台以资产级服务凭据发起出站调用；调用按人鉴权资产时需持有人本人已配置个人出站凭据。
- **PAT 范围约束**：PAT 可勾选的对象为持有人已获授权对象的子集（已订阅的资产、有权限的知识库；平台原生工具不在其列）。当某项授权失效（订阅被取消、资产被下架或被删除、知识库权限被 Alice 回收）时，该 PAT 对**该对象**的访问立即失效，PAT 本身及其对其他对象的访问不受影响。
- **主体侧失效**：持有人账号被 Alice 停用时，其名下**全部 PAT 与全部个人出站凭据立即失效**——这与上述「对象侧失效」并列为两类失效来源。恢复账号后需重新签发（原令牌不复活）。
- **有效期起算**：PAT 有效期自创建时刻起算，默认 90 天。

### 9.4 发布准入测评规则

- 被测对象锁定为待上架的 Agent（MCP 不执行发布准入测评，其工具描述与返回内容的安全由运行时输出侧护栏覆盖，依据 `docs/adr/0008`），测评模板锁定为发布准入测评模板，Owner 不可更换。
- **通过判定**：三类测评（提示词注入、意图偏离、内容安全）**各自有独立的通过阈值**（如「未被诱导样本占比」），阈值由平台管理员在准入测评模板中维护、随部署给出初值。**三类均达标才算整体通过**——不加权、不允许一类的高分拉平另一类。整体未通过时是否阻断上架，由平台管理员配置的单一总开关决定（M8-2，默认关闭）。分项得分与各类阈值在资产详情页的测评信息页签展示。
- Agent 的版本发布（含首发与重新上架）前测评必须执行；纯使用条款的轻发布豁免测评。执行结果（通过或未通过）与执行时间回写资产状态。测评执行失败（基础设施原因）视同未通过，可重测。
- **测评结果是执行时点的快照**。详情页展示执行时间并明确标注时效性；持续安全责任归业务场景方，重测由 Owner 通过发布新版本驱动（依据 `docs/adr/0011`）。
- 测评模板的问题集仅平台管理员可修改，修改不影响已完成的历史测评记录。
- 准入测评的裁判模型复用模型清单中的对话类模型。

### 9.5 护栏运行时规则

- 平台网关是护栏的唯一执行点，对一切经平台流转的对话（资产 Agent 会话与平台 Chat agent-runtime 会话）生效。
- 每个资产 Agent 绑定恰好一个启用状态的护栏策略模板；平台 Chat agent-runtime 适用平台默认护栏策略模板。任一会话恰好适用一个模板，不存在叠加。
- 模板条目由护栏、灵敏度与作用侧组成；作用侧（输入侧、输出侧或双侧）由平台管理员逐护栏配置。模板条目明细对 Owner **只读可见**（创建向导与资产控制台改绑界面展示），Owner 不参与数值配置。
- **平台默认模板恒在**：当前充当平台默认护栏策略模板的模板不可直接停用——平台管理员须先指定另一启用状态的模板为新默认，原模板方可停用。平台 Chat agent-runtime 的会话始终有模板适用。
- **命中即拦截**：输入侧命中直接拦截并拒答；输出侧命中拦截并以「已拦截」占位文本替代原输出。响应中回传命中的护栏类型。平台不设脱敏与告警档位，废弃置信度分档。
- **与流式输出的关系**：输出侧检测针对**完整回答**执行——平台网关缓冲模型输出的完整内容，检测通过后按段回放给用户（保留逐段到达的观感）；命中则全文不下发。用户中止生成时，对已生成部分同样先执行输出侧检测，通过后方可回放。回答首段的到达延迟因此包含全文生成与检测时长。
- 灵敏度取值 0 至 100，数值越高越容易命中，是护栏行为的唯一旋钮。
- 模板修改对已绑定 Agent 即时生效；模板停用只影响新绑定，存量 Agent 继续按该模板运行直到 Owner 改绑（改绑在资产控制台执行，即时生效）。**但下一次质量门控重跑（版本发布或重新上架）时强制校验所绑模板处于启用状态**，未启用则阻断并引导改绑。
- 外部接入的 MCP 不单独绑定护栏；其返回内容进入对话上下文后由输出侧检测覆盖。
- 对话中上传的临时文件内容**视同用户输入**，纳入输入侧护栏检测，命中处置相同（拒答并回传护栏类型）。临时文件上传为 P1 功能（M1-4），本条规则随其上线生效。

### 9.6 知识库与文件状态机

**知识库三态**（依据 `docs/adr/0013`）：

```
草稿 →（库内首份文档完成向量化）→ 可用 ⇄（知识库 Owner 手动停用 / 重新启用）→ 已停用
可用 →（删除库内最后一份已向量化文档）→ 草稿
```

**执行主体**：上述由「知识库 Owner」执行的动作，在**我的目录**的知识库中由**创建者本人**执行（我的目录不调用 Alice、不存在角色概念，见 §9.7）。

| 状态 | 含义 | 可被挂载与检索 |
| --- | --- | --- |
| 草稿 | 已创建，尚无任何文档完成向量化 | 否 |
| 可用 | 至少一份文档已完成向量化 | 是 |
| 已停用 | 知识库 Owner 手动停用 | 否 |

- 转为「可用」是自动的，不设人工发布闸门。
- 全库重建期间知识库保持「可用」，继续以旧索引提供检索，避免重建造成空窗。
- 草稿状态的库对其创建者与知识库 Owner 仍可见可编辑，只是不可被消费。
- **知识库删除**：知识库 Owner 可执行，需二次确认；「可用」状态的库须先停用方可删除。删除为**系统软删除**——知识库卡片对全部用户不可见、不参与挂载与检索，数据清理周期随 §9.8 由合规确认；公共目录的知识库删除后，平台调用 Alice 接口清理该库的三个角色。软删除的知识库不计入目录删除前置条件（§9.7）。
- **文档删除**：知识库 Owner 与知识库 Contributor 可删除库内文档（我的目录为创建者本人）。**回「草稿」仅对「可用」态生效**：处于「可用」的知识库删除其最后一份已向量化文档时自动回「草稿」；处于「已停用」的知识库**不因文档删除而改变状态**——否则 Contributor 的删除动作会静默解除知识库 Owner 的停用决定，离开「已停用」只能由知识库 Owner 显式操作。
- **挂载采用会话级快照**：会话挂载知识库时锁定快照，会话存续期间不因该库随后被停用、回「草稿」、被软删除或调用者权限被回收而改变检索行为，直至会话结束（新会话按最新状态与权限计算可选范围）。因此知识库停用**对新会话生效**，不中断进行中的会话（该口径与止损时效的关系见 §13.9 待确认清单）。
- **构建互斥**：同一知识库任一时刻至多允许一条构建流水线。全库重建进行中时，库级参数保存、新的一键构建、分阶段构建、切片编辑保存与文档导入均被阻断并提示当前重建进度；构建完成或失败的通知发给触发者与知识库 Owner。
- **构建中的检索一致性**：正在重建的文档沿用其上一次成功的向量化结果参与检索，直到新结果就绪（库级规则「重建期间保持可用并服务旧索引」在文件级的延伸）。全库重建后若存在构建失败文档，在知识库详情页与挂载列表中标注「部分文档构建失败」；若已向量化文档数归零则回「草稿」。
- **向量化模型的更换**：向量化模型与向量数据库锁定在库级，唯一允许突破该锁定的动作是「更换知识库向量化模型」（知识库 Owner 执行，触发全库重建）。若无此动作，知识库的向量化模型选择将终身不可逆。

**文件五态 + 失败态**：

```
未解析 → 已解析 → 已切片 → 已增强 → 已向量化
任一阶段失败 → 构建失败（记录失败阶段与原因）
构建失败 →（修复后从失败阶段重跑）→ 该阶段及后续阶段
已向量化 →（切片编辑保存 / 库级参数变更触发全库重建）→ 重新增强与向量化
任一状态 →（知识库 Owner 或 Contributor 删除文档）→ 已删除（终态）
```

- 与手动分阶段构建的「前序阶段未完成则后续阶段锁定」规则一一对应。
- 只有「已向量化」的文档参与检索。
- 构建失败的文档在列表中置顶，可修复后从失败阶段重跑。

### 9.7 知识治理规则

- 知识库只能创建在叶子目录；知识库创建后**不可在既有目录之间移动、不可复制**。
- 公共目录建库时平台调用 Alice 接口创建该知识库的三个角色；**我的目录建库不调用 Alice，创建者是其唯一使用者，不存在角色概念**。
- 公共目录与知识库的角色由平台在对象创建时调用 Alice 接口发起创建，Alice 是存储与真相来源。
- 公共目录建库时，平台在调用 Alice 接口创建该库三个角色的同时，将**知识库 Owner 角色授予创建者**（建库者即刻可管理自己的库）；知识库 Contributor 与知识库 Consumer 的授予与回收由上级目录控制角色审批（单级审批，§9.2.1）。
- 平台管理员仅负责冷启动：创建一级目录并指定一级目录控制角色与知识库创建角色的持有人；其余层级的角色授予与回收由上级目录控制角色审批维护。
- 父级目录的目录控制角色自动拥有其全部子级目录的控制权限。
- 目录的日常维护（重命名、新建子目录、在知识库上层增加层级并迁入）由目录控制角色持有人在平台内直接操作，即时生效，平台负责同步至 Alice。
- 在已含知识库的目录下创建子目录时，该目录原有的知识库整体迁入新建的子目录（下沉分层）。这是唯一允许的移位方式：发生在同一目录控制角色的子树内，控制链不变，知识库的 Alice 角色与权限 ID 不变。
- 目录删除的前置条件：该目录及其所有子目录下的知识库数量为零（软删除的知识库不计入）。
- 我的目录中的知识库仅本人可见可用；其全部管控动作（停用与重新启用、文档删除、知识库删除、子目录维护、更换向量化模型）由**创建者本人**执行，不存在角色概念。创建者账号被 Alice 停用时，其我的目录下的知识库随之软删除（§9.6）。
- 知识库构建所需的外部服务凭据在平台侧只保存密钥库中的引用位置，不保存明文密钥。
- **导入权限与通道凭据**：执行导入需操作者具备该知识库的**知识库 Contributor 及以上权限**（我的目录为创建者本人）。三个外部通道经对应的平台原生工具拉取，使用**导入操作人在密钥库配置的个人出站凭据**（未配置时引导至密钥库配置），操作人只能导入其在来源系统中有权阅读的内容；P1 定时同步的凭据主体与「配置人离职导致同步中断」的风险随 P1 规划展开（§13.9 第 9 项）。
- **内容准入责任归建库方**：导入外部来源文档即代表建库方（知识库创建角色持有人及其后的知识库 Owner）确认该内容可被本库全体知识库 Consumer 检索；平台不复制来源系统的权限模型（与 `docs/adr/0004` 的业务方自负其责定位同构）。权限放大风险已向合规明示（§13.9 第 8 项）。
- 知识库的「可见范围」是**卡片可发现性**控制，不是访问控制：「公开」表示知识库卡片对全员可见（无权限者点击展示 Alice 权限 ID 与申请入口）；「不公开」表示卡片仅对已有权限者可见，其他用户只能经 Alice 申请权限。访问权限始终由 Alice 唯一决定。公共目录建库默认为「公开」；我的目录的知识库仅本人可见，不适用该字段。

## 11. 验收标准框架

- **验收原则**：只验证外部可观察的行为与状态流转，不验证内部实现方式。以 §6 用户旅程为端到端验收脚本，以 §8 用户故事为验收清单索引。
- **必须覆盖的验收点**：
  1. 订阅引擎：表单定义解析与异常回退、使用条款勾选门控、**并行多级审批（各级同时收到待办、每级至少一人通过、任一驳回即整单驳回）**、**死锁回落至 Owner**、**在途申请锁定审批链快照**、驳回与重新申请、Owner 取消与订阅者退订、被取消方通知、**下架时待审批申请自动取消并通知申请人且审批人待办清除**、**资产重新上架不恢复订阅并通知下架时刻的存量订阅者与待审批申请人**。
  2. 资产生命周期：质量门控按资产类型的硬阻断（Agent 七项含**负责人冗余**与**护栏模板启用态**、MCP 六项）、测评阻断开关开启与关闭两种情形、**MCP 不经准入测评直接上架**、**下架需二次确认与必填原因**、**下架使全部订阅失效并通知（附原因）**、**下架后一切经平台流向该资产的调用失败并返回明确提示、入口置灰**、**已下架资产可编辑未发布修订并据此重新上架**、**重新上架为版本号递增的新版本发布**、**已下架资产的五界面表现**、**平台管理员无法改变资产状态**、**出站调用停用与资产状态正交（重新上架不自动解除）**、**下架自动退出推荐位且重新上架不自动回位**。
  3. 凭据规则：**服务间鉴权资产由平台以资产级服务凭据发起调用、订阅者零配置**、**按人鉴权资产未配置个人凭据时调用失败且不回落共享身份**、**鉴权声明变更后订阅者无需任何操作**、审计记录实际凭据主体、PAT 唯一入站与范围子集约束（**含我的目录知识库**）、授权失效时的联动失效、知识库写接口的知识库 Owner/Contributor 权限校验、**管理员停用出站调用后的调用失败与提示**。
  4. 知识管线：目录删除阻断、叶子目录建库限制、**知识库不可在既有目录间移动、不可复制（子树内下沉分层除外）**、我的目录免授权且不调 Alice、目录操作即时生效与 Alice 同步、参数作用域覆盖规则。
  5. **知识库与文件状态机**：首份文档向量化后知识库自动转「可用」、草稿与已停用库不出现在挂载列表、全库重建期间保持可用并服务旧索引、文件五阶段推进与失败态记录失败阶段。
  6. 护栏：模板必选且恰好一个、默认模板覆盖平台 Chat agent-runtime 会话、作用侧配置生效、命中即拦截并回传护栏类型、模板修改即时生效与停用只影响新绑定、**门控重跑时校验所绑模板处于启用状态**。
  7. Alice 集成：角色由平台调接口发起创建、授权结果同步展示、申请跳转、**知识授权为单级审批**、平台侧不可修改授权决策。
  8. 版本与变更：**未发布修订与在架版本并存且在架版本持续服务**、**修订载荷仅含版本类配置与使用条款**、**新版上架整体替换且订阅者自动跟随**、**一切版本替换均通知订阅者（申报者附影响说明与迁移指引、未申报者为轻量通知）**、**使用条款轻发布生效并通知存量订阅者且不要求重签**、测评快照时间展示、**热改类即时生效且不影响在架可见性**。
  9. **对话工作台与会话边界**：**Chat 不调用任何资产**（对话中不出现资产 Agent 与资产 MCP 的调用）、**知识库挂载仅在 Chat 会话可用**（资产 Agent 会话无挂载入口）、**MCP 无「去使用」入口**、平台原生工具免启用可用且对话中使用平台内置统一凭据、**详情页按订阅状态分层**（未订阅不可见服务地址与接口清单）、抽屉两区与三种点击去向、四类资产不可用文案。
  10. **资产终局与并发**：未发布三态与已下架可软删除且对全部用户不可见、「已发布」删除被阻断并提示先下架、**发布进行中下架被阻断且「中止发布」可解锁**、发布语义按完成时刻状态判定、热改类并发写入被版本校验拒绝、同一知识库并发构建被互斥阻断。
  11. **通知与知情**：十二类事件的受众正确（尤其条款升版含待审批申请人、Health Check 连续失败通知负责人、出站停用附必填原因）、出站停用状态在资产控制台常驻可见。
  12. **权限与初始化**：未配置映射的 Alice 角色可正常对话与浏览（基线权限）、**审批人可从创作者中心进入审批人视图且无发布与热改权限**、部署初始化清单中的六类对象在首次启动后即存在。
- **端到端脚本**：P0 范围内的旅程 J1、J2、J4、J5、J6、J7、J8。
