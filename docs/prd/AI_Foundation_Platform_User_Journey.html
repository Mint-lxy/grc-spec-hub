三、用户旅程：发现资产、申请订阅、开始使用

3.0

业务上下文（来源：用户旅程文档）

用户在日常工作中需要使用一个 Agent 或 MCP。用户的核心目标是先在平台中找到适合自己业务场景的资产，再提交订阅申请、获得使用授权，并清楚知道订阅需要填写什么、由谁审批、审批通过后如何使用，以及后续资产变化会怎样影响自己。

  • 发现与判断：用户进入 Marketplace 后选择 Agent 或 MCP 频道，通过推荐、热门、全部列表或搜索浏览资产。列表只展示状态为「已发布」且质量门控全部通过的资产，资产卡片展示名称、类型、业务标签、状态、是否按人鉴权以及健康检查结果。Agent 详情包含基本信息、接入配置、测评信息和发布记录；基本信息展示能力标签、适用场景和负责人，测评信息展示准入测评结果、分项得分和执行时间，发布记录展示版本、发布说明和变更记录。MCP 详情包含基本信息、接入配置、工具能力和凭据状态。未订阅用户只看到订阅决策所需信息。
  • 提交申请：用户在详情页点击「订阅」后直接进入单页申请。申请表包含资产说明、业务系统、使用场景和创建者配置的自定义字段，并展示当前版本使用条款与并行多级审批人链。用户勾选同意后一次提交；申请记录锁定审批链快照，使用条款版本以审批通过生效时刻的现行版本为准。
  • 跟踪结果：用户可在订阅者中心通过「已通过、待审批、被驳回、已取消」四类统计查看申请状态；点击统计卡可查看对应资产，悬停状态可查看各级审批进展。待审批时可查看各级审批进展；被驳回时可查看理由并重新申请；已取消时可查看取消理由与取消来源。
  • 使用平台 Chat：用户登录后可直接进入对话工作台，默认使用平台 Chat；可选择模型、挂载有权限且可用的知识库，并调用平台原生工具。回答经过护栏检测后按段展示，可查看思考过程、检索证据和引用来源，也可随时停止生成。
  • 使用已订阅 Agent：Agent 订阅通过后，详情页出现「去使用」。用户进入该 Agent 的专属对话页，页面顶部展示 Agent 名称；该会话不能挂载知识库，能力以 Agent 自身返回内容为准。
  • 使用 MCP：MCP 不是对话对象，不能在 Chat 中直接调用；可由已订阅 Agent 的服务端接入，也可由外部系统通过平台开放接口调用。服务间鉴权通常无需用户配置凭据；按人鉴权时，用户需要在密钥库配置个人凭据，缺失或失效时调用失败且不使用共享身份替代。
  • 订阅变化与后续管理：资产下架时，已通过订阅失效、待审批申请自动取消，用户收到附原因的通知。资产重新上架后，原订阅不会自动恢复，重新上架通知不附带一键重新申请入口，用户需要从资产详情页重新申请。资产发布新版本或使用条款升版时，订阅者与待审批申请人会收到通知；申报为强治理变更时，通知附带影响说明与迁移指引。不再需要资产时，用户可在订阅者中心主动退订。

四、创建者旅程：创建、上架、维护 Agent 或 MCP

4.0

业务上下文（来源：用户旅程文档）

创建者希望把自己的 Agent 或 MCP 发布到平台，让其他用户订阅使用。创建资产的用户自动成为该资产的首位创建者，也可以在创建过程中增加共同创建者和 Deputy，保证后续有人共同维护资产、审批订阅申请并处理上下架。

  • 创建高代码 Agent：从创作者中心点击「创建 Agent」，选择高代码方式并接入已部署的 Agent 服务。依次完成基础信息、接入配置、鉴权配置、能力声明、订阅申请表单、使用条款、审批人链、护栏策略模板和发布说明。鉴权支持静态凭据与动态凭据，可声明 API Key、Bearer Token、OAuth2 或自定义 Header；服务间鉴权资产需要配置并探测资产级服务凭据。
  • 创建低代码 Agent（二期能力）：选择有创建权限的 Dify 工作区，前往 Dify 完成应用编排。Dify 侧发布只表示应用可在 Dify 中运行，不代表已经在本平台 Marketplace 上架；平台同步元数据后，创建者仍需补齐治理字段，并继续走平台上架流程。
  • 创建 MCP：从创作者中心点击「创建 MCP」，依次完成基础信息、链接配置、鉴权配置、能力声明、订阅申请配置和发布说明。
  • 测评并上架：Agent 通过质量门控后进入发布准入测评；三类测评均达到平台阈值才算整体通过。测评通过后可直接上架；测评未通过时是否阻断上架由平台管理员的阻断开关决定，默认不阻断。开关关闭时资产仍可上架，但详情页标注「准入测评未通过」。MCP 不执行发布准入测评，质量门控全部通过后即可自助上架。
  • 资产日常管理：创建者可在资产控制台查看基本信息、订阅管理、测评结果、发布记录和使用情况；可审批或驳回订阅申请，也可取消他人订阅并填写理由；可维护共同创建者和 Deputy，保证已发布资产始终满足负责人冗余要求。
  • 热改与版本变更：负责人名单、订阅申请表单、审批人链、护栏策略绑定、基础信息、超时与重试等配置可即时生效；服务地址、鉴权声明、能力声明等版本类配置通过未发布修订提交，重走门控与测评；只修改使用条款时走轻发布。发布完成前当前版本持续对外服务，新版本替换后全体订阅者自动跟随；创建者发布时显式申报是否为强治理变更，申报时必填影响说明与迁移指引。
  • 发布互斥与中止发布：资产处于发布进行中时，下架与删除会被阻断；任一创建者或Deputy可执行「中止发布」，中止后修订保留并通知发起人。
  • 下架与修复：创建者可在资产控制台下架资产，需要二次确认并填写下架原因。下架后订阅失效、待审批申请取消、审批人待办清除、平台调用停止。创建者仍可修改未发布修订并重新上架；重新上架不恢复原订阅，订阅者需重新申请。
  • 删除资产：已发布资产须先下架才能删除，未发布或已下架资产可直接删除。删除是终态，资产对全部用户不可见且不可恢复；订阅历史等业务记录永久保留，资产级服务凭据被清理，已签发的 PAT 对该资产的访问随之失效。

五、知识库管理员旅程：建库、导入、构建、开放使用

5.0

业务上下文（来源：用户旅程文档）

知识库管理员希望把业务资料整理成可检索的企业知识库，让有权限的用户可以在 Chat 中挂载知识库并检索，也让外部系统可以通过开放接口调用知识库能力。目录和知识库的权限以 Alice 为唯一授权来源；平台提供目录与知识库入口、展示权限状态、发起权限申请，并管理文档导入、解析和向量化流程。

  • 进入目录：知识库管理员进入知识管理，从目录树选择公共目录或我的目录。拥有目录控制权限的用户可在授权范围内新建子目录、重命名或删除目录；目录调整即时生效并同步至 Alice；含知识库的目录不允许删除。没有权限时，页面展示 Alice 权限编号并跳转权限申请，目录权限申请由上级目录拥有目录控制权限的用户单级审批。
  • 创建知识库：在叶子目录创建知识库。公共目录建库需要知识库创建权限，建库者自动获得知识库 Owner 权限；我的目录由创建者本人直接管理，知识库仅创建者本人可见和使用。建库时填写名称、可见范围、描述和标签，并配置解析、切片、内容增强、向量模型和向量库实例；默认采用 Docling 解析、语义切片、摘要与关键词增强、BGE-M3 向量化和 Milvus 存储。可见范围只控制卡片可发现性，访问权限始终由 Alice 决定；公开知识库卡片对全员可见，无权限用户点击后可看到 Alice 权限编号和申请入口。知识库创建后不可在既有目录间移动、不可复制，唯一允许的移位方式是在同一目录控制权限的子树内下沉分层。
  • 导入文件：知识库支持四个导入入口：本地上传、Confluence、SharePoint 与 OneDrive、对象存储。执行导入需要操作者具备知识库 Contributor 及以上权限。本地上传支持单文件不超过 40 MB，也支持压缩包展开预览；只有外部通道导入才使用操作人在密钥库中配置的个人凭据。导入前提供文件预览，不支持的文件格式自动置灰。
  • 执行构建：导入后文件初始状态为「未解析」。用户可勾选文件后一键构建，也可切换手动模式按阶段执行；手动模式下前一阶段未完成时，后一阶段不能执行。平台按解析、切片、内容增强、向量化四个阶段处理文件；构建失败时展示原因，失败文件置顶，可修复后从失败阶段重新执行。
  • 知识库转为可用：库内首份文件完成向量化后，知识库自动从「草稿」转为「可用」。只有可用的知识库才会出现在 Chat 挂载列表，并可被开放接口检索。全库重建期间继续使用原有索引，不会因重建而暂时失去检索能力。
  • 知识库详情：详情页展示文档数、切片数、向量数和就绪度，并包含文档、设置、总览三个区域。知识库卡片支持查看权限、重命名和删除。设置区域用于维护库级默认参数，保存库级解析器、切片或内容增强配置会触发全库重建；向量模型和向量数据库锁定在知识库级别。总览区域用于查看知识库描述、内容摘要、构建状态和可共享能力。
  • 文件与内容维护：用户可进入文件详情页分页预览源文件，查看解析后的内容、文档摘要、关键词和解析信息；可搜索并逐条编辑切片，保存后重新执行内容增强和向量化。也可批量调整文档级参数，范围限于解析器、切片策略和内容增强。知识库 Owner 或知识库 Contributor 可删除库内文档，删除后的文档不再参与检索。
  • 停用与删除：知识库 Owner 可停用知识库，停用后新会话不再挂载或检索，进行中的会话继续使用会话级快照直至结束。知识库 Owner 可删除知识库；可用状态的知识库须先停用，删除需要二次确认。公共目录下的知识库删除后，平台调用 Alice 清理该知识库的角色。

六、平台管理员旅程：测评、护栏与管理后台治理

6.0

业务上下文（来源：用户旅程文档）

平台管理员负责维护平台统一的测评基线和护栏基线，为创建者的 Agent 发布提供质量与安全判断依据。平台管理员不直接审批用户的资产订阅，也不代替创建者上下架资产；管理员主要维护模板、开关、平台资源和运行控制。

  • 测评管理：平台管理员维护发布准入测评模板，覆盖提示词注入、意图偏离和内容安全三类问题集，并为三类测评分别设置通过阈值。发布流程中的准入测评由创建者触发；独立的测评中心、数据集管理、任务中心和对比报告属于二期能力。
  • 测评模板配置：二期模板可配置裁判模型、被测 Agent、数据集、测评指标、并发度、单条样本超时、失败重试次数和失败处理策略。部分指标要求数据集提供预期输出；数据集缺少预期输出时，平台提示相关指标不可用。任务绑定模板与数据集快照，后续修改模板或数据集不影响已完成任务结果。
  • 数据集与任务（二期能力）：管理员可导入、校验、复制和编辑数据集，也可创建测评任务、查看运行状态、样本明细、重试失败样本并导出结果。
  • 护栏策略：平台管理员创建、编辑、启用或停用护栏策略模板，配置护栏组合、灵敏度和作用侧；护栏可覆盖个人信息识别、毒性内容过滤、提示注入和违禁词。管理员还需指定一个全局唯一的平台默认模板，用于平台 Chat 会话；当前默认模板不能直接停用，需要先指定另一个启用模板。
  • 运行时生效：创建者创建 Agent 时，只能从启用模板中选择一个并绑定，并可只读查看模板明细。平台网关对 Chat 和资产 Agent 会话执行护栏检测；输入侧命中时直接拒答，输出侧命中时拦截原回答并展示命中的护栏类型。模板修改对已绑定 Agent 即时生效；模板停用只影响新绑定，但资产下一次发布或重新上架时会强制校验所绑模板仍处于启用状态。
  • 运营看板（二期能力）：管理员可查看各策略的检测量、命中率、近期拦截次数和命中记录，并据此调整护栏组合、灵敏度与作用侧。
  • 管理后台治理：管理员在治理中心查看全平台资产、按资产维度停用或恢复出站调用、为孤儿资产补充新负责人；同时维护平台原生工具、平台资源、推荐位、用户视图、角色映射、公共目录冷启动和模型清单。

七、密钥库旅程：个人访问令牌与个人出站凭据

7.0

业务上下文（来源：用户旅程文档）

用户在调用按人鉴权资产、导入外部知识来源、通过开放接口集成外部系统，或使用个人模型能力时，需要在密钥库中管理自己的凭据。密钥库只管理用户侧凭据的两个入口：入站的个人访问令牌，以及出站的个人凭据。资产级服务凭据由创建者在资产配置中维护；平台资源凭据由平台管理员在平台资源注册表中维护。

  • 入站个人访问令牌：用户创建令牌时填写名称和有效期，默认有效期为自创建时刻起算 90 天。令牌权限范围只能选择用户已经订阅或已经获得权限的资产和知识库，外部系统如需调用 MCP，也需勾选对应的已授权 MCP；选择时进行权限校验。令牌明文只在创建成功时完整展示一次；用户可停用、删除或重新生成令牌，停用和删除需要二次确认，重新生成后原令牌立即失效。
  • 按人鉴权资产凭据：目标列表只展示用户已订阅且声明按人鉴权的资产。平台根据资产声明的鉴权方式生成认证表单，资产已声明字段只读，用户填写个人凭据并执行一键探测。凭据未配置或探测失败时，平台不会在资产调用中回落到共享身份。
  • 外部知识来源凭据：用户可为 Confluence、SharePoint 与 OneDrive、对象存储三个知识导入通道配置凭据。执行导入时，用户还需要具备目标知识库的知识库 Contributor 或更高权限。
  • 个人模型凭据：用户可配置多条个人模型凭据，通过启用、禁用和排序决定使用顺序。保存后平台执行一次模型可用性检测并保存结果，用户也可手动刷新。后续模型调用优先使用可用个人凭据，无可用个人凭据时使用平台默认凭据。真实调用发生鉴权或权限失败时，本次调用改用平台默认凭据，并通知用户更新凭据或申请模型权限；瞬时故障不改写检测结果，也不发送通知。
  • 凭据展示与维护：个人凭据的密文字段默认掩码展示，用户可查看明文，查看动作会被记录。用户可更新、停用、删除或重新探测凭据。
