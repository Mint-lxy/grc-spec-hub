# J1 普通用户：发现资产 → 订阅 → 使用

## 场景、角色与意图

用户在日常工作中需要使用 AI Agent 或 MCP，希望在平台中找到合适的资产，再完成订阅申请并获得使用授权。
用户不需要了解资产的内部实现，只需通过 Marketplace 判断资产是否适合自己的工作，清楚订阅需提交的信息、审批情况、如何使用，以及后续资产发生变化时的影响。

## 一. 进入 Marketplace 浏览资产

1. 用户进入 Marketplace 后，选择 Agent 或 MCP 频道。页面提供热门和全部列表，用户可浏览平台中已经上架的资产，也可以使用搜索框按照资产名称、业务标签和简介进行搜索。
2. 列表只展示状态为“已发布”且上架时点质量门控全部通过的资产；其中智能体的质量门控包含“所绑护栏策略模板处于启用状态”。模板后续停用不影响存量在架资产的列表可见性，仅在下一次门控重跑时校验。用户通过资产卡片，可以看到名称、类型、业务标签和当前状态；Health Check 连续失败的资产会标注“当前不可达”，但不改变资产状态。用户可点击【详情】，进入资产详情页，查看详细信息。
3. 对于 Agent，详情页包含五个页签：基本信息、接入配置、测评信息、发布记录和凭据状态。未订阅时仅可见基本信息、测评信息和发布记录；接入配置中的服务地址、接口清单等细节，以及本人对该资产的个人凭据配置状态与配置入口，在订阅后可见。用户可以通过基本信息了解 Agent 能力标签、适用场景、负责人和最近一次 Health Check 结果，通过测评信息查看准入测评结果、分项得分和测评执行时间，通过发布记录了解版本、发布说明、强治理变更申报、使用条款版本历史以及相关变更记录。
4. 对于 MCP，详情页包含四个页签：基本信息、接入配置、工具能力和凭据状态。未订阅时仅可见基本信息；接入配置、工具能力和凭据状态在订阅后可见。用户需要先通过基本信息确认 MCP 是否适合自己的业务场景，再决定是否进入订阅流程。
5. 用户确认资产符合自己的需求后，在资产详情页点击“订阅”。点击后直接进入单页订阅申请，不再经过一个只展示资产说明的中间页面。

## 二. 提交订阅申请

1. 用户进入单页订阅申请页后，页面顶部展示资产说明摘要，包括资产名称、资产类型、资产拥有者。
2. 页面中部为申请信息。用户填写业务系统、使用场景，以及该 Owner 配置的自定义表单字段。自定义字段由 Owner 配置（YAML），用户按照页面要求填写相应信息。
3. 页面底部为确认提交区域。该区域展示当前版本的发布说明（Release Note）与订阅审批链概览；用户可展开查看全部审批人。使用条款默认收起，用户点击后可展开全文与版本号。用户确认信息后，勾选同意使用条款并提交申请。提交成功后，系统创建一条订阅申请记录，并将申请发送给对应的审批链。
4. 订阅申请提交后，用户可以进入【订阅者中心】跟踪申请状态。订阅者中心最上方提供四个状态统计卡，已通过、待审批、被驳回和已取消。点击对应的统计卡，会出现下拉列表，用户可以查看对应的资产和状态。
5. 用户在卡片右上角的状态悬停时，可以查看各级审批进展。审批链按并行多级方式推进：各级同时收到待办，每级至少一人通过；任一审批人驳回则整单驳回。对于被驳回的申请，用户可查看驳回理由，并通过【重新申请】再次提交。重新申请会创建一条新的订阅申请记录，原申请连同驳回理由、驳回人与时间永久保留，不会被新的申请覆盖。对于已取消的申请，用户可以查看取消理由和取消来源。取消来源可能是用户主动退订、Owner 取消、资产下架、资产删除或账号失效。

## 三. 进入平台 Chat

1. 用户登录平台后，可以直接进入对话工作台，默认使用平台 Chat。对话能力按会话类型分两类：平台 Chat agent-runtime 与资产 Agent。平台 Chat 的会话仅支持模型对话与知识库检索（检索证据、图片与插图内嵌），可开启深度分析、查看思考过程、选择对话模型（下拉列表只展示对话类与多模态类模型）；平台 Chat 不调用平台原生工具，也不调用任何资产。对话工作台提供资产 Agent 选择器（例如下拉菜单），用户必须显式选择要使用的资产 Agent；选择后会切换到该资产 Agent 的专属透传会话。资产 Agent 会话为透传会话，模型由该资产自身决定，用户不能在对话页选择模型。
2. 用户在 Chat 中输入问题后，平台执行输入侧和输出侧护栏检测。流式回答按滑动窗口检测并在窗口通过后释放内容；非流式回答先缓冲全文，检测通过后直接完整呈现。输出侧命中时平台立即终止生成、撤回已下发内容并展示护栏命中提醒与命中的护栏类型，命中轮次在历史回看中显示占位文案。用户可以查看思考过程、检索证据和引用来源，也可以随时中止生成。
3. 回答渲染能力（2026-08-25 裁定）：Markdown 表格过宽时支持横向滚动；代码块带语法高亮、行号与一键复制；支持 Mermaid 图表与数学公式渲染；流式输出期间版面防闪烁、不强制滚动到底部；长回答自动折叠可展开。Chat 的多模态输入（图片/文件理解）本期不支持，以资产原生视觉能力为主路线。
4. 用户可以在对话工作台中管理历史会话：按名称搜索、按 Agent 筛选、打开恢复继续对话、删除或新建会话。会话在服务端保留 90 天（自最后一条消息起算）。如果会话对应的资产已经下架，该会话仍可以打开只读回看历史消息，但不能再发送新消息。
5. 用户可以在对话工作台打开“我的资产”抽屉。抽屉分“已订阅”与“收藏”两区；收藏不要求先订阅。点击已订阅的 Agent 进入其对话页；点击 MCP 或未订阅资产进入详情页；已下架资产保留条目但置灰。

## 四. 订阅通过后使用 Agent

1. 当 Agent 的订阅申请审批通过后，用户可以在 Agent 详情页看到【去使用】入口，也可以在对话工作台的资产 Agent 选择器中显式选择该 Agent。两种入口都会进入该 Agent 的专属对话页，平台通过网关代理透传请求到该资产 Agent。
2. Agent 对话页的顶部会展示当前 Agent 的名称。该会话是资产 Agent 的透传会话，用户不能挂载知识库。资产 Agent 能提供哪些能力，以该资产自身返回的内容为准。
3. 用户在对话输入区提交问题后，平台网关执行统一的护栏检测。输入侧命中时直接拒答并展示命中的护栏类型；输出侧按流式滑动窗口或非流式全文缓冲检测，命中时撤回已下发内容并展示护栏命中提醒与命中的护栏类型。用户可以在生成过程中随时点击“停止生成”。
4. 平台内使用资产时，平台使用当前订阅者已为该资产配置并绑定的个人凭据发起调用，并在请求中传递当前用户身份上下文，供资产内部处理用户级数据权限。用户通过平台开放接口在平台外调用已订阅资产时，使用 PAT 作为入站认证；平台校验订阅后同样使用持有人的个人凭据调用资产。静态凭据未配置或未绑定时，页面引导用户配置凭据；动态凭据尚未完成代颁发时，页面展示“颁发中”或“颁发失败”状态。未配置、未绑定、凭据失效或调用失败时，资产调用失败，平台不使用共享身份替代。

## 五. 订阅通过后使用 MCP

1. 用户订阅 MCP 后，进入 MCP 详情页查看接入配置、工具能力和凭据状态。MCP 不是对话对象，不能在 Chat 中直接调用；它可以由已订阅的 Agent 服务端接入，也可以由外部系统通过平台开放接口调用。
2. 平台内由已订阅 Agent 服务端接入 MCP 时，平台使用当前订阅者已为该 MCP 配置并绑定的个人凭据发起调用。用户通过平台开放接口在平台外调用 MCP 时，使用 PAT 作为入站认证；平台校验订阅后同样使用持有人的个人凭据调用 MCP。静态凭据未配置或未绑定时，页面引导用户配置凭据；动态凭据尚未完成代颁发时，页面展示“颁发中”或“颁发失败”状态。未配置、未绑定、凭据失效或调用失败时调用失败，平台不会使用共享身份替代。

## 六. 订阅状态变化和后续管理

1. 如果资产在申请审批期间被 Owner 下架，所有待审批申请会自动转为“已取消”。用户收到的资产下架通知。
2. 订阅通过并开始使用后，若出现：订阅被 Owner 取消、资产被 Owner 下架、资产发布新版本以及资产使用条款更新等情况，用户均会收到站内通知。资产发布新版本时，若 Owner 申报为强治理变更，通知会附带影响说明与迁移指引；未申报时，用户收到轻量版本更新通知。资产重新上架会重走发布流程，由资产发布通知覆盖，不单独发送重新上架通知。
3. 如果资产在通过后被下架，通知中会附下架原因。用户原有订阅失效，待审批申请会被取消。资产重新上架后，原有订阅不会自动恢复，用户需要在看到发布通知后重新提交新的订阅申请。
4. 用户不再需要某项资产时，可以在订阅者中心主动退订。用户确认退订后，订阅状态变为“已取消”，使用授权立即失效。

# J2 Owner：创建 Agent / MCP 并自助上架

## 场景、角色与意图

创建者希望把自己的 Agent 或 MCP 发布到平台，让其他用户能够订阅使用。创建者需要完成资产信息、服务接入、鉴权、能力声明、订阅配置和安全校验；首次发布成功后转为 Owner，并继续处理订阅审批、资产维护和版本变更。
创建资产的用户在首发成功前是创建者；首次发布成功后才成为该资产首位 Owner。创建者在首发前必须指定不少于一位 Deputy（可多位），被指定者自动成为草稿协作者并与创建者同权限，首发成功时转为 Deputy，确保后续有人可以共同维护资产、处理订阅申请和执行资产治理操作。

## 一. 创作者中心，创建 Agent 资产

进入创作者中心，点击“+创建”，点击“创建 Agent”，选择高代码或低代码方式，进入对应的创建 Pipeline。

### (一) 创建高代码 Agent

1. 高代码 Agent 直接接入已经部署、符合 A2A 协议的服务，创建者完成六步创建向导。
2. 第一步：基础信息。创建者填写资产名称、分类和描述，并指定不少于一位 Deputy；被指定者自动成为草稿协作者，与创建者同权限。
3. 第二步：接入配置。创建者填写 Agent Endpoint URL；协议固定为 A2A 并只读展示；Health Check 为强制必选，支持一键探测，并配置超时与重试。
4. 第三步：鉴权配置。创建者选择静态凭据或动态凭据，仅声明凭据元数据（鉴权方式、变量名、注入位置、必填性；动态模式另含授权申请接口地址与令牌回写字段）。创建者全程不接触密钥值；后续资产调用统一使用订阅者个人凭据。
5. 第四步：能力声明。创建者点击“拉取 Agent Card”，平台从服务地址读取 Agent Card 和接口元数据，并以只读镜像方式展示协议版本、接口数量和鉴权方式。
6. 第五步：订阅配置。创建者通过 YAML 文件上传或编辑订阅申请表单，平台解析后实时预览；使用条款独立配置，必须包含条款内容和版本号；创建者配置并行多级审批人链，也可以关闭审批链。关闭审批链后，订阅申请进入全体 Owner 与 Deputy 的待办队列，任一负责人处理即可，不会自动通过。
7. 第六步：护栏策略与发布说明。创建者为 Agent 选择一个已启用的护栏策略模板，每个 Agent 必须绑定一个策略，创建者可以查看策略明细，但无法自行修改规则和灵敏度；随后填写 Release Note 并提交发布，之后进入质量门控、测评和发布流程。

### (二) 创建低代码 Agent（P1）

1. 前置条件：平台管理员已经在后台配置好 Dify 的实例与 Workspace。
2. 创建者点击“创建低代码 Agent”后，先选择自己有权限的“实例 + Workspace”。
3. 平台提供两种入口：其一，跳转 Dify 创建或编排新的 Agent；其二，展示该 Workspace 下已经建好的 Agent 列表，创建者勾选已有 Agent 接入平台。
4. 平台拉取目标 Agent 的元数据，落入该资产的未发布修订；之后平台会周期性重新同步该 Agent 在 Dify 里的最新元数据，同步结果同样落入未发布修订，由创建者确认后再发布生效，不绕过版本流程。
5. 创建者在平台内补录治理字段，包括名称、业务归属和简介，并完成订阅申请表单、使用条款、审批人链和护栏策略等平台治理配置。
6. 依次进入质量门控和发布准入测评，通过后创建者完成自助上架并转为 Owner。

## 二. 创作者中心，创建 MCP 资产

1. 进入创作者中心，点击“+创建”，点击“创建 MCP”。创建者共需完成五个步骤，分别是：基础信息、MCP 链接配置、鉴权配置、能力声明、订阅配置与发布说明。
2. 基础信息：创建者填写资产名称、分类和描述，并指定不少于一位 Deputy；被指定者自动成为草稿协作者，与创建者同权限。
3. MCP 链接配置：创建者填写服务地址；协议 P0 固定为 Streamable HTTP、托管方式 P0 固定为“远程服务（业务方自托管）”，均只读展示为接入要求；Health Check 为强制必选，支持一键探测，并配置超时与重试。
4. 鉴权配置：创建者选择静态凭据或动态凭据，并声明凭据元数据。静态模式说明订阅者需在平台外获取并在密钥库填入的凭据要求；动态模式声明资产提供的授权申请接口地址与令牌回写字段，订阅通过后平台代订阅者请求颁发动态凭据。
5. 能力声明：填写 MCP Manifest 链接并点击“拉取 Tool List”。平台读取 MCP Manifest，并以只读镜像方式展示工具名称、能力说明、参数摘要、鉴权方式和识别状态。
6. 订阅配置与发布说明：该步骤分两个子区域——订阅配置包含申请表单、使用条款与审批配置；发布说明用于填写本次发布的 Release Note。完成后提交发布。

## 三. Agent 创建后测评并发布

1. Agent 在成功通过质量门控后，将进入发布测评。创建者进入创作者中心，找到刚刚创建好的 Agent。此时 Agent 的状态为“待测评”，操作按钮为“去测评”。
2. 点击“去测评”后进入测评 Pipeline。发布准入测评使用平台管理员维护的全局准入模板，创建者不可选择或替换；模板覆盖提示词注入、意图偏离和内容安全三类测评。二期独立测评中心开放后，Owner 可在发布流程之外使用自助测评模板进行版本回归。
3. 查看测评结果页面，页面展示测评模板、测试能力和对应的测评进度。提示词注入、意图偏离、内容安全三类测评各自有独立通过阈值，三类均达到阈值才算整体通过。测评结果记录执行时间，并在资产详情页的测评信息页签中展示。
4. 测评通过后，创建者可以完成上架发布。测评未通过时是否阻断上架由平台管理员配置的阻断开关决定，默认不阻断；开关关闭时仍可上架，但资产详情页标注“准入测评未通过”。首次上架成功后，资产状态变为“已发布”，创建者转为 Owner、草稿协作者转为 Deputy，并进入 Marketplace 列表。
5. MCP 不执行发布准入测评。MCP 在质量门控全部通过后，可以直接完成自助上架；首次上架成功后同样完成创建者与草稿协作者的负责人身份转换。

## 四. 资产管理

1. 【创作者中心】主页顶部提供四个统计卡，按顺序展示：已创建资产、待审批订阅申请、已下架资产、待发布资产；其中“已创建资产”是统计口径，不是资产生命周期状态。Owner 点击对应统计卡后，可以查看对应的资产或订阅请求。
2. 统计卡下方分两个区域：我的资产、待我审批。Owner 点击创作者中心主页中的资产卡片，进入资产控制台。资产控制台支持查看基本信息、订阅管理、发布记录和每个订阅者的请求历史统计。订阅管理包括用户管理和订阅设置；用户管理支持订阅审批、驳回、查看订阅者信息和用量。订阅设置支持修改订阅申请表单与订阅审批人链。
3. Owner 可以在资产控制台取消他人的订阅。取消时需要填写取消理由，被取消的订阅者会收到通知，使用授权立即失效。
4. Owner 可以维护多个 Owner 与 Deputy。已发布资产在移除负责人时，不能使 Deputy 数为零；如果发布中的资产负责人不满足“已指定不少于一位 Deputy”的门控要求，平台会阻断发布，Owner 需要补充有效 Deputy。
5. 负责人名单、订阅申请表单、订阅审批人链、护栏策略模板改绑、资产基础信息、超时与重试配置等热改配置修改即时生效，不进入版本发布流程，也不触发质量门控和发布准入测评。订阅审批人链修改只对新申请生效，已提交的在途申请继续使用提交时的审批链快照。资产服务 Health Check 连续失败时，平台会通知该资产全体负责人，通知包含失败起始时间与连续失败次数。

## 五. 更新和下架

1. Owner 点击进入创作者中心，进入主页后，点击目标资产卡片。点击进入资产卡片内部后，右上角提供“发布新版”和“下架”两个操作。
2. Owner 点击“发布新版”后，进入未发布修订流程。页面中的版本类配置与使用条款默认沿用当前版本，Owner 只修改本次需要变更的内容；基础信息、订阅申请表单、审批人链等热改字段不在发布新版流程中修改，需要在资产控制台即时维护。
3. Owner 完成修改后提交，平台重新执行对应的质量门控。Agent 还需要执行发布准入测评。发布时，Owner 需要显式申报是否为强治理变更；凭据元数据变更必须强制申报为强治理变更，并填写影响说明与迁移指引。校验通过后，新版本发布并替换当前版本，订阅者自动使用新版本；在发布完成前，当前版本继续对外服务。发布（重跑质量门控与测评）进行中，有权用户可以点击“中止发布”终止本次发布；首发前有权用户为创建者与草稿协作者，首发后为 Owner 与 Deputy。中止后未发布修订会被保留、可以继续编辑，平台按阶段通知对应治理集合。发布进行中会阻断下架和删除操作，需要先中止发布才能执行。
4. 如果 Owner 只修改使用条款，系统按照轻发布处理，条款版本更新并通知存量订阅者与待审批申请人；不需要重新进行质量门控和发布准入测评，也不要求订阅者重新确认。
5. Owner 需要撤下资产时，点击资产卡片右上角的“下架”。系统弹出确认窗口，Owner 确认后填写下架原因并提交。资产状态变为“已下架”，所有已通过订阅立即失效，待审批申请自动取消，相关用户收到带有下架原因的通知。平台同时停止经平台流向该资产的调用，并返回“该资产已被下架”；已下架资产暂停 Health Check 周期探测与连续失败通知。
6. 资产下架后，Owner 仍可以点击“发布新版”进行修复。系统继续沿用原有配置，Owner 修改需要修复的内容后重新提交，并重新执行对应的质量门控和发布流程。修复发布成功后，资产重新上架，但原有订阅不会自动恢复，原订阅者需要重新申请。
7. Owner 需要删除资产时，可以点击“删除”。“已发布”状态的资产必须先下架才能删除；未发布或已下架的资产可以直接删除。删除是系统软删除终态：删除后资产对所有用户不可见，且不能恢复，但订阅历史等业务记录会永久保留；全部订阅者对该资产的个人凭据绑定随之失效，已签发 PAT 对该资产的访问也随对象侧失效。

# J3 知识维护员：目录管理 → 建库 → 构建 → 开放使用

## 场景、角色与意图

知识维护员希望把业务资料整理成可检索的企业知识库，让有权限的用户可以在 Chat 中挂载知识库并检索，也可以让外部系统通过开放接口调用知识库能力。
公共目录与公共知识库的权限和目录角色由 Alice 作为唯一授权来源；我的目录的平台内分享授权为例外，不调用 Alice。平台负责提供目录和知识库的操作入口、展示权限状态、发起 Alice 权限申请，并管理文档导入、解析和向量化流程。

## 一. 进入知识管理，选择目录

1. 知识维护员进入知识管理页面，从目录树中选择公共目录或我的目录。公共目录由目录控制角色持有人维护。目录控制角色持有人可以在范围内新建子目录、重命名、删除目录。知识库创建角色持有人可以在叶子目录创建知识库。目录结构调整后平台即时更新，并同步至 Alice。删除目录前，系统会检查该目录及其子目录下是否还存在知识库；存在知识库时不允许删除。
2. 如果用户没有访问某个目录的权限，点击受限目录后，页面展示对应的 Alice 权限 ID，并提供复制和跳转 Alice 申请的入口。目录权限申请采用单级审批，由上级目录控制角色持有人处理。
3. 我的目录由用户本人管理，默认不需要目录角色，也不经过 Alice 授权。我的目录下创建的知识库默认仅创建者本人可见和使用；创建者可以将原知识库分享给其他用户，被分享者不获得副本，而是在自己的“我的知识库”中的“分享给我的”子分区看到该知识库。分享授权为平台内授权，不调用 Alice；创建者可选择“可查看”或“可编辑”：可查看对应知识库 Consumer 的读取语义，可编辑对应知识库 Contributor 的读写语义。创建者可随时撤销分享授权；被分享者账号被 Alice 停用时，其分享授权立即失效；创建者账号被 Alice 停用时，其我的目录知识库随之软删除，全部分享授权同步失效。

## 二. 在叶子目录创建知识库

1. 拥有知识库创建角色的用户，可以选择一个叶子目录，点击“创建知识库”，进入建库向导。公共目录下，创建者需在建库向导中同时指定该知识库的知识库 Owner 与知识库 Deputy（可为创建者本人）；确认创建后，平台据此同步调用 Alice 接口创建该知识库的三个维护角色（知识库 Owner、知识库 Contributor、知识库 Consumer），并将知识库 Owner 角色授予指定的 Owner 与 Deputy（权限等同，负责人冗余）；知识库创建角色只授予建库能力，不自动获得维护角色；三个维护角色的后续授予与回收由知识库 Owner 或 Deputy 审批。知识库 Owner 与 Deputy 全部失效时按双层兜底补员（2026-08-25 裁定）：先由上级目录控制角色补员，再兜底至 Alice 侧管理员或应用账号。
2. 第一步，在【基础信息】中，创建成员需填写知识库名称、可见范围、描述和标签；其中描述为必填（2026-08-30 裁定，字数限制待裁定）。可见范围分三档（2026-08-25 裁定，原两档扩为三档）：**公开可用**（全员可发现可申请使用）、**公开需申请**（全员可发现，使用须经审批；公共目录的默认档）、**完全隐藏**（无权限用户不可发现）。可见范围只控制知识库卡片是否对用户可发现，不代表访问权限；访问权限始终由 Alice 唯一决定。无权限用户对可发现的知识库可在 Information 页看到 Owner 信息（展示字段待裁定），并在显著位置获得 Alice 权限 ID 与申请入口；「完全隐藏」的知识库不向无权限用户暴露任何信息。
3. 第二步，创建成员在【Pipeline配置】中，构建知识库配置。此处有5个板块，分别是解析器、切片、内容增强、向量模型、向量库。默认配置使用 Docling 解析、语义切片、摘要和关键词增强、BGE-M3 向量化以及 Milvus 存储。创建成员可以自定义内置参数。
4. 确认创建后，该知识库将会出现在对应的目录中。知识库卡片右上角的交互操作支持查看权限、重命名与删除；公共目录中仅知识库 Owner 可重命名，我的目录中仅创建者本人可重命名。知识库一旦创建，不支持复制，也不支持挪到其他既有目录下；唯一允许的移位方式是目录控制角色在同一子树内新建子目录并下沉分层。卡片操作里不会出现"复制"或"移动"这类入口，这是设计上的限制，不是功能缺失。

## 三. 知识库文件

1. 公共目录中，持有知识库 Owner 或知识库 Contributor 角色的用户可以点击知识库卡片，进入详情页编辑该知识库；我的目录中，创建者本人或获得「可编辑」分享授权的用户可以进入详情页编辑。知识库页面的角色交互边界（2026-08-28 裁定）：知识库 Viewer 在列表仅见名称与更新时间、不可进入详情；知识库 Consumer 可见完整列表与详情但全部只读（Pipeline 只读）；知识库 Contributor 与 Owner 可见全部状态并可维护，进入详情默认落在 Documents 页签；无权限用户仅见可发现知识库的 Information 页（Viewer 档不展示 Pipeline）。首页上方展示了该知识库的文档数、切片数、向量数、就绪度4个数据；就绪度 = 已向量化文档数 / 未删除文档数，以百分比展示。下方共有三个section, 分别是Document, Settings, Overview。
2. Document页，展示了该知识库的所有文档，知识库 Owner、知识库 Contributor，或我的目录中获得「可编辑」分享授权的用户可以在此页面导入文件。共有四个入口导入文件：本地上传、Confluence、SharePoint 与 OneDrive、S3 与 Azure Blob 对象存储。本地上传支持单文件不超过 40 MB 的文件，也支持上传 ZIP 文件。从 Confluence、SharePoint/OneDrive 或 S3/Azure Blob 导入时，用户需使用自己在密钥库中配置的个人出站凭据。未配置对应凭据时，平台提示其进入密钥库完成配置。平台支持文件预览功能，预览中不支持的文件格式会自动置灰，无法勾选上传此类文件。
3. 确认导入后，文件进入知识库文件列表，初始状态为“未解析”。知识库 Owner、知识库 Contributor，或我的目录中获得「可编辑」分享授权的用户可在文件列表中勾选一个或多个文件后，可点击“一键构建”。平台按照解析、切片、内容增强和向量化四个阶段依次处理文件，并在列表中展示每个文件当前所处的阶段。库内第一份文件完成向量化后，该知识库即可正常使用。
4. 如果需要调试某个阶段或分批处理文件，可以切换到手动模式，按阶段单独执行。前一阶段没有完成时，后一阶段不能执行。
5. 构建失败时，平台立即弹窗说明失败原因，并将失败文件置顶。知识库 Owner、知识库 Contributor，或我的目录中获得「可编辑」分享授权的用户可以打开文件状态查看失败阶段和失败原因，修复问题后从失败阶段重新执行。
6. 库内第一份文件完成向量化后，知识库自动从“草稿”变为“可用”。只有“可用”的知识库才会出现在 Chat 的挂载列表中，也才能被开放接口检索。知识库在全库重建期间继续使用原有索引，不因为重建过程暂时失去检索能力。
7. Setting页，知识库 Owner、知识库 Contributor，或我的目录中获得「可编辑」分享授权的用户可以查看整个知识库的默认解析器、切片策略、内容增强配置；但**保存构建参数的权限仅知识库 Owner 与 Deputy 持有**（2026-08-25 裁定收敛），库级参数保存后触发全库重建（重建触发细则待终态裁定）。向量模型和向量数据库固定在知识库级别。
8. Overview页，知识库 Owner、知识库 Contributor，或我的目录中获得「可编辑」分享授权的用户可以查看知识库描述、内容摘要与构建状态。

## 四. 编辑知识库文件内容

1. 进入知识库卡片内，在文档列表中，知识库 Owner、知识库 Contributor，或我的目录中获得「可编辑」分享授权的用户可以点击文件进入文件详情页，可以分页预览源文件，查看解析后的 Markdown 内容、文档摘要、关键词和解析信息。
2. 在切片列表中，知识库 Owner、知识库 Contributor，或我的目录中获得「可编辑」分享授权的用户可以搜索切片并逐条编辑。切片保存后，平台重新执行该文件的内容增强和向量化，使修改后的内容重新参与检索。
3. 知识库 Owner、知识库 Contributor，或我的目录中获得「可编辑」分享授权的用户可以在文件列表中选择单个文件，也可以批量选择多个文件，然后打开批量配置修改。批量配置只修改所选文件的文档级参数，包括解析器、切片策略和内容增强。保存后，平台对受影响的文件重新执行对应的构建流程。
4. 知识库 Owner、知识库 Contributor，或我的目录中获得「可编辑」分享授权的用户可以在文件列表中选择一个或多个文件，点击删除并确认。文件删除后进入“已删除”终态，不再参与后续检索。如果知识库当前是“可用”状态，且删除的是库内最后一份已向量化的文档，知识库会自动变回“草稿”，并在文档列表处提示“当前无已向量化文档，请导入并构建”；需要重新构建至少一份文档才能再次变为“可用”；如果知识库当前是“已停用”状态，删除文档不会改变这个状态。
5. 知识库 Owner 或我的目录创建者本人可以手动停用知识库；获得分享授权的用户不可停用。停用后，知识库变为“已停用”，立即退出挂载列表且不可检索——进行中的会话同样立即生效（检索行为由检索时刻的知识库状态与权限决定，不设会话级快照）。知识库修复完成后，知识库 Owner 或我的目录创建者本人可以重新启用知识库。
6. 知识库 Owner 或我的目录创建者本人可以删除知识库；获得分享授权的用户不可删除。处于“可用”状态的知识库需要先停用才能删除；删除需要二次确认。删除为软删除终态，删除后知识库卡片不再对用户展示，也不再参与挂载和检索。删除后的数据分层处理（2026-08-25 裁定）：向量索引立即物理删除；PG 中的原始切片与元数据按可配置保留期保留，仅供审计排查（默认周期待合规裁定）；平台不支持恢复完整知识库。到期物理清理由平台统一定时清理任务执行（含状态监控与失败告警），禁止人工直接操作数据库。公共目录下的知识库删除后，平台同步调用 Alice 清理该知识库的角色。

# J4 平台管理员：测评中心（P1，含 P0 准入模板维护）

## 场景、角色与意图

平台管理员负责维护平台统一的测评基线，为 Owner 的 Agent 发布提供质量和安全判断依据。
平台管理员不直接审批用户的资产订阅，也不替 Owner 上下架资产。管理员主要通过数据集、测评模板和测评任务管理平台的测评流程。测评中心共有：数据集管理，任务中心，模板管理三大板块。

## 一. 进入测评中心

1. 平台管理员进入测评中心。P0 中，发布准入测评模板由管理员维护，但测评任务由 Owner 在 Agent 发布流程中触发；独立的测评中心、数据集管理和完整任务能力属于 P1；P0 不提供独立测评中心导航入口，也不做置灰占位。
2. 在数据集管理中，管理员可以查看已有数据集，搜索数据集，并导入新的测评数据集。导入时可以下载数据集模板，上传 `.xlsx` 或 `.csv` 文件，并填写数据集名称。平台完成基础校验后，展示样本数量、预期输出列、异常行和数据集状态。
3. 管理员需要修改已有数据集时，可以复制并编辑数据集。复制后形成一个独立的数据集副本，原数据集和已经完成的任务不受影响。编辑完成后保存新数据集，后续任务使用新的数据集版本。

## 二. 管理测评模板

1. 管理员进入模板管理，创建或编辑测评模板。模板中可以配置模板名称、裁判模型、被测 Agent、数据集和测评指标，也可以设置执行参数，例如并发度、单条样本超时时间、失败重试次数和失败处理策略。
2. 管理员可以选择回答相关性、正确性、安全性等测评指标。部分指标需要数据集提供预期输出；如果数据集不包含预期输出，平台会提示相关指标不可用。
3. 模板保存的是一份测评配置快照。模板本身不直接发起测评任务，真正执行测评时，任务会绑定具体的 Agent 和数据集快照，保证后续修改模板或数据集不会影响已经完成的任务结果。
4. P0 的发布准入测评模板由平台管理员维护三类问题集：提示词注入、意图偏离和内容安全，并为三类测评分别设置通过阈值。Owner 在发布 Agent 时使用这套平台模板，不能自行替换；模板更新不会修改历史测评记录。

## 三. 创建和执行测评任务

1. 管理员进入任务中心，点击创建测评任务，选择被测 Agent、测评模板和可用数据集。任务会记录被测对象、模板和数据集快照，管理员再设置立即执行或定时执行、并发度、超时时间、失败重试次数和失败处理策略。
2. 管理员提交任务后，可以在任务中心-运行中，查看任务状态，例如待执行、执行中、已完成或执行失败。任务详情页展示任务基础信息、样本总数、成功和失败数量、各项指标得分以及样本明细。
3. 管理员可以按照全部、成功或失败筛选样本，打开单条样本查看输入、预期输出、Agent 实际输出、失败原因和各项指标得分。任务结果支持导出；在同一模板下的已完成任务之间，管理员可以选择任务生成对比报告，查看不同任务的指标变化。
4. 如果测评结果未通过，或出现样本失败的情况，管理员可根据失败原因调整配置或重试失败样本。P0 发布流程中的准入测评由 Owner 通过发布流程重测，P1 独立测评中心则由管理员在任务中心管理任务。

# J5 平台管理员：护栏策略

## 场景、角色与意图

平台管理员负责维护平台统一的护栏策略，保证平台 Chat 和资产 Agent 的对话受到统一的内容安全保护，并通过运营看板了解护栏的检测和拦截情况。

## 一. 创建和维护护栏策略

1. 平台管理员进入护栏策略中心，查看已有策略模板，并通过搜索定位目标策略。管理员可以创建、启用、停用或另存为新策略模板；模板创建后不可原地修改，模板不支持删除，停用即为终态。
2. 创建策略时，管理员填写策略名称和说明，并配置护栏组合。管理员可以为每个护栏设置灵敏度，并选择作用侧：输入侧、输出侧或输入和输出两侧。
3. 保存后，管理员可以进入策略详情查看每个护栏的配置、灵敏度和作用侧；需要调整规则时，管理员另存为新模板并启用，再由 Owner 将资产改绑到新模板。
4. 管理员指定一个全局唯一的平台默认护栏策略模板，用于平台 Chat agent-runtime 的会话。当前默认模板不能直接停用，管理员需要先指定另一个启用中的模板作为新的默认模板。

## 二. 护栏策略绑定和运行时生效

1. Owner 创建 Agent 时，从启用中的策略模板中选择一个并绑定到 Agent。每个 Agent 只能绑定一个策略，Owner 可以查看策略明细，但不能修改护栏规则和灵敏度。
2. 平台网关对所有经平台流转的对话执行护栏检测。资产 Agent 会话使用该 Agent 绑定的策略；平台 Chat 会话使用平台默认策略。
3. 输入侧命中护栏时，平台直接拒答，并向用户展示命中的护栏类型。输出侧按上游响应形态分双路径：流式响应采用滑动窗口检测，窗口通过才释放内容；非流式响应缓冲全文检测，通过后直接完整呈现。输出侧命中时，平台立即终止上游生成、撤回全部已下发内容，并展示护栏命中提醒和命中的护栏类型；命中轮次不落库，历史回看显示占位文案。
4. 管理员不能原地修改已绑定策略；规则变更通过“另存为新模板、启用新模板、Owner 改绑资产”的路径到达存量 Agent。Owner 改绑模板对进行中会话即时生效，不设会话级快照。管理员停用策略时，不影响已经绑定该策略的存量 Agent，只影响后续新的绑定；Agent 下一次发布新版本或重新上架时，平台会检查所绑定的策略是否仍处于启用状态。

## 三. 查看护栏运营看板

1. 管理员进入护栏运营看板后，可以查看数据总览和命中记录。数据总览包括各策略的检测量、命中率和近期拦截次数。
2. 管理员进入命中记录后，可以查看具体策略的命中情况，并点击“查看明细”查看命中时间、命中条目、用户、护栏类型、拦截信息和当时的模板条目快照；输出侧命中轮次不展示被拦截原文。
3. 管理员根据运营数据判断策略是否过于宽松或严格，并返回策略中心另存新模板来调整护栏组合、灵敏度和作用侧。护栏运营看板和命中记录查询属于 P1，P0 只包含策略配置和运行时拦截。

# J6 平台管理员：治理中心

## 场景、角色与意图

平台管理员需要在不干预资产上下架状态的前提下，对存在风险的资产保留最后的平台侧止损手段，并让 Owner 与调用方看到明确原因。

## 一. 治理中心查看资产

1. 平台管理员进入管理后台的治理中心，查看全平台 Agent 与 MCP 的名称、类型、状态、负责人与出站调用停用标记。

## 二. 停用资产出站调用

1. 平台管理员可对某个资产执行“停用出站调用”，必须填写停用原因。
2. 停用后，该资产的全部个人凭据解析一并禁用，平台网关不再为该资产发起出站调用；平台内使用与平台外调用均失败，并提示“该资产的出站调用已被平台停用”。
3. 停用原因与停用时间在该资产的资产控制台顶部常驻可见，并通知该资产全体负责人。
4. 停用与资产上下架状态正交：资产下架后重新上架，未解除的停用仍继续生效。
5. 平台管理员可手动恢复出站调用；恢复动作留痕并通知该资产全体负责人。

## 三. 孤儿资产补员

1. 如果资产的全部 Owner 与 Deputy 账号都被 Alice 停用，该资产成为孤儿资产；平台不改变资产状态，资产保持运行，但订阅入口关闭并提示负责人暂不可用。
2. 治理中心对孤儿资产显著标记。平台管理员可为其补员，须同次指定新 Owner 与至少一位 Deputy，提交时一次性满足有效负责人冗余。
3. 补员操作留痕并通知新指定负责人；补员后订阅入口与 Owner 职能恢复。原负责人账号恢复后，其负责人身份自动恢复，孤儿标记解除，并通知该资产全体有效负责人。

## 四. 平台资源与模型设置

1. 平台管理员在平台资源注册表中登记 Milvus 与 PGVector 实例，维护连接信息、凭据与可用范围；Azure Document Intelligence 与 Azure AI Search 服务随二期管线组件启用。
2. 平台管理员可按资源逐人分配可使用人员；授予与回收即时生效并留痕，回收不影响已建在实例上的存量知识库。
3. 平台管理员在模型设置中只读查看随部署内置的模型清单、启用态与默认模型，并在线维护既有模型条目的平台默认凭据引用；P0 不提供运行期新增、编辑、删除、启停用模型或切换默认模型入口。模型平台默认凭据只能引用平台资源注册表中的平台内部 Nexus 凭据对象。

## 五. 角色映射与公共目录冷启动

1. 平台管理员查看从 Alice 同步的用户与角色只读视图，并配置 Alice 角色到平台功能点与可用模型的映射；未显式配置映射的 Alice 角色享有基线权限。
2. 平台管理员创建公共目录一级节点，并指定一级目录控制角色与一级目录知识库创建角色的持有人；后续层级的目录维护与角色授予由上级目录控制角色负责。

# J7 密钥库：配置调用凭据

## 场景、角色与意图

用户在平台内或平台外调用已订阅资产、导入外部知识来源、通过 OpenAPI 调用平台，或使用个人模型能力时，需要在密钥库中管理自己的凭据；其中资产调用一律使用订阅者个人凭据，且不回落任何共享身份。
密钥库只管理用户侧的两类凭据：入站 PAT 和出站个人凭据。资产侧无凭据，Owner 只声明凭据元数据；实例类平台资源凭据与平台内部 Nexus 凭据对象由平台管理员在平台资源注册表中维护，模型类平台默认凭据在模型设置中仅维护对 Nexus 凭据对象的引用，均不在密钥库中配置。

## 一. 管理入站 PAT

1. 用户进入密钥库的“入站管理”，点击创建 PAT，填写 PAT 名称和有效期。有效期默认从创建时起算 90 天。
2. 用户选择 PAT 的权限范围。可选择的对象只能是用户已经订阅或已经获得权限的资产和知识库；如果用户需要让外部系统通过 OpenAPI 调用某个 MCP，还需要在这里勾选对应的已授权 MCP。平台在选择时进行权限校验，未获授权的对象不能被选择。
3. PAT 创建成功后，平台只在成功页面完整展示一次令牌明文。用户需要立即复制并安全保存，再将 PAT 配置到自己的 Agent、业务系统或外部开发者使用的调用环境中。
4. 用户可以在入站 PAT 列表中查看 PAT 状态和权限范围，也可以停用或删除 PAT。停用和删除需要二次确认；PAT 创建后名称、有效期与范围均锁定，不支持重新生成或延长有效期。用户账号被 Alice 停用时，其名下全部 PAT 与个人出站凭据立即失效。

## 二. 管理出站个人凭据

1. 用户进入密钥库的“出站管理”，先选择凭据目标类型。平台提供三类目标：资产调用、平台原生工具和 Nexus 模型服务。
2. 对于资产调用，目标列表只展示用户已经订阅的资产。静态模式下，用户按资产提示在平台外获取凭据后填入密钥库，并在资产详情页绑定为该资产的调用凭据；绑定关系按用户×资产唯一，一条凭据可绑定该用户的多个资产。动态模式下，订阅通过后平台按资产声明的授权申请接口代为请求颁发动态凭据并入库；颁发期间密钥库条目显示“颁发中”，颁发失败时订阅仍生效、条目显示“颁发失败”，平台不通知任何一方、不自动重试，用户可手动重新颁发。凭据未配置、未绑定、失效或调用失败时，资产调用失败，平台不会回落到共享身份。
3. 对于平台原生工具，用户可以配置知识库导入所需的 Confluence、SharePoint/OneDrive 或 OSS 凭据。用户选择对应的导入通道后，平台展示该通道要求的认证字段，用户填写凭据并执行探测。执行导入时，用户需要同时具备目标知识库的知识库 Contributor 或更高权限；我的目录中，创建者本人或获得「可编辑」分享授权的用户也可执行导入。
4. 对于 Nexus 模型服务，用户可以配置多条个人模型凭据，并通过启用/禁用和排序决定使用顺序。用户保存凭据后，平台对当前全部模型各执行一次可用性检测并保存模型可用性快照，后续模型调用根据快照选择第一条可用的个人凭据。用户也可以手动刷新检测结果。
5. 个人凭据的密文字段默认掩码显示，用户可以点击查看明文；查看动作会被记录。资产调用个人凭据、知识导入通道凭据与 Nexus 模型服务凭据均支持停用、删除或重新执行一键探测；用户自填的凭据值可编辑，保存后自动重新探测。
6. 如果个人模型凭据在真实调用中发生鉴权或权限失败，平台本次调用改用平台默认凭据，并通知用户前往 Nexus 申请权限或更新凭据。瞬时故障不会改写可用性快照。
