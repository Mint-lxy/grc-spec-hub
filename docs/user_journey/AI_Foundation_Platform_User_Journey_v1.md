# J1 资产订阅者：

## 场景、角色与意图

用户在日常工作中需要使用AI Agent 或 MCP，希望在平台中找到合适的资产，再完成订阅申请并获得使用授权。
用户不需要了解资产的内部实现，只需通过 Marketplace 判断资产是否适合自己的工作，清楚订阅需提交的信息、审批情况、如何使用，以及后续资产发生变化时的影响。

## 一. 进入 Marketplace 浏览资产

1. 用户进入 Marketplace 后，选择 Agent 或 MCP 频道。页面提供推荐、热门和全部列表，用户可浏览平台中已经上架的资产，也可以使用搜索框按照资产名称、业务标签和简介进行搜索。
2. 列表只展示状态为“已发布”且Guardrail全部通过的资产。用户通过资产卡片，可以看到名称、类型、业务标签和当前状态。用户可点击【详情】，进入资产详情页，查看详细信息。
3. 对于 Agent，详情页包含四个页签：基本信息、接入配置、测评信息和发布记录。用户可以通过基本信息了解 Agent 能力标签、适用场景和负责人，通过测评信息查看准入测评结果、分项得分和测评执行时间，通过发布记录了解版本、发布说明以及相关变更记录。
4. 对于 MCP，详情页包含四个页签：基本信息、接入配置、工具能力和凭据状态。用户需要先通过基本信息确认 MCP 是否适合自己的业务场景，再决定是否进入订阅流程。
5. 用户确认资产符合自己的需求后，在资产详情页点击“订阅”。点击后直接进入单页订阅申请，不再经过一个只展示资产说明的中间页面。

## 二. 提交订阅申请

1. 用户进入订阅申请页后，共有三个界面，首页为【资产说明】。页面顶部展示资产说明摘要，包括资产名称、资产类型、资产拥有者。
2. 第二页为【申请信息】。用户填写业务系统、使用场景，以及该资产创建者配置的自定义表单字段。自定义字段由资产创建者配置（YAML），用户按照页面要求填写相应信息。
3. 第三页为【确认提交】。该页面展示了当前版本的Release Note与所有订阅审批人。用户确认信息后，勾选同意使用条款并提交申请。提交成功后，系统创建一条订阅申请记录，并将申请发送给对应的审批人。
4. 订阅申请提交后，用户可以进入【订阅者中心】跟踪申请状态。订阅者中心最上方的Subscribe Console提供四个状态统计卡，已通过、待审批、被驳回和已取消。点击对应的统计卡，会出现下拉列表，用户可以查看对应的资产和状态。
5. 用户在卡片右上角的状态悬停时，可以查看各级审批进展。对于待审批申请，用户可查看当前处理进度。对于被驳回的申请，用户可查看驳回理由，并通过【重新申请】再次提交。重新申请会创建一条新的订阅申请记录。对于已取消的申请，用户可以查看取消理由和取消来源。取消来源可能是用户主动退订、资产下架、资产删除或账号失效。

## 三. 进入平台 Chat

1. 用户登录平台后，可以直接进入对话工作台，默认使用平台 Chat。对话能力按会话类型分两类：平台 Chat agent-runtime与资产Agent。平台Chat的会话可挂载知识库（检索证据、图片与插图内嵌）、调用平台原生工具、开启深度分析、查看思考过程、选择对话模型（下拉列表只展示对话类与多模态类模型）。资产 Agent 会话为透传会话，模型由该资产自身决定，用户不能在对话页选择模型。
2. 用户在 Chat 中输入问题后，平台执行输入侧和输出侧护栏检测。回答通过检测后按段回放，用户可以查看思考过程、检索证据和引用来源，也可以随时中止生成。
3. 用户可以在对话工作台中管理历史会话：按名称搜索、按 Agent 筛选、打开恢复继续对话、删除或新建会话。会话在服务端保留 90 天（自最后一条消息起算）。如果会话对应的资产已经下架，该会话仍可以打开只读回看历史消息，但不能再发送新消息。

## 四. 订阅通过后使用 Agent

1. 当 Agent 的订阅申请审批通过后，用户可以在 Agent 详情页看到【去使用】入口。用户点击进入该 Agent 的专属对话页，平台通过网关代理透传请求到该资产 Agent。
2. Agent 对话页的顶部会展示当前 Agent 的名称。该会话是资产 Agent 的透传会话，用户不能挂载知识库。资产 Agent 能提供哪些能力，以该资产自身返回的内容为准。
3. 用户在对话输入区提交问题后，平台网关执行统一的护栏检测。如果输入或输出命中护栏，平台拦截对应内容，并向用户展示命中的护栏类型和拦截结果。用户可以在生成过程中随时点击“停止生成”。
4. 绝大多数资产不需要订阅者额外配置凭据，平台会使用该资产的服务凭据发起调用。只有当资产在鉴权配置中声明为“按人鉴权”时，用户才需要在密钥库中配置自己的个人出站凭据。如果按人鉴权资产配置已失效，页面需要明确提示用户，并提供进入密钥库的跳转入口。

## 五. 订阅通过后使用 MCP

1. 用户订阅 MCP 后，进入 MCP 详情页查看接入配置、工具能力和凭据状态。MCP 不是对话对象，不能在 Chat 中直接调用；它可以由已订阅的 Agent 服务端接入，也可以由外部系统通过平台开放接口调用。
2. 如果 MCP 是服务间鉴权，平台使用该 MCP 的资产级服务凭据发起调用，用户通常不需要配置个人凭据。如果 MCP 是按人鉴权，用户需要按照详情页提示在密钥库配置个人出站凭据；凭据缺失或失效时调用失败，平台不会使用共享身份替代。

## 六. 订阅状态变化和后续管理

1. 如果资产在申请审批期间被创建者下架，所有待审批申请会自动转为“已取消”。用户收到的资产下架通知。
2. 订阅通过并开始使用后，若出现：订阅被创建者取消、资产被创建者下架、资产发布新版本以及资产使用条款更新等情况，用户均会收到站内通知。
3. 如果资产在通过后被下架，通知中会附下架原因。用户原有订阅失效，待审批申请会被取消。资产重新上架后，原有订阅不会自动恢复，用户需要重新提交新的订阅申请。
4. 用户不再需要某项资产时，可以在订阅者中心主动退订。用户确认退订后，订阅状态变为“已取消”，使用授权立即失效。

# J2 资产创建者：

## 场景、角色与意图

创建者希望把自己的 Agent 或 MCP 发布到平台，让其他用户能够订阅使用。创建者需要完成资产信息、服务接入、鉴权、能力声明、订阅配置和安全校验，并在资产发布后继续处理订阅审批、资产维护和版本变更。
创建资产的用户会自动成为该资产的首位创建者。创建者可以添加新共创者或Deputy，确保后续有人可以共同维护资产、处理订阅申请和执行资产治理操作。

## 一. 创作者中心，创建 Agent 资产

进入创作者中心，点击“+创建”，点击“创建 Agent”，选择高代码或低代码方式，进入对应的创建 Pipeline。

### (一) 创建高代码 Agent

1. 高代码 Agent 直接接入已经部署、符合 A2A 协议的服务，创建者完成8步创建向导。
2. 基础信息：创建者填写资产名称、分类和描述，并确认资产负责人（默认为首位创建者，可增加共同创建者与 Deputy）。
3. 接入配置：创建者填写 Agent Endpoint URL，开启 Health Check 功能并可一键探测。
4. 鉴权配置：创建者选择静态凭据或自动模式，声明 API Key、Bearer Token、OAuth2 或自定义 Header 等鉴权方式，并声明该资产采用服务间鉴权还是按人鉴权。服务间鉴权资产需要配置资产级服务凭据并进行探测；按人鉴权资产由订阅者在个人密钥库中配置个人出站凭据。
5. 能力声明：创建者点击“拉取 Agent Card”，平台从服务地址读取 Agent Card 和接口元数据，并展示协议版本、接口数量和鉴权方式。
6. 订阅申请表单：创建者通过 YAML 文件上传或编辑订阅申请表单，平台解析后实时预览。使用条款独立配置，必须包含条款内容和版本号；
7. 订阅审批人：创建者可选择是否开始订阅审批功能，若开始，可配置多位共创者/Deputy。
8. 护栏策略：创建者为 Agent 选择一个已启用的护栏策略模板。每个 Agent 必须绑定一个策略，创建者可以查看策略明细，但无法自行修改规则和灵敏度。
9. 创建者填写 Release Note 并提交发布，之后进入质量门控、测评和发布流程。

### (二) 创建低代码 Agent（P1）

1. 前置条件：平台管理员已经在后台配置好 Dify 的实例与 Workspace，创建者要接入的 Agent 也已提前搭建完成。
2. 创建者点击"创建低代码 Agent"后，先选择自己有权限的"实例 + Workspace"。
3. 选定 Workspace 后，平台展示这个 Workspace 下已经自建好的 Agent 列表，创建者从中勾选想要接入平台的 Agent，之后进行发布。
4. 平台拉取被勾选 Agent 的元数据，落入该资产的未发布修订；之后平台会周期性重新同步该 Agent 在 Dify 里的最新元数据，同步结果同样落入未发布修订，由创建者确认后再发布生效，不绕过版本流程。
5. 创建者在平台内补录治理字段，包括名称、业务归属、简介和建议可见范围。
6. 依次进入质量门控和发布准入测评，通过后创建者完成自助上架。

## 二. 创作者中心，创建 MCP 资产

1. 进入创作者中心，点击“+创建”，点击“创建 MCP”。创建者共需填写六个模块，分别是：基础信息、MCP 链接配置、鉴权配置、能力声明、订阅审批人和发布记录。
2. 基础信息：支持创建者填写资产名称、分类、托管方式和描述。
3. MCP 链接配置：创建者填写服务地址、协议类型和托管方式，并开启 Health Check 功能。
4. 鉴权配置：支持创建者选择静态凭据。
5. 能力声明：填写 MCP Manifest 链接并点击“拉取 Tool List”。平台读取 MCP Manifest，并在页面展示工具名称、能力说明、参数摘要、鉴权方式和识别状态。
6. 订阅申请：设置审批人。
7. 填写 Release Note 并提交发布。

## 三. Agent 创建后测评并发布

1. Agent 在成功通过质量门控后，将进入发布测评。创建者进入创作者中心，找到刚刚创建好的 Agent。此时 Agent 的状态为“已创建”，操作按钮为“去测评”。
2. 点击“去测评”后进入测评 Pipeline。创建者选择测评模板，包括提示词注入、意图偏离和内容安全三类测评。选择完成后点击发起测评。
3. 查看测评结果页面，页面展示测评模板、测试能力和对应的测评进度。测评结果记录执行时间，并在资产详情页的测评信息页签中展示。
4. 测评通过后，创建者可以完成上架发布。上架成功后，资产状态变为“已发布”，并进入 Marketplace 列表。
5. MCP 不执行发布准入测评。MCP 在质量门控全部通过后，可以直接完成自助上架。

## 四. 资产管理

1. 【创作者中心】主页上方的 Provider Console 提供四个状态统计卡：已创建、待审批、待发布和已下架。创建者点击对应的统计卡后，可以查看对应的资产和订阅请求。
2. 创建者点击创作者中心主页中的资产卡片，进入资产控制台。资产控制台支持查看基本信息、订阅管理、测评结果、发布记录和用量检测。订阅管理包括用户管理和订阅设置；用户管理支持订阅审批、驳回、查看订阅者信息和用量。订阅设置支持修改订阅申请表单与订阅审批人链。
3. 创建者可以在资产控制台取消他人的订阅。取消时需要填写取消理由，被取消的订阅者会收到通知，使用授权立即失效。
4. 创建者可以维护共创者和 Deputy。已发布资产在移除负责人时，不能使有效负责人数量低于平台要求；如果发布中的资产负责人不满足冗余要求，平台会阻断发布，创建者需要补充共创者或 Deputy。
5. 负责人名单、订阅申请表单、资产基础信息等热改配置修改即时生效，不进入版本发布流程，也不触发质量门控和发布准入测评。

## 五. 更新和下架

1. 创建者点击进入创作者中心，进入主页后，点击目标资产卡片。点击进入资产卡片内部后，右上角提供“发布新版”和“下架”两个操作。
2. 创建者点击“发布新版”后，进入创建该资产时使用的同一套配置流程。Agent 和 MCP 分别进入各自的创建流程，页面中的基础信息、服务地址、鉴权配置、能力声明、订阅配置和发布说明等内容默认沿用当前资产配置，创建者只需要修改本次更新的内容。
3. 创建者完成修改后提交，平台重新执行对应的质量门控。Agent 还需要执行发布准入测评。校验通过后，新版本发布并替换当前版本，订阅者自动使用新版本；在发布完成前，当前版本继续对外服务。发布（重跑质量门控与测评）进行中，创建者或 Deputy 可以点击“中止发布”终止本次发布，未发布修订会被保留、可以继续编辑，平台会通知发起本次发布的人。发布进行中会阻断下架和删除操作，需要先中止发布才能执行。
4. 如果创建者只修改使用条款，系统按照轻发布处理，条款版本更新并通知存量订阅者与待审批申请人；不需要重新进行质量门控和发布准入测评，也不要求订阅者重新确认。
5. 创建者需要撤下资产时，点击资产卡片右上角的“下架”。系统弹出确认窗口，创建者确认后填写下架原因并提交。资产状态变为“已下架”，所有已通过订阅立即失效，待审批申请自动取消，相关用户收到带有下架原因的通知。平台同时停止经平台流向该资产的调用，并返回“该资产已被下架”。
6. 资产下架后，创建者仍可以点击“发布新版”进行修复。系统继续沿用原有配置，创建者修改需要修复的内容后重新提交，并重新执行对应的质量门控和发布流程。修复发布成功后，资产重新上架，但原有订阅不会自动恢复，原订阅者需要重新申请。
7. 创建者需要删除资产时，可以点击“删除”。“已发布”状态的资产必须先下架才能删除；未发布或已下架的资产可以直接删除。删除是终态：删除后资产对所有用户不可见，且不能恢复，但订阅历史等业务记录会永久保留；资产级服务凭据会被清理，已签发的 PAT 对该资产的访问随之失效。

# J3 知识库管理员：

## 场景、角色与意图

知识库管理员希望把业务资料整理成可检索的企业知识库，让有权限的用户可以在 Chat 中挂载知识库并检索，也可以让外部系统通过开放接口调用知识库能力。
知识库的权限和目录角色由 Alice 作为唯一授权来源。平台负责提供目录和知识库的操作入口、展示权限状态、发起 Alice 权限申请，并管理文档导入、解析和向量化流程。

## 一. 进入知识管理，选择目录

1. 知识库管理员进入知识管理页面，从目录树中选择公共目录或我的目录。公共目录由目录控制权限持有人维护。拥有“目录控制权限“的管理员，可以在范围内新建子目录、重命名、删除目录。拥有”知识库创建权限”的管理员，可以在最子级目录创建知识库。目录结构调整后平台即时更新，并同步至 Alice。删除目录前，系统会检查该目录及其子目录下是否还存在知识库；存在知识库时不允许删除。
2. 如果用户没有访问某个目录的权限，点击受限目录后，页面展示对应的 Alice 权限 ID，并提供复制和跳转 Alice 申请的入口。目录权限申请采用单级审批，由上级目录控制角色持有人处理。
3. 我的目录由用户本人管理，不需要目录角色，也不经过 Alice 授权。我的目录下创建的知识库仅创建者本人可见和使用。

## 二. 在叶子目录创建知识库

1. 拥有知识库创建权限的用户，可以选择一个叶子目录，点击“创建知识库”，进入建库向导。
2. 第一步，在【基础信息】中，创建成员需填写知识库名称、可见范围、描述和标签。公开知识库的卡片对全员可见，没有访问权限的用户点击后会看到 Alice 权限 ID 和申请入口
3. 第二步，创建成员在【Pipeline配置】中，构建知识库配置。此处有5个板块，分别是解析器、切片、内容增强、向量模型、向量库。默认配置使用 Docling 解析、语义切片、摘要和关键词增强、BGE-M3 向量化以及 Milvus 存储。创建成员可以自定义内置参数。
4. 确认创建后，该知识库将会出现在对应的目录中。知识库卡片右上角的交互操作，可以支持查看权限，重命名与删除。知识库一旦创建，不支持复制，也不支持挪到其他目录下——卡片操作里不会出现"复制"或"移动"这类入口，这是设计上的限制，不是功能缺失。

## 三. 知识库文件

1. 拥有知识库Owner以及Contributer权限的用户，可以点击知识库卡片，进入详情页对该知识库编辑。首页上方展示了该知识库的文档数、切片、向量、就绪度4个数据。下方共有三个section, 分别是Document, Settings, Overview。
2. Document页，展示了该知识库的所有文档，知识库Owner/Contributer可以在此页面导入文件。共有四个入口导入文件：本地上传、Confluence、SharePoint 与 OneDrive、S3 与 Azure Blob 对象存储。本地上传支持单文件不超过 40 MB 的文件，也支持上传 ZIP 文件。从 Confluence、SharePoint/OneDrive 或 S3/Azure Blob 导入时，用户需使用自己在密钥库中配置的个人出站凭据。未配置对应凭据时，平台提示其进入密钥库完成配置。平台支持文件预览功能，预览中不支持的文件格式会自动置灰，无法勾选上传此类文件。
3. 确认导入后，文件进入知识库文件列表，初始状态为“未解析”。知识库Owner/Contributer可在文件列表中勾选一个或多个文件后，可点击“一键构建”。平台按照解析、切片、内容增强和向量化四个阶段依次处理文件，并在列表中展示每个文件当前所处的阶段。若全部文档都显示已完成，则该知识库即可正常使用。
4. 如果需要调试某个阶段或分批处理文件，可以切换到手动模式，按阶段单独执行。前一阶段没有完成时，后一阶段不能执行。
5. 构建失败时，平台立即弹窗说明失败原因，并将失败文件置顶。权限用户可以打开文件状态查看失败阶段和失败原因，修复问题后从失败阶段重新执行。
6. 库内第一份文件完成向量化后，知识库自动从“草稿”变为“可用”。只有“可用”的知识库才会出现在 Chat 的挂载列表中，也才能被开放接口检索。知识库在全库重建期间继续使用原有索引，不因为重建过程暂时失去检索能力。
7. Setting页，知识库Owner/Contributer可以修改整个知识库的默认解析器、切片策略、内容增强配置，库级参数保存后触发全库重建。但向量模型和向量数据库固定在知识库级别。
8. Overview页，知识库Owner/Contributer可以查看知识库描述、内容摘要、构建状态、以及Sharable Capability.

## 四. 编辑知识库文件内容

1. 进入知识库卡片内，在文档列表中，知识库Owner/Contributer可以点击文件进入文件详情页，可以分页预览源文件，查看解析后的 Markdown 内容、文档摘要、关键词和解析信息。
2. 在切片列表中，知识库Owner/Contributer可以搜索切片并逐条编辑。切片保存后，平台重新执行该文件的内容增强和向量化，使修改后的内容重新参与检索。
3. 知识库Owner/Contributer可以在文件列表中选择单个文件，也可以批量选择多个文件，然后打开批量配置修改。批量配置只修改所选文件的文档级参数，包括解析器、切片策略和内容增强。保存后，平台对受影响的文件重新执行对应的构建流程。
4. 知识库 Owner 或 Contributor 可以在文件列表中选择一个或多个文件，点击删除并确认。文件删除后进入“已删除”终态，不再参与后续检索。如果知识库当前是“可用”状态，且删除的是库内最后一份已向量化的文档，知识库会自动变回“草稿”（重新出现在建库向导式的引导中，需要重新构建至少一份文档才能再次变为“可用”）；如果知识库当前是“已停用”状态，删除文档不会改变这个状态。
5. 知识库 Owner 可以手动停用知识库。停用后，知识库变为“已停用”，不再出现在新会话的挂载列表中，也不再被新会话检索。已经进行中的会话继续使用挂载时保存的会话级快照，直到会话结束。知识库修复完成后，Owner 可以重新启用知识库。
6. 知识库 Owner 可以删除知识库。处于“可用”状态的知识库需要先停用才能删除；删除需要二次确认。删除后知识库卡片不再对用户展示，也不再参与挂载和检索。公共目录下的知识库删除后，平台同步调用 Alice 清理该知识库的角色。

# J4 平台管理员：测评中心

## 场景、角色与意图

平台管理员负责维护平台统一的测评基线，为创建者的 Agent 发布提供质量和安全判断依据。
平台管理员不直接审批用户的资产订阅，也不替创建者上下架资产。管理员主要通过数据集、测评模板和测评任务管理平台的测评流程。测评中心共有：数据集管理，任务中心，模板管理三大板块。

## 一. 进入测评中心

1. 平台管理员进入测评中心。P0 中，发布准入测评模板由管理员维护，但测评任务由资产创建者在 Agent 发布流程中触发；独立的测评中心、数据集管理和完整任务能力属于 P1。
2. 在数据集管理中，管理员可以查看已有数据集，搜索数据集，并导入新的测评数据集。导入时可以下载数据集模板，上传 `.xlsx` 或 `.csv` 文件，并填写数据集名称。平台完成基础校验后，展示样本数量、预期输出列、异常行和数据集状态。
3. 管理员需要修改已有数据集时，可以复制并编辑数据集。复制后形成一个独立的数据集副本，原数据集和已经完成的任务不受影响。编辑完成后保存新数据集，后续任务使用新的数据集版本。

## 二. 管理测评模板

1. 管理员进入模板管理，创建或编辑测评模板。模板中可以配置模板名称、裁判模型、被测 Agent、数据集和测评指标，也可以设置执行参数，例如并发度、单条样本超时时间、失败重试次数和失败处理策略。
2. 管理员可以选择回答相关性、正确性、安全性等测评指标。部分指标需要数据集提供预期输出；如果数据集不包含预期输出，平台会提示相关指标不可用。
3. 模板保存的是一份测评配置快照。模板本身不直接发起测评任务，真正执行测评时，任务会绑定具体的 Agent 和数据集快照，保证后续修改模板或数据集不会影响已经完成的任务结果。
4. P0 的发布准入测评模板由平台管理员维护三类问题集：提示词注入、意图偏离和内容安全，并为三类测评分别设置通过阈值。创建者在发布 Agent 时使用这套平台模板，不能自行替换；模板更新不会修改历史测评记录。

## 三. 创建和执行测评任务

1. 管理员进入任务中心，点击创建测评任务，选择被测 Agent、测评模板和可用数据集。任务会记录被测对象、模板和数据集快照，管理员再设置立即执行或定时执行、并发度、超时时间、失败重试次数和失败处理策略。
2. 管理员提交任务后，可以在任务中心-运行中，查看任务状态，例如待执行、执行中、已完成或执行失败。任务详情页展示任务基础信息、样本总数、成功和失败数量、各项指标得分以及样本明细。
3. 管理员可以按照全部、成功或失败筛选样本，打开单条样本查看输入、预期输出、Agent 实际输出、失败原因和各项指标得分。任务结果支持导出；在同一模板下的已完成任务之间，管理员可以选择任务生成对比报告，查看不同任务的指标变化。
4. 如果测评结果未通过，或出现样本失败的情况，管理员可根据失败原因调整配置或重试失败样本。P0 发布流程中的准入测评由创建者通过发布流程重测，P1 独立测评中心则由管理员在任务中心管理任务。

# J5 平台管理员：护栏策略

## 场景、角色与意图

平台管理员负责维护平台统一的护栏策略，保证平台 Chat 和资产 Agent 的对话受到统一的内容安全保护，并通过运营看板了解护栏的检测和拦截情况。

## 一. 创建和维护护栏策略

1. 平台管理员进入护栏策略中心，查看已有策略模板，并通过搜索定位目标策略。管理员可以创建、编辑、启用或停用策略模板。
2. 创建策略时，管理员填写策略名称和说明，并配置护栏组合。原型中的护栏包括 PII Detection、Toxicity Filter、Prompt Injection 和 Banned Words。管理员可以为每个护栏设置灵敏度，并选择作用侧：输入侧、输出侧或输入和输出两侧。
3. 保存后，管理员可以进入策略详情查看每个护栏的配置、灵敏度和作用侧。
4. 管理员指定一个全局唯一的平台默认护栏策略模板，用于平台 Chat agent-runtime 的会话。当前默认模板不能直接停用，管理员需要先指定另一个启用中的模板作为新的默认模板。

## 二. 护栏策略绑定和运行时生效

1. 创建者创建 Agent 时，从启用中的策略模板中选择一个并绑定到 Agent。每个 Agent 只能绑定一个策略，创建者可以查看策略明细，但不能修改护栏规则和灵敏度。
2. 平台网关对所有经平台流转的对话执行护栏检测。资产 Agent 会话使用该 Agent 绑定的策略；平台 Chat 会话使用平台默认策略。
3. 输入侧命中护栏时，平台直接拒答，并向用户展示命中的护栏类型。输出侧先缓冲完整回答，检测通过后再按段回放；如果命中护栏，原回答不下发，用户看到“已拦截”和命中的护栏类型。
4. 管理员修改已绑定策略后，修改会对已绑定的 Agent 即时生效。管理员停用策略时，不影响已经绑定该策略的存量 Agent，只影响后续新的绑定。Agent 下一次发布新版本或重新上架时，平台会检查所绑定的策略是否仍处于启用状态。

## 三. 查看护栏运营看板

1. 管理员进入护栏运营看板后，可以查看数据总览和命中记录。数据总览包括各策略的检测量、命中率和近期拦截次数。
2. 管理员进入命中记录后，可以查看具体策略的命中情况，并点击“查看明细”查看命中时间、命中条目、用户、拦截信息以及输入输出内容。
3. 管理员根据运营数据判断策略是否过于宽松或严格，并返回策略中心调整护栏组合、灵敏度和作用侧。护栏运营看板和命中记录查询属于 P1，P0 只包含策略配置和运行时拦截。

# J6 密钥库：配置调用凭据

## 场景、角色与意图

用户在调用已订阅的按人鉴权资产、导入外部知识来源、通过 OpenAPI 调用平台，或使用个人模型能力时，需要在密钥库中管理自己的凭据。
密钥库只管理用户侧的两类凭据：入站 PAT 和出站个人凭据。资产级服务凭据由创建者在资产配置中维护，平台资源凭据由平台管理员在平台资源注册表中维护，不在密钥库中配置。

## 一. 管理入站 PAT

1. 用户进入密钥库的“入站管理”，点击创建 PAT，填写 PAT 名称和有效期。有效期默认从创建时起算 90 天。
2. 用户选择 PAT 的权限范围。可选择的对象只能是用户已经订阅或已经获得权限的资产和知识库；如果用户需要让外部系统通过 OpenAPI 调用某个 MCP，还需要在这里勾选对应的已授权 MCP。平台在选择时进行权限校验，未获授权的对象不能被选择。
3. PAT 创建成功后，平台只在成功页面完整展示一次令牌明文。用户需要立即复制并安全保存，再将 PAT 配置到自己的 Agent、业务系统或外部开发者使用的调用环境中。
4. 用户可以在入站 PAT 列表中查看 PAT 状态和权限范围，也可以停用、删除或重新生成 PAT。停用和删除需要二次确认；重新生成后，原 PAT 立即失效。

## 二. 管理出站个人凭据

1. 用户进入密钥库的“出站管理”，先选择凭据目标类型。平台提供三类目标：按人鉴权资产、平台原生工具和 Nexus 模型服务。
2. 对于按人鉴权资产，目标列表只展示用户已经订阅且声明为按人鉴权的资产。用户选择目标后，平台根据资产声明的鉴权方式生成对应的认证表单。已由资产声明的字段以只读方式展示，用户填写自己的个人凭据并执行一键探测。凭据未配置或探测失败时，平台不会在资产调用中回落到共享身份。
3. 对于平台原生工具，用户可以配置知识库导入所需的 Confluence、SharePoint/OneDrive 或 OSS 凭据。用户选择对应的导入通道后，平台展示该通道要求的认证字段，用户填写凭据并执行探测。执行导入时，用户需要同时具备目标知识库的 Contributor 或更高权限。
4. 对于 Nexus 模型服务，用户可以配置多条个人模型凭据，并通过启用/禁用和排序决定使用顺序。用户保存凭据后，平台对当前模型执行一次可用性检测并保存模型可用性快照，后续模型调用根据快照选择第一条可用的个人凭据。用户也可以手动刷新检测结果。
5. 个人凭据的密文字段默认掩码显示，用户可以点击查看明文；查看动作会被记录。用户可以更新、停用或删除个人凭据，也可以重新执行一键探测。
6. 如果个人模型凭据在真实调用中发生鉴权或权限失败，平台本次调用改用平台默认凭据，并通知用户前往 Nexus 申请权限或更新凭据。瞬时故障不会改写可用性快照。
