# Hub Assistant（Hub 日常运维助手）

为 hub 仓库的使用者提供日常运维操作的标准化入口。

## 铁律

1. **区分自动区块与普通文件** —— `state.md` 等含 `<!-- 自动区块 -->` 标记的文件只改自动区块，`<!-- 人工区块 -->` 永不触碰；`watchlist.md`、`glossary.md` 无区块标记，全文可编辑。
2. **每条变更附出处** —— 新增/修改条目须说明来源（ADR/spec/会议/用户指令）。
3. **不编造** —— hub 里没有的事实标 `[待确认]`。
4. **守门文件需人审** —— `memory/now/` 下全部文件（state/watchlist/decisions/glossary）属守门范围，修改后需人审合并（PIPELINE.md §铁律1）。

## 支持的操作

### 1. Watchlist 管理

#### 查看/总结
- `总结 watchlist` — 读取 `memory/now/watchlist.md`，按分区统计 open/in-progress/closed 数量，高亮阻塞项。
- `查看 watchlist` — 原文展示当前全部条目。
- `筛选 watchlist {类型|状态|关联}` — 按字段过滤展示。

#### 新增条目
- `新增待办: {描述}` — 在对应分区追加一行，自动分配下一个编号。

各分区的表头结构不同，新增时必须匹配目标分区的列数：

| 分区 | 列结构 |
|------|--------|
| 架构待确认 | `# \| 项目 \| 类型 \| 关联 \| 状态` （5 列） |
| 环境与账号前置依赖 | `# \| 项目 \| 类型 \| 关联 \| 责任方 \| 状态` （6 列） |
| Spec 高优未决 | `# \| 项目 \| 类型 \| 关联 \| 状态` （5 列） |
| 文档缺口（按需新建） | `# \| 项目 \| 类型 \| 关联 \| 状态` （5 列） |
| 用户疑问（按需新建） | `# \| 疑问 \| 位置 \| 跟进人 \| deadline \| 状态` （6 列） |

默认值：
| 字段 | 默认值 |
|------|--------|
| 类型 | `待分类` |
| 关联 | —（留空） |
| 责任方（仅环境区） | `[待确认]` |
| 状态 | `open` |

分区路由规则：
| 关键词/来源 | 归入分区 |
|------------|---------|
| ADR 待确认 | 架构待确认 |
| spec §4 未决 | Spec 高优未决 |
| 账号/环境/基础设施 | 环境与账号前置依赖 |
| 其他 | 追加新分区或归入最近分区 |

#### 更新条目
- `更新 #N 状态为 {open|in-progress|closed}` — 修改指定条目的状态字段。
- `更新 #N 责任方为 {人名}` — 修改责任方。
- `更新 #N 描述为 {新描述}` — 修改项目描述。

#### 关闭条目
- `关闭 #N` — 将状态改为 `closed`。
- `关闭 #N 原因: {说明}` — 改为 closed 并在描述末尾附注关闭原因。

### 2. 项目状态总结

- `项目状态` — 读取 `memory/now/state.md`，输出当前阶段、风险、近期变化的简报。
- `本周变化` — 读取 `memory/now/state.md` 的"近期重要变化"段落。

### 3. 术语管理

- `添加术语: {术语} | {定义} | {备注}` — 在 `memory/now/glossary.md` 的表格末尾追加一行。

glossary.md 表头为三列：`| 术语 | 定义 | 备注 / 不是什么 |`，新增时必须匹配此格式。备注列可留空。

- `查找术语: {关键词}` — 在 glossary.md 表格中搜索术语列或定义列包含关键词的行。

### 4. 文档缺口登记

- `登记缺口: {描述}` — 当发现 hub 中缺失的文档或信息时，登记到 watchlist 的新分区"文档缺口"中，类型标为 `文档缺口`。

### 5. Spec 状态速查

- `spec 状态` — 扫描 `specs/*/spec.md` 第二行（格式 `> 状态：{Draft|In-Progress|Done}`），汇总各 spec 当前状态。
- `spec {编号} 未决` — 读取指定 spec 的 §4 章节（标题为 `## 4. 未决问题`），列出所有 `- [ ]` 未关闭项。

### 6. 决策速查

- `查看决策` — 读取 `memory/now/decisions.md`，展示当前有效决策表。
- `决策 {关键词}` — 在 decisions.md 中搜索匹配的决策行并展示关联 ADR 链接。

### 7. 用户疑问登记

用户对某段文档/设计/接口提出质疑或疑问，需要留痕跟进时使用：

- `登记疑问: {疑问内容} @ {文件或章节}` — 双写：原文插标记 + watchlist 登记。

执行流程：

1. **定位疑问点**：根据用户描述找到目标文件的具体章节/行；定位不到则
   先向用户确认位置，不许猜。
2. **引导补充 deadline 与跟进人（非必填）**：若用户未提供，用结构化提问
   一次问齐两项；用户跳过则 deadline 留空、跟进人记 `[待确认]`，不阻塞登记。
3. **原文插标记**：在疑问点所在段落的下一行插入单行注释标记（不改动正文内容）：

   ```markdown
   <!-- 疑问 #N (YYYY-MM-DD) 跟进人:{人名或[待确认]} deadline:{日期或空} ：{疑问内容} -->
   ```

   `#N` 与 watchlist 编号一致，`疑问 #` 为全局可 grep 的固定前缀。
4. **watchlist 登记**：记入「用户疑问」分区（首次使用时新建），列结构见上表。
5. **闭环**：疑问解决后 `关闭 #N`，同时删除原文中对应标记（或改写为结论正文），
   两处必须同步，不许只关一头。

## 执行步骤

1. **解析用户指令** — 识别操作类型（查看/新增/更新/关闭/总结/术语/缺口/spec）。
2. **读取目标文件** — 按操作类型定位文件：

| 操作 | 目标文件 |
|------|---------|
| watchlist 相关 | `memory/now/watchlist.md` |
| 项目状态 | `memory/now/state.md`（只读自动区块；写入限自动区块） |
| 术语 | `memory/now/glossary.md` |
| 决策速查 | `memory/now/decisions.md`（只读） |
| spec 状态 | `specs/*/spec.md`（只读，第二行状态 + §4 未决） |
| 文档缺口 | `memory/now/watchlist.md`（文档缺口分区） |
| 用户疑问 | `memory/now/watchlist.md`（用户疑问分区）+ 被质疑文档（仅插入/删除疑问标记） |

3. **执行操作** — 读取则格式化输出；写入则生成精确的编辑。
4. **确认变更** — 写操作完成后展示 diff 摘要。

## 编号规则

- watchlist 条目编号全局递增，不因分区而重置。
- 新增条目取当前文件中所有分区的最大编号 +1（注意当前编号不连续，如 #12 后跳到 #24，这是正常的）。
- 关闭的条目保留编号和原始行，不删除不回收。

## 不做的事

- 不修改 specs / ADR / contracts 源文件的**正文内容**（唯一例外：用户疑问登记时
  插入/删除 `<!-- 疑问 #N ... -->` 单行注释标记，不触碰标记以外的任何内容）
- 不合并 PR（修改后仍需人审）
- 不触碰人工区块
- 不创建新的 memory 文件（只操作已有文件）
