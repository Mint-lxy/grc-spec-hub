# Feature Specification: 护栏策略（模板化内容防护与运行时拦截）

**Feature Branch**: `spec-sync-prd-v1.2`（本文件为既有 AC 格式 spec 的 spec-kit 风格重写，对齐 PRD v1.2 全量口径；原 AC 编号对照见文末附录）

**Created**: 2026-08-13（初版，随 specs/001–009 拆解）；2026-08-21（v1.2 同步）；2026-08-24（spec-kit 风格重写，待 peer review）

**Status**: Draft

**PRD 来源（v1.2）**: §7 M6（功能清单）、§6 J7（用户旅程）、§8.6 US106–US114、§9.5（护栏运行时规则）、§12.3（部署初始化清单）、§12.1/§12.2、hub `architecture/adr/001-service-split.md`

**Input**: 内容安全防护基线：平台管理员维护护栏策略模板（护栏组合 + 灵敏度 + 作用侧）并指定全局唯一的平台默认模板；Owner 创建 Agent 时必选恰好一个启用模板；平台网关在运行时对一切经平台流转的对话统一执行检测——输入侧命中直接拒答、输出侧命中全文不下发，响应回传命中的护栏类型。

---

## 背景与目标

提供平台的内容安全防护基线，回应「资产上线后缺少内容护栏防护」的问题（PRD §2）。治理模型为模板化：平台管理员维护护栏策略模板（护栏组合、逐条灵敏度与作用侧、启用状态）并指定平台默认模板；Owner 强制绑定一个启用模板（创建时选择、控制台可改绑）；平台网关是唯一执行点，对一切经平台流转的对话生效——资产 Agent 会话适用该 Agent 绑定的模板，平台 Chat agent-runtime（Chat）会话适用平台默认模板，任一会话恰好适用一个模板。命中即拦截，不设脱敏与告警档位、废弃置信度分档（hub `architecture/adr/001-service-split.md`）。对话侧场景（流式回放、停止生成、命中提示展示）定义处在 spec 001；门控检查项定义处在 spec 003；本 spec 承载模板管理、绑定规则、适用规则与命中处置语义。

## Clarifications

### Session 2026-08-24

- Q: 输出侧护栏的检测机制基线？ → A: **原则上采纳 Zhang 对 001 的机制裁定作为技术方案基线**——上游流式响应采用重叠滑动窗口检测，非流式响应采用全文缓冲检测（用户裁定）。
- Q: 资产流式输出时滑动窗口命中，此前已下发的安全前缀是否保留？ → A: **不允许保留，坚持全文零字下发终态**——保持与非流式输出接近的用户体验：用户体感上可能短时间看到部分安全前缀，继而看到全部内容**瞬时撤回**，并展示**安全护栏命中提醒**（占位替换＋护栏类型；命中轮次不落库，历史回看显示同一占位文案）（用户裁定）。
- Q: 滑动窗口参数与检测引擎选型是否写入 spec？ → A: **不写入**——窗口大小、重叠长度、检测超时、首段延迟基线、长响应上限与引擎 SaaS/自建选型均不在 spec 定义，作为待办在 watchlist 体现（#1/#50）（用户裁定）。
- Q: 非流式响应检测通过后是否按段回放（假流式）？ → A: **不做**——非流式在安全护栏检测通过后直接完整呈现全部内容，不额外做按段回放；滑动窗口仅用于流式响应、保留真实流式机制（2026-08-24 用户裁定修正，FR-042/FR-045 同步）。
- Q: 安全护栏命中提醒的形态与文案（含命中轮次在历史会话中的呈现）？ → A: **占位替换 + 护栏类型**——撤回后原位展示「该回答因命中安全护栏已被撤回」并含命中的护栏类型；命中轮次的回答**不落库**（与 spec 001 FR-036 失败轮次不落库同规，防止污染历史与上下文），历史会话回看中该轮显示同一占位文案（用户裁定）。
- Q: 模板编辑是否产生版本历史？命中事件的审计如何对齐「当时的模板内容」？ → A: **不引入模板版本概念**（用户明确不倾向），三个配套裁定：①命中事件**内联快照**当时的模板条目集（命中护栏＋灵敏度＋作用侧的当时值）——审计可追溯且不引入版本轴；②**模板创建后不可原地修改——修改即另存为新模板，原模板保留**（模板序列而非版本号；规则变更经「新模板＋启用＋Owner 改绑」到达存量资产）；③模板启用状态由管理员总控（管理「生效模板集合」——哪些模板可被 Owner 选中配置），**Owner/Deputy 为每个资产配置恰好一个生效模板**（现状绑定模型确认不变）（用户裁定）。
- Q: P0 内置护栏的类型枚举？ → A: **暂定四类**：提示词注入检测、有害内容检测、意图偏离检测、违禁词检测——**不包含个人身份信息（PII）检测**（与准入测评三类题集对齐；护栏清单结构上可扩展，P0 不开放自助注册新类型）。**备注：该枚举待客户确认**（watchlist #61）（用户裁定）。
- Q: 模板变更（另存新模板/改绑/停用）对进行中会话的生效边界？ → A: **改绑即时生效、无会话级快照**——进行中会话的下一条内容起即按新的绑定关系检测。模板创建后不可原地修改，因此不存在「已绑定模板内容被原地编辑后即时生效」；模板停用只移出新绑定候选集合，不影响存量已绑定 Agent 运行，存量资产需经 Owner 改绑才切换规则。
- Q: 违禁词表上传的校验规则？ → A: 纯文本逐行一条（模板下载即格式说明）；**非法/重复条目整块拒绝并逐条报告**（不允许部分写入——与订阅表单 YAML「不合规不允许保存」惯例一致）；违禁词表是护栏策略模板条目集的一部分，模板创建后不可原地修改，因此既有模板的词表调整必须通过「基于此模板另存为新模板」承载，新模板启用并由 Owner 改绑后到达存量资产；单表条目上限与单文件大小上限记为待审定项，审定后补入 PRD §9.10 参数基线（用户裁定）。
- Q: 护栏策略模板能否被删除？ → A: **不支持删除**——模板只可停用、不可删除，停用即终态（模板是治理记录：命中事件与审计以模板为参照，删除会切断追溯链；与平台「业务记录永久保留」原则同构）（用户裁定）。

## User Scenarios & Testing

### User Story 1 — 平台管理员维护护栏策略模板 (Delivery: P0, Story Order: S1)

平台管理员创建护栏策略模板并可基于既有模板另存为新模板：模板由若干护栏组成，逐条配置灵敏度（0 至 100，数值越高越容易命中）与作用侧（输入侧/输出侧/双侧）；支持启用与停用；违禁词表支持下载模板与上传，作为模板条目集的一部分不可在既有模板上原地修改。

**Why this priority**: 模板是全部防护能力的载体——无模板则网关无检测规则、Agent 无绑定对象、Chat 无默认防护。

**Independent Test**: 创建一个含多种护栏的模板并逐条配置灵敏度与作用侧，验证启停用流转、违禁词表上传与条目明细。

**Acceptance Scenarios**:

1. **Given** 平台管理员进入护栏策略管理, **When** 创建模板, **Then** 模板由若干护栏条目组成，每条含护栏类型、灵敏度（0 至 100）与作用侧（输入侧/输出侧/双侧）；灵敏度是护栏行为的唯一旋钮（平台不设置信度分档）。
2. **Given** 已有模板, **When** 维护, **Then** 支持只读查看、基于此模板另存为新模板、启用、停用（停用即终态、不可重新启用，恢复规则须另存新模板——2026-08-25 用户裁定补充）；违禁词表支持下载模板与上传，词表调整必须随另存新模板一起生效。
3. **Given** 模板需要调整规则, **When** 管理员操作, **Then** 不可原地修改——另存为新模板（原模板保留），启用后由 Owner 改绑到达存量资产；改绑即时生效（含进行中会话，无快照）。
4. **Given** 模板被停用, **When** 停用生效, **Then** 只影响新绑定——存量已绑定 Agent 继续按该模板运行，直到 Owner 改绑（停用不可重新启用，2026-08-25 用户裁定补充）；但下一次质量门控重跑（版本发布或重新上架）时强制校验启用状态，未启用则阻断并引导改绑。

### User Story 2 — 平台默认模板指定与恒在保障 (Delivery: P0, Story Order: S2)

平台管理员从启用模板中指定全局唯一的平台默认护栏策略模板，适用于平台 Chat agent-runtime 的会话；当前默认模板不可直接停用，须先指定另一启用模板为新默认——Chat 恒可用且始终有模板适用。

**Why this priority**: Chat 是平台默认对话对象与第一触点；「默认模板恒在」是「首日对话不无护栏运行」的冷启动保障（PRD §12.3）。

**Independent Test**: 指定默认模板；尝试停用当前默认模板（被阻断）；指定新默认后停用旧默认（通过）；验证平台部署后默认模板即存在。

**Acceptance Scenarios**:

1. **Given** 平台部署完成, **When** 首次启动, **Then** 平台默认护栏策略模板已随部署内置存在（管理员只维护、不创建——避免上线瞬间模板数为零导致「Chat 恒可用」「每会话恰好一个模板」「默认模板恒在」互相矛盾，PRD §12.3）。
2. **Given** 至少一个启用模板, **When** 平台管理员指定默认, **Then** 从启用模板中指定全局唯一一个，适用于 Chat 会话。
3. **Given** 当前默认模板, **When** 管理员尝试直接停用, **Then** 被阻断；须先指定另一启用状态的模板为新默认，原模板方可停用。

### User Story 3 — 运行时命中处置 (Delivery: P0, Story Order: S3)

平台网关对一切经平台流转的对话执行检测：输入侧命中直接拦截并拒答；输出侧按上游响应形态分双路径——流式响应采用重叠滑动窗口检测（窗口通过才释放其内容，保留真实流式机制）、非流式响应采用全文缓冲检测（通过后直接完整呈现，不做按段回放式的假流式）；输出侧命中时坚持全文零字下发终态：终止上游生成与后续输出、**瞬时撤回全部已下发内容**，并展示安全护栏命中提醒；响应回传命中的护栏类型；中止生成时未释放内容按当前路径完成检测，未通过不得继续下发、已下发部分按命中规则撤回。

**Why this priority**: 命中处置是护栏的运行时价值兑现点，直接决定敏感内容不外泄的底线。

**Independent Test**: 分别构造输入命中、输出命中、中止生成三类场景，验证拦截/占位/回放行为与护栏类型回传。

**Acceptance Scenarios**:

1. **Given** 用户发送的消息命中输入侧护栏, **When** 提交, **Then** 直接拦截并拒答，响应回传命中的护栏类型（对话页展示与提示语义见 spec 001）。
2. **Given** 上游提供非流式响应（完整回答返回）, **When** 输出侧护栏全文检测, **Then** 通过则直接完整呈现全部内容（不做按段回放式的假流式）；命中则全文不呈现并展示安全护栏命中提醒。
3. **Given** 上游提供流式响应, **When** 输出内容持续到达, **Then** 按重叠滑动窗口执行输出侧检测，窗口通过才释放其内容下发；任一窗口命中时：立即终止上游生成与后续输出，**瞬时撤回全部已下发内容（含此前已通过窗口的前缀）**，原位展示「该回答因命中安全护栏已被撤回」并含命中的护栏类型——终态全文零字留存；命中轮次的回答不落库，历史回看中该轮显示同一占位文案（2026-08-24 用户裁定）。
4. **Given** 回答正在生成或回放, **When** 用户点击停止生成, **Then** 停止读取后续内容，未释放的已生成内容按当前路径完成检测；检测未通过则按命中规则处置（撤回全部已下发内容并展示命中提醒）。
5. **Given** 护栏命中（输入或输出侧）, **When** 响应返回, **Then** 响应中回传命中的护栏类型。
6. **Given** 输出侧检测执行机制, **When** 评审该机制, **Then** 以「流式滑动窗口 / 非流式全文缓冲」双路径为技术方案基线（采纳 Zhang 对 001 的机制裁定）；窗口参数与引擎选型不在 spec 定义，挂 watchlist #1/#50 留 plan 阶段压测与选型（2026-08-24 用户裁定）。

### User Story 4 — Owner 绑定与改绑 (Delivery: P0, Story Order: S4)

Owner 创建 Agent 时从启用状态的模板中选择恰好一个（不可不选、不可多选）；选择前可只读查看模板条目明细（护栏、灵敏度、作用侧）——选择不是盲选；上架后可在资产控制台改绑其他启用模板，即时生效。

**Why this priority**: 绑定是「上线即符合平台防护基线」的落点；依赖模板管理与门控先行。

**Independent Test**: 创建 Agent 不选模板（阻断）、查看条目明细后选择一个、上架后改绑并验证即时生效。

**Acceptance Scenarios**:

1. **Given** 创建 Agent 的向导末步, **When** 选择护栏策略模板, **Then** 必须从启用状态的模板中选择恰好一个；选择前可只读查看启用模板的条目明细（护栏、灵敏度、作用侧）（创建向导侧语义见 spec 003 FR-011）。
2. **Given** 已上架 Agent, **When** Owner 在资产控制台改绑另一启用模板, **Then** 即时生效（热改类，不进入修订、不重跑门控——spec 004 FR-016）。
3. **Given** Agent 未绑定模板或所绑模板被停用, **When** 下一次门控重跑（版本发布/重新上架）, **Then** 强制校验所绑模板处于启用状态，未启用则阻断并引导改绑（spec 003 FR-022⑦ 联动）。

### Edge Cases

- 创建 Agent 时无任何启用模板可选？——部署内置的平台默认模板恒存在，该场景不发生；若发生（默认模板被异常删除）则创建阻断并提示联系平台管理员（§12.3 的前提保障）。
- 模板另存/改绑与进行中会话并发？——模板不可原地修改（另存为新模板）；改绑即时生效、无会话级快照：会话中下一条内容起按变更后的绑定检测（FR-003/FR-004，2026-08-24 用户裁定）。
- 已下架资产的历史会话？——不产生新对话，护栏无检测对象（下架语义见 spec 004）。
- 对话中上传的临时文件？——内容视同用户输入，纳入输入侧护栏检测，命中处置相同（拒答并回传护栏类型）；临时文件上传为 P1 功能（M1-4），本条规则随其上线生效。
- MCP 资产的返回内容？——MCP 不单独绑定护栏；其返回内容进入对话上下文后由输出侧检测覆盖。
- 灵敏度调边（0 与 100）？——0 等于近乎不命中、100 等于极易命中；具体映射随护栏引擎实现（watchlist #1）确定，spec 只承诺单调性。
- 命中撤回后，该轮在历史会话中显示什么？——命中轮次的回答不落库；回看时该轮显示「该回答因命中安全护栏已被撤回」占位（含护栏类型）（FR-042，2026-08-24 用户裁定）。
- 违禁词表上传含重复或非法条目？——整块拒绝并逐条报告问题条目，不允许部分写入（FR-003，2026-08-24 用户裁定）。
- 废弃模板堆积？——模板不可删除，废弃模板以停用为终态保留（治理记录可追溯；FR-003，2026-08-24 用户裁定）。

## Requirements

### Functional Requirements

**模板管理（平台管理员）**

- **FR-001**: 护栏策略模板管理 MUST 仅平台管理员可用（原 AC-1；PRD M6-1、§5.3）。
- **FR-002**: 模板 MUST 由若干护栏条目组成，逐条配置灵敏度（0 至 100，数值越高越容易命中——护栏行为的唯一旋钮，不设置信度分档）与作用侧（输入侧、输出侧或双侧）。P0 内置护栏类型 MUST 为四类：提示词注入检测、有害内容检测、意图偏离检测、违禁词检测——**不包含个人身份信息（PII）检测**；护栏清单结构上可扩展，P0 MUST NOT 开放自助注册新类型（原 AC-1/AC-16；PRD M6-1、§9.5；类型枚举为 2026-08-24 用户裁定，待客户确认，watchlist #61）。
- **FR-003**: 模板 MUST 支持创建、启用、停用与「另存为新模板」（**模板创建后不可原地修改——修改即另存为新模板，原模板保留**，模板序列而非版本号，2026-08-24 用户裁定）；MUST NOT 支持删除——停用即模板的终态（治理记录永久保留，命中事件与审计以模板为参照可追溯；2026-08-24 用户裁定）。模板启用状态由管理员总控——管理员管理「生效模板集合」（哪些模板可被 Owner 选中配置）；启用动作仅用于将新建/另存后的未启用模板加入生效集合，模板一旦停用即不可重新启用，如需恢复规则须另存为新模板。违禁词表 MUST 支持下载模板与上传，且作为模板条目集的一部分随模板创建/另存生效，不得在既有模板上原地修改。上传校验（2026-08-24 用户裁定）：纯文本逐行一条（下载模板即格式说明）；非法/重复条目 MUST 整块拒绝并逐条报告（不允许部分写入）；单表条目上限与单文件大小上限为待审定项，审定后补入 PRD §9.10 基线（原 AC-2；PRD M6-1、US-111）。
- **FR-004**: 模板不可原地修改（FR-003）——规则变更 MUST 经「另存新模板 → 管理员启用 → Owner 改绑」路径到达存量资产；改绑即时生效。模板停用 MUST 只影响新绑定——存量 Agent 继续按该模板运行直到 Owner 改绑。**生效边界（2026-08-24 用户裁定）**：改绑对进行中会话即时生效、不设会话级快照——会话中下一条内容起即按变更后的绑定关系检测；停用本身不改变存量已绑定会话的检测模板（原 AC-3；PRD §9.5、J7——「模板修改即时生效」的原文口径随不可变模型收敛为改绑路径）。

**平台默认模板**

- **FR-010**: 平台管理员 MUST 可从启用模板中指定全局唯一的平台默认护栏策略模板，适用于平台 Chat agent-runtime 的会话（原 AC-4；PRD M6-2、§9.5）。
- **FR-011**: 当前默认模板 MUST NOT 可直接停用——须先指定另一启用状态的模板为新默认，原模板方可停用（默认模板恒在，Chat 始终有模板适用）（原 AC-5；PRD §9.5、M6-2）。
- **FR-012**: 平台默认护栏策略模板 MUST 随平台部署内置（内容随部署定义；管理员只维护、不创建），避免冷启动矛盾（PRD §12.3）。

**模板绑定（Owner 侧）**

- **FR-020**: Owner 创建 Agent 时 MUST 从启用状态的模板中选择恰好一个（不可不选、不可多选）（原 AC-6；PRD M6-3、hub `architecture/adr/001-service-split.md`；创建向导侧见 spec 003 FR-011）。
- **FR-021**: Owner MUST 可只读查看启用模板的条目明细（护栏、灵敏度、作用侧）——选择不是盲选；Owner 不参与数值配置（原 AC-7；PRD M6-3、§9.5）。
- **FR-022**: 上架后 Owner MUST 可在资产控制台改绑其他启用模板，即时生效（热改类，不进入修订、不重跑门控）（原 AC-8；PRD §9.5；通道归属见 spec 004 FR-016）。

**绑定有效性与门控联动**

- **FR-030**: 质量门控第七项（仅 Agent）MUST 为「所绑护栏策略模板当前处于启用状态」——检查项定义处为 spec 003 FR-022，本 spec 仅引用（原 AC-9；PRD M6-4、M3-4）。
- **FR-031**: 存量在架资产 MUST NOT 受模板停用影响；仅在下一次门控重跑（版本发布或重新上架）时强制校验所绑模板处于启用状态，未启用则阻断并引导改绑（原 AC-10；PRD §9.5、J7、M6-4）。

**运行时命中处置**

- **FR-040**: 平台网关 MUST 是护栏的唯一执行点，对一切经平台流转的对话（资产 Agent 会话与 Chat 会话）生效（原 AC-11；PRD §9.5、hub `architecture/adr/001-service-split.md`）。
- **FR-041**: 命中即拦截 MUST 为唯二处置形态：输入侧命中直接拦截并拒答；输出侧命中拦截并以「该回答因命中安全护栏已被撤回」占位文本替代原输出，且展示命中的护栏类型。响应 MUST 回传命中的护栏类型。平台 MUST NOT 设脱敏与告警档位（原 AC-12/AC-15；PRD §9.5、M6-5）。
- **FR-042**: 输出侧检测 MUST 按上游响应形态执行双路径（2026-08-24 用户裁定采纳 Zhang 机制基线）：**流式响应**——重叠滑动窗口检测，窗口通过才释放其内容下发（保留真实流式机制）；**非流式响应**——缓冲完整回答并全文检测，通过后**直接完整呈现全部内容**，MUST NOT 做按段回放式的假流式（2026-08-24 用户裁定修正）。**命中处置终态 MUST 为全文零字留存**：立即终止上游生成与后续输出、瞬时撤回全部已下发内容（含此前已通过窗口的前缀——用户体感为短时可见部分内容后整体撤回）、原位展示「该回答因命中安全护栏已被撤回」并含命中的护栏类型；**命中轮次的回答 MUST NOT 落库**（与 spec 001 FR-036 失败轮次不落库同规），历史会话回看中该轮显示同一占位文案（提醒形态为 2026-08-24 用户裁定）。窗口参数与引擎选型 MUST NOT 在 spec 定义（挂 watchlist #1/#50 留 plan 阶段）（原 AC-13；PRD §9.5、M1-6——§9.5「命中则全文不下发」承诺在流式链路扩展为「撤回全部已下发内容」）。
- **FR-043**: 中止生成时 MUST 停止读取上游后续内容；对未释放的已生成内容按当前路径完成检测（流式完成当前窗口、非流式完成已有内容）；检测未通过 MUST 按 FR-042 命中规则处置（撤回全部已下发内容并展示命中提醒），通过则可保留已下发部分（原 AC-14；PRD §9.5、M1-6；2026-08-24 用户裁定口径）。
- **FR-044**: 临时文件内容 MUST 视同用户输入、纳入输入侧护栏检测，命中处置相同（拒答并回传护栏类型）；本条随 P1 临时文件上传功能（M1-4）上线生效（PRD §9.5）。
- **FR-045**: 回答呈现与延迟口径随双路径区分：非流式响应在全文生成与检测完成后一次性完整呈现（无按段回放）；流式响应首段到达延迟仅含首个窗口的生成与检测时长（具体基线不入 spec，随 plan 阶段压测确定，watchlist #44/#50）（2026-08-24 用户裁定口径）。

**护栏适用规则**

- **FR-050**: 资产 Agent 会话 MUST 适用该 Agent 绑定的模板；Chat 会话 MUST 适用平台默认模板；任一会话 MUST 恰好适用一个模板，不存在叠加（原 AC-17/AC-18；PRD §9.5、J7）。
- **FR-051**: 外部接入的 MCP MUST NOT 单独绑定护栏；其返回内容进入对话上下文后由输出侧检测覆盖（原 AC-19；PRD §9.5）。

### Key Entities

- **护栏（Guardrail）**: 内容安全检测能力原子。P0 内置四类：提示词注入检测、有害内容检测、意图偏离检测、违禁词检测（不含个人身份信息检测——2026-08-24 用户裁定，待客户确认，watchlist #61）。不直接绑定 Agent，只能被组合进模板。
- **护栏策略模板（Guardrail Policy Template）**: 平台管理员维护的护栏组合。关键属性：条目集（护栏 + 灵敏度 0–100 + 作用侧）、启用状态、违禁词表引用。**创建后不可变**——修改即另存为新模板、原模板保留（模板序列而非版本号）；不可删除，停用即终态；规则变更经「新模板＋启用＋Owner 改绑」到达存量资产。
- **平台默认模板指定（Default Designation）**: 全局唯一的指向关系（Chat 会话适用）；恒须存在（随部署内置；先指定新默认方可停用旧默认）。
- **绑定（Binding）**: Agent 与一个启用模板的关系（恰好一个；控制台改绑即时生效；门控重跑时校验启用态）。
- **命中事件（Hit Event）**: 一次护栏命中。关键属性：命中护栏类型、作用侧、处置结果（输入侧拒答／输出侧全文零字留存）；**内联快照当时的模板条目集**（命中护栏＋灵敏度＋作用侧的当时值——模板无版本概念，审计可追溯性由内联快照承载，2026-08-24 用户裁定）；输出侧命中时含「已下发内容撤回」标记与命中时刻已下发的前缀范围（供审计与运营复盘）；命中记录的查询与运营看板为 P1。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 输入侧护栏命中的消息 100% 被拦截拒答，且 100% 回传命中的护栏类型。
- **SC-002**: 输出侧护栏命中的回答终态 0 字留存：非流式命中 0 字下发；流式命中时命中窗口及其后 0 字下发、此前已下发的前缀 100% 被瞬时撤回，且 100% 展示安全护栏命中提醒。
- **SC-003**: 任一会话 100% 恰好适用一个模板；Chat 会话 100% 适用平台默认模板。
- **SC-004**: 平台部署后首次启动即存在默认模板（冷启动矛盾 0 次发生）；当前默认模板被直接停用 100% 被阻断。
- **SC-005**: 模板停用后存量已绑定 Agent 0 影响；下一次门控重跑时未启用模板的绑定 100% 被阻断并引导改绑；模板变更对进行中会话 100% 自下一轮内容起生效（无快照残留）。
- **SC-006**: Agent 创建时未选模板或多选 100% 被阻断；模板条目明细 100% 可只读查看（无盲选）。
- **SC-007**: 中止生成时已生成部分 100% 先检测后呈现（流式保留已下发部分、非流式完整呈现——2026-08-25 用户裁定措辞修订，消除与「不做假流式」的措辞矛盾）。
- **SC-008**: 灵敏度调整对命中率单调有效（提高灵敏度不降低命中率——随护栏引擎实测验证，watchlist #1）。
- **SC-009**: 命中事件 100% 内联当时的模板条目集快照；模板被另存/停用后，历史命中记录 100% 可还原当时的检测规则。

## Assumptions

- 护栏检测在平台网关执行；检测引擎的实现形态（SaaS 服务或自建）待 PoC 裁定（watchlist #1）。
- 对话侧场景（流式回放、停止生成、命中提示的页面展示、输入侧拒答提示文案）定义处在 spec 001；本 spec 只定义处置语义与类型回传。
- 质量门控检查项定义处为 spec 003（FR-022）；门控触发与发布链路见 spec 004。
- 平台默认模板与发布准入测评模板均随部署内置（PRD §12.3）。
- 命中处置的响应格式遵循统一错误码与响应包络规范（hub ADR-002/006）。

## Non-Goals / Boundaries

- **护栏运营看板与命中记录查询**（P1：按模板聚合的检测量、命中率、近 24 小时拦截次数；命中记录列表与明细）（PRD M6-6）。
- **脱敏与告警档位**：不设（命中即拦截为唯二处置形态，hub `architecture/adr/001-service-split.md`）。
- **置信度分档**：已废弃；灵敏度是唯一旋钮（PRD §9.5）。
- **模板删除**：不提供——模板只可停用（治理记录永久保留，2026-08-24 用户裁定）。
- **对话侧交互**：流式回放、停止生成、命中提示展示——spec 001。
- **门控项定义与发布链路**：spec 003/004。
- **平台原生工具的护栏**：不绑定护栏模板，导入内容沉淀进知识库后由检索回答的输出侧检测覆盖（PRD §9.5、M1-13c）。
