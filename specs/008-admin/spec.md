## 背景与目标

管理后台提供平台管理员的「模板化与开关式治理」能力，覆盖平台自有对象与治理开关，而不介入资产 Owner/Deputy 的生命周期权责。管理员唯一的资产运行控制手段是按资产维度停用出站调用：该动作禁用该资产的全部个人凭据解析，使一切经平台流向该资产的调用失败，但不改变资产状态；撤下、重新上架与删除仍完全归 Owner/Deputy（hub `architecture/adr/001-service-split.md`）。

本 spec 承载 008 管理后台页面与治理动作：治理中心、发布准入测评模板维护、测评阻断开关、平台原生工具维护、平台资源注册表、用户视图、角色映射、公共目录冷启动、模型设置。护栏策略模板的业务语义与运行时检测定义处在 spec 006；发布链路如何消费测评模板与阻断开关定义处在 spec 004；用户侧凭据与解析规则定义处在 spec 007；知识目录日常维护定义处在 spec 005。

## Clarifications

### Session 2026-08-24

- Q: 孤儿资产补员一次性指定谁？ → A: 同次指定新 Owner 与至少一位 Deputy，提交时一次性满足有效负责人冗余。
- Q: 多个 Alice 角色如何合并功能点与可用模型？ → A: 并集合并：任一角色授予即有效；未配置角色贡献基线权限。
- Q: P0 是否支持模型线上生命周期变更？ → A: P0 不支持模型线上生命周期变更。模型清单、启用态与默认模型随部署内置或通过部署配置变更，不在管理后台运行期修改；管理后台 P0 仅可查看模型清单、在角色映射中引用既有模型，并在线维护模型条目的平台默认凭据。模型删除/停用在用校验降为 P1 或部署变更流程约束。
- Q: 平台原生工具「鉴权配置」保存什么？ → A: 区分连接器技术鉴权与来源内容访问凭据。管理员可维护平台调用/管理原生工具连接器所需的服务端技术配置或平台侧凭据；但不得配置可代替操作人读取来源内容的共享账号或共享密钥。知识导入访问来源内容时一律使用操作人个人凭据。
- Q: Nexus 令牌与「每个模型的平台默认凭据」是什么关系？ → A: 平台资源注册表维护一个或多个平台内部 Nexus 凭据对象；模型条目的平台默认凭据只引用其中一个，不重复保存密钥值。

## User Scenarios & Testing

### User Story 1 — 平台管理员治理资产运行风险 (Delivery: P0, Story Order: S1)

平台管理员在治理中心查看全平台 Agent 与 MCP 的状态、负责人、出站调用停用标记和孤儿资产标记；可按资产维度停用或恢复出站调用，并为孤儿资产补员。管理员不下架、不删除、不修改资产状态。

**Why this priority**: 这是平台管理员的底线治理能力：既保留平台对经平台流转调用的止血手段，又不破坏 Owner/Deputy 对资产状态的责任边界。

**Independent Test**: 构造正常资产、已下架资产、已发布但出站停用资产、孤儿资产四类样本，验证总览标记、停用/恢复、补员、通知与资产状态不变。

**Acceptance Scenarios**:

1. **Given** 平台存在 Agent 与 MCP 资产, **When** 管理员打开治理中心, **Then** 看到全平台资产表，包含名称、类型、状态、出站调用停用标记与负责人信息；孤儿资产显著标记。
2. **Given** 管理员停用某资产出站调用, **When** 填写原因并确认, **Then** 该资产的全部个人凭据解析被禁用，一切经平台流向该资产的调用失败并返回「该资产的出站调用已被平台停用」；资产状态保持不变。
3. **Given** 已被出站调用停用的资产被 Owner 下架后重新上架, **When** 未被管理员手动恢复, **Then** 资产可显示为「已发布」，但出站调用停用仍继续生效。
4. **Given** 管理员恢复某资产出站调用, **When** 恢复生效, **Then** 该资产不再因平台停用而失败，治理中心与资产控制台的停用标记同步解除，操作留痕并通知全体负责人。
5. **Given** 某资产全部 Owner 与 Deputy 账号均被 Alice 停用, **When** 管理员在治理中心补员, **Then** 同次指定新 Owner 与至少一位 Deputy，提交时实时复核孤儿性与补员后的有效负责人冗余，并在补员后恢复订阅入口与 Owner 职能；补员操作留痕并通知新指定负责人。
6. **Given** 管理员查看任一资产行, **When** 执行治理动作, **Then** 管理员无法改变资产状态，无法代 Owner/Deputy 下架、重新上架或删除资产。

### User Story 2 — 平台管理员维护发布准入模板与阻断策略 (Delivery: P0, Story Order: S2)

平台管理员维护全局唯一的发布准入测评模板（提示词注入、意图偏离、内容安全三类问题集与各自阈值），并配置测评未通过时是否阻断上架的单一总开关。模板随部署内置，管理员维护而非创建；新发起的发布准入测评使用届时模板，已发起任务使用发起时快照。

**Why this priority**: 准入测评是 Agent 上架前的安全质量基线；模板和阻断开关决定测评结果对发布链路的治理强度。

**Independent Test**: 修改模板问题集与阈值，发起两次发布准入测评，验证新任务使用新模板、已发起任务不受影响；分别切换阻断开关开/关，验证测评未通过的发布结果。

**Acceptance Scenarios**:

1. **Given** 平台部署完成, **When** 管理员进入准入测评模板维护页, **Then** 全局唯一的发布准入测评模板已存在，含三类初始问题集与三类初始阈值。
2. **Given** 管理员修改模板问题集或阈值, **When** 保存成功, **Then** 后续新发起的发布准入测评使用修改后的模板；已完成历史测评记录不变，进行中测评继续按发起时模板快照执行与判定。
3. **Given** 管理员配置测评阻断开关, **When** 开关开启, **Then** Agent 准入测评整体未通过时阻断上架；开关关闭（默认）时允许上架但资产详情页标注「准入测评未通过」。
4. **Given** MCP 发布流程, **When** 质量门控通过, **Then** MCP 不执行发布准入测评，测评模板与阻断开关不作用于 MCP。

### User Story 3 — 平台管理员维护平台资源与平台原生工具 (Delivery: P0, Story Order: S3)

平台管理员维护平台资源注册表（Milvus/PGVector 实例、预留 Azure 服务类型、平台内部 Nexus 凭据对象）及逐人授权；维护三个平台原生工具的服务地址、连接器技术鉴权配置与启停用。平台资源不是资产；平台原生工具仅作为知识导入通道，导入访问来源内容时使用操作人个人凭据。

**Why this priority**: 平台资源决定知识库构建与模型调用是否有可用基础设施；平台原生工具决定外部内容源是否可被导入知识库。

**Independent Test**: 创建和授权一个额外向量数据库实例，验证用户侧选择器仅展示默认实例与本人获授权实例；回收授权后验证新建不可选但存量知识库不受影响；停用一个平台原生工具后验证新导入入口不可用。

**Acceptance Scenarios**:

1. **Given** 平台部署完成, **When** 管理员查看平台资源注册表, **Then** 默认 Milvus 实例、默认 PGVector 实例与至少一个平台内部 Nexus 凭据对象已存在。
2. **Given** 管理员登记平台资源实例, **When** 填写资源类型、连接信息、凭据与可用范围, **Then** 实例类条目可一键探测连接与凭据；模型类资源不在注册表中维护。
3. **Given** 平台资源可用范围为授权可用, **When** 管理员逐人授予或回收可使用人员, **Then** 授予与回收即时生效、留痕、不经 Alice、不发站内通知；回收不影响已建在该实例上的存量知识库。
4. **Given** 用户在建库或构建参数中选择向量库实例, **When** 展示候选项, **Then** 只展示默认实例与该用户本人已获授权实例。
5. **Given** 管理员维护平台原生工具, **When** 配置 Confluence MCP、SharePoint/OneDrive MCP、OSS（S3/Blob）MCP, **Then** 可维护服务地址、连接器技术鉴权配置与启停用；原生工具不上 Marketplace、免订阅、无 Owner、不适用质量门控与准入测评。
6. **Given** 知识库通过平台原生工具导入内容, **When** 发起导入, **Then** 访问来源内容时使用操作人在密钥库配置的个人凭据；平台原生工具不得使用管理员配置的共享来源账号或共享密钥代替操作人个人凭据。

### User Story 4 — 平台管理员维护身份映射与公共目录冷启动 (Delivery: P0, Story Order: S4)

平台管理员查看从 Alice 同步的用户只读列表，配置 Alice 角色到平台功能点与可用模型的映射，并创建公共目录一级节点、指定一级目录控制角色与一级目录知识库创建角色持有人。未配置映射的角色仍享有基线权限。

**Why this priority**: 身份与权限配置决定平台导航、模型可用性和公共知识目录的治理起点；若配置缺失，普通用户不能出现空导航或空模型列表。

**Independent Test**: 构造已配置角色、未配置角色、多个角色叠加用户，验证功能点可见性、可用模型与基线权限；创建一级公共目录并验证后续日常维护不在管理后台。

**Acceptance Scenarios**:

1. **Given** Alice 同步用户数据, **When** 管理员查看用户视图, **Then** 只读展示账号、角色与状态；不提供新增用户、设置密码或修改 Alice 角色能力。
2. **Given** 管理员配置角色映射, **When** 选择 Alice 角色, **Then** 可配置该角色对应的平台功能点与可用模型；功能点枚举以 PRD §5.3 为准。
3. **Given** 用户的 Alice 角色未显式配置映射, **When** 用户登录平台, **Then** 仍享有基线权限：全员功能点可见，默认模型可用。
4. **Given** 管理员执行公共目录冷启动, **When** 创建一级目录, **Then** 必须指定一级目录控制角色与一级目录知识库创建角色的持有人；其余层级目录维护与角色授予不在管理后台，由目录控制角色持有人在知识管理中完成。

### User Story 5 — 平台管理员查看模型清单并维护平台默认凭据 (Delivery: P0, Story Order: S5)

平台管理员可查看随部署内置的模型清单、启用态与默认模型，并为既有模型条目在线维护平台默认凭据引用；P0 不支持运行期新增、编辑、删除、启停用模型，也不支持在线更换默认模型。模型分为对话、多模态、重排序、向量化四类。平台资源注册表维护一个或多个平台内部 Nexus 凭据对象，模型条目的平台默认凭据只引用其中一个，不重复保存密钥值。

**Why this priority**: 模型清单是 Chat、知识构建、检索重排序与准入测评裁判的共同模型目录；P0 将模型生命周期收敛为部署配置，降低线上治理风险，同时保留平台默认凭据在线维护以保障模型类资源兜底可用。

**Independent Test**: 查看部署内置模型清单与默认模型；为既有模型条目选择平台资源注册表中的 Nexus 凭据对象作为平台默认凭据；验证页面不提供模型新增、编辑、删除、启停用或默认模型切换入口，且不重复保存密钥值。

**Acceptance Scenarios**:

1. **Given** 平台部署完成, **When** 管理员查看模型设置, **Then** 可只读查看随部署内置的模型清单、启用态与默认模型；模型必须归入对话、多模态、重排序或向量化四类之一，内容增强与准入测评裁判模型复用对话类模型。
2. **Given** 管理员在 P0 模型设置中操作, **When** 查看页面, **Then** 不提供运行期新增、编辑、删除、启停用模型或切换默认模型入口；这些变更只能通过部署配置变更或 P1 能力处理。
3. **Given** 管理员为既有模型条目配置平台默认凭据, **When** 选择凭据来源, **Then** 只能从平台资源注册表的平台内部 Nexus 凭据对象中选择一个作为引用，不在模型条目重复保存密钥值；用户没有可用个人模型凭据时，模型类调用可按 spec 007 / ADR-0016 规则回落该平台默认凭据，该回落只适用于平台自有模型资源，不适用于资产调用。

### Edge Cases

- 出站调用停用作用于已发布、已下架、待发布等任一资产状态？——停用与资产状态正交；状态不变，停用标记持续存在，重新上架不自动解除。
- 出站调用停用是否绕过订阅与个人凭据差异？——不绕过，按资产维度禁用该资产的全部个人凭据解析；无论调用方使用哪条个人凭据，经平台流向该资产的调用均失败。
- 管理员停用出站调用时未填写原因？——提交被阻断；原因随通知发送给全体负责人，并在资产控制台常驻可见。
- 孤儿资产在管理员打开页面后被原负责人恢复？——提交补员时实时复核孤儿性，已不满足孤儿条件则拒绝并提示刷新。
- 准入测评模板在测评执行中被修改？——进行中测评使用发起时模板快照；新发起测评使用修改后模板。
- 三类准入测评阈值任一未达标？——整体未通过；不加权、不允许其他类别高分拉平。
- 每类向量数据库没有默认实例？——违反部署初始化与默认可用恒在规则；管理员不得使每类向量数据库的默认实例数降为零。
- 平台资源授权被回收后，用户已建知识库如何处理？——存量知识库继续运行；被回收人只是新建或新选择时看不到该授权实例。
- 平台原生工具被停用？——新发起的对应外部导入入口不可用或被阻断；已导入并进入知识库的内容不因此删除。
- 用户具有多个 Alice 角色？——角色映射按所有匹配角色合并计算；未配置角色贡献基线权限，显式配置角色贡献其配置的功能点与可用模型。
- 模型新增后个人模型凭据快照如何处理？——属于 spec 007 凭据可用性快照规则：存量个人凭据对新增模型为未检测，按不可用解析，引导用户手动刷新；平台默认凭据由本 spec 的模型设置维护。

## Requirements

### Functional Requirements

**治理中心**

- **FR-001**: 治理中心 MUST 仅平台管理员可用，并 MUST 展示全平台 Agent 与 MCP 资产表，至少包含资产名称、类型、状态、出站调用停用标记、Owner/Deputy 信息；负责人全部失效的孤儿资产 MUST 显著标记（原 AC-1；PRD M8-1、US122/US135）。
- **FR-002**: 治理中心 MUST 提供资产详情入口，但管理员 MUST NOT 可通过治理中心改变资产状态；下架、重新上架、删除一律由 Owner/Deputy 在资产控制台执行（原 AC-4；PRD M8-1、hub `architecture/adr/001-service-split.md`）。
- **FR-003**: 平台管理员 MUST 可按资产维度停用出站调用；停用 MUST 要求填写原因，缺失原因时阻断提交（原 AC-2；PRD M8-1、J5-4、US126）。
- **FR-004**: 出站调用停用生效后，平台 MUST 禁用该资产的全部个人凭据解析，一切经平台流向该资产的调用均失败并向调用方返回「该资产的出站调用已被平台停用」的明确提示；停用不改变资产状态（原 AC-2；PRD M8-1，2026-08-24 凭据模型裁定）。
- **FR-005**: 出站调用停用 MUST 与资产状态正交：资产下架、重新上架或版本发布均 MUST NOT 自动解除停用；恢复 MUST 由平台管理员手动执行（原 AC-2；PRD M8-1、US127）。
- **FR-006**: 出站调用停用与恢复 MUST 留痕，并 MUST 通知该资产全体有效 Owner/Deputy；停用通知 MUST 附必填原因。停用状态、原因与停用时间 MUST 在该资产的资产控制台常驻可见，并在创作者中心与治理中心以标记呈现（PRD M8-1、M9-1、US150）。
- **FR-007**: 孤儿资产补员 MUST 仅对当前仍为孤儿资产的行可提交；提交时 MUST 实时复核孤儿性，若已不满足孤儿条件则拒绝并提示刷新（原 AC-3；PRD M8-1、US134/US135）。
- **FR-008**: 孤儿资产补员 MUST 同次指定新 Owner 与至少一位 Deputy，并在提交时一次性满足有效负责人冗余；补员完成后 MUST 恢复订阅入口与 Owner 职能；补员操作 MUST 永久留痕并通知新指定负责人（原 AC-3；PRD M8-1、§9.1.2；2026-08-24 clarify）。
- **FR-009**: 孤儿资产原负责人的 Alice 账号恢复时，其负责人身份 MUST 自动恢复，孤儿标记 MUST 解除，并 MUST 通知该资产全体有效负责人（2026-08-25 用户裁定补充——对齐 glossary「孤儿资产」与 PRD §9.1.2 既有口径，补全 FR-007/008 未承载的后半段语义）。

**发布准入测评模板与阻断开关**

- **FR-010**: 发布准入测评模板维护 MUST 仅平台管理员可用；模板 MUST 全局唯一，随部署内置，管理员维护而非创建（PRD M5-2、J5-1、§12.3；watchlist #33 已确认归 008）。
- **FR-011**: 发布准入测评模板 MUST 包含三类测评问题集：提示词注入、意图偏离、内容安全；并 MUST 为三类分别维护独立通过阈值。三类均达标才算整体通过，不加权、不允许一类高分拉平另一类（PRD M5-2、§9.4）。
- **FR-012**: 管理员修改发布准入测评模板的问题集或阈值后，MUST 只影响后续新发起的发布准入测评；已完成历史测评记录 MUST 不变，进行中测评 MUST 使用发起时模板快照继续执行与判定（PRD §9.4；spec 004 Clarification）。
- **FR-013**: 发布准入测评的裁判模型 MUST 来自随部署内置的模型清单中的对话类模型；P0 后台不提供裁判模型生命周期变更，模型平台默认凭据引用维护见 FR-070~FR-076（PRD §9.4、M8-7；2026-08-24 clarify）。
- **FR-014**: 测评阻断开关 MUST 为单一总开关，默认关闭；当 Agent 发布准入测评整体未通过时，开关开启则阻断上架，开关关闭则允许上架但标注「准入测评未通过」（原 AC-13；PRD M8-2、M5-1）。
- **FR-015**: 测评阻断开关 MUST NOT 作用于 MCP 发布与纯使用条款轻发布；MCP 免跑发布准入测评，纯使用条款轻发布豁免测评（PRD M5-1、M8-2；spec 004）。

**平台原生工具维护**

- **FR-020**: 平台原生工具维护 MUST 仅平台管理员可用，并 MUST 覆盖三个随部署内置的工具：Confluence MCP、SharePoint/OneDrive MCP、OSS（S3/Blob）MCP（原 AC-5；PRD M8-1b、§12.3）。
- **FR-021**: 平台管理员 MUST 可维护平台原生工具的服务地址、连接器技术鉴权配置与启停用。连接器技术鉴权配置仅用于平台调用/管理原生工具连接器本身，可包含服务端技术配置或平台侧凭据；MUST NOT 被用作来源内容访问凭据，MUST NOT 保存可代替操作人读取 Confluence、SharePoint/OneDrive 或 OSS 内容的共享账号或共享密钥（原 AC-5；PRD M8-1b、J5-5b、ADR-0015、ADR-005；2026-08-24 clarify）。
- **FR-022**: 平台原生工具 MUST 仅作为知识库外部导入通道；导入访问来源内容时 MUST 使用操作人在密钥库配置的个人凭据。平台原生工具 MUST NOT 使用平台内置统一凭据、管理员共享来源账号或管理员共享来源密钥替代操作人个人凭据（原 AC-5；PRD M8-1b、M7-1；2026-08-24 clarify）。
- **FR-023**: 平台原生工具 MUST 不上 Marketplace、免订阅、无 Owner、不适用质量门控与发布准入测评（原 AC-6；PRD M8-1b、ADR-0015）。
- **FR-024**: 平台原生工具停用后，新的对应外部导入 MUST 被阻断并明确提示；已导入且已进入知识库的内容 MUST 不因工具停用而删除（PRD M8-1b、M4 导入边界）。

**平台资源注册表**

- **FR-030**: 平台资源注册表 MUST 仅平台管理员可用；每个条目 MUST 表示一个平台资源实例，包含资源类型、连接信息（实例类）、凭据、可用范围与授权信息（原 AC-7；PRD M8-7b、ADR-0016）。
- **FR-031**: P0 资源类型 MUST 包含 Milvus 实例与 PGVector 实例；Azure Document Intelligence 服务、Azure AI Search 服务 MUST 作为预留类型枚举存在，但其消费随 P1 管线组件启用（原 AC-8；PRD M8-7b、M4-13、§12.2）。
- **FR-032**: 可用范围 MUST 为三种：默认可用、授权可用、平台内部。默认可用表示全员可选；授权可用表示按资源逐人分配；平台内部表示不出现在任何用户选择器（原 AC-9；PRD M8-7b、ADR-0016）。
- **FR-033**: 每类 P0 向量数据库（Milvus、PGVector）MUST 至少存在一个默认可用实例且恒存在；系统 MUST 阻止管理员使任一类别默认实例数降为零（原 AC-10；PRD M8-7b、§12.3）。
- **FR-034**: 平台资源注册表 MUST 随部署内置默认 Milvus 实例、默认 PGVector 实例与至少一个平台内部 Nexus 凭据对象；这些条目是建库与模型默认调用的自举前提（原 AC-11；PRD §12.3；2026-08-24 clarify）。
- **FR-035**: 授权可用资源的逐人授予与回收 MUST 不经 Alice、即时生效并留痕、不发站内通知；回收 MUST NOT 影响已建在该实例上的存量知识库（原 AC-9；PRD M8-7b、ADR-0016）。
- **FR-036**: 用户侧向量库实例选择器 MUST 仅展示默认可用实例与该用户本人已获授权实例；平台内部条目 MUST 不出现在任何用户选择器（PRD M4-12、M8-7b）。
- **FR-037**: 实例类平台资源 MUST 支持连接与凭据一键探测；探测结果 MUST 给出明确成功/失败反馈（原 AC-12；PRD M8-7b）。
- **FR-038**: 模型类平台资源 MUST NOT 在平台资源注册表中维护；模型清单与模型条目平台默认凭据由模型设置维护（PRD M8-7/M8-7b、ADR-0016）。
- **FR-039**: 平台资源凭据 MUST NOT 作为用户资产调用的兜底；一切资产调用使用订阅者个人凭据，未配置/失效时不回落任何共享身份（PRD M8-7b、§12.4、ADR-005）。

**用户视图与角色映射**

- **FR-050**: 用户视图 MUST 从 Alice 同步并只读展示用户账号、角色与状态；管理后台 MUST NOT 提供新增用户、设置密码或修改 Alice 角色功能（原 AC-14；PRD M8-4、US129）。
- **FR-051**: 角色映射配置 MUST 仅平台管理员可用，并 MUST 支持配置 Alice 角色到平台功能点与可用模型的映射；功能点枚举 MUST 以 PRD §5.3 的 P0 功能点清单为准（原 AC-15；PRD M8-5、US130）。
- **FR-052**: 未显式配置映射的 Alice 角色 MUST 享有基线权限：全员功能点全部可见，可用模型为随部署内置的默认模型（2026-08-25 用户裁定措辞修订——P0 管理后台不提供切换默认模型入口，原「管理后台设置的默认模型」主语不存在）；平台管理员同时具备普通用户全部基线权限（原 AC-15；PRD §5.3、M8-5）。
- **FR-053**: 当用户具备多个 Alice 角色时，平台 MUST 按所有匹配角色的映射并集合并可见功能点与可用模型：任一角色授予即有效；未配置角色贡献基线权限（2026-08-24 clarify）。
- **FR-054**: Alice 账号状态为停用时，该用户 MUST 不计入资产负责人冗余、资源授权可用人员或公共目录冷启动持有人有效性；历史配置与审计记录保留（PRD §9.1.2、§9.3、M8-4）。

**公共目录冷启动**

- **FR-060**: 公共目录冷启动 MUST 仅平台管理员可用，并 MUST 支持创建公共目录一级节点（原 AC-16；PRD M8-6、US131）。
- **FR-061**: 创建一级目录时，管理员 MUST 指定一级目录控制角色与一级目录知识库创建角色的持有人；持有人必须是 Alice 中的有效账号（原 AC-16；PRD M8-6、J5-9）。
- **FR-062**: 一级目录创建后的其余层级目录维护、目录角色授予与知识库授权 MUST NOT 在管理后台处理；由目录控制角色持有人在知识管理中完成（PRD M8-6、§9.7；spec 005）。
- **FR-063**: 公共目录冷启动涉及 Alice 角色创建或授予失败时，平台 MUST 不产生半初始化一级目录；失败原因需明确反馈给管理员（与 spec 005 公共目录建库 Alice 失败整体回滚口径同构）。

**模型设置**

- **FR-070**: 模型设置 MUST 仅平台管理员可用；P0 MUST 仅支持查看随部署内置的模型清单、启用态与默认模型，并在线维护既有模型条目的平台默认凭据（PRD M8-7 原「新增/编辑/删除/启停用/设置默认模型」口径经 2026-08-24 clarify 收敛）。
- **FR-071**: 模型 MUST 分为四类：对话、多模态、重排序、向量化；内容增强与发布准入测评裁判模型 MUST 复用对话类模型（原 AC-17；PRD M8-7、§9.4）。
- **FR-072**: 每个既有模型条目 MUST 可在线配置平台默认凭据引用；平台默认凭据 MUST 引用平台资源注册表中的一个平台内部 Nexus 凭据对象，MUST NOT 在模型条目重复保存密钥值。平台默认凭据用于模型类资源的「个人模型凭据优先、无可用个人凭据时平台默认凭据兜底」解析规则。该兜底仅适用于平台自有模型资源，MUST NOT 用于资产调用（原 AC-18；PRD M8-7、§9.3、ADR-0016、ADR-005；2026-08-24 clarify 保留 P0 在线维护）。
- **FR-073**: 模型清单 MUST 随部署内置至少一个启用的默认对话模型，保证基线权限用户可直接使用平台 Chat agent-runtime；默认模型 P0 不支持线上切换，只能通过部署配置变更处理（PRD §5.3、§12.3；2026-08-24 clarify）。
- **FR-074**: P0 模型设置 MUST NOT 提供运行期新增、编辑、删除、启用、停用模型或切换默认模型入口；模型生命周期变更属于部署配置变更或 P1 能力（2026-08-24 clarify）。
- **FR-075**: 模型删除/停用的在用引用校验不作为 P0 后台在线能力；若未来 P1 或部署变更流程支持模型生命周期变更，必须校验知识库向量化模型、角色映射可用模型、默认模型与发布准入测评裁判模型等引用并给出迁移/替代路径（由后续 plan 或 P1 spec 承载）。
- **FR-076**: 新增模型不作为 P0 后台在线动作；若通过部署配置新增模型，个人模型凭据对该模型的可用性快照处理 MUST 遵循 spec 007：存量个人凭据对新增模型为未检测，按不可用解析，引导用户手动刷新；平台不自动补测（ADR-0016）。

### Key Entities

- **治理资产投影（Governance Asset Projection）**: 治理中心展示的资产只读视图。关键属性：资产 ID、名称、类型、状态、出站调用停用标记、Owner/Deputy 列表、孤儿标记。
- **出站调用停用记录（Outbound Disable Record）**: 管理员对单个资产的调用级控制记录。关键属性：资产、状态（停用/恢复）、原因、操作人、操作时间；停用原因在资产控制台常驻可见，记录永久留痕。
- **孤儿资产补员记录（Orphan Reassignment Record）**: 管理员为孤儿资产补充有效负责人的治理记录。关键属性：资产、补员前负责人失效快照、新指定 Owner、新指定 Deputy、操作人、操作时间。
- **发布准入测评模板（Admission Evaluation Template）**: 全局唯一、随部署内置的测评模板。关键属性：三类问题集、三类独立阈值、最近维护时间；发布任务使用发起时快照。
- **测评阻断开关（Evaluation Blocking Switch）**: 单一总开关。关键属性：开启/关闭、最近操作人、最近操作时间；默认关闭。
- **平台原生工具配置（Native Tool Configuration）**: 三个随部署内置导入通道的配置。关键属性：工具类型、服务地址、连接器技术鉴权配置、启用状态；连接器技术鉴权可包含平台调用/管理连接器所需的平台侧凭据，但不含操作人的密钥值，也不得包含可代替操作人访问来源内容的共享账号或共享密钥。
- **平台资源条目（Platform Resource Entry）**: 注册表中的实例类或平台内部资源。关键属性：资源类型、连接信息、凭据、可用范围、探测状态；默认 Milvus、默认 PGVector 与至少一个平台内部 Nexus 凭据对象随部署内置。
- **资源授权（Resource Authorization）**: 授权可用资源对用户的逐人授权。关键属性：资源、被授权用户、授予/回收状态、操作人、操作时间；不经 Alice、不通知。
- **Alice 用户快照（Alice User Snapshot）**: 从 Alice 同步的用户只读信息。关键属性：账号、角色、状态、同步时间。
- **角色映射（Role Mapping）**: Alice 角色到平台功能点与可用模型的映射。关键属性：角色、功能点集合、模型集合；未配置时使用基线权限。
- **公共目录一级节点（Top-Level Public Directory）**: 管理员冷启动创建的公共目录一级节点。关键属性：目录名称、一级目录控制角色持有人、一级目录知识库创建角色持有人、Alice 同步状态。
- **模型条目（Model Entry）**: 随部署内置的平台代理模型。关键属性：名称、类别、启用状态、是否默认、平台默认凭据引用；P0 后台只读其生命周期属性，仅允许在线维护平台默认凭据引用。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 管理员经治理中心执行的出站停用、恢复、孤儿补员 100% 留痕；其中 0 次改变资产状态。
- **SC-002**: 被出站调用停用的资产，100% 经平台流向该资产的调用失败并展示明确停用提示；资产重新上架后未手动恢复的停用 100% 继续生效。
- **SC-003**: 孤儿资产订阅入口关闭率 100%；补员完成后订阅入口与 Owner 职能恢复率 100%。
- **SC-004**: 准入测评任务 100% 锁定发起时模板快照；模板修改导致进行中或历史测评结果变化的次数为 0。
- **SC-005**: 未配置授权的平台资源实例在用户侧选择器中出现次数为 0；每类 P0 向量数据库默认实例数降为 0 的保存成功次数为 0。
- **SC-006**: 授权可用资源的授予与回收 100% 即时影响新选择候选；回收导致存量知识库不可用的次数为 0；资源授权通知发送次数为 0。
- **SC-007**: P0 模型设置中出现模型新增、编辑、删除、启停用或默认模型切换入口的次数为 0；既有模型平台默认凭据引用在线维护成功率为 100%；模型条目重复保存 Nexus 密钥值的次数为 0。
- **SC-008**: 未配置 Alice 角色映射的用户出现空导航或空模型列表的次数为 0；基线权限可用率 100%。
- **SC-009**: 平台原生工具导入访问来源内容时使用平台内置统一凭据、管理员共享来源账号或管理员共享来源密钥的次数为 0；来源内容访问凭据 100% 归属于操作人个人凭据。

## Assumptions

- 平台管理员身份由 Alice 授予；平台不自建账号密码体系。
- 护栏策略模板管理与运行时拦截定义处在 spec 006；008 不重复定义护栏模板规则，只在管理后台导航/权限层面承接管理员入口。
- 发布准入测评执行、发布状态流转、中止发布与失败落点定义处在 spec 004；008 只维护模板与阻断开关。
- 密钥库用户侧凭据、个人模型凭据可用性快照与资产调用凭据解析定义处在 spec 007；008 只维护平台资源凭据与模型条目的平台默认凭据。

- 管理员首页概览（P1）。
- 系统公告（P1）。
- Dify 实例管理（P1）。
- 监控中心与异常告警处置（P1）。

- Marketplace 人工推荐位：不承接，Marketplace 仅保留热门榜、全部列表与搜索。
- 平台资源按 Alice 角色批量授权：P0 不承接，平台资源授权为逐人分配。
- 模型运行期新增、编辑、删除、启停用与默认模型切换：P0 不承接；模型生命周期变更通过部署配置变更或 P1 能力处理。
- 平台管理员代 Owner/Deputy 下架、重新上架或删除资产：不提供。
- 经 PAT 调用平台原生工具：P0 不开放。
- 平台资源凭据兜底用户资产调用：不提供；资产调用一律使用订阅者个人凭据。
- 服务实现、接口契约字段与具体存储设计：进入 plan / contracts 阶段处理。
