# Spec 002 — Marketplace 与订阅

> 状态：Draft
> PRD 来源（v1.2）：§7 M2（功能清单）、§6 J1.1–J1.4/J1.7（用户旅程）、§8.2 US22–US38（US-21 已随人工推荐位取消删除）、§8.3 US-54b（创作者中心统计卡）、§9.2 订阅状态机

## 1. 背景与目标

提供全平台 Agent 与 MCP 的统一发现与订阅入口。订阅即授权，授权全程留痕。包含频道/搜索/详情页/订阅申请/并行多级审批/订阅者中心/创作者中心/资产控制台。

## 2. 功能需求

### 2.1 资产发现

- **AC-1** — Agent 与 MCP 两个频道，各含热门/全部两个子页签。
- **AC-2** — 热门为近 30 天新增「已通过」订阅数降序（同数按调用量降序——调用量＝全部经平台流转的调用总量，含平台内透传会话与平台外 PAT 开放接口调用，与审计记录同源；每日刷新一次，基于截至前一日的统计数据，§9.10。理由：只算单渠道会系统性低估另一侧的高频资产——2026-08-21 用户确认）；订阅数计近 30 天新增且当前仍有效的「已通过」订阅（下架转已取消即不计），调用量按近 30 天实际发生、不随订阅取消回滚——热门榜反映当前真实采用度（2026-08-21 用户确认）；全部按上架时间倒序。
- **AC-3** — 搜索按名称、业务标签与简介模糊匹配（子串不区分大小写、命中高亮；结果按名称优先、业务标签次之、简介末位排序，§9.10）。
- **AC-4** — 列表仅展示状态为「已发布」且上架时点质量门控全部通过的资产（智能体的门控含所绑护栏策略模板处于启用状态；模板后续停用不影响存量在架可见性，仅下次门控重跑时校验——门控结果为上架时点快照，PRD §7 M2-3）。
- **AC-5** — 卡片展示名称、类型、业务标签与状态；Health Check 连续失败的资产标注「当前不可达」。
- **AC-5b** — 收藏：可在 Marketplace 与「我的资产」抽屉收藏或取消收藏任意已发布资产——收藏即关注，不以订阅为前提（PRD §7 M1-15「我的资产抽屉（含收藏动作）」）；收藏设数量上限（建议值随 §9.10 参数基线审定——2026-08-21 用户裁定，防止收藏夹无限膨胀失去关注意义）；收藏为个人偏好标记，不构成授权、不发通知、不纳入审计留痕。已下架资产的收藏条目保留并置灰标注（§9.1 五界面语义）。

### 2.2 资产详情页

- **AC-6** — Agent 详情四页签（基本信息/接入配置/测评信息/发布记录），按订阅状态分层：未订阅仅见基本信息、测评信息与发布记录。
- **AC-7** — MCP 详情四页签（基本信息/接入配置/工具能力/凭据状态），未订阅仅见基本信息；凭据状态页签展示资产级服务凭据是否就绪，以及本人用于平台外调用的个人出站凭据签发状态与申请入口（带参跳转密钥库，PRD §7 M2-6）。
- **AC-8** — MCP 不提供「去使用」；Agent 已订阅后可点击「去使用」进入对话页。
- **AC-9** — 已下架资产占位页：展示资产名称、状态、下架原因；非负责人经详情页直连、订阅者中心已取消记录或通知入口访问已下架资产时均落此页（§9.1 五界面语义）；负责人访问进完整控制台。

### 2.3 订阅申请与审批

- **AC-10** — 单页表单：顶部资产说明摘要（资产名称、类型、Owner）+ 申请字段（固定字段为业务系统与使用场景，外加 Owner 经 YAML 配置的自定义字段）+ 当前版本发布说明 + 使用条款（默认收起、可展开，含版本号）+ 多级审批人链概览（可展开全部审批人）+ 勾选提交（旅程 J1 二）。
- **AC-10b** — 同一申请人对同一资产至多一条在途（待审批）申请：存在在途申请时，该资产的订阅入口对该用户置灰不可提交并提示已有在途申请。（理由：防止审批人待办被同一申请人多单刷屏、避免多单并行的审批歧义；入口前置阻断优于提交时报错——2026-08-21 用户裁定。）
- **AC-10c** — 禁止自审：各级审批人计算时排除申请人本人；该级因此无有效审批人时按既有死锁规则回落 Owner/Deputy；多级链中其余各级审批要求不受影响。（理由：职责分离——2026-08-21 用户裁定。）
- **AC-10d** — 提交前校验申请字段的必填与格式，失败时阻断并定位错误字段（字段级校验规则在实现工单中承载，PRD 文档定位）。
- **AC-11** — 孤儿资产关闭订阅入口并提示；平台管理员补员新 Owner 后，Owner 职能与订阅入口一并恢复（CONTEXT 孤儿资产词条、PRD §9.1.2）。
- **AC-11b** — Owner 与 Deputy 对自己的资产免订阅可用——订阅是消费方准入机制，不适用于负责人（PRD §4 角色表：订阅授权＝Owner 对消费方的审批）；审批人（非负责人）仍需正常订阅（审批权≠使用权）。（理由：与 AC-10c 禁止自审自洽——Owner 若需订阅则申请无人可批构成死锁；所有权天然包含使用权。2026-08-21 用户确认。）
- **AC-12** — 并行多级审批：各级同时收到待办、每级至少一人通过即该级通过、任一驳回即整单驳回。
- **AC-12b** — 整单驳回后其余各级未处理的待办立即清除、已处理记录保留（审批留痕）；驳回时理由必填、建议补充项选填（US-33、US-57）。
- **AC-13** — 死锁兜底：某级无有效审批人时回落 Owner/Deputy。
- **AC-14** — 在途申请锁定提交时审批链快照。
- **AC-15** — 「重新申请」一律新建记录（以原申请内容预填）；原记录连同驳回理由、驳回人与时间永久保留；同一资产的多次申请折叠为时间线展示（PRD §9.2）。
- **AC-16** — 「已取消」记录取消来源（主动退订/Owner 取消/下架/删除/账号失效）与取消理由（Owner 取消的必填理由随记录展示，旅程 J1 二.5）。
- **AC-16b** — 使用条款的版本号、确认人与确认时间随订阅记录持久化（PRD §9.2——授权留痕的合规凭证）。

### 2.4 订阅者中心

- **AC-17** — 四个状态统计卡（已通过/待审批/被驳回/已取消）点击筛选对应列表；支持按资产类型筛选；卡片可查看各级审批进展——展示各级的待审批/已通过/已驳回状态、审批人姓名与处理时间（理由：企业内网审批人身份对申请人透明，可定位催办对象，与 §13.10 #15 催办兜底兼容——2026-08-21 用户确认）；「被驳回」统计卡按历史累计计数（PRD §7 M2-10、§9.2）。
- **AC-18** — 提供去使用（Agent）、配置个人凭据（平台外资产调用）、查看驳回理由、重新申请、主动退订入口。

### 2.5 创作者中心与资产控制台

- **AC-19** — 顶部四个统计卡（已创建资产、待审批订阅申请、已下架资产、待发布资产），统计卡可点击钻取至对应分区的筛选视图（与订阅者中心统计卡交互一致——2026-08-21 用户确认）；两分区：我的资产（我是 Owner 或 Deputy——展示上架进度、是否存在未发布修订、出站调用停用标记、下一步动作入口、待审批订阅数量）+ 待我审批（展示资产名称与待审批申请数量，点击进入资产控制台审批人视图）（PRD §7 M2-11）。
- **AC-20** — 资产控制台负责人视图：订阅管理、资产级服务凭据配置、热改类配置、未发布修订管理、下架/重新上架/删除。
- **AC-21** — 资产控制台审批人视图：仅可见资产基本信息与待其审批的订阅申请，可通过或驳回（驳回必填理由，PRD §7 M2-12、§4 角色表）；申请内容全量可见（业务系统、使用场景、自定义字段与使用条款确认记录——审批判断的依据，2026-08-21 用户确认）；无发布/热改/下架/删除/凭据配置。
- **AC-22** — 出站调用被停用时控制台顶部常驻提示（含原因与停用时间）。

### 2.6 订阅状态机

- **AC-23** — 待审批 → 已通过 / 被驳回（终态）/ 已取消（终态）。
- **AC-24** — 已通过 → 已取消（Owner 取消/退订/下架/删除/账号失效）；主动退订需二次确认，确认后使用授权立即失效（旅程 J1 六.4）。
- **AC-25** — 资产下架时全部待审批自动转已取消，审批人待办清除。
- **AC-26** — 重新上架不恢复订阅。
- **AC-27** — 主体侧失效：账号被停用时在途申请与已通过订阅转已取消。
