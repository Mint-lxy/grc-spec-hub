## Clarifications

### Session 2026-08-21

- Q: 同一级两名审批人几乎同时处理同一申请（一人通过、一人驳回），以谁为准？ → A: 以服务端最先落库的审批动作为准；后到者操作被拒并提示「该申请此级已被处理」并刷新（与「每级至少一人通过即该级通过」的并行语义兼容）。
- Q: 资产的订阅申请表单定义损坏（YAML 无法解析、字段残缺）时，订阅申请页如何表现？ → A: 源头杜绝——Owner 配置表单时（创建向导与资产控制台热改通道）强制通过格式与 schema 校验，不合规定义不允许保存，问题不流到订阅者侧；防御性兜底：若运行时仍无法渲染，阻断订阅并提示联系资产负责人。
- Q: 在途（待审批）申请是否允许申请人编辑修改已提交的内容？ → A: 不允许——在途申请只读不可变；填错只能等驳回后重新申请（或未来若 §13.10 #14 裁定纳入则撤回重提）；与审批链快照锁定语义一致，审批留痕最干净。

## User Scenarios & Testing

### User Story 1 — 资产发现与评估 (Priority: P1)

普通用户进入 Marketplace，在 Agent 或 MCP 频道浏览热门榜与全部列表、按名称/业务标签/简介搜索，经资产卡片与详情页评估资产是否适合自己的场景，未订阅时仅见订阅决策所需信息。

**Why this priority**: 发现与评估是订阅漏斗的入口，没有它后续订阅与使用无从发生。

**Independent Test**: 以未订阅用户浏览榜单与搜索，打开 Agent 与 MCP 详情页，验证可见性分层与卡片标注均正确。

**Acceptance Scenarios**:

1. **Given** 用户进入 Marketplace, **When** 选择 Agent 或 MCP 频道, **Then** 各含热门/全部两个子页签（无推荐位）；热门按近 30 天新增且当前仍有效的「已通过」订阅数降序（同数按近 30 天全部经平台流转的调用量降序），每日刷新一次；全部按上架时间倒序。
2. **Given** 列表或搜索结果, **When** 浏览, **Then** 仅出现状态为「已发布」且上架时点质量门控全部通过的资产（智能体门控含所绑护栏策略模板处于启用状态；模板后续停用不影响存量在架可见性）；卡片展示名称、类型、业务标签与状态，Health Check 连续失败的资产标注「当前不可达」。
3. **Given** 用户搜索, **When** 输入关键词, **Then** 按名称、业务标签与简介子串不区分大小写匹配并高亮命中，结果按名称优先、业务标签次之、简介末位排序。
4. **Given** 未订阅用户打开 Agent 详情页, **When** 浏览页签, **Then** 仅可见基本信息、测评信息与发布记录；接入配置（服务地址、接口清单）不可见。
5. **Given** 未订阅用户打开 MCP 详情页, **When** 浏览页签, **Then** 仅可见基本信息；接入配置、工具能力与凭据状态不可见；MCP 不提供「去使用」。

### User Story 2 — 提交订阅申请 (Priority: P1)

用户在资产详情页点击订阅，进入单页订阅申请：顶部资产说明摘要、中部申请字段（固定字段＋Owner 自定义字段）、底部当前版本发布说明、使用条款与审批人链概览，勾选同意后一次提交。

**Why this priority**: 订阅申请是授权产生的唯一入口，是订阅域的核心交易。

**Independent Test**: 对一个已发布资产完成一次申请提交，验证表单结构、在途唯一阻断、字段校验与记录创建。

**Acceptance Scenarios**:

1. **Given** 已发布资产的详情页, **When** 用户点击订阅, **Then** 直接进入单页申请（无纯展示中间页）：顶部资产说明摘要（名称、类型、Owner），中部申请字段（固定字段为业务系统与使用场景，外加 Owner 经 YAML 配置的自定义字段），底部为当前版本发布说明、使用条款（默认收起、可展开全文与版本号）与多级审批人链概览（可展开全部审批人），勾选同意后提交。
2. **Given** 用户对该资产已有一条待审批申请, **When** 查看该资产, **Then** 订阅入口置灰不可提交并提示已有在途申请（同一申请人对同一资产至多一条在途申请）。
3. **Given** 孤儿资产（负责人全部失效）, **When** 用户尝试订阅, **Then** 订阅入口禁用并提示「该资产负责人暂不可用，暂不接受订阅申请」，直至平台管理员补员。
4. **Given** 申请字段未通过必填或格式校验, **When** 用户提交, **Then** 阻断并定位错误字段。
5. **Given** 勾选同意使用条款并提交成功, **Then** 创建订阅申请记录（条款版本号、确认人与确认时间随记录持久化），全部审批级同时收到待办。

### User Story 3 — 并行多级审批 (Priority: P1)

审批人在创作者中心「待我审批」分区或资产控制台审批人视图处理申请：各级并行推进、每级至少一人通过、任一驳回即整单驳回；禁止自审；无有效审批人时回落负责人。

**Why this priority**: 审批是授权把关点，并行结构与兜底规则决定授权时效与合规性。

**Independent Test**: 构造多级审批链提交申请，验证并行待办、驳回联动清除、自审排除与死锁回落。

**Acceptance Scenarios**:

1. **Given** 申请已提交, **When** 审批开始, **Then** 各级同时收到待办、级间无顺序；每级至少一人通过即该级通过，全部级通过则申请通过。
2. **Given** 任一审批人驳回, **When** 驳回生效, **Then** 整单驳回（终态）；其余各级未处理的待办立即清除、已处理记录保留；驳回理由必填、建议补充项选填。
3. **Given** 申请人本人被列入某级审批人, **When** 计算该级有效审批人, **Then** 排除申请人本人（禁止自审）；该级因此无有效审批人时按死锁规则回落 Owner/Deputy，多级链其余各级要求不受影响。
4. **Given** 某级审批人全部离职或账号被停用, **When** 申请在途, **Then** 该级自动回落由任一 Owner 或 Deputy 审批并标注回落。
5. **Given** 在途申请, **When** Owner 修改审批链, **Then** 在途申请按提交时锁定的审批链快照走完，新链仅对新申请生效。
6. **Given** 审批人打开待审批申请, **When** 查看详情, **Then** 申请内容全量可见（业务系统、使用场景、自定义字段与使用条款确认记录）；无发布/热改/下架/删除/凭据配置权限。

### User Story 4 — 订阅者中心跟踪与后续管理 (Priority: P2)

申请人在订阅者中心跟踪申请状态（四统计卡、各级审批进展）、查看驳回理由并重新申请、主动退订、查看已取消记录的来源与理由。

**Why this priority**: 申请后的可跟踪性与后续管理是订阅体验闭环，但不阻塞首单申请。

**Independent Test**: 覆盖四种状态的申请各一条，验证统计卡筛选、审批进展粒度、重新申请新建记录与退订生效。

**Acceptance Scenarios**:

1. **Given** 订阅者中心, **When** 打开, **Then** 顶部四个状态统计卡（已通过/待审批/被驳回/已取消）可点击筛选对应列表，支持按资产类型筛选；「被驳回」统计卡按历史累计计数。
2. **Given** 一条待审批申请, **When** 查看审批进展, **Then** 展示各级的待审批/已通过/已驳回状态、审批人姓名与处理时间。
3. **Given** 被驳回的申请, **When** 用户点击重新申请, **Then** 以原申请内容预填创建一条新记录；原记录连同驳回理由、驳回人与时间永久保留；同一资产的多次申请折叠为时间线展示。
4. **Given** 一条已取消记录, **When** 查看, **Then** 展示取消来源（主动退订/Owner 取消/资产下架/资产删除/账号失效）与取消理由（Owner 取消的必填理由随记录展示）。
5. **Given** 一条已通过订阅, **When** 用户主动退订并二次确认, **Then** 订阅转「已取消」，使用授权立即失效。

### User Story 5 — 创作者中心与资产控制台 (Priority: P2)

Owner 在创作者中心总览自己的资产与待办（四统计卡＋两分区），进入资产控制台负责人视图管理订阅与配置；审批人经「待我审批」进入审批人视图。

**Why this priority**: 负责人与审批人的工作台是供给侧运营效率的关键，次于消费侧首单链路。

**Independent Test**: 以 Owner 与审批人两种身份分别进入创作者中心与资产控制台，验证统计卡钻取、两分区内容与两种视图的权限边界。

**Acceptance Scenarios**:

1. **Given** Owner 进入创作者中心, **When** 打开, **Then** 顶部四个统计卡（已创建资产、待审批订阅申请、已下架资产、待发布资产）可点击钻取至对应分区的筛选视图；下方「我的资产」分区展示上架进度、是否存在未发布修订、出站调用停用标记、下一步动作入口与待审批订阅数量。
2. **Given** 审批人（非负责人）进入创作者中心, **When** 查看「待我审批」分区, **Then** 展示资产名称与待审批申请数量，点击进入该资产控制台的审批人视图。
3. **Given** 负责人视图, **When** Owner 处理, **Then** 可用订阅管理、资产级服务凭据配置、热改类配置、未发布修订管理、下架/重新上架/删除。
4. **Given** 资产的出站调用被平台停用, **When** 负责人打开控制台, **Then** 页面顶部常驻提示（含原因与停用时间）。

### User Story 6 — 收藏关注资产 (Priority: P3)

用户在 Marketplace 或「我的资产」抽屉收藏任意已发布资产（含未订阅资产），以便持续关注。

**Why this priority**: 收藏是关注机制而非授权链路，价值真实但不阻塞订阅主流程。

**Independent Test**: 收藏一个未订阅资产，验证其出现在抽屉「收藏」分区；取消收藏后消失；达上限时阻断。

**Acceptance Scenarios**:

1. **Given** 任意已发布资产, **When** 用户在 Marketplace 或「我的资产」抽屉收藏, **Then** 进入其抽屉「收藏」分区（不以订阅为前提）；收藏为个人偏好标记，不构成授权、不发通知、不纳入审计留痕。
2. **Given** 收藏数量达到 50 个上限, **When** 再次收藏, **Then** 阻断并提示已达上限。
3. **Given** 已收藏的资产被下架, **When** 查看抽屉, **Then** 条目保留并置灰标注「已下架」。

### User Story 7 — 资产生命周期变化对订阅的联动 (Priority: P2)

资产下架、删除、重新上架与负责人失效时，订阅与在途申请按既定规则联动失效或保持，用户经通知与占位页感知。

**Why this priority**: 生命周期联动决定授权的时效正确性，是治理闭环的消费侧体现。

**Independent Test**: 对含已通过订阅与待审批申请的资产执行下架与重新上架，验证状态联动、通知与占位页表现。

**Acceptance Scenarios**:

1. **Given** 资产被下架, **When** 下架生效, **Then** 全部已通过订阅失效转「已取消」（来源＝资产下架），全部待审批申请自动转「已取消」且审批人待办清除。
2. **Given** 已下架资产, **When** 非负责人经详情页直连、订阅者中心已取消记录或通知入口访问, **Then** 落占位页：仅展示资产名称、「已下架」状态与下架原因；负责人访问则进入完整资产控制台。
3. **Given** 资产重新上架, **When** 发布完成, **Then** 原订阅不恢复，用户需重新提交申请（新建记录、重走审批链）。
4. **Given** 申请人或订阅者账号被 Alice 停用, **When** 停用生效, **Then** 其在途申请与已通过订阅转「已取消」（主体侧失效）。
5. **Given** Owner 或 Deputy, **When** 使用自己的资产, **Then** 免订阅可用（订阅是消费方准入机制，不适用于负责人）。

### Edge Cases

- 某级审批人全部失效（离职或账号停用）→ 自动回落 Owner/Deputy 并标注回落；审批链被 Owner 关闭时，申请进入全体 Owner 与 Deputy 待办，任一处理即可，不自动通过。
- 审批期间使用条款升版 → 在途申请生效时适用审批通过时刻的现行版本，升版通知同时发给待审批申请人（PRD §13.10 #12 已确认）。
- 审批期间资产下架 → 申请自动转「已取消」，申请人收到的下架通知中一并告知（不双发）。
- 平台管理员停用资产出站调用 → 该资产的全部凭据解析被禁用，与资产状态正交（含 Owner 免订阅调用同样失败并提示）。
- 同一用户既是 Owner 又是审批人 → 两种视图权限叠加：负责人视图包含审批人视图能力。
- 收藏达 50 个上限后继续收藏 → 阻断并提示。

## Requirements

### Functional Requirements

**资产发现**

- **FR-001**: 系统 MUST 提供 Agent 与 MCP 两个频道，各含热门/全部两个子页签（不承接人工推荐位，PRD §12.4）。
- **FR-002**: 热门榜 MUST 按近 30 天新增且当前仍有效的「已通过」订阅数降序（下架转已取消即不计）；同数按调用量降序——调用量＝近 30 天全部经平台流转的调用总量（平台内透传会话＋平台外 PAT 开放接口调用），不随订阅取消回滚；每日刷新一次，基于截至前一日的统计数据（§9.10）。全部列表按上架时间倒序。（理由：只算单渠道会系统性低估另一侧的高频资产；已取消订阅计入会夸大当前采用度——2026-08-21 用户确认。）
- **FR-003**: 搜索 MUST 按名称、业务标签与简介模糊匹配：子串不区分大小写、命中高亮；结果按名称优先、业务标签次之、简介末位排序（§9.10）。
- **FR-004**: 列表与搜索 MUST 仅展示状态为「已发布」且上架时点质量门控全部通过的资产；智能体的门控含所绑护栏策略模板处于启用状态；模板后续停用不影响存量在架可见性，仅下次门控重跑时校验（门控结果为上架时点快照，PRD §7 M2-3）。
- **FR-005**: 资产卡片 MUST 展示名称、类型、业务标签与状态；Health Check 连续失败的资产标注「当前不可达」（不改变资产状态）。
- **FR-006**: 用户 MUST 可在 Marketplace 与「我的资产」抽屉收藏或取消收藏任意已发布资产——收藏即关注，不以订阅为前提（PRD §7 M1-15）；收藏数量上限为 50 个（2026-08-21 用户裁定，防止收藏夹无限膨胀失去关注意义；§9.10 参数基线审定）；收藏不构成授权、不发通知、不纳入审计留痕；已下架资产的收藏条目保留并置灰标注（§9.1 五界面语义）。

**资产详情页**

- **FR-007**: Agent 详情 MUST 含四页签（基本信息/接入配置/测评信息/发布记录）并按订阅状态分层：未订阅仅见基本信息、测评信息与发布记录（均为订阅决策所需）；接入配置（服务地址、接口清单）仅订阅者与负责人可见。
- **FR-008**: MCP 详情 MUST 含四页签（基本信息/接入配置/工具能力/凭据状态），未订阅仅见基本信息；凭据状态页签展示资产级服务凭据是否就绪，以及本人用于平台外调用的个人出站凭据签发状态与申请入口（带参跳转密钥库，PRD §7 M2-6）。
- **FR-009**: P0 中 MCP 资产 MUST 不提供「去使用」（不是对话对象）；Agent 已订阅后展示「去使用」进入其对话页。P1 预留 Chat 调用已订阅 MCP 资产工具的入口能力，入口形态随 P1 设计展开。
- **FR-010**: 已下架资产对非负责人 MUST 展示占位页（资产名称、「已下架」状态、下架原因；不展示接入配置与能力细节）；详情页直连、订阅者中心已取消记录与通知入口均落此页（§9.1 五界面语义）；负责人访问进入完整资产控制台。

**订阅申请与审批**

- **FR-011**: 订阅申请 MUST 为单页表单：顶部资产说明摘要（资产名称、类型、Owner）＋申请字段（固定字段为业务系统与使用场景，外加 Owner 经 YAML 配置的自定义字段）＋当前版本发布说明＋使用条款（默认收起、可展开全文与版本号）＋多级审批人链概览（可展开全部审批人）＋勾选同意后一次提交（旅程 J1 二）。
- **FR-012**: 同一申请人对同一资产 MUST 至多一条在途（待审批）申请：存在在途申请时订阅入口对该用户置灰不可提交并提示。（理由：防止审批人待办被同一申请人多单刷屏、避免多单并行的审批歧义；入口前置阻断优于提交时报错——2026-08-21 用户裁定。）
- **FR-013**: 系统 MUST 禁止自审：各级审批人计算时排除申请人本人；该级因此无有效审批人时按死锁规则回落 Owner/Deputy；多级链中其余各级审批要求不受影响。（理由：职责分离——2026-08-21 用户裁定。）
- **FR-014**: 提交前 MUST 校验申请字段的必填与格式，失败时阻断并定位错误字段（字段级校验规则在实现工单中承载，PRD 文档定位）。申请表单定义的格式与 schema 校验 MUST 前置到 Owner 配置侧（创建向导与资产控制台热改通道保存时强制校验，不合规定义不允许保存，spec 003 承载），订阅者侧不存在表单损坏降级态；防御性兜底：运行时仍无法渲染时阻断订阅并提示联系资产负责人（2026-08-21 clarify 用户裁定：源头杜绝，问题不流到订阅者侧）。
- **FR-015**: 孤儿资产（全部 Owner 与 Deputy 账号失效）MUST 关闭订阅入口并提示「该资产负责人暂不可用，暂不接受订阅申请」；平台管理员补员新 Owner 后，Owner 职能与订阅入口一并恢复（CONTEXT 孤儿资产词条、PRD §9.1.2）。
- **FR-016**: Owner 与 Deputy MUST 对自己的资产免订阅可用——订阅是消费方准入机制，不适用于负责人；审批人（非负责人）仍需正常订阅（审批权≠使用权）。（理由：与 FR-013 禁止自审自洽——Owner 若需订阅则申请无人可批构成死锁；所有权天然包含使用权。2026-08-21 用户确认。）
- **FR-017**: 审批 MUST 为并行多级：申请提交后全部级同时收到待办、级间无顺序；每级至少一人通过即该级通过，全部级通过则申请通过；任一审批人驳回即整单驳回。同一级并发处理时以最先落库的审批动作为准，后到操作被拒并提示「该申请此级已被处理」（2026-08-21 clarify 确认）。
- **FR-018**: 整单驳回后其余各级未处理的待办 MUST 立即清除、已处理记录保留（审批留痕）；驳回时理由必填、建议补充项选填（US-33、US-57）。
- **FR-019**: 死锁兜底：某级无有效审批人（离职或账号被停用，实时校验）时 MUST 自动回落由任一 Owner 或 Deputy 审批并标注回落；Owner 关闭审批链时申请进入全体 Owner 与 Deputy 待办，任一处理即可，不自动通过。
- **FR-020**: 在途申请 MUST 锁定提交时的审批链快照并按快照走完；Owner 修改审批链仅对新申请生效。在途申请内容对申请人只读不可变——填错只能等驳回后重新申请（或未来若 §13.10 #14 裁定纳入则撤回重提）（2026-08-21 clarify 确认：与快照锁定语义一致，审批留痕最干净）。
- **FR-021**: 「重新申请」MUST 一律新建记录（以原申请内容预填）；原记录连同驳回理由、驳回人与时间永久保留；同一资产的多次申请在订阅者中心折叠为时间线展示（PRD §9.2）。
- **FR-022**: 「已取消」记录 MUST 标注取消来源（主动退订/Owner 取消/下架/删除/账号失效）与取消理由（Owner 取消的必填理由随记录展示，旅程 J1 二.5）。
- **FR-023**: 使用条款的版本号、确认人与确认时间 MUST 随订阅记录持久化（PRD §9.2——授权留痕的合规凭证）。

**订阅者中心**

- **FR-024**: 订阅者中心 MUST 提供四个状态统计卡（已通过/待审批/被驳回/已取消）点击筛选对应列表；支持按资产类型筛选；可查看各级审批进展——展示各级的待审批/已通过/已驳回状态、审批人姓名与处理时间（理由：企业内网审批人身份对申请人透明，可定位人工沟通对象；P0 不提供系统催办或超时回落——2026-08-22 BA 裁定）；「被驳回」统计卡按历史累计计数（PRD §7 M2-10、§9.2）。
- **FR-025**: 订阅者中心 MUST 提供去使用（仅 Agent）、配置个人凭据（平台外资产调用）、查看驳回理由、重新申请、主动退订入口。

**创作者中心与资产控制台**

- **FR-026**: 创作者中心 MUST 顶部按顺序提供四个统计卡（已创建资产、待审批订阅申请、已下架资产、待发布资产），统计卡可点击钻取至对应分区的筛选视图（与订阅者中心交互一致——2026-08-21 用户确认）；下方两分区：我的资产（我是 Owner 或 Deputy——展示上架进度、是否存在未发布修订、出站调用停用标记、下一步动作入口、待审批订阅数量）＋待我审批（展示资产名称与待审批申请数量，点击进入资产控制台审批人视图）（PRD §7 M2-11）。
- **FR-027**: 资产控制台负责人视图（Owner 与 Deputy，权限等同）MUST 提供：订阅管理（查看申请、审批、驳回、取消他人订阅并必填理由）、每个订阅者的请求历史统计、资产级服务凭据配置、热改类配置、未发布修订管理、下架/重新上架/删除（PRD §7 M2-12）。
- **FR-028**: 资产控制台审批人视图 MUST 仅可见资产基本信息与待其审批的订阅申请，可通过或驳回（驳回必填理由）；申请内容全量可见（业务系统、使用场景、自定义字段与使用条款确认记录——审批判断的依据，2026-08-21 用户确认）；无发布/热改/下架/删除/凭据配置（PRD §7 M2-12、§4 角色表）。
- **FR-029**: 出站调用被平台停用时，资产控制台负责人视图 MUST 于页面顶部常驻提示（含原因与停用时间）。

**订阅状态机**

- **FR-030**: 订阅状态机 MUST 为：待审批 → 已通过 / 被驳回（终态）/ 已取消（终态）；「被驳回」与「已取消」均为终态，无原地流转。
- **FR-031**: 已通过 → 已取消的触发 MUST 为：Owner 取消/订阅者退订/资产下架/资产删除/账号失效；主动退订需二次确认，确认后使用授权立即失效（旅程 J1 六.4）。
- **FR-032**: 资产下架时该资产全部待审批申请 MUST 自动转「已取消」，审批人待办同步清除；申请人收到的下架通知中一并告知申请已取消（不双发）。
- **FR-033**: 资产重新上架 MUST 不恢复订阅；不单独发送重新上架通知，由发布流程的资产发布通知覆盖（PRD §9.1.1/§9.2）。
- **FR-034**: 主体侧失效：账号被 Alice 停用时，其名下在途申请与已通过订阅 MUST 转「已取消」（来源＝账号失效），审批人待办同步清除。

### Key Entities

- **资产（Asset）**: 可上架与订阅的对象，仅 Agent 与 MCP 两类。关键属性：名称、类型、业务标签、状态（六态）、负责人名单、质量门控结果快照、运行状态（最近一次 Health Check 结果）。
- **订阅申请/订阅记录（Subscription）**: 申请信息、使用条款确认与审批的过程与记录。关键属性：状态（待审批/已通过/被驳回/已取消）、条款版本号与确认人及确认时间、审批链快照、取消来源与取消理由、驳回理由与驳回人及时间。业务记录永久保留。
- **审批人链（Approval Chain）**: Owner 配置的并行多级审批结构。关键属性：级列表、每级审批人、启用/关闭；申请提交时锁定快照。
- **收藏（Favorite）**: 个人偏好标记，不构成授权。关键属性：目标资产、收藏时间；数量上限为 50 个（PRD §9.10）。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户从进入 Marketplace 到成功提交订阅申请的全流程可在 3 分钟内完成（单页表单，无中间页）。
- **SC-002**: 列表与搜索结果 100% 不出现未发布、上架时点门控未通过或已下架的资产。
- **SC-003**: 申请提交后全部审批级同时收到待办（级间零等待）；任一驳回后其余各级未处理待办 100% 清除。
- **SC-004**: 在途申请唯一性 100% 生效——不存在同一申请人对同一资产的第二条待审批申请。
- **SC-005**: 申请人 100% 不可审批本人提交的申请（各级审批人计算排除本人）。
- **SC-006**: 订阅记录的状态流转、取消来源与理由、条款确认（版本号/确认人/时间）100% 留痕可查且永久保留。
- **SC-007**: 热门榜每日刷新一次，订阅数与调用量口径与审计记录同源一致。
- **SC-008**: 孤儿资产的订阅入口 100% 关闭并提示，补员后恢复。

## Assumptions

- Alice 可提供账号有效性（停用）状态，平台据此执行主体侧失效与审批人有效性实时校验。
- Health Check 探测由平台侧供给（PRD §9.10：每 10 分钟探测一次、单次超时 10 秒、连续 3 次失败触发标注与通知）。
- 申请字段的字段级校验规则（必填、格式、长度）在实现工单中承载。
- 收藏数量上限为 50 个，列表分页默认 20 条；其他数值以 PRD §9.10 容量与默认参数基线为准。
- 通知的生成与投递由 spec 009 承载，本 spec 只约定触发时机与受众。

## Non-Goals / Boundaries

- **MCP 使用记录页签**（P1）。
- **平台级用量统计**（P1）。
- **低代码 Agent 订阅**（P1，Dify 接入资产的订阅链路随 P1 展开）。
- **订阅者撤回申请**（不承接，2026-08-22 BA 裁定；P0 待审批申请无申请人出边）。
- **Marketplace 人工推荐位**（不承接，PRD §12.4）。
- 资产的创建、发布、下架与删除动作本身（spec 003/004 承载）；本 spec 只约定其对订阅的联动。
