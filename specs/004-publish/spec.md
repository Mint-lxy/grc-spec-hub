**Feature Branch**: `spec-sync-prd-v1.2`（本文件为既有 AC 格式 spec 的 spec-kit 风格重写，对齐 PRD v1.2 全量口径；原 AC 编号对照见文末附录）

**Status**: Reviewed

**PRD 来源（v1.2）**: §7 M2-13/M3-6/M5-1（功能清单）、§6 J2.3–J2.9/J6（用户旅程）、§8.3 US46/US50–US53/US64、§8.5 US97–US99、§8.8 US123–US127/US133、§8.9 US142–US145/US147/US148/US150、§9.1/§9.1.1/§9.1.2/§9.4、§9.8、§11、§12.1/§12.3/§12.4

**Input**: 资产从创建到上架的发布链路：发布准入测评（仅 Agent）、测评阻断开关消费侧语义、未发布修订与版本整体替换、使用条款轻发布、强治理变更申报、发布互斥与中止发布、下架与重新上架、资产软删除。单活版本，订阅不绑定版本；下架权完全归 Owner/Deputy，平台管理员不改变资产状态。

---

## 背景与目标

实现资产的发布链路引擎——同一引擎承载全部触发口：首次上架、版本发布（含版本类字段的修订）、使用条款轻发布、重新上架（含空载荷），以及其逆动作（中止发布、下架、删除）。核心治理语义：任一时刻只有一个活版本对外服务、订阅不绑定版本；未发布修订与在架版本并存且修订期间在架版本持续服务；一切版本替换均通知订阅者；下架是平台唯一撤下动作且完全归 Owner/Deputy；发布优先互斥保证应急路径不被发布流程堵死。质量门控检查项定义唯一出处在 spec 003（PRD M3-4），本 spec 定义发布链路对门控的触发与消费；订阅状态机定义在 spec 002（PRD §9.2），本 spec 只定义下架/删除的触发点；通知事件定义在 spec 009，本 spec 定义触发条件与受众口径；出站调用停用的执行在 spec 008，本 spec 只定义其与资产状态的正交规则。

## Clarifications

### Session 2026-08-23

- Q: 发布并发互斥的口径——版本发布进行中时，Owner 能否发起轻发布（条款升版）或第二次版本发布？ → A: **全互斥**——同一资产任一时刻至多一次发布进行中，版本发布与轻发布互斥；进行中重复发起发布被阻断并提示当前发布进度（与单一未发布修订模型自洽；消除「轻发布在版本发布飞行中落地、随后被版本发布覆盖」的语义陷阱——用户裁定）。
- Q: 订阅申请表单与使用条款的变更通道归属复核？ → A: 维持 PRD §9.1.1 口径——**订阅申请表单为热改类**（资产控制台即时生效，不走发布流程）；**使用条款不是热改类**，走独立的第三通道「轻发布」（进入未发布修订、发布后生效、条款版本递增、通知存量订阅者与待审批申请人、豁免门控与测评、不要求重签）。依据：PRD §13.6——v0.7 刻意推翻 v0.6「条款热改不通知」裁决（条款是约束订阅者的治理文本，变更须保障知情权；但纯文本无检测对象，走完整版本发布属范畴错配）（用户确认）。
- Q: 中止发布时，进行中的准入测评任务如何处置？ → A: 中止即取消测评任务——执行器收到取消信号尽快停止，已产生的部分结果不落库、详情页不展示该次测评（无对应发布事件的测评记录会使详情页出现快照语义悬空的结果，违背 §9.4 快照语义严肃性，且节约裁判模型算力）；重新发起发布将重新触发测评（用户裁定）。
- Q: 管理员在测评执行中途修改准入测评模板（问题集或阈值），进行中的测评按哪个版本执行与判定？ → A: 发起时快照——测评任务在发起时刻锁定并携带模板快照（问题集与三类阈值），执行与判定全程不受模板后续修改影响；新发起的发布使用修改后的模板（保障测评结果的可复现性与模板治理的严肃性——用户裁定）。
- Q: 准入测评「执行失败」的时间口径——测评任务的整体超时上限是多少？ → A: 建议值 30 分钟，超时视同执行失败、可重测（参照 §9.10 既有刻度：构建单阶段 10 分钟、调用超时上限 120 秒；与「重测」兜底配合）。**记录为架构/开发待确认项**：需补入 PRD §9.10 参数基线审定后方可作为工单基线（用户裁定）。
- Q: 资产名称的唯一性规则与已删除资产名称的处置？ → A: 资产的唯一身份恒为**资产 ID**（订阅、PAT 范围勾选、调用、通知归因均按 ID）；但资产名称 MUST 校验**全平台唯一**（创建与基础信息热改时校验），**软删除后名称即释放、可被新资产重新使用**——与用户感知一致（用户裁定）。注：该规则超出 PRD 原表述（PRD 仅对知识库名称定义唯一性），已于 2026-08-23 随业务规则补遗回写 PRD §9.1.1 与 CONTEXT.md。
- Q: 发布进行中（门控/测评执行期间），修订编辑与热改类变更是否冻结？ → A: **全冻结**——发布进行中阻断修订编辑与影响调用的热改字段（超时与重试），提示「发布进行中，配置已冻结」；基础信息、订阅表单、审批链、负责人名单、护栏模板改绑等纯运营/展示字段不受限（与模板快照裁定同构：测评可复现性要求被测对象与模板双冻结；复用全互斥同一道锁；紧急轮换可先中止发布解锁——用户裁定）。
- Q: 已下架资产的 Health Check 周期探测与「连续失败」通知是否继续？ → A: **已下架即暂停**——周期探测与连续失败通知均暂停，「当前不可达」标记随下架移除（探测结果对已下架资产无展示位与消费方，通知为纯噪音）；重新上架时门控本身含 Health Check 探测成功项，可用性验证在重新上架链路被覆盖，恢复周期探测（用户裁定）。
- Q: 轻发布是否需要填写发布说明、是否需要强治理变更申报？ → A: **发布说明选填、无强治理申报**——轻发布通知已强制携带实质内容（新版条款全文/凭据变更事实），申报语义由专属通知事件承载，再要求申报属双通道噪音；发布记录照常留痕（用户裁定）。
- Q（用户主动裁定）: 资产级服务凭据密钥值的变更通道？ → A: **从热改类移入第三通道（轻发布）**——与使用条款一致：进入未发布修订、经发布动作生效、豁免门控与测评、写入发布记录、通知存量订阅者与待审批申请人；**通知仅含变更事实（「资产服务凭据已更新」），不得包含密钥值本身**；发布前强制探测可用保留（替代原保存前探测）。**部分调整 v0.9「密钥值属热改」裁决**——原动机（轮换与泄露处置不被门控/测评拖住）由轻发布的免验证特性继续满足，新裁定补回发布留痕与订阅者知情。轻发布载荷从「仅使用条款」扩为「使用条款与/或密钥值」。需回写 PRD §9.1.1/§9.3/J2-7、CONTEXT.md 词条与 ADR-0014 补注，并同步 spec 003（用户裁定；2026-08-23 BA Lead peer review 确认采纳）。**同日再修正（spec 009 澄清会话，用户裁定）**：密钥值通知受众自「存量订阅者与待审批申请人」收窄为**全体负责人（Owner/Deputy）**——密钥值是平台与资产的契约，非订阅者与资产的契约；FR-018 已同步。

## User Scenarios & Testing

### User Story 1 — Owner 首次发布 Agent（门控 → 准入测评 → 自助上架） (Priority: P1)

Owner 完成创建向导后提交，系统运行质量门控（硬阻断），门控全部通过后执行发布准入测评（仅 Agent；MCP 免跑直接上架），测评通过则直接上架；未通过时按平台管理员的测评阻断开关处理（默认关闭——可上架但详情页标注「准入测评未通过」）。详情页展示测评执行时间并标注快照语义。

**Why this priority**: 首次上架是资产进入 Marketplace 的唯一通道，无此链路平台没有任何可订阅资产，是全部后续场景的根基。

**Independent Test**: 分别构造门控通过/不通过、测评通过/未通过×阻断开关开/关的组合，验证状态机流转（草稿→待发布→待测评→已发布）、阻断行为与详情页标注。

**Acceptance Scenarios**:

1. **Given** Owner 提交了资产创建向导, **When** 系统运行质量门控, **Then** 按资产类型参数化硬阻断（Agent 七项 / MCP 六项，定义处见 spec 003）；任一项未通过则资产停留「待发布」并阻断进入下一步，修改后需重新运行。
2. **Given** Agent 质量门控全部通过, **When** 进入「待测评」, **Then** 执行发布准入测评——被测对象锁定为本资产、测评模板锁定为全局唯一的发布准入测评模板（Owner 不可更换）；发布流程页内展示执行进度、样本明细与三类分项得分；测评完成通知资产全体负责人（spec 009）。
3. **Given** 测评执行完毕, **When** 判定结果, **Then** 三类测评（提示词注入/意图偏离/内容安全）各自对照独立阈值，三类均达标才算整体通过（不加权）；执行失败（被测服务不可达、超时等基础设施原因）视同未通过，可重测。
4. **Given** 测评整体通过, **When** 结果回写, **Then** 资产直接转「已发布」：全平台可浏览、使用需订阅、进入 Marketplace 列表。
5. **Given** 测评未通过且阻断开关开启, **When** 结果回写, **Then** 资产停留「待测评」不可上架，可改进后重测；阻断开关关闭（默认）则可转「已发布」，且详情页标注「准入测评未通过」。
6. **Given** 资产详情页测评信息页签, **When** 任意用户查看, **Then** 展示准入测评结果、三类分项得分与各自阈值、测评执行时间，并明确标注结果仅代表执行时点的快照。
7. **Given** MCP 资产质量门控全部通过, **When** 进入发布, **Then** 不执行准入测评，直接转「已发布」（其工具描述与返回内容的安全由运行时输出侧护栏覆盖）。

### User Story 2 — Owner 发布新版本（含强治理变更申报） (Priority: P1)

已发布资产的 Owner 在资产控制台编辑未发布修订（仅限版本类配置与使用条款），修订存在期间在架版本持续对外服务；含版本类字段的修订发布时重跑质量门控与准入测评，通过后新版本瞬间整体替换在架版本、版本号递增，全体订阅者自动跟随。发布时 Owner 显式申报是否为强治理变更（申报必填影响说明与迁移指引），一切版本替换均通知全部订阅者。

**Why this priority**: 版本迭代是资产的日常维护主路径；「修订期间在架版本持续服务 + 整体替换 + 订阅者自动跟随 + 强制通知」是迭代不中断服务且订阅者知情的核心承诺。

**Independent Test**: 对已发布 Agent 创建含服务地址变更的修订，发布期间验证在架版本持续服务，发布完成后验证版本号递增、订阅者跟随、通知内容与申报留痕；再对未申报场景验证轻量通知兜底。

**Acceptance Scenarios**:

1. **Given** 已发布资产, **When** Owner 变更版本类配置（服务地址/Health Check/鉴权声明/能力声明/MCP 托管方式）或使用条款, **Then** 变更进入该资产的未发布修订（一份可选待发布配置，非状态机节点）；修订存在期间在架版本持续对外服务，全部流量仍走在架版本。
2. **Given** 修订不含版本类字段（仅使用条款与/或密钥值）, **When** Owner 执行发布, **Then** 走轻发布：发布后生效、写入发布记录、通知受众按载荷区分（条款升版→通知全部存量订阅者与该资产的待审批申请人并附新版条款；密钥轮换→仅通知全体负责人，仅含变更事实、不含密钥值）；豁免质量门控与准入测评；不阻断存量订阅者继续使用、不要求重新确认；发布说明选填、无强治理变更申报；条款升版时条款版本递增、新订阅按当前版本签署。
3. **Given** 修订含任一版本类字段, **When** Owner 执行发布, **Then** 重跑质量门控与发布准入测评（MCP 仅质量门控），通过后新版本瞬间整体替换在架版本，版本号递增并写入发布记录，全体订阅者自动跟随（订阅不绑定版本）。
4. **Given** Owner 发布新版本, **When** 填写发布说明, **Then** 必须显式申报是否为强治理变更；申报为强治理变更时必填影响说明与迁移指引，缺失则阻断发布提交。
5. **Given** 版本替换完成, **When** 通知订阅者, **Then** 已申报强治理变更的在版本替换的同一时刻向全部订阅者发出通知（附影响说明与迁移指引）并留痕——订阅者无缓冲窗口；未申报的同样发出轻量通知；平台不自行检测是否构成强治理变更。
6. **Given** 任一热改类字段（订阅表单/审批链/负责人名单/护栏模板改绑/基础信息五字段/超时重试）, **When** Owner 修改, **Then** 只能经资产控制台即时通道生效，不进入修订——一个字段恰有一条变更通道；热改即时生效、审计留痕、不通知订阅者、不触发门控与测评重跑、不影响在架可见性。资产级服务凭据密钥值不在此列——其变更走轻发布（FR-018）。
7. **Given** 发布记录页, **When** 查看, **Then** 保留完整版本历史、各版本发布说明、测评结果快照、强治理变更申报记录、使用条款版本历史、下架与重新上架记录（含下架原因），永久保留。
8. **Given** 已发布或已下架资产的版本发布失败（门控未全部通过，或测评未通过且阻断开关开启）, **When** 发布任务结束, **Then** 资产状态不变、在架版本持续服务零中断、未发布修订保留，可修改后再次发起（FR-042）。
9. **Given** 存在未发布修订且无发布任务进行中, **When** Owner 或 Deputy 执行「放弃修订」并二次确认, **Then** 修订清空、在架版本零影响（FR-043）。

### User Story 3 — Owner 下架资产（二次确认与连带处置） (Priority: P1)

Owner 或 Deputy 在资产控制台执行下架（含安全事件等应急场景）：弹窗二次确认并必填下架原因；全部已通过订阅失效、待审批申请自动取消并通知、审批人待办清除；运行时即时感知——一切经平台流向该资产的调用失败并返回「该资产已被下架」，入口置灰；下架不触碰未发布修订。

**Why this priority**: 下架是平台唯一的撤下动作与应急止血手段（撤销能力完全在 Owner 侧），其连带处置与运行时效力直接决定安全事件的影响半径。

**Independent Test**: 对已有订阅与在途申请的已发布资产执行下架，验证二次确认与原因必填、订阅/申请状态转移与合并通知、调用拦截文案与五界面语义、修订保留。

**Acceptance Scenarios**:

1. **Given** 已发布资产, **When** Owner 或 Deputy 执行下架, **Then** 弹窗二次确认（轻量提醒，不引入审批或他人环节）并必填下架原因；原因随业务记录永久留痕，并随下架通知发给受影响方。
2. **Given** 下架生效, **When** 处理订阅侧连带, **Then** 全部「已通过」订阅转「已取消」（取消来源＝资产被下架）；全部「待审批」申请转「已取消」并通知申请人，审批人待办同步清除；待审批申请人收到的下架通知中一并告知其申请已取消（合并为一条，不双发）。
3. **Given** 下架生效, **When** 任何调用经平台流向该资产（资产会话透传或 PAT 开放接口调用）, **Then** 调用失败并返回「该资产已被下架」；平台不做意图路由，下架资产不再列为路由候选；「去使用」入口与我的资产抽屉条目同步置灰。
4. **Given** 已下架资产, **When** 各界面访问, **Then** Marketplace 列表与搜索不出现；详情页直连的非负责人看到占位页（资产名称、「已下架」状态、下架原因；不展示接入配置与能力声明等细节），负责人进入完整资产控制台；资产收藏保留条目置灰并标注「已下架」；历史会话可打开只读回看、发送新消息被拒并提示「该资产已被下架」。
5. **Given** 已下架资产携带未发布修订, **When** 下架完成, **Then** 修订原样保留，Owner 可在「已下架」状态继续编辑修订以修复问题（含服务地址、鉴权声明等版本类配置）。
6. **Given** 资产处于发布进行中, **When** 任一 Owner 或 Deputy 尝试下架或删除, **Then** 被阻断并提示「该资产正在发布，请先中止发布」；任一 Owner 或 Deputy 可执行「中止发布」，中止后修订保留并通知发起该次发布的 Owner/Deputy——应急路径不被发布流程堵死。

### User Story 4 — 已下架资产的修复与重新上架 (Priority: P2)

因接入配置损坏等原因下架的资产，Owner 在「已下架」状态编辑未发布修订修复问题后重新发布——重新上架即一次版本发布（版本号递增、重走门控与测评、发布记录留痕）；修订为空时按当前在架配置发起空载荷版本发布。重新上架不恢复订阅，不单独发送重新上架通知；未解除的出站调用停用继续生效。

**Why this priority**: 打通「版本类配置损坏导致下架」的修复死锁，是下架动作可逆性的唯一出路；依赖下架与发布主链路先行。

**Independent Test**: 构造携带修订与空修订两种已下架资产分别重新上架，验证版本语义、通知受众（下架时刻的存量订阅者与待审批申请人）、订阅不恢复与出站停用正交。

**Acceptance Scenarios**:

1. **Given** 已下架资产, **When** Owner 编辑修订并发布, **Then** 重新上架＝一次版本发布：重走质量门控与发布准入测评（MCP 仅门控），通过后版本号递增并写入发布记录。
2. **Given** 已下架资产的修订为空, **When** Owner 直接发起重新上架, **Then** 按当前在架配置发起一次空载荷版本发布——版本号仍递增并留痕，门控与测评照常重跑。
3. **Given** 发布完成, **When** 判定发布语义, **Then** 以发布完成时刻的资产状态为准：从「已发布」完成的走版本发布语义（通知全部订阅者）；从「已下架」完成的走重新上架语义（通知下架时刻的存量订阅者与待审批申请人）；不单独发送「资产重新上架」通知，由发布流程的资产发布通知覆盖。
4. **Given** 重新上架完成, **When** 处理订阅侧, **Then** 不恢复任何订阅——「已取消」是终态，原申请人需自行重新申请（新建记录、审批链重新执行），PAT 集成需在密钥库重新勾选该资产范围。
5. **Given** 资产下架前被平台管理员停用了出站调用且未解除, **When** 重新上架完成, **Then** 资产显示「已发布」但调用仍失败（停用与资产状态正交），恢复需平台管理员手动解除。
6. **Given** 已下架期间负责人收缩, **When** 重新上架, **Then** 质量门控重新校验负责人冗余（多于一位 Owner 或已设 Deputy，口径为账号有效的负责人数），不满足则阻断。

### User Story 5 — Owner 删除资产（软删除终态） (Priority: P2)

Owner 或 Deputy 可删除处于草稿、待发布、待测评、已下架的资产（需弹窗二次确认）；「已发布」须先下架。删除为系统软删除：资产对全部用户不可见（含负责人与平台管理员），清理资产级服务凭据并使各 PAT 对该资产的访问失效；业务记录（订阅记录、条款确认、审批留痕、发布记录、下架原因）永久保留。

**Why this priority**: 删除是资产的终局出路，避免废弃资产永久堆积；其「软删除 + 记录永存」口径是合规追溯的底线。依赖下架链路先行（已发布须先下架）。

**Independent Test**: 对四个可删除状态逐一验证删除通过；对「已发布」验证阻断；删除后验证五处不可见、凭据清理、PAT 对象侧失效与业务记录可查。

**Acceptance Scenarios**:

1. **Given** 处于「草稿」「待发布」「待测评」或「已下架」的资产, **When** Owner 或 Deputy 执行删除, **Then** 弹窗二次确认后删除生效。
2. **Given** 处于「已发布」的资产, **When** 尝试删除, **Then** 被阻断并提示须先下架（与知识库「可用态须先停用方可删除」同构）。
3. **Given** 删除生效, **When** 任意用户（含负责人与平台管理员）访问, **Then** 资产对全部用户不可见，退出创作者中心、治理中心与已下架占位页；删除动作及操作人永久留痕。
4. **Given** 删除生效, **When** 处理凭据, **Then** 清理该资产的资产级服务凭据；各 PAT 对该资产的访问随之失效（对象侧失效——PAT 本身及其对其他对象的访问不受影响）。
5. **Given** 删除生效, **When** 追溯业务记录, **Then** 订阅记录、使用条款确认记录、审批留痕、发布记录与下架原因按 PRD §9.8 继续永久保留——留痕的是记录，不是资产条目。
6. **Given** 删除生效, **When** 检查通知, **Then** 不向任何用户发送通知（「已发布」须先下架、下架通知已覆盖；未发布三态无订阅者；「已下架」删除时订阅早已清空）；删除动作与操作人永久留痕（FR-044）。

### Edge Cases

- 资产在「待测评」期间 Owner 变更了版本类配置？——质量门控须重跑，资产回「待发布」（状态机回退边，FR-001）。
- 阻断开关在测评执行中途被管理员切换？——按测评结果回写（判定）时刻的开关状态生效（合理默认，plan 阶段确认实现点）。
- 中止发布时准入测评正在执行？——任务被取消，部分结果不落库、详情页不展示该次测评；重新发起发布会重新触发测评（FR-025，2026-08-23 用户裁定）。
- 测评执行中途管理员修改了准入测评模板？——进行中的测评按发起时刻锁定的模板快照执行与判定，不受修改影响；新发起的发布使用修改后的模板（FR-008，2026-08-23 用户裁定）。
- 发布进行中另一位 Owner 再次发起发布（含轻发布）？——全互斥：同一资产任一时刻至多一次发布进行中，版本发布与轻发布互斥；重复发起被阻断并提示当前发布进度（FR-024，2026-08-23 用户裁定）。
- 发布进行中 Owner 想改修订内容或调整超时/重试？——配置已冻结，阻断并提示「发布进行中，配置已冻结」；确需变更先中止发布（FR-024③，2026-08-23 用户裁定）。
- 下架瞬间存在进行中的调用？——下架即时生效：新调用一律被拦截并返回「该资产已被下架」；进行中的调用不做强制中断承诺，自然完成或失败。
- 修订为空时重新上架？——按当前在架配置发起空载荷版本发布，版本号仍递增并留痕，门控与测评照常重跑（FR-033 对应 User Story 4 场景 2）。
- 轻发布自身的互斥窗口有多长？——轻发布豁免门控与测评、即时生效，「进行中」窗口极短；但它仍参与全互斥——版本发布进行中不可发起轻发布，反之亦然（FR-024，2026-08-23 用户裁定）。
- 强治理变更申报但未填影响说明或迁移指引？——必填校验阻断发布提交（FR-020）。
- 已下架期间负责人收缩至单人？——「已下架」期间允许收缩（整改期可能需要人员重组），重新上架时门控重新校验负责人冗余（FR-039）。
- 创建或改名与现有资产（含「已下架」）重名？——阻断并提示名称已被占用；已删除资产的名称已释放、不占用（FR-040，2026-08-23 用户裁定）。
- 版本发布执行失败（门控未过 / 测评未过且阻断开启）？——首发资产停留「待发布」/「待测评」；已发布/已下架资产状态不变、修订保留，可修改后再次发起，失败零对外影响（FR-042，2026-08-23 BA Lead 裁定）。
- Owner 改了修订但后悔？——可一键放弃修订（二次确认），修订清空、在架版本不受影响；发布进行中须先中止（FR-043，2026-08-23 BA Lead 裁定）。
- 删除资产要通知谁？——谁都不通知：已发布须先下架（下架通知已覆盖）、未发布三态无订阅者、已下架删除时订阅早已清空；删除动作与操作人永久留痕（FR-044，2026-08-23 BA Lead 裁定）。

## Requirements

### Functional Requirements

**资产生命周期状态机**

- **FR-001**: 系统 MUST 实现资产生命周期六态：`草稿 → 待发布 →（质量门控全部通过）→ 待测评 →（发布准入测评执行完毕）→ 已发布 →（Owner 或 Deputy 下架）→ 已下架 →（重新上架）→ 已发布`；`草稿 / 待发布 / 待测评 / 已下架 →（Owner 或 Deputy 删除，二次确认）→ 已删除（终态）`；回退边：`待测评 →（版本类配置变更，门控须重跑）→ 待发布`。MCP MUST NOT 执行发布准入测评，质量门控全部通过后直接转「已发布」，其余流转与 Agent 相同（原 AC-27；PRD §9.1）。
- **FR-002**: 各状态的可见范围 MUST 为：草稿/待发布/待测评仅 Owner 与 Deputy 可见；已发布为全平台可浏览、使用需订阅；已下架的全部订阅停止生效、界面语义见 FR-030；已删除对全部用户不可见（含负责人与平台管理员），退出创作者中心、治理中心与已下架占位页（PRD §9.1 状态表）。
- **FR-003**: 发布流程中质量门控 MUST 硬阻断：未全部通过则阻断进入下一步，修改后需重新运行；门控检查项定义的唯一出处为 spec 003（PRD M3-4：Agent 七项——含负责人冗余与所绑护栏策略模板启用态；MCP 六项），本 spec 不重复定义（原 AC-12 部分语境；PRD §9.1、M3-4）。
- **FR-004**: 质量门控与发布准入测评的结果 MUST 均为上架时点快照：Marketplace 列表条件中的「质量门控全部通过」指上架时点的结果；上架后的热改类配置变更与纯条款轻发布 MUST NOT 触发门控重跑、不影响在架可见性（PRD §9.1.1）。

**发布准入测评（仅 Agent）**

- **FR-005**: 发布准入测评 MUST 在 Agent 的首发、含版本类字段的版本发布与重新上架（含空载荷）发布前执行；纯使用条款轻发布豁免（行为与接入配置均未变，无检测对象）；MCP 全程免跑（原 AC-1；PRD §9.4、M5-1）。
- **FR-006**: 测评执行 MUST 双锁定：被测对象锁定为待上架的本资产，测评模板锁定为全局唯一的发布准入测评模板，Owner 不可更换；模板含三类初始问题集与三类初始阈值，随平台部署内置（原 AC-2；PRD §9.4、§12.3）。
- **FR-007**: 通过判定 MUST 为：三类测评（提示词注入/意图偏离/内容安全）各自对照独立的通过阈值，三类均达标才算整体通过——不加权、不允许一类高分拉平另一类；阈值由平台管理员在准入测评模板中维护；分项得分与各类阈值 MUST 在资产详情页测评信息页签展示（原 AC-3；PRD §9.4）。
- **FR-008**: 测评 MUST 在发布流程页内执行并展示执行进度、样本明细与三类分项得分；测评完成 MUST 通知资产全体负责人（通知事件定义见 spec 009）；执行结果（通过或未通过）与执行时间 MUST 回写资产发布状态。测评任务 MUST 在发起时刻锁定并携带模板快照（问题集与三类阈值），执行与判定全程不受模板后续修改影响；新发起的发布使用届时模板（PRD J6、M5-1、M9-1；快照语义为 2026-08-23 用户裁定。契约影响：`eval-task` 事件载荷需携带模板快照或其版本引用）。
- **FR-009**: 测评未通过时 MUST 按测评阻断开关处理：开关开启则资产停留「待测评」不可上架、可改进后重测；开关关闭（默认）则可转「已发布」，且详情页 MUST 标注「准入测评未通过」。阻断开关为单一总开关、默认关闭，定义处在管理后台（spec 008 / PRD M8-2），本 spec 仅消费（原 AC-4；PRD §9.1、M8-2）。
- **FR-010**: 测评执行失败（被测服务不可达、超时等基础设施原因）MUST 视同未通过，按阻断开关处理，Owner 可重测；整体超时上限建议值 30 分钟（待架构/开发确认并补入 PRD §9.10 审定，见 Open Questions）（原 AC-6；PRD §9.4；超时口径为 2026-08-23 澄清建议值）。
- **FR-011**: 详情页 MUST 展示测评执行时间并明确标注测评结果仅代表执行时点的快照；测评模板问题集的修改 MUST NOT 影响已完成的历史测评记录；持续安全责任归业务场景方，重测由 Owner 通过发布新版本驱动（原 AC-5；PRD §9.4、`docs/adr/0011`）。
- **FR-012**: 准入测评的裁判模型 MUST 复用模型清单中的对话类模型；裁判模型的模型调用凭据按触发人（执行发布的 Owner）解析——个人模型凭据优先、平台默认凭据兜底（解析规则定义处见 spec 007 / PRD §9.3、`docs/adr/0016`）（PRD §9.4、§9.3）。

**未发布修订与配置两分**

- **FR-013**: 系统 MUST 保证任一时刻只有一个活版本对外服务，订阅记录不绑定版本；平台 MUST NOT 提供多版本共存托管（原 AC-7；PRD §9.1.1、`docs/adr/0012`）。
- **FR-014**: 未发布修订 MUST 是资产的一份可选数据属性（非状态机节点）：「已发布」与「已下架」状态均可携带一份；修订与在架版本并存，修订存在期间在架版本 MUST 持续对外服务，全部流量仍走在架版本（原 AC-8/AC-10；PRD §9.1.1）。
- **FR-015**: 修订载荷 MUST 仅限版本类配置、使用条款与资产级服务凭据密钥值；热改类配置 MUST 只能经资产控制台即时通道生效，不进入修订——一个字段恰有一条变更通道（原 AC-9；PRD §9.1.1；密钥值入修订载荷为 2026-08-23 用户裁定，部分调整 v0.9）。
- **FR-016**: 配置变更两分 MUST 按下表归属（分类原则：字段是否进入调用契约或需要门控/测评验证）：

  | 类别 | 字段 | 生效方式 |
  | --- | --- | --- |
  | 热改类 | 订阅申请表单、订阅审批人链、负责人名单、护栏策略模板改绑、基础信息（资产名称、业务标签、简介、能力标签、适用场景）、超时与重试 | 资产控制台即时生效，不进入修订；审计留痕、不通知订阅者 |
  | 版本类 | 服务地址、Health Check、鉴权声明（鉴权模式即静态凭据或动态凭据、鉴权方式与参数名、动态模式的授权申请接口地址与令牌回写字段）、能力声明、MCP 托管方式 | 仅能经未发布修订以新版本发布变更，重跑质量门控与发布准入测评 |
  | 轻发布 | 使用条款、资产级服务凭据的密钥值（静态模式的固定密钥、动态模式用于换取令牌的密钥） | 经未发布修订发布后生效，豁免门控与测评；通知受众按载荷区分——条款升版通知存量订阅者与该资产的待审批申请人（附新版条款），密钥值轮换仅通知全体负责人（仅含变更事实、不得包含密钥值本身，2026-08-23 收窄裁定）；密钥值发布前强制探测可用 |

  （PRD §9.1.1、`docs/adr/0014`；鉴权声明属版本类——进调用契约的字段变更须重验证。使用条款不设为热改系 PRD §13.6 的 v0.7 裁决：条款是约束订阅者的治理文本，变更须递增版本并通知以保障订阅者知情权；但纯文本无检测对象，故豁免门控与测评——轻发布即「有版本递增与通知、免验证」的第三通道，2026-08-23 复核确认。密钥值于 2026-08-23 用户裁定自热改类移入轻发布：轮换与泄露处置仍不被门控/测评拖住（豁免验证），同时获得发布留痕与订阅者知情；**通知不得包含密钥值本身**）
- **FR-017**: 资产级服务凭据密钥值经轻发布通道变更时 MUST 在发布前强制探测可用（探测不通过则阻断发布）；热改类配置的写入 MUST 做版本校验——提交时携带读取时的版本，不匹配则拒绝并提示「配置已被他人修改，请刷新后重试」（PRD §9.1.1、§9.1.2；密钥值探测时点随 2026-08-23 通道裁定自「保存前」调整为「发布前」）。
- **FR-043**: Owner 或 Deputy MUST 可一键放弃未发布修订（弹窗二次确认）：放弃后修订清空、对在架版本零影响；有发布任务进行中时 MUST 先中止发布方可放弃（2026-08-23 BA Lead grill 复核裁定——给 Owner 反悔出路，避免手动逐字段改回）。

**发布（两种形态）**

- **FR-018**: 轻发布（修订不含任何版本类字段——仅含使用条款与/或资产级服务凭据密钥值）MUST：发布后生效、写入发布记录、豁免质量门控与发布准入测评；MUST NOT 阻断存量订阅者继续使用、MUST NOT 要求重新确认。通知受众按载荷区分：载荷为使用条款时条款版本递增、通知全部存量订阅者与该资产的待审批申请人（附新版条款）、新订阅按当前版本签署；载荷为密钥值时 MUST 仅通知该资产全体负责人（Owner/Deputy）、通知仅含变更事实（「资产服务凭据已更新」）、MUST NOT 包含密钥值本身、MUST NOT 通知订阅者（密钥值是平台与资产的契约，非订阅者与资产的契约——2026-08-23 用户裁定收窄，修正本 FR 原口径），且不递增资产版本号与条款版本号。轻发布的发布说明 MUST 为选填、MUST NOT 要求强治理变更申报（申报仅适用于版本发布与重新上架，见 FR-020）（原 AC-11；PRD §9.1.1、M3-6；密钥值载荷与说明/申报口径为 2026-08-23 用户裁定）。
- **FR-019**: 版本发布（修订含任一版本类字段）MUST：重跑质量门控与发布准入测评（MCP 仅质量门控），期间在架版本保持服务；通过后新版本瞬间整体替换在架版本，版本号递增并写入发布记录，全体订阅者自动跟随（原 AC-12；PRD §9.1.1）。
- **FR-020**: Owner 执行版本发布或重新上架时 MUST 显式申报是否为强治理变更（轻发布不适用——其通知已携带实质内容，2026-08-23 用户裁定）；申报时必填影响说明与迁移指引（缺失阻断提交）；平台 MUST 在版本替换的同一时刻通知全部订阅者（附申报内容）并留痕——订阅者无缓冲窗口，迁移指引是唯一的补偿手段；平台 MUST NOT 自行检测是否构成强治理变更（原 AC-13；PRD §9.1、§9.1.1、`docs/adr/0011`）。
- **FR-021**: 一切版本替换 MUST 通知全部订阅者：已申报强治理变更的附影响说明与迁移指引，未申报的发轻量通知（原 AC-14；PRD §9.1.1、M9-1）。
- **FR-022**: 发布语义 MUST 按发布完成时刻的资产状态判定：从「已发布」完成的走版本发布语义（通知全部订阅者）；从「已下架」完成的走重新上架语义（通知下架时刻的存量订阅者与待审批申请人）；配合发布优先互斥（FR-024），不出现向已被清空的订阅者集合发通知的空转（原 AC-23；PRD §9.1.1）。
- **FR-023**: 发布记录 MUST 保留完整版本历史、各版本的发布说明、测评结果快照、强治理变更申报记录、使用条款版本历史与下架及重新上架记录（含下架原因）；发布记录属业务记录，按 PRD §9.8 永久保留（PRD §9.1.1、§9.8）。注：中止发布**不**写入发布记录（仅通知发起该次发布的 Owner/Deputy——2026-08-23 BA Lead peer review 裁定，推翻同日早些时候「中止留痕」裁定；用户终审确认）。
- **FR-041**: 「发布进行中」MUST 定义为**发布任务（publish job）的状态而非资产状态机节点**：已发布/已下架资产发起发布时对外状态不变、在架版本持续对外服务，资产状态仅在发布完成时刻流转（FR-022）；FR-024 的阻断判定依据＝存在进行中的发布任务（2026-08-23 BA Lead grill 复核裁定）。
- **FR-042**: 版本发布失败（质量门控未全部通过，或准入测评未通过且阻断开关开启）时：首发资产 MUST 停留「待发布」（门控未过）/「待测评」（测评未过被阻断）；已发布与已下架资产 MUST 状态不变、在架版本持续服务、未发布修订保留，Owner 可修改后再次发起——失败零对外影响。发布任务失败 MUST 通知资产全体负责人（附失败阶段与原因摘要；门控失败与 MCP 发布失败原无通知承载，2026-08-23 用户终审裁定；事件归类随 spec 009 重写与 watchlist #54 裁定）（2026-08-23 BA Lead grill 复核裁定 + 用户终审补充）。

**发布互斥与中止发布**

- **FR-024**: 发布互斥（发布优先）MUST 覆盖三类冲突：①资产处于发布进行中（质量门控与发布准入测评执行期间）时，下架与删除动作被阻断并提示「该资产正在发布，请先中止发布」；②同一资产任一时刻至多一次发布进行中，版本发布与轻发布互斥——进行中重复发起发布被阻断并提示当前发布进度；③**配置冻结**——发布进行中阻断修订编辑与影响调用的热改字段（超时与重试），提示「发布进行中，配置已冻结」；基础信息、订阅表单、审批链、负责人名单、护栏模板改绑等纯运营/展示字段不受限（原 AC-16；PRD §9.1、M2-13；②③为 2026-08-23 用户裁定）。
- **FR-025**: 发布进行中任一 Owner 或 Deputy MUST 可执行「中止发布」；中止后修订保留并通知发起该次发布的 Owner/Deputy（「发起人」恒指发起该次发布的 Owner 或 Deputy，不是新角色）。中止 MUST 即取消进行中的准入测评任务——执行器收到取消信号尽快停止，已产生的部分结果 MUST NOT 落库、详情页 MUST NOT 展示该次测评；重新发起发布将重新触发测评（原 AC-15；PRD §9.1、M2-13；测评取消语义为 2026-08-23 用户裁定。契约影响：`eval-task` 事件域需支持任务取消信号）。

**下架**

- **FR-026**: 下架 MUST 是平台上唯一的撤下动作，且只有 Owner 与 Deputy 可执行（应急场景同样如此）；平台管理员 MUST NOT 改变任何资产状态——其对他人资产唯一的运行控制手段是按资产维度停用出站调用（执行语义见 spec 008 / PRD M8-1、`docs/adr/0009`）（PRD §9.1）。
- **FR-027**: 执行下架 MUST 经弹窗二次确认（轻量提醒，不引入审批或他人环节）并必填下架原因；原因 MUST 随业务记录永久留痕，并随下架通知发给受影响方（原 AC-17；PRD §9.1）。
- **FR-028**: 下架的连带处置 MUST 为：全部「已通过」订阅转「已取消」（取消来源＝资产被下架）；全部「待审批」订阅申请转「已取消」并通知申请人，审批人待办同步清除；待审批申请人收到的下架通知中一并告知其申请已随之取消（合并为一条通知，不双发）（原 AC-18；PRD §9.1、§9.2、M9-1）。
- **FR-029**: 平台运行时 MUST 即时感知下架状态：一切经平台流向该资产的调用（资产会话透传与 PAT 开放接口调用）失败并返回「该资产已被下架」；平台不做意图路由（`docs/adr/0015`），下架资产不再列为路由候选；「去使用」入口与我的资产抽屉条目同步置灰。**已下架即暂停该资产的 Health Check 周期探测与连续失败通知**，「当前不可达」标记随下架移除；重新上架（门控含探测成功项，spec 003 FR-022②）后恢复周期探测（原 AC-19；PRD §9.1；探测暂停为 2026-08-23 用户裁定）。
- **FR-030**: 已下架资产的界面语义 MUST 为：Marketplace 列表与搜索不出现；详情页直连的非负责人看到占位页（资产名称、「已下架」状态、下架原因；不展示接入配置与能力声明等细节），负责人进入完整资产控制台；资产收藏保留条目并置灰标注「已下架」；历史会话可打开只读回看、发送新消息被拒并提示「该资产已被下架」；我的资产抽屉保留条目置灰——Agent 条目不可进入对话页，MCP 与收藏条目仅可进入已下架占位页（PRD §9.1 五界面语义表）。
- **FR-031**: 下架 MUST NOT 触碰未发布修订——Owner 可在「已下架」状态继续编辑修订以修复问题（含服务地址、鉴权声明等版本类配置）（原 AC-20；PRD §9.1.1）。

**重新上架**

- **FR-032**: 重新上架 MUST 是一次版本发布：已下架资产编辑修订后发布即重新上架，重走质量门控与发布准入测评（MCP 仅门控），版本号递增并写入发布记录（原 AC-21；PRD §9.1.1）。
- **FR-033**: 修订为空时的重新上架 MUST 按当前在架配置发起一次空载荷版本发布——版本号仍递增并留痕，门控与测评照常重跑（PRD §9.1.1）。
- **FR-034**: 重新上架 MUST NOT 恢复订阅：「已取消」是终态，原申请人需自行重新申请（新建记录、审批链重新执行），PAT 集成需在密钥库重新勾选该资产范围；MUST NOT 单独发送「资产重新上架」通知，由发布流程的资产发布通知覆盖（受众为下架时刻的存量订阅者与待审批申请人，见 FR-022）（原 AC-22；PRD §9.2、M9-1）。
- **FR-035**: 出站调用停用与资产状态 MUST 正交：二者可同时成立；资产下架后重新上架，未解除的出站调用停用继续生效（资产显示为「已发布」但调用仍失败），恢复需平台管理员手动解除（停用动作本身见 spec 008）（原 AC-28；PRD §9.1、§9.3）。

**资产删除**

- **FR-036**: Owner 或 Deputy MUST 可删除处于「草稿」「待发布」「待测评」「已下架」的资产，需弹窗二次确认；「已发布」资产 MUST 先下架方可删除（与知识库「可用态须先停用方可删除」同构）（原 AC-24；PRD §9.1）。
- **FR-037**: 删除 MUST 为系统软删除（终态）：资产对全部用户不可见（含负责人与平台管理员），退出创作者中心、治理中心与已下架占位页；删除动作及操作人永久留痕（原 AC-25；PRD §9.1）。
- **FR-038**: 删除生效时 MUST 同时清理该资产的资产级服务凭据；各 PAT 对该资产的访问随之失效（对象侧失效——PAT 本身及其对其他对象的访问不受影响）；业务记录（订阅记录、使用条款确认记录、审批留痕、发布记录、下架原因）MUST 按 PRD §9.8 永久保留——留痕的是记录，不是资产条目（原 AC-26；PRD §9.1、§9.3、§9.8）。
- **FR-044**: 资产删除 MUST NOT 触发任何通知——「已发布」须先下架（下架通知已覆盖订阅者）；未发布三态无订阅者；「已下架」删除时订阅早已全部取消；删除动作与操作人永久留痕（FR-037）（2026-08-23 BA Lead grill 复核裁定；与 PRD M9-1 通知 12 类无「资产被删除」一致）。
- **FR-040**: 资产的唯一身份 MUST 恒为资产 ID（订阅、PAT 范围勾选、调用、通知归因均按 ID）；资产名称 MUST 全平台唯一——校验时点为**提交（门控）时**与基础信息热改（改名）时，重名阻断并提示；草稿可同名并存、不占用唯一约束；**软删除后名称即释放**、可被新资产重新使用（与用户感知一致）（2026-08-23 用户裁定，校验时点为同日裁定；创建向导侧校验联动 spec 003。契约影响：名称冲突需对应错误码，对齐 hub ADR-002）。

**负责人冗余（发布链路相关面）**

- **FR-039**: 发布前质量门控 MUST 校验负责人冗余：多于一位 Owner 或已设至少一名 Deputy，冗余口径为「账号有效的负责人数」（被 Alice 停用的账号不计入）；该冗余对已发布资产是持续约束——任何负责人移除操作若会使「已发布」资产不再满足冗余 MUST 阻断并提示；「已下架」期间允许收缩（整改期可能需要人员重组），重新上架时质量门控重新校验（PRD §9.1.2）。
- **FR-045**: 发布链路全部动作的执行主体 MUST 统一为 **Owner 或 Deputy 均可**（权限等同，PRD §9.1.2）：发起发布（含轻发布与重新上架）、申报强治理变更、重测、放弃修订、中止发布、下架、删除；本 spec 及 User Story 中单独写「Owner」处 MUST 按此理解（2026-08-23 BA Lead grill 复核裁定）。

### Key Entities

- **资产（Asset）**: 生命周期状态机的承载者（Agent 或 MCP）。关键属性：资产 ID（唯一身份）、名称（全平台唯一，软删除后释放）、状态（六态）、当前版本号、在架版本引用、未发布修订（0 或 1 份）、出站调用停用标记（与状态正交）、负责人名单（Owner/Deputy）。
- **版本（Version）**: 一次发布的产物。关键属性：版本号（递增）、发布说明、发布人与发布时间、强治理变更申报（影响说明与迁移指引，可空）、测评结果快照引用、使用条款版本。任一资产任一时刻恰有一个活版本。
- **未发布修订（Revision）**: 资产的可选待发布配置（数据属性，非状态机节点）。载荷仅限版本类配置、使用条款与资产级服务凭据密钥值；空载荷合法（重新上架场景按当前在架配置发起）。
- **使用条款**: 资产的独立必填配置，自带版本号。关键属性：条款版本号、全文；升版走轻发布；确认记录（版本号、确认人、确认时间）随订阅记录持久化（订阅侧语义见 spec 002）。
- **发布记录（Release Record）**: 资产的全部发布事实集合：版本历史、条款版本历史、下架与重新上架记录（含下架原因）、强治理变更申报记录。业务记录，永久保留。
- **准入测评结果（Evaluation Snapshot）**: 一次准入测评的时点快照。关键属性：三类分项得分、三类各自阈值、整体通过判定、执行时间、触发人（执行发布的 Owner）、发起时刻锁定的模板快照引用；模板后续修改不回溯影响。中止的发布不产生测评结果记录（FR-025）。
- **下架记录（Delisting Record）**: 关键属性：下架原因（必填）、操作人、下架时间；永久留痕并随通知发出。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 版本发布执行期间，在架版本服务中断时长为零——修订存在期间 100% 流量走在架版本，通过后一次性整体替换。
- **SC-002**: 阻断开关开启时，准入测评未通过（含执行失败视同未通过）的上架阻断率为 100%；开关关闭时，未通过即上架的资产详情页 100% 标注「准入测评未通过」与测评执行时间。
- **SC-003**: 一切版本替换的订阅者通知触达率为 100%；强治理变更的通知与版本替换同一时刻发出（无缓冲窗口），未申报场景 100% 有轻量通知兜底。
- **SC-004**: 下架生效时，100% 的「已通过」订阅与「待审批」申请即时转「已取消」，审批人待办 100% 清除；待审批申请人因同一下架事件只收到 1 条合并通知。
- **SC-005**: 下架生效后，一切经平台流向该资产的调用 100% 失败并返回「该资产已被下架」；「去使用」入口与抽屉条目 100% 置灰；五个界面（列表/搜索、详情直连、收藏、历史会话、抽屉）的已下架语义 100% 符合 FR-030。
- **SC-006**: 发布进行中的下架、删除与重复发起发布（含轻发布）100% 被阻断并提示；中止发布后修订 100% 保留、发起该次发布的 Owner/Deputy 100% 收到通知。

- **SC-008**: 重新上架 100% 不恢复订阅、100% 不单独发送重新上架通知；版本号 100% 递增并留痕（含空载荷场景）。

## Assumptions

- 质量门控检查项的定义唯一出处在 spec 003（PRD M3-4）；本 spec 只定义发布链路对门控的触发与结果消费。
- 订阅状态机、「已取消」终态与取消来源语义的定义处在 spec 002（PRD §9.2）；本 spec 只定义下架/删除对订阅的触发点与连带口径。
- 通知事件的定义与通道在 spec 009（PRD M9-1）；本 spec 只定义触发条件与受众口径。
- 出站调用停用的执行动作与界面在 spec 008（PRD M8-1）；本 spec 只定义其与资产状态的正交规则。
- 准入测评模板维护（PRD M5-2）与测评阻断开关配置（PRD M8-2）为平台管理员侧能力（阻断开关当前由 spec 008 承载）；准入测评模板含三类初始问题集与初始阈值，随平台部署内置（PRD §12.3）。
- 阻断开关按测评结果回写（判定）时刻的状态生效——实现侧合理默认，plan 阶段确认。（发布并发全互斥已于 2026-08-23 经用户裁定转为正式需求，见 FR-024。）
- 测评任务执行由 evaluation-service 承担、经事件驱动触发（hub ADR-001）；发布链路状态机与资产目录由 mgmt-service 承载（architecture/service-map.md）；下架与出站停用的运行时拦截在平台网关执行（`docs/adr/0009`、hub ADR-005）。
- 平台不做意图路由（`docs/adr/0015`）——「下架资产不再列为路由候选」表现为入口置灰与调用拦截，而非路由排除逻辑。
- 资产版本号为从 1 起始的递增整数；仅版本发布与重新上架使其递增，轻发布只递增使用条款版本号（2026-08-23 BA Lead peer review 确认为正式口径）。
- 版本发布的发布说明必填（与首发一致——发布记录保留「各版本发布说明」隐含每版均有；2026-08-23 BA Lead peer review 升级为正式裁定，推翻同日早些时候「均选填」裁定；轻发布说明仍为选填，FR-018）。
- 版本发布与轻发布均沿用「发布后生效」语义，不存在灰度/分批放量——整体替换即全部订阅者同时跟随（PRD §9.1.1「瞬间整体替换」的直接读法）。

## Non-Goals / Boundaries

- **多版本共存托管**（PRD §12.4）：任一时刻只有一个活版本，订阅不绑版本。
- **平台对资产的持续安全检测**（PRD §12.4、`docs/adr/0011`）：不做指纹比对与周期性自动重测，重测由 Owner 发布新版本驱动。
- **能力声明的运行时白名单**（PRD §9.1.1、§12.4）：能力声明是上架时点的契约记录，网关不按声明清单拦截实际调用；持续一致性责任归 Owner。
- **应急隐藏与平台管理员应急停用/代下架**（PRD §12.4、`docs/adr/0009`）：已裁决取消；管理员唯一手段是按资产维度停用出站调用（spec 008）。
- **订阅「已挂起」中间态**（PRD §12.4）：下架即订阅失效（终态），不设可恢复挂起。
- **使用条款升版的强制重新确认**（PRD §12.4）：轻发布通知但不要求重签，新订阅按当前版本签署。
- **自助测评中心**（P1）：自助测评模板、数据集管理、任务中心、对比报告与独立导航入口均为 P1（PRD M5-4~M5-7）；P0 的测评仅为发布流程内的准入测评。
- **准入测评模板维护与阻断开关配置界面**：管理员侧能力（PRD M5-2/M8-2，spec 归属待裁定，见 Open Questions）；本 spec 只承载消费侧语义。
- **质量门控检查项定义**：spec 003；**订阅状态机**：spec 002；**通知事件定义**：spec 009；**出站停用执行**：spec 008；**凭据解析规则**：spec 007；**护栏模板启用态校验的运行时语义**：spec 006。
