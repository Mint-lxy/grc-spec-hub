# Spec 005 — 知识管理

**Created**: 2026-08-20

**Status**: Draft

**PRD 来源（v1.2）**: §7 M4（功能清单）、§6 J4（用户旅程）、§8.4 US67–US96、§9.6/§9.7/§9.10

**Input**: 企业知识目录树管理（公共目录与我的目录）、知识库全生命周期（建库→导入→构建→消费→停用→删除）、四阶段构建管线与参数治理、知识库状态机与文件状态机、对外开放接口、Alice 角色集成、平台资源授权。

## Clarifications

### Session 2026-08-20

- Q: 四种切片策略（语义、固定长度、父子、层级）的独立参数分别是什么？ → A: 通用参数矩阵——语义（阈值 0.0–1.0、最大切片词元数、最小切片词元数）；固定长度（切片大小/词元数、重叠/词元数）；父子（父切片大小、子切片大小、重叠）；层级（按标题层级拆分的层级深度 1–6、叶切片最大词元数、重叠）。
- Q: 每个内容增强选项有哪些可配参数？ → A: 各项独立参数——问答对生成（每切片生成数量 1–5、生成语言）；摘要（最大长度/字数）；关键词（提取数量 3–10）。三项均为可选开关，默认全关。
- Q: 解析器除 OCR 与表格识别开关外是否还需暴露其他参数？ → A: P0 仅支持 Docling 与 MinerU 两个解析器；参数增加语言提示（中文/英文/日文/自动检测）、图片提取模式（提取并 OCR/提取但不 OCR/忽略图片）、布局分析精度（快速/精确）。
- Q: 向量化模型的可配参数范围是什么？ → A: 仅模型选择（BGE-M3 / text-embedding-3-large / Voyage-3 / Qwen-embedding）+ 向量维度只读联动，无其他用户可配参数。
- Q: 检索重排序除启用/禁用开关外是否需要其他参数？ → A: 增加重排序模型选择与重排序 top-k（10–50）。

## User Scenarios & Testing

### User Story 1 — 知识维护员建库与构建 (Priority: P1)

知识维护员在目录树中选择一个叶子目录，通过两步建库向导创建知识库并配置构建管线参数；随后通过四个通道导入文档，勾选文档一键构建，实时查看四个阶段的进度；构建完成后知识库自动转为「可用」，可被对话工作台挂载与开放接口检索。

**Why this priority**: 建库与构建是知识管理的核心链路，不完成此项其他所有功能均无意义。

**Independent Test**: 从建库向导创建一个知识库，上传一份 PDF 文档，执行一键构建，验证四阶段顺序执行且状态从「草稿」自动转为「可用」，在对话工作台可挂载该库。

**Acceptance Scenarios**:

1. **Given** 知识维护员具备叶子目录的知识库创建角色, **When** 进入该叶子目录的建库向导并完成基础信息与构建管线配置, **Then** 知识库创建成功且初始状态为「草稿」，平台调用 Alice 接口创建该库的三个角色（知识库 Owner、知识库 Contributor、知识库 Consumer）并将知识库 Owner 授予创建者。
2. **Given** 知识库已创建且处于「草稿」, **When** 知识维护员通过本地上传导入一份 PDF 并勾选执行一键构建, **Then** 文档依次经历未解析→已解析→已切片→已增强→已向量化五个阶段，页面实时展示各阶段进度。
3. **Given** 库内首份文档完成向量化, **When** 向量化阶段成功完成, **Then** 知识库状态自动从「草稿」转为「可用」，无需人工发布操作。
4. **Given** 建库向导中选择构建管线配置, **When** 知识维护员查看向量库实例选择器, **Then** 仅展示默认实例与本人已获授权的平台资源实例，不展示未获授权的实例。
5. **Given** 建库向导基础信息步, **When** 知识维护员填写可见范围字段, **Then** 公共目录建库默认为「公开」（卡片对全员可见，无权限者展示 Alice 权限 ID 与申请入口）；我的目录建库不适用该字段。

### User Story 2 — 四通道文档导入 (Priority: P1)

知识维护员通过本地上传、Confluence、SharePoint/OneDrive、S3/Azure Blob 四个通道导入文档。外部通道使用操作人在密钥库配置的个人出站凭据拉取，操作人只能导入其在来源系统中有权阅读的内容。导入前提供目录预览与勾选，不支持的格式自动置灰。

**Why this priority**: 文档导入是构建的前提，四通道覆盖企业主要知识来源。

**Independent Test**: 分别通过本地上传与 Confluence 通道各导入一份文档，验证格式过滤、重名提示与凭据校验均正常。

**Acceptance Scenarios**:

1. **Given** 知识维护员具备知识库 Contributor 及以上权限, **When** 通过本地上传导入一份 35MB 的 PDF, **Then** 导入成功，文件初始状态为「未解析」。
2. **Given** 知识维护员上传一份 45MB 的文件, **When** 提交导入, **Then** 导入被阻断并提示单文件不超过 40MB。
3. **Given** 知识维护员上传一个 ZIP 包, **When** 选择该 ZIP, **Then** 系统展开预览包内文件列表（单层展开，包内不超过 200 个文件，解包后总大小不超过 500MB），白名单外的格式置灰不可勾选。
4. **Given** 知识维护员尝试通过 Confluence 通道导入, **When** 操作人未在密钥库配置 Confluence 的个人出站凭据, **Then** 系统引导至密钥库配置页面。
5. **Given** 知识维护员通过 Confluence 通道选择文档, **When** 某文档的文件名与库内已有文档重名, **Then** 系统要求确认是否覆盖已有文档。
6. **Given** 知识维护员导入外部通道文档, **When** 操作人在来源系统无该文件的阅读权限, **Then** 该文件不在可选列表中出现（权限边界由来源系统控制）。
7. **Given** 知识维护员不具备该知识库的 Contributor 及以上权限, **When** 尝试执行导入, **Then** 导入操作被阻断。
8. **Given** 导入预览中展示文件列表, **When** 某文件格式不在白名单中（白名单：PDF、Word(doc/docx)、Excel(xls/xlsx)、PowerPoint(ppt/pptx)、纯文本、Markdown、HTML、CSV、图片(PNG/JPG)），**Then** 该文件行置灰且不可勾选。
9. **Given** 我的目录知识库, **When** 创建者本人执行导入, **Then** 不需要任何角色校验，直接允许操作。
10. **Given** 单次导入操作, **When** 勾选文件数超过 200 份, **Then** 系统阻断并提示单次导入文件数上限为 200 份。

### User Story 3 — 构建执行与失败处理 (Priority: P1)

知识维护员对已导入文档执行构建，支持一键构建（自动执行四阶段）与手动分阶段构建（逐阶段单独执行或重跑）。构建失败时立即弹窗说明原因，失败文件在列表中置顶，可从失败阶段重跑。

**Why this priority**: 构建是从文档到可检索向量的核心转换过程，失败处理直接影响知识库可用性。

**Independent Test**: 导入多份文档后执行一键构建，模拟一份文档解析失败，验证失败文档置顶、原因展示与从失败阶段重跑均正常。

**Acceptance Scenarios**:

1. **Given** 知识库中有多份状态为「未解析」的文档, **When** 知识维护员勾选文档执行一键构建, **Then** 系统自动依序执行解析→切片→内容增强→向量化四阶段，页面实时展示各阶段进度。
2. **Given** 未勾选任何文档, **When** 知识维护员点击一键构建, **Then** 系统阻止执行并提示需先勾选文档。
3. **Given** 知识维护员选择手动分阶段构建, **When** 前序阶段（如解析）未完成, **Then** 后续阶段（如切片）锁定不可执行。
4. **Given** 某文档在切片阶段失败, **When** 失败发生, **Then** 立即弹窗说明失败原因（原因分类：格式不支持、文件损坏、解析超时、内容为空、向量化模型不可用、向量库写入失败、外部通道拉取失败、凭据失效），该文件在列表中置顶并标记失败阶段。
5. **Given** 一份文档在增强阶段失败, **When** 知识维护员修复后选择重跑, **Then** 从增强阶段开始执行，不重复前序已完成的阶段。
6. **Given** 同一知识库已有一条构建流水线在执行, **When** 另一操作者尝试发起新的构建, **Then** 系统阻断并提示当前已有构建正在进行及其进度。
7. **Given** 库级参数变更触发全库重建正在执行, **When** 知识维护员尝试执行新的一键构建、分阶段构建、切片编辑保存或文档导入, **Then** 均被阻断并提示当前重建进度。
8. **Given** 全库重建期间知识库状态为「可用」, **When** 用户在对话中检索该知识库, **Then** 系统继续以旧索引提供检索结果，不出现空窗。
9. **Given** 单文档单阶段执行, **When** 执行时长超过 10 分钟, **Then** 该阶段超时，系统自动重试 1 次；重试仍失败则标记为构建失败。
10. **Given** 正在重建的文档, **When** 用户检索该知识库, **Then** 该文档沿用上一次成功的向量化结果参与检索，直到新结果就绪。

### User Story 4 — 目录树管理与权限 (Priority: P2)

知识维护员通过目录树浏览公共目录与我的目录，目录控制角色持有人可创建子目录、重命名、删除目录；无权限用户看到 Alice 权限 ID 与申请入口。

**Why this priority**: 目录是知识库的组织容器，权限体系保障知识治理。

**Independent Test**: 以目录控制角色创建子目录、重命名、删除空目录，验证操作即时生效；以无权限用户验证提示展示。

**Acceptance Scenarios**:

1. **Given** 目录树加载, **When** 用户查看目录树, **Then** 展示公共目录与我的目录两个根节点，支持按名称搜索并高亮命中项（父节点命中时其子树一并展示），各节点展示知识库数量。
2. **Given** 目录控制角色持有人, **When** 在叶子目录下创建子目录, **Then** 子目录创建成功，操作即时生效，平台同步至 Alice。
3. **Given** 一个已含知识库的目录, **When** 目录控制角色持有人在该目录下创建子目录, **Then** 该目录原有的知识库整体迁入新建的子目录（下沉分层），知识库的 Alice 角色与权限 ID 不变。
4. **Given** 目录控制角色持有人, **When** 尝试删除一个目录, **Then** 当且仅当该目录及其所有子目录下知识库数量为零（软删除的知识库不计入）时可删除，否则阻断并提示。
5. **Given** 目录层级已达五层, **When** 尝试继续创建子目录, **Then** 系统阻断并提示已达层级上限。
6. **Given** 无权限用户, **When** 点击受限的目录或知识库, **Then** 页面展示对应的 Alice 权限 ID（可一键复制）与申请跳转入口。
7. **Given** 我的目录, **When** 创建者本人执行子目录维护（创建、重命名、删除）, **Then** 操作直接执行，不涉及角色与 Alice 同步。
8. **Given** 父级目录的目录控制角色持有人, **When** 查看子级目录, **Then** 自动拥有全部子级目录的控制权限。

### User Story 5 — 知识库状态管理 (Priority: P2)

知识库 Owner 管理知识库的三态生命周期（草稿→可用→已停用），包括手动停用与重新启用。停用对新会话生效，进行中会话按会话级快照继续到结束。

**Why this priority**: 状态管理是知识库治理的核心，停用机制保障问题库的使用面收敛。

**Independent Test**: 将一个「可用」知识库手动停用，验证新会话无法挂载，进行中会话不受影响；重新启用后新会话可再次挂载。

**Acceptance Scenarios**:

1. **Given** 知识库处于「可用」状态, **When** 知识库 Owner 手动停用, **Then** 知识库转为「已停用」，不再出现在对话工作台的挂载列表中，不再被新会话检索。
2. **Given** 知识库刚被停用, **When** 一个进行中的会话已挂载该库, **Then** 该会话按会话级快照继续检索该库至会话结束，不因停用而中断。
3. **Given** 知识库处于「已停用」, **When** 知识库 Owner 重新启用, **Then** 知识库转为「可用」，重新出现在挂载列表中。
4. **Given** 知识库处于「可用」, **When** 删除库内最后一份已向量化文档, **Then** 知识库自动回「草稿」状态。
5. **Given** 知识库处于「已停用」, **When** 删除库内文档, **Then** 知识库状态不变，仍为「已停用」（离开已停用只能由知识库 Owner 显式操作）。
6. **Given** 知识库处于「草稿」或「已停用」, **When** 用户在对话中尝试挂载, **Then** 该库不出现在可挂载列表中。
7. **Given** 我的目录知识库, **When** 创建者本人执行停用与重新启用, **Then** 操作正常执行，不涉及角色概念。

### User Story 6 — 角色授予与权限申请 (Priority: P2)

目录控制角色持有人审批本目录及子级目录的角色授予与回收（单级审批）；平台调用 Alice 接口完成角色写入。

**Why this priority**: 权限体系是知识治理的基础，确保内容访问受控。

**Independent Test**: 以目录控制角色审批一个知识库 Consumer 的权限申请，验证 Alice 角色写入成功。

**Acceptance Scenarios**:

1. **Given** 目录控制角色持有人, **When** 收到本目录或子级目录的角色授予申请, **Then** 可通过单级审批流程批准或驳回。
2. **Given** 角色授予审批通过, **When** 目录控制角色批准, **Then** 平台调用 Alice 接口完成角色写入，被授予方即时获得相应权限。
3. **Given** 角色回收, **When** 目录控制角色发起回收, **Then** 平台调用 Alice 接口完成角色移除。
4. **Given** 公共目录建库完成, **When** 平台创建该库的三个角色, **Then** 知识库 Owner 角色授予创建者，知识库 Contributor 与知识库 Consumer 的授予由上级目录控制角色审批。
5. **Given** 我的目录知识库, **When** 查看权限信息, **Then** 不展示任何角色信息，不调用 Alice（不存在角色概念）。

### User Story 7 — 文件详情与切片编辑 (Priority: P2)

知识维护员在文件详情中审阅构建结果，包括源文件分页预览、解析后的 Markdown 内容、切片列表的搜索与逐条编辑，以及文档摘要与关键词。编辑保存后自动触发该文档的重新增强与向量化。

**Why this priority**: 切片质量直接决定检索效果，需要精细调优能力。

**Independent Test**: 打开一份已构建文档的详情，编辑一个切片内容，验证保存后自动触发增强与向量化。

**Acceptance Scenarios**:

1. **Given** 一份已向量化的文档, **When** 知识维护员打开文件详情, **Then** 可查看源文件分页预览、解析后的 Markdown 内容、切片列表、文档摘要与关键词、解析信息。
2. **Given** 文件详情的切片列表, **When** 知识维护员搜索特定内容, **Then** 切片列表按关键词过滤展示匹配结果。
3. **Given** 知识维护员编辑一个切片内容, **When** 保存编辑, **Then** 系统重算该切片的词元数，并自动触发该文档重新增强与向量化。
4. **Given** 文件列表, **When** 知识维护员查看文件列表, **Then** 每份文档展示当前停留的构建阶段，失败文档展示失败阶段信息。

### User Story 8 — 构建参数配置 (Priority: P2)

知识维护员配置库级与文档级的构建参数，包括解析器、切片策略、内容增强、向量化模型、向量数据库与检索重排序。库级参数保存后触发全库重建；文档级参数可覆盖部分库级默认。

**Why this priority**: 参数调优直接影响检索质量，需要灵活的覆盖机制。

**Independent Test**: 修改库级解析器参数并保存，验证触发全库重建；为单个文档设置不同的切片策略，验证覆盖生效。

**Acceptance Scenarios**:

1. **Given** 知识维护员打开构建参数配置, **When** 查看解析器选项, **Then** 展示两个选项（Docling、MinerU），各含 OCR 开关、表格识别开关、语言提示（中文/英文/日文/自动检测）、图片提取模式（提取并 OCR/提取但不 OCR/忽略图片）、布局分析精度（快速/精确）。
2. **Given** 构建参数配置, **When** 查看切片策略, **Then** 展示四个选项（语义——阈值、最大/最小切片词元数；固定长度——切片大小、重叠；父子——父/子切片大小、重叠；层级——标题层级深度、叶切片最大词元数、重叠）。
3. **Given** 构建参数配置, **When** 查看内容增强, **Then** 展示三个可选开关（问答对生成——每切片数量、生成语言；摘要——最大长度；关键词——提取数量），默认全关。
4. **Given** 构建参数配置, **When** 查看向量化模型, **Then** 展示四个选项（BGE-M3、text-embedding-3-large、Voyage-3、Qwen-embedding），向量维度随模型自动填充且只读。
5. **Given** 构建参数配置, **When** 查看向量数据库, **Then** 展示两个选项（Milvus、PGVector），含索引类型、距离算法、实例选择与用量展示，可选实例范围为默认实例与本人已获授权的平台资源。
6. **Given** 知识维护员修改库级参数, **When** 保存, **Then** 触发全库重建。
7. **Given** 知识维护员为单份文档设置文档级参数, **When** 选择覆盖项, **Then** 仅允许覆盖解析器、切片策略、内容增强三类；向量化模型与向量数据库不可在文档级覆盖。
8. **Given** 构建参数, **When** 查看向量化模型与向量数据库, **Then** 两者锁定在库级，不可按文档覆盖（P0 不提供更换向量化模型入口，但架构预留灵活性）。

### User Story 9 — 知识库与文档删除 (Priority: P2)

知识库 Owner 可删除知识库（须先停用，软删除），知识库 Owner 与 Contributor 可删除库内文档。

**Why this priority**: 删除是知识库生命周期的终局操作，规则直接影响目录治理。

**Independent Test**: 停用一个「可用」知识库后执行删除，验证知识库卡片不可见、Alice 角色被清理。

**Acceptance Scenarios**:

1. **Given** 知识库处于「可用」, **When** 知识库 Owner 尝试删除, **Then** 系统阻断并提示须先停用。
2. **Given** 知识库处于「已停用」, **When** 知识库 Owner 执行删除, **Then** 弹窗二次确认后执行软删除，知识库卡片对全部用户不可见、不参与挂载与检索。
3. **Given** 公共目录知识库被软删除, **When** 删除完成, **Then** 平台调用 Alice 接口清理该库的三个角色。
4. **Given** 软删除的知识库, **When** 查看该目录, **Then** 该知识库不计入目录删除的前置条件。
5. **Given** 知识库 Owner 或 Contributor, **When** 删除库内文档, **Then** 文档被删除。
6. **Given** 知识库处于「可用」且仅剩一份已向量化文档, **When** 该文档被删除, **Then** 知识库自动回「草稿」。
7. **Given** 知识库处于「已停用」且删除文档, **When** 删除完成, **Then** 知识库状态不变。
8. **Given** 我的目录知识库, **When** 创建者本人执行删除, **Then** 操作正常执行，不调用 Alice 清理角色（无角色概念）。
9. **Given** 创建者账号被 Alice 停用, **When** 停用生效, **Then** 其我的目录下的知识库随之软删除。

### User Story 10 — 开放接口 (Priority: P3)

外部系统通过 PAT 认证调用知识库的三个开放接口（读取元数据、检索、更新内容），实现系统间集成。

**Why this priority**: 开放接口使知识库能力可被外部系统消费，但优先级低于核心的建库与构建。

**Independent Test**: 使用有效 PAT 调用检索接口返回结果，使用无权限 PAT 调用更新接口被拒。

**Acceptance Scenarios**:

1. **Given** 持有 PAT 的外部系统, **When** 调用读取知识库元数据接口, **Then** 返回该 PAT 持有人有权限（知识库 Consumer 及以上）的知识库元数据。
2. **Given** 持有 PAT 的外部系统, **When** 调用检索知识库接口, **Then** 返回匹配的检索结果（要求知识库 Consumer 及以上权限）。
3. **Given** 持有 PAT 的外部系统, **When** 调用更新知识库内容接口, **Then** 要求 PAT 持有人具备知识库 Owner 或 Contributor 权限，否则拒绝。
4. **Given** 我的目录的知识库, **When** 外部系统通过 PAT 调用三个接口, **Then** 仅限创建者本人的 PAT 可调用。
5. **Given** PAT 持有人的知识库权限被 Alice 回收, **When** 使用该 PAT 调用接口, **Then** 对该知识库的访问立即失效。

### User Story 11 — 对话中的知识库挂载与检索 (Priority: P2)

普通用户在平台 Chat agent-runtime（Chat）会话中挂载有权限且状态为「可用」的知识库，回答附带引用来源与检索证据，图片与图表类证据内嵌渲染。

**Why this priority**: 知识检索是知识管理模块面向终端用户的核心价值输出。

**Independent Test**: 在 Chat 会话中挂载一个知识库，提问后验证回答附带引用来源、相似度分值与来源文档。

**Acceptance Scenarios**:

1. **Given** 普通用户在 Chat 会话中, **When** 打开知识库挂载面板, **Then** 可按目录树浏览、按名称搜索、按知识库多选、按文档单选；仅展示状态为「可用」且当前用户被 Alice 授予知识库 Consumer 及以上权限的知识库（含我的目录下状态为「可用」的知识库）。
2. **Given** 会话挂载了知识库, **When** 用户提问, **Then** 回答末尾展示引用来源标签；展开「回答依据」可见每条命中切片的排序位次、相似度分值、所属知识库与来源文档，可打开原文。
3. **Given** 检索命中了图片或图表类证据, **When** 回答生成, **Then** 该证据在回答中内嵌渲染并标注来源文档。
4. **Given** 单会话挂载知识库, **When** 已挂载 5 个知识库, **Then** 不允许继续挂载（单会话上限 5 个）。
5. **Given** 检索执行, **When** 多库检索, **Then** 每个知识库各取相似度最高的前 5 条切片，跨库按相似度归并后取前 10 条，按来源文档去重。
6. **Given** 资产 Agent 透传会话, **When** 查看挂载面板, **Then** 无知识库挂载入口（仅 Chat 会话可挂载）。
7. **Given** 会话挂载了知识库后该库被停用, **When** 会话继续, **Then** 按会话级快照继续检索直至会话结束；新会话按最新状态计算可选范围。

### User Story 12 — 平台管理员目录冷启动 (Priority: P3)

平台管理员创建公共目录一级节点，指定一级目录控制角色与知识库创建角色的持有人；之后各层级由目录控制角色自行维护。

**Why this priority**: 冷启动是目录结构的初始化，仅在平台上线时执行。

**Independent Test**: 平台管理员创建一级目录并指定角色持有人，验证该持有人可在其下管理子目录。

**Acceptance Scenarios**:

1. **Given** 平台管理员, **When** 创建公共目录一级节点, **Then** 成功创建并可指定一级目录控制角色与一级目录知识库创建角色的持有人。
2. **Given** 一级目录已创建, **When** 被指定的目录控制角色持有人, **Then** 可在该目录下创建子目录、重命名、管理角色授予。
3. **Given** 一级目录数量, **When** 已有 20 个一级目录, **Then** 不允许继续创建（上限 20 个）。

### User Story 13 — 我的目录平台内分享授权 (Priority: P2)

我的目录知识库创建者将知识库平台内分享给同事（可查看/可编辑两级，不调用 Alice），被分享者在「我的知识库 > 分享给我的」子分区按授权级别使用；授权可撤销，账号失效即失效。

**Why this priority**: 分享授权是我的目录协作的核心机制，小范围协作无需走企业授权流程。

**Independent Test**: 创建者以「可编辑」分享知识库给同事，验证同事在「分享给我的」子分区看到该库并可导入文档；撤销后同事立即失去访问。

**Acceptance Scenarios**:

1. **Given** 我的目录知识库创建者, **When** 分享知识库并选择「可查看」, **Then** 被分享者在「我的知识库 > 分享给我的」子分区看到该库并可检索，不可导入、构建与编辑。
2. **Given** 创建者分享时选择「可编辑」, **Then** 被分享者可执行文档导入、构建与内容编辑，但不可执行停用、删除、子目录维护与再分享等管控动作。
3. **Given** 分享授权已存在, **When** 创建者撤销, **Then** 被分享者立即失去访问，子分区条目消失。
4. **Given** 被分享者账号被 Alice 停用, **When** 停用生效, **Then** 其已获得的全部分享授权立即失效。
5. **Given** 创建者账号被 Alice 停用, **When** 停用生效, **Then** 其我的目录知识库随之软删除，全部分享授权同步失效。

### User Story 14 — 知识库重命名、详情指标与批量参数 (Priority: P2)

知识库 Owner 可重命名知识库；知识库详情页展示文档数、切片数、向量数与就绪度；文件列表支持批量选择并批量修改文档级参数。

**Why this priority**: 均为知识库日常维护的增效能力，不改变核心生命周期与状态机。

**Independent Test**: 重命名一个知识库并验证权限边界；打开详情页核对四项指标；批量选择 3 份文件修改文档级参数并验证仅所选文件受影响。

**Acceptance Scenarios**:

1. **Given** 公共目录知识库, **When** 知识库 Owner 执行重命名, **Then** 成功；知识库 Contributor 与知识库 Consumer 执行则被拒。
2. **Given** 我的目录知识库, **When** 非创建者（含获得「可编辑」分享授权的用户）执行重命名, **Then** 被拒；创建者本人执行成功。
3. **Given** 知识库详情页, **When** 打开, **Then** 展示文档数、切片数、向量数与就绪度（已向量化文档数/未删除文档数，未删除文档数为零时展示 0%）。
4. **Given** 文件列表, **When** 批量选择多份文件并修改文档级参数, **Then** 仅所选文件生效，库级默认不变。

### Edge Cases

- 知识库内最后一份文档构建失败（非「已向量化」状态）时，知识库是否仍处于「草稿」？——是，仅「已向量化」的文档参与可用判定。
- 全库重建后存在构建失败文档时如何处理？——知识库详情页与挂载列表标注「部分文档构建失败」；若已向量化文档数归零则知识库回「草稿」。
- 构建流水线执行中操作者账号被 Alice 停用时如何处理？——构建任务继续执行至完成或失败，通知发给知识库 Owner。
- 单库文档数达到 5000 份上限后尝试导入？——导入被阻断并提示已达文档数上限。
- 知识库被软删除后，已挂载该库的进行中会话如何处理？——按会话级快照继续检索直至会话结束。
- 我的目录知识库创建者账号恢复后，之前软删除的知识库是否恢复？——不恢复（软删除为终态处理，数据清理周期待合规确认）。
- 导入同名文件并确认覆盖后，旧版本的向量数据如何处理？——直接替换旧版本，视为被确认的替换动作。
- 目录控制角色持有人在自己子树内新建子目录并下沉知识库后，知识库的权限是否变化？——不变，知识库的 Alice 角色与权限 ID 不变。

## Requirements

### Functional Requirements

**目录树与权限**

- **FR-001**: 系统 MUST 提供公共目录与我的目录两个根节点的目录树，最多支持五层嵌套，一级目录上限 20 个。
- **FR-002**: 系统 MUST 在各目录节点展示知识库数量，支持按名称搜索并高亮命中项，父节点命中时其子树一并展示。
- **FR-003**: 系统 MUST 允许目录控制角色持有人直接执行目录维护操作（创建子目录、重命名、删除），操作即时生效，平台同步至 Alice。
- **FR-004**: 系统 MUST 在已含知识库的目录下创建子目录时，将原有知识库整体迁入新子目录（下沉分层），知识库的 Alice 角色与权限 ID 不变。
- **FR-005**: 系统 MUST 在目录删除时校验前置条件：当且仅当该目录及其所有子目录下知识库数量为零（软删除的知识库不计入）时可删除，否则阻断并提示。
- **FR-006**: 系统 MUST 对我的目录免除角色与 Alice 同步，创建者本人直接执行全部子目录维护操作。
- **FR-007**: 系统 MUST 使父级目录的目录控制角色自动拥有全部子级目录的控制权限。
- **FR-008**: 系统 MUST 对无权限用户展示对应的 Alice 权限 ID（可一键复制）与申请跳转入口。
- **FR-009**: 系统 MUST 通过目录控制角色审批（单级审批）处理角色授予与回收，并调用 Alice 接口完成写入。

**建库向导**

- **FR-010**: 系统 MUST 提供两步建库向导：基础信息（存放路径、名称、可见范围、描述、标签）→ 构建管线配置（底部直接创建，配置摘要就地折叠展示，不设纯展示的确认步）。
- **FR-011**: 系统 MUST 将可见范围定义为卡片可发现性控制——「公开」表示知识库卡片对全员可见（无权限者展示 Alice 权限 ID 与申请入口），「不公开」表示卡片仅对已有权限者可见；公共目录访问权限始终由 Alice 唯一决定，我的目录的平台内分享授权为例外（平台管理、不写入 Alice，见「我的目录平台内分享授权」组）。公共目录建库默认「公开」，我的目录不适用该字段。
- **FR-012**: 系统 MUST 限制知识库只能创建在叶子目录。
- **FR-013**: 系统 MUST 在公共目录建库时校验操作者具备知识库创建角色，并调用 Alice 接口创建该库的三个角色（知识库 Owner、知识库 Contributor、知识库 Consumer），将知识库 Owner 角色授予创建者。
- **FR-014**: 系统 MUST 允许我的目录建库无需授权、不调用 Alice、无 Alice 角色概念；创建者可经平台内分享授权将库分享给其他用户（见「我的目录平台内分享授权」组）。
- **FR-015**: 系统 MUST 将新建知识库初始状态设为「草稿」。
- **FR-016**: 系统 MUST 禁止知识库在既有目录之间移动、禁止复制（子树内下沉分层除外）。
- **FR-017**: 建库向导中向量库实例选择器 MUST 仅展示默认实例与本人已获授权的平台资源实例。

**四通道文档导入**

- **FR-018**: 系统 MUST 提供四个导入通道：本地上传（单文件上限 40MB，支持 ZIP 展开预览——单层展开、包内不超过 200 个文件、解包后总大小不超过 500MB）、Confluence、SharePoint/OneDrive、S3/Azure Blob。
- **FR-019**: 系统 MUST 校验导入操作者具备该知识库的知识库 Contributor 及以上权限（我的目录为创建者本人或获得「可编辑」分享授权的用户）。
- **FR-020**: 三个外部通道 MUST 分别经对应的平台原生工具拉取（Confluence MCP、SharePoint/OneDrive MCP、OSS MCP），使用导入操作人在密钥库配置的个人出站凭据，未配置时引导至配置页面。
- **FR-021**: 系统 MUST 在导入前提供目录预览与勾选；白名单内的格式为：PDF、Word（doc/docx）、Excel（xls/xlsx）、PowerPoint（ppt/pptx）、纯文本、Markdown、HTML、CSV、图片（PNG/JPG，经 OCR）；白名单外的格式置灰不可选。ZIP 仅作为容器。
- **FR-022**: 系统 MUST 在文件名与库内已有文档重名时要求确认是否覆盖。
- **FR-023**: 系统 MUST 限制单次导入文件数上限为 200 份、单库文档数上限为 5000 份、单用户我的目录知识库数上限为 20 个。
- **FR-024**: 系统 MUST 将导入后的文件初始状态设为「未解析」。

**四阶段构建**

- **FR-025**: 系统 MUST 执行四阶段构建流水线：解析→切片→内容增强→向量化，支持一键构建（自动执行四阶段并实时展示进度）与手动分阶段构建（逐阶段单独执行，前序未完成则后续锁定）。
- **FR-026**: 系统 MUST 在构建失败时立即弹窗说明失败原因（分类：格式不支持、文件损坏、解析超时、内容为空、向量化模型不可用、向量库写入失败、外部通道拉取失败、凭据失效），失败文件在列表中置顶，可从失败阶段重跑。
- **FR-027**: 系统 MUST 实施构建互斥——同一知识库任一时刻至多一条构建流水线；全库重建进行中时，库级参数保存、新的一键构建、分阶段构建、切片编辑保存与文档导入均被阻断并提示当前重建进度。
- **FR-028**: 系统 MUST 在全库重建期间保持知识库「可用」状态，继续以旧索引提供检索，正在重建的文档沿用上一次成功的向量化结果参与检索。
- **FR-029**: 系统 MUST 将单文档单阶段超时设为 10 分钟，失败自动重试 1 次。
- **FR-030**: 构建完成或失败的通知 MUST 发给触发者与知识库 Owner。

**知识库状态机**

- **FR-031**: 系统 MUST 实现知识库三态状态机：草稿→可用→已停用。库内首份文档完成向量化时自动从「草稿」转为「可用」，无需人工发布操作。
- **FR-032**: 系统 MUST 允许知识库 Owner（我的目录为创建者本人）手动停用知识库（转「已停用」，对新会话生效——不再出现在挂载列表、不再被新会话检索；进行中的会话按会话级快照继续到结束）并可重新启用（转「可用」）。
- **FR-033**: 系统 MUST 在「可用」状态下删除最后一份已向量化文档时自动将知识库回「草稿」；「已停用」状态不因文档删除而改变状态。
- **FR-034**: 系统 MUST 实现挂载采用会话级快照：会话挂载知识库时锁定快照，会话存续期间不因该库随后被停用、回「草稿」、被软删除或调用者权限被 Alice 回收而改变检索行为，直至会话结束。

**文件状态机与详情**

- **FR-035**: 系统 MUST 实现文件五态状态机：未解析→已解析→已切片→已增强→已向量化；任一阶段可进入「构建失败」状态并记录失败阶段与原因。
- **FR-036**: 系统 MUST 仅允许「已向量化」的文档参与检索。
- **FR-037**: 系统 MUST 在文件详情中展示：源文件分页预览、解析后的 Markdown 内容、切片列表（支持搜索与逐条编辑，编辑保存后重算词元数并触发该文档重新增强与向量化）、文档摘要与关键词、解析信息。

**构建参数**

- **FR-038**: 系统 MUST 提供以下构建参数配置：解析器二选一（Docling、MinerU，含 OCR 开关、表格识别开关、语言提示——中文/英文/日文/自动检测、图片提取模式——提取并 OCR/提取但不 OCR/忽略图片、布局分析精度——快速/精确）、切片策略四选一（语义——阈值 0.0–1.0、最大切片词元数、最小切片词元数；固定长度——切片大小/词元数、重叠/词元数；父子——父切片大小、子切片大小、重叠；层级——标题层级深度 1–6、叶切片最大词元数、重叠）、内容增强三选（问答对生成——每切片生成数量 1–5、生成语言；摘要——最大长度/字数；关键词——提取数量 3–10；三项均为可选开关，默认全关）、向量化模型四选一（BGE-M3、text-embedding-3-large、Voyage-3、Qwen-embedding，向量维度随模型自动填充且只读，无其他用户可配参数）、向量数据库二选一（Milvus、PGVector，含索引类型、距离算法、实例选择与用量展示）、检索重排序（启用/禁用开关、重排序模型选择、重排序 top-k 10–50）。
- **FR-039**: 系统 MUST 实现参数作用域：库级参数为全库默认值，保存后触发全库重建；文档级参数可覆盖库级默认，覆盖范围仅限解析器、切片策略、内容增强三类。
- **FR-040**: 系统 MUST 将向量化模型与向量数据库（类型与实例）锁定在库级，不可按文档覆盖。P0 不提供更换向量化模型入口，但架构预留灵活性。

**知识库与文档删除**

- **FR-041**: 系统 MUST 允许知识库 Owner（我的目录为创建者本人）删除知识库，需二次确认；「可用」状态须先停用方可删除。
- **FR-042**: 知识库删除 MUST 为系统软删除：卡片对全部用户不可见、不参与挂载与检索；公共目录的知识库删除后，平台调用 Alice 接口清理该库的三个角色。
- **FR-043**: 系统 MUST 允许知识库 Owner 与知识库 Contributor（我的目录为创建者本人或获得「可编辑」分享授权的用户）删除库内文档。
- **FR-044**: 创建者账号被 Alice 停用时，系统 MUST 将其我的目录下的知识库随之软删除，这些知识库的全部分享授权同步失效。

**开放接口**

- **FR-045**: 系统 MUST 提供三个知识库开放接口（读取元数据、检索、更新内容），统一使用 PAT 认证。
- **FR-046**: 读取元数据与检索接口 MUST 要求 PAT 持有人具备知识库 Consumer 及以上权限；更新内容接口 MUST 要求知识库 Owner 或 Contributor 权限。
- **FR-047**: 我的目录知识库的三个接口 MUST 按分享授权分级调用：创建者本人与获得「可查看」或「可编辑」分享授权的用户可调用读取元数据与检索接口，更新内容接口仅创建者本人与获得「可编辑」分享授权的用户可调用；无分享授权的用户不可调用。

**对话中的知识库挂载**

- **FR-048**: 系统 MUST 仅允许平台 Chat agent-runtime（Chat）会话挂载知识库，资产 Agent 透传会话不可挂载。
- **FR-049**: 挂载面板 MUST 支持按目录树浏览、按名称搜索、按知识库多选、按文档单选，可选范围为状态为「可用」且当前用户有知识库 Consumer 及以上权限的知识库（含我的目录下状态为「可用」的知识库——本人创建或获得「可查看」/「可编辑」分享授权的）。
- **FR-050**: 单会话可挂载知识库数上限 MUST 为 5 个。
- **FR-051**: 检索 MUST 按以下参数执行：每个知识库各取相似度最高的前 5 条切片，跨库按相似度归并后取前 10 条，按来源文档去重。
- **FR-052**: 回答 MUST 附带引用来源标签，展开可见命中切片的排序位次、相似度分值、所属知识库与来源文档，可打开原文。
- **FR-053**: 命中的图片、插图、图表或表格类证据 MUST 在回答中内嵌渲染并标注来源文档。

**平台管理员冷启动**

- **FR-054**: 平台管理员 MUST 可创建公共目录一级节点并指定一级目录控制角色与一级目录知识库创建角色的持有人。

**知识库重命名与详情指标**

- **FR-055**: 系统 MUST 允许知识库 Owner 重命名知识库（我的目录知识库仅创建者本人可重命名）；知识库 Contributor、知识库 Consumer 与被分享者不可重命名。
- **FR-056**: 系统 MUST 在知识库详情展示文档数、切片数、向量数与就绪度；就绪度＝已向量化文档数/未删除文档数，以百分比展示，未删除文档数为零时展示 0%；就绪度仅为展示指标，不改变知识库状态机。

**文档级参数批量修改**

- **FR-057**: 系统 MUST 支持批量选择多个文件并批量修改文档级参数，修改仅作用于所选文件、不影响库级默认。

**我的目录平台内分享授权**

- **FR-058**: 系统 MUST 允许我的目录知识库创建者将知识库平台内分享给其他用户，授权分「可查看」（对应知识库 Consumer 的读取语义）与「可编辑」（对应知识库 Contributor 的导入、构建与内容编辑语义）两级；分享授权由平台管理、不调用 Alice、不写入 Alice；创建者可随时撤销。
- **FR-059**: 被分享者 MUST 在自己的「我的知识库 > 分享给我的」子分区看到被分享的知识库，不获得副本。
- **FR-060**: 被分享者账号被 Alice 停用时，系统 MUST 使其已获得的全部分享授权立即失效。
- **FR-061**: 我的目录知识库的管控动作（停用与重新启用、知识库删除、子目录维护、分享撤销）MUST 仅创建者本人可执行，被分享者（含「可编辑」）不可执行。

### Key Entities

- **目录（Directory）**: 知识库的组织容器，分公共目录与我的目录两个根节点。关键属性：名称、层级（最多五层）、父目录、所属根类型（公共/我的）。公共目录关联 Alice 目录控制角色与知识库创建角色；我的目录无角色概念。
- **知识库（Knowledge Base）**: 文档的集合与检索单元。关键属性：名称、描述、标签、可见范围（公开/不公开）、状态（草稿/可用/已停用）、所属目录、构建管线配置（解析器、切片策略、内容增强、向量化模型、向量数据库实例）。公共目录知识库关联三个 Alice 角色（Owner/Contributor/Consumer）。
- **文档（Document）**: 知识库内的单个文件。关键属性：文件名、格式、大小、构建状态（未解析/已解析/已切片/已增强/已向量化/构建失败）、失败阶段与原因、来源通道、导入时间、文档级参数覆盖。
- **切片（Chunk）**: 文档经切片策略处理后的最小检索单元。关键属性：内容文本、词元数、向量、所属文档、排序位次。
- **构建流水线（Build Pipeline）**: 文档从导入到可检索的处理过程。四个阶段：解析→切片→内容增强→向量化。同一知识库至多一条活跃流水线。
- **知识侧角色（Knowledge Role）**: 由平台调用 Alice 接口创建的五种角色——目录控制角色、知识库创建角色、知识库 Owner、知识库 Contributor、知识库 Consumer。授予与回收由上级目录控制角色单级审批。
- **分享授权（Share Grant）**: 我的目录知识库的平台内授权记录。关键属性：目标知识库、被分享者、授权级别（可查看/可编辑）、创建时间。由平台管理、不写入 Alice；被分享者账号被 Alice 停用即失效；创建者账号被停用时随知识库软删除同步失效。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 知识维护员从建库到首份文档可被检索（草稿→可用）的全流程可在 15 分钟内完成（不含文档构建耗时）。
- **SC-002**: 四阶段构建在单文档处理失败时不影响同批次其他文档的构建进度。
- **SC-003**: 全库重建期间，用户对该知识库的检索请求 100% 返回结果（使用旧索引），不出现空窗。
- **SC-004**: 知识库停用后，新会话 100% 无法挂载该库；进行中会话 100% 按快照继续服务至结束。
- **SC-005**: 目录操作（创建、重命名、删除）执行后即时反映在目录树中。
- **SC-006**: 四通道导入中，格式白名单外的文件 100% 被置灰拦截，无法进入构建流水线。
- **SC-007**: 切片编辑保存后，该文档的重新增强与向量化自动触发，用户无需手动发起。
- **SC-008**: 对话中挂载知识库后，检索结果附带完整引用信息（排序位次、相似度、来源文档），可追溯率 100%。
- **SC-009**: 知识库软删除后，该库在所有用户视角（含负责人与管理员）100% 不可见。
- **SC-010**: 构建互斥规则 100% 生效——同一知识库不允许并发执行两条构建流水线。

## Assumptions

- Alice 作为唯一授权权威可正常提供角色创建与查询接口，平台与 Alice 的接口契约已确定。
- 平台资源注册表已内置默认 Milvus 实例与默认 PGVector 实例（随部署内置，见 PRD §12.3），建库向导中至少有一个默认向量库实例可选。
- 三个平台原生工具（Confluence MCP、SharePoint/OneDrive MCP、OSS MCP）已部署并可正常拉取文档。
- 向量化模型（BGE-M3、text-embedding-3-large、Voyage、Qwen）通过 Nexus 网关可正常调用。
- 知识库构建的外部服务凭据在平台侧只保存密钥库中的引用位置，不保存明文密钥，底层由企业 Key Vault 加密存储。
- 检索重排序模型通过 Nexus 网关可正常调用（凭据按触发人解析，个人凭据优先、平台默认凭据兜底）。
- 内容准入责任归建库方——导入外部来源文档即代表建库方确认该内容可被本库全体知识库 Consumer 检索，平台不复制来源系统的权限模型。
- 知识库数据清理（软删除后的物理清理）周期由合规团队确认后执行。

## Non-Goals / Boundaries

- **导入通道定时同步**（P1）：按设定频率自动抓取来源变更，凭据主体与配置人离职风险随 P1 展开。
- **库内重复文档识别**（P1）：相似度计算口径与处置形态随 P1 设计。同名覆盖确认保留为 P0（属被确认的替换动作）。
- **检索测试**（P1）：输入查询语句查看召回结果的调试能力。
- **更换知识库向量化模型**（P1 功能入口，P0 预留架构灵活性）：仅库级、操作前提示全库重建，数据模型与管线设计不得封死可变更性。
- **Azure Document Intelligence 解析器与 Azure AI Search 向量数据库**（P1）：其实例经平台资源注册表登记与授权后可用。
- **知识库复制与既有目录间移动**：复制会把受控语料带出 Alice 授权面，移动会静默转移控制权，二者均不提供。
- **结构化数据库子模块**：表格、SQL 模板、指标定义类结构化数据资产暂不承接。
- **临时文件上传**（P1）：上传文件参与当前会话但不入知识库，会话结束即失效。
