# Spec 000 — 平台总体（Platform Charter）

> 状态：Draft（第 0 周奠基会产出，团队共同完成）
> 这是所有 feature spec 的上位约束。

## 1. 愿景与目标

为奔驰中国（GRC）各业务团队提供企业内部的智能体统一上架平台。解决资产难以发现、使用授权无留痕、质量与安全无基线、调用凭据分散、知识检索无统一入口五大问题。平台提供测评工具、基础通用的内容防护能力，以及统一的授权、凭据与审计底座；各智能体的安全与质量由其所属业务场景方自行负责。

## 3. 服务划分依据

按**业务能力与数据所有权**划分。划分原则：
- 一个服务拥有一块数据，其他服务只能通过契约访问；
- 依赖方向单向，避免环（见 `architecture/service-map.md`）；
- 平台网关是护栏的唯一执行点，所有对话流量必经网关；凭据解析的业务规则由 mgmt-service 提供（hub ADR-005），运行时组件只发起解析请求并消费结果。

初始服务集合见 `architecture/service-map.md`。

## 4. 全局验收基线

所有服务共同遵守（细则见 `standards/` 与 `architecture/cross-cutting/`）：
- **AC-G1** — 跨服务交互只经 `contracts/` 声明的接口。
- **AC-G2** — 每个服务提供健康检查与结构化日志。
- **AC-G3** — 认证/授权遵循 `architecture/cross-cutting/auth.md`；平台账号由 SSO 开通，Alice 为唯一授权权威。
- **AC-G4** — 入站统一为 PAT；资产侧无平台代持凭据（资产只声明凭据元数据，2026-08-24 凭据模型裁定），密钥库承载入站 PAT 与出站个人凭据（一切资产调用使用订阅者个人凭据）；模型类调用按触发人解析，个人模型凭据优先、平台默认凭据兜底。
- **AC-G5** — 护栏由平台网关统一执行，命中即拦截；所有对话流量必经网关。
- **AC-G6** — 每次调用审计记录实际凭据主体（个人凭据/平台资源凭据；资产侧无平台代持凭据）。
- **AC-G7** — 数据留存分层：审计与调用日志 3 年、对话内容与命中原文经脱敏/敏感字段遮蔽后保留 90 天、业务记录永久。

## 5. 明确不在范围内

- Skill / 指令集 / 提示词模板能力
- 上架审批工作台（自助上架，无审批环节）
- 结构化数据库子模块（表格、SQL 模板、指标定义类资产）
- 平台自建账号密码体系（账号由 SSO 开通）
- 平台侧知识授权审批（归 Alice）
- 知识库复制与既有目录间移动
- 知识库独立 API Key（入站统一为 PAT）
- 平台对资产的持续安全检测（重测由 Owner 驱动）
- 能力声明的运行时白名单约束
- 应急隐藏与平台管理员应急停用（下架权归 Owner）
- 多版本共存托管（单活版本）
- 用户资产调用的系统凭据兜底
