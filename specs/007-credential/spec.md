# Feature Specification: 密钥库与凭据体系（PAT、个人出站凭据与凭据解析）

**Feature Branch**: `spec-sync-prd-v1.2`（本文件为既有 AC 格式 spec 的 spec-kit 风格重写，对齐 PRD v1.2 全量口径并纳入 2026-08-23 密钥值通道等裁定；原 AC 编号对照见文末附录）

**Created**: 2026-08-13（初版，随 specs/001–009 拆解）；2026-08-21（v1.2 同步）；2026-08-23（spec-kit 风格重写 + 两轮澄清，用户终审通过并授权直升 Reviewed）

**Status**: Reviewed

**PRD 来源（v1.2）**: §7 M7（功能清单）、§6 J8（用户旅程）、§8.7 US115–US121c、§9.3（凭据规则）、§9.8（审计留存）、§9.10（参数基线）、§11、§12.1/§12.4、`docs/adr/0014`、`docs/adr/0016`

**Input**: 统一的凭据托管与解析体系：密钥库承载用户侧凭据的两个管理面——入站 PAT（全部开放接口的唯一入站凭据）与出站个人凭据（三类目标：平台外资产调用、知识导入通道、Nexus 模型服务）；模型类调用按触发人解析、个人凭据优先、平台默认凭据兜底（可用性快照驱动）；管理员停用优先于一切解析；每次调用审计记录实际凭据主体。资产级服务凭据是资产属性（spec 003/004），平台资源凭据在管理后台（spec 008），均不在密钥库。

---

## 背景与目标

提供平台的凭据统一托管与解析底座，回应「调用凭据分散在个人手中、无统一托管、无最小化授权、无轮换机制」的问题（PRD §2）。密钥库只承载**用户侧**凭据的两个管理面：入站 PAT 与出站个人凭据；资产级服务凭据（资产属性，创建向导与资产控制台维护）与平台资源凭据（管理后台注册表与模型设置）不在此处（`docs/adr/0014`、`docs/adr/0016`）。核心语义：认证不等于授权（PAT 与出站凭据只是认证方式，不能扩张持有人已有的授权范围）；平台外资产调用不回落任何共享身份；模型类调用（平台自有资源）允许个人优先、平台默认兜底——两条规则的适用域互不重叠。每次调用审计记录实际使用的凭据主体，安全事件可归因。

**凭据体系总览（四类凭据的无歧义定义，2026-08-23 用户裁定补齐）**：

| 凭据 | 方向与用途 | 是什么 | 不是什么 | 管理者 / 管理面 |
|---|---|---|---|---|
| **PAT（个人访问令牌）** | 入站：外部系统 → 平台开放接口（四类：资产调用、读取知识库元数据、检索知识库、更新知识库内容） | 平台签发的平台 API 令牌；持有人已授权对象的子集为范围；认证不扩张授权 | 不是资产服务的凭据、不是 Nexus 凭据、不是导入通道凭据 | 持有人在密钥库（入站管理面）签发与吊销 |
| **个人出站凭据** | 出站：平台 → 外部资源（三类目标：平台外资产调用、平台原生工具导入通道、Nexus 模型服务） | 按人持有的外部资源凭据；平台外资产调用类由平台签发并绑定用户与资产，另两类由用户自填 | 不是 PAT（方向相反）、不是平台统一凭据 | 持有人在密钥库（出站管理面）管理 |
| **资产级服务凭据** | 出站：平台 → 资产服务（平台内资产调用） | 资产属性，每资产一份；平台内调用统一使用并传递当前用户身份上下文；鉴权声明属版本类、密钥值走轻发布通道 | 不在密钥库管理；订阅者不可见不配置 | Owner 在创建向导鉴权配置步与资产控制台维护（spec 003/004） |
| **平台资源凭据** | 平台内部：平台 → 平台自有资源（Nexus 令牌、实例类资源连接凭据） | 平台自有资源的连接与调用凭据 | 不作为用户资产调用的兜底；不出现给用户 | 平台管理员在管理后台（注册表/模型设置）维护（spec 008） |

## Clarifications

### Session 2026-08-23

- Q: 凭据管理动作的语义矩阵——「停用」「撤销」「删除」分别是什么？ → A: **统一动作词表**（与资产/知识库/会话的动作语义同构）：「停用」＝临时禁用、可恢复（可重新启用）；「删除」＝终态移除、不可恢复；凭据语境的「撤销」统一写「删除」；三类凭据（PAT、平台外资产调用凭据、导入通道/Nexus 凭据）适用同一套语义（用户裁定）。
- Q: 平台签发的个人出站凭据（平台外资产调用）有没有有效期？ → A: **不设独立有效期**——凭据生命周期完全跟随订阅与失效规则（订阅失效/主体侧失效/管理员停用即失效）；其授权根基是订阅关系本身，叠加第二条生命周期会制造「订阅有效但凭据过期」的莫名断点；安全风险由既有防线覆盖（主体侧失效、订阅取消联动、管理员停用）。PRD §9.3 的「凭据已过期」指目标服务侧失效或凭据被删除后的调用失败，不是平台侧有效期（用户裁定）。
- Q: SDK 凭据解析缓存 TTL 是否吸收实现侧的 60 秒？ → A: **记录为架构/开发待确认项，spec 不定死**——参照值 60 秒（当前实现）；**既有实现不是权威、不构成既定标准**，待架构/开发确认后补入 PRD §9.10 参数基线审定，审定前任何一侧（spec 或实现）的取值都不作基线（用户裁定）。
- Q: 导入通道与平台外调用凭据的「一键探测」口径？ → A: **真实鉴权**——以配置凭据对目标（平台原生工具/已订阅资产）发起真实认证调用，认证通过才算探测可用（与 spec 003「真实鉴权」裁定同构，全平台「探测可用」只有一个含义）；**具体发起真实认证调用的设计留待架构与开发确认**（watchlist #58）（用户裁定）。
- Q: 个人模型凭据调用失败的「鉴权类失效 vs 瞬时故障」判定基线？ → A: **非 BA 裁定事项，挂为待澄清依赖项**——转交 Zhang Hao 处理并决定（watchlist #59，含完整背景与建议基线：401/403＝失效类、网络错误/超时/5xx＝瞬时类）；裁定前 FR-021 的双分支与 SC-003 不作为可测基线（2026-08-23 用户裁定）。

### Session 2026-08-23（第二轮）

- Q: PAT 到期后的行为——到期即失效，是否有到期前提醒？ → A: **到期即失效、不发送到期提醒、不新增通知事件类型**；PAT 列表页 MUST 呈现每个 PAT 的到期时间（以界面可见性代替通知——用户裁定）。
- Q: PAT「重新生成」的功能定位（泄漏应急/轮换/续期）？ → A: **取消该功能**——不支持 PAT 重新生成、不支持有效期延长（用户裁定，zoom-out 分析后）：三条初衷（泄漏应急/定期轮换/到期续期）都可通过新建 PAT 解决，且新建几乎无成本、操作很快；任何场景用户都必须到自己应用系统中更换 PAT 值，「重新生成」相对「新建+删除旧」无增量收益。正规路径明示：泄漏应急与轮换与续期一律走「新建同范围 PAT → 在自有系统切换 → 删除旧 PAT」（单用户上限 20 个支持灰度切换）。同原则推导：平台外资产调用凭据的「重新生成」一并移除（与「再次申请生成」完全等价）。
- Q: 三类凭据的编辑范围矩阵（先 zoom out 盘清 PRD 缺失）？ → A: **采用不可变优先矩阵**（用户裁定）：PAT 创建后全部锁定（名称/有效期/范围不可改，改＝新建+删旧）；平台外资产调用凭据无可编辑内容（平台签发）；导入通道与 Nexus 模型凭据仅可编辑凭据值（目标与鉴权方式只读；启停与排序为独立动作不算编辑）；**编辑凭据值保存后自动重检/探测一次**（模型凭据全量重建快照、其他凭据自动探测，更新＝保存语义，快照永远对应当前值）。同步补齐四类凭据的无歧义定义总览（见「背景与目标」凭据体系总览表），并挂 watchlist #60 提醒 Zhang Hao 高优查看确认。
- Q: 审计记录的「凭据主体」粒度——每条调用日志记到什么精度？ → A: **三元组**：凭据 ID + 凭据类型 + 持有人账号（资产级服务凭据记资产 ID 与资产名）——可精确归因到条（同一用户可有多条同类型凭据，仅记类型无法区分；安全事件可归因的最小完备集，且与密钥库实体现有属性对应、无额外采集成本）（用户裁定）。
- Q: PAT「重新生成」的功能定位（泄漏应急/轮换/续期）？ → A: **取消该功能**——不支持 PAT 重新生成、不支持有效期延长（用户裁定，zoom-out 分析后）：三条初衷（泄漏应急/定期轮换/到期续期）都可通过新建 PAT 解决，且新建几乎无成本、操作很快；任何场景用户都必须到自己应用系统中更换 PAT 值，「重新生成」相对「新建+删除旧」无增量收益。正规路径明示：泄漏应急与轮换与续期一律走「新建同范围 PAT → 在自有系统切换 → 删除旧 PAT」（单用户上限 20 个支持灰度切换）。同原则推导：平台外资产调用凭据的「重新生成」一并移除（与「再次申请生成」完全等价）。

## User Scenarios & Testing

### User Story 1 — 外部系统经 PAT 调用平台开放接口 (Priority: P1)

用户创建 PAT（名称、有效期、权限范围——只能勾选本人已授权对象的子集），用于外部系统调用平台四类开放接口：资产调用、读取知识库元数据、检索知识库、更新知识库内容。明文仅创建时完整显示一次；重新生成使原令牌立即失效；授权失效时对该对象的访问即时联动失效。

**Why this priority**: PAT 是平台对外系统集成的唯一入站口，承载「凭据治理只有一个入口」与「认证不扩张授权」两条底线。

**Independent Test**: 创建 PAT 并勾选越权对象（被阻断）、调用四类接口、重新生成与停用/删除、模拟授权失效（订阅取消/资产下架/知识库权限回收/账号停用）验证联动失效。

**Acceptance Scenarios**:

1. **Given** 用户创建 PAT, **When** 填写名称、有效期与权限范围, **Then** 有效期默认 90 天（自创建时刻起算，允许设为永不过期）；权限范围只能勾选持有人已获授权的对象（已订阅的资产、有权限的知识库；平台原生工具不在其列），勾选时联动校验；单用户 PAT 数上限 20 个。
2. **Given** PAT 创建成功, **When** 展示明文, **Then** 令牌明文仅在该时刻完整显示一次，此后不再可查看。
3. **Given** 已有 PAT, **When** 停用或删除, **Then** 需二次确认；停用可恢复（重新启用）、删除终态不可恢复；不提供重新生成与有效期延长——泄漏应急/轮换/续期一律走「新建同范围 PAT → 切换 → 删除旧 PAT」（2026-08-23 用户裁定）。
3b. **Given** PAT 到达有效期终点, **When** 到期, **Then** 立即失效且不发送任何提醒通知；PAT 列表页始终呈现每个 PAT 的到期时间（2026-08-23 用户裁定）。
4. **Given** 某项授权失效（订阅被取消、资产被下架或删除、知识库权限被 Alice 回收）, **When** 该 PAT 调用该对象, **Then** 对该对象的访问立即失效，PAT 本身及其对其他对象的访问不受影响（对象侧失效）。
5. **Given** 持有人账号被 Alice 停用, **When** 停用生效, **Then** 其名下全部 PAT 与全部个人出站凭据（含个人模型凭据）立即失效；恢复账号后需重新签发，原令牌不复活（主体侧失效）。
6. **Given** 外部系统以 PAT 调用资产, **When** 平台处理, **Then** 先校验持有人已订阅该资产，再使用平台为持有人签发的个人出站凭据发起平台外资产调用。

### User Story 2 — 平台外资产调用的个人出站凭据 (Priority: P1)

订阅者在平台外调用已订阅资产时，由平台签发绑定用户与资产的个人出站凭据；未生成、凭据失效或调用失败时调用失败并引导至密钥库申请生成——不回落任何共享身份。

**Why this priority**: 「平台外调用不回落共享身份」是权限放大防线（共享身份会击穿目标服务的按人授权），是本 spec 的安全核心。

**Independent Test**: 已订阅资产分别在有/无凭据、凭据失效三种状态下发起平台外调用，验证签发、失败引导与零回落。

**Acceptance Scenarios**:

1. **Given** 用户已订阅某资产, **When** 申请平台外调用凭据, **Then** 平台签发绑定该用户与该资产的个人出站凭据；目标限当前用户已订阅的资产。
2. **Given** 未生成个人出站凭据, **When** 发起平台外调用, **Then** 调用失败并引导至密钥库申请生成；不回落至任何共享身份。
3. **Given** 个人出站凭据, **When** 管理, **Then** 支持申请生成、停用、撤销与重新生成。
4. **Given** 平台内资产调用（透传会话等）, **When** 发起, **Then** 不使用个人出站凭据——平台以资产级服务凭据发起并传递当前用户身份上下文（spec 003 FR-009）。

### User Story 3 — 个人模型凭据与模型类调用解析 (Priority: P1)

用户在密钥库配置个人模型凭据（Nexus 模型服务，可多条、有序、各有启停开关）；保存后平台自动对当前全部模型各执行一次可用性检测并保存「模型可用性列表」快照；模型类调用按触发人解析——按序取第一条「启用中且快照标记该模型可用」的个人凭据，无候选则用平台默认凭据；真实调用鉴权类失败时回落平台默认、改写快照并通知本人。

**Why this priority**: 模型类调用覆盖平台全部 AI 能力（对话、知识库构建、检索重排序、准入测评裁判），其凭据解析规则是性能隔离（个人凭据隔离平台统一凭据并发拥挤）与可用性兜底的平衡点。

**Independent Test**: 配置多条凭据并调整顺序/启停，验证按序解析、快照驱动、新增模型按未检测处理、鉴权失败回落与通知、瞬时故障不改写快照。

**Acceptance Scenarios**:

1. **Given** 用户保存一条个人模型凭据, **When** 保存成功, **Then** 平台自动对当前全部模型各执行一次测试调用（单模型检测超时 10 秒）并保存「模型可用性列表」快照；此后可手动刷新；平台新增模型后，存量快照对新模型为「未检测」、按不可用处理并提示可重新检测；单用户上限 5 条。
2. **Given** 一次模型类调用（Chat 会话归会话用户、知识库构建的向量化与内容增强归操作人、检索重排序归检索发起者含 PAT 检索接口持有人、准入测评裁判模型归执行发布的 Owner——spec 004 FR-012）, **When** 解析凭据, **Then** 按触发人名下「启用中且快照标记该模型可用」的个人凭据按列表顺序取第一条使用；无候选则使用平台默认凭据。
3. **Given** 个人凭据真实调用发生鉴权/权限类失败, **When** 失败发生, **Then** 本次调用改用平台默认凭据、快照中相应模型（令牌失效时为全部模型）置不可用，并通知本人（「请前往 Nexus 申请该模型的权限或更新凭据」——通知语义见 spec 009 FR-032）；瞬时故障不改写快照、不发通知。
4. **Given** 模型类兜底与平台外资产调用, **When** 比较两条规则, **Then** 适用域互不重叠——模型类是平台自有资源、允许回落平台默认凭据；平台外资产调用一律不回落共享身份（`docs/adr/0016` 与 `docs/adr/0014` 的适用域边界）。

### User Story 4 — 知识导入通道凭据 (Priority: P2)

知识库三个外部导入通道（Confluence、SharePoint/OneDrive、OSS（S3/Blob）——对应的平台原生工具）使用操作人在密钥库配置的个人出站凭据，三者鉴权方式各不相同；执行导入需知识库 Contributor 及以上权限（我的目录为创建者本人或获得「可编辑」分享授权的用户）。

**Why this priority**: 导入通道是知识库的供给线，凭据防线在操作人（只能导入其在来源系统有权阅读的内容）；依赖密钥库主体能力先行。

**Independent Test**: 未配置凭据时执行导入（引导配置）、配置后导入、权限不足时导入被拒，三类通道各自的鉴权表单。

**Acceptance Scenarios**:

1. **Given** 用户执行外部通道导入, **When** 未配置对应个人出站凭据, **Then** 引导至密钥库配置；已配置则使用操作人本人凭据——操作人只能导入其在来源系统中有权阅读的内容（内容准入责任归建库方，PRD §9.7）。
2. **Given** 三类通道, **When** 配置凭据, **Then** 三者鉴权方式各不相同，认证表单按目标声明的鉴权方式动态生成；执行导入需知识库 Contributor 及以上权限（我的目录为创建者本人或「可编辑」分享授权用户）（触发与导入语义见 spec 005）。
3. **Given** 平台原生工具, **When** 外部系统尝试经 PAT 调用, **Then** 被阻断——P0 不开放经 PAT 调用平台原生工具（外部系统可直连来源系统，经平台中转无增量价值）。

### User Story 5 — 凭据管理体验（单页配置、探测与跨页跳转） (Priority: P2)

出站个人凭据的统一交互：单页配置（资源选择器 + 动态认证表单同屏，已声明字段只读；带参跳转进入时选择器折叠为只读摘要）；密文字段默认掩码显示、可切换明文（切换留痕）；一键探测；从资产详情页/MCP 详情页/订阅者中心跳转凭据配置时带入目标资产信息，保存或签发后自动返回来源页面。

**Why this priority**: 交互一致性降低凭据配置的错误率与跳出感；属体验增强层，依赖凭据域主链路先行。

**Independent Test**: 从三个来源页分别带参跳转配置凭据，验证选择器折叠、动态表单、掩码切换留痕、探测反馈与保存后返回来源页。

**Acceptance Scenarios**:

1. **Given** 出站个人凭据配置页, **When** 进入, **Then** 单页配置：资源选择器与动态认证表单同屏；认证表单按目标声明的鉴权方式动态生成，已声明字段只读。
2. **Given** 从 MCP 详情页、订阅者中心或 Agent 详情页跳转凭据配置, **When** 带参进入, **Then** 带入目标资产信息、选择器折叠为只读摘要；Owner 跳转至该资产的资产控制台凭据配置，订阅者跳转至密钥库个人凭据配置；保存或签发后自动返回来源页面。
3. **Given** 凭据表单中的密文字段, **When** 查看, **Then** 默认掩码显示，可切换明文（切换动作留痕）。
4. **Given** 个人出站凭据, **When** 一键探测, **Then** 返回明确成败反馈（探测超时 10 秒，PRD §9.10）。

---

### Edge Cases

- PAT 勾选范围时资产恰好被下架？——勾选时联动校验按当时授权状态判定；下架后该 PAT 对该资产的访问即时失效（对象侧失效）。
- 凭据探测超时（10 秒）？——视为探测不可用，给出明确反馈；不阻断凭据保存本身（探测结果供参考与门控使用，门控语义见 spec 003）。
- 个人模型凭据全部禁用或全部快照不可用？——无候选，使用平台默认凭据（不视为错误）。
- 多条个人模型凭据同时「启用且快照可用」？——按列表顺序取第一条；排序由用户维护。
- 鉴权类失败与瞬时故障的区分不清（如目标返回 5xx 伴随 401）？——按响应的鉴权/权限语义判定；判定规则随 spec 007 实现工单细化（见 Open Questions）。
- 账号从 Alice 停用中恢复？——PAT 与个人凭据不复活，需重新签发/生成（主体侧失效不可逆）。
- 平台签发的平台外调用凭据会「过期」吗？——平台侧不设独立有效期（生命周期跟随订阅与失效规则）；若目标服务侧的凭据失效（如资产服务侧轮换密钥）导致调用失败，引导重新生成（FR-011，2026-08-23 用户裁定）。
- 管理员停用某资产出站调用后？——该资产的资产级服务凭据与全部个人出站凭据的解析一并禁用，优先于一切解析规则（含持 PAT 的外部系统）；恢复需管理员手动解除（spec 008）。

## Requirements

### Functional Requirements

**入站 PAT**

- **FR-001**: PAT MUST 是外部系统调用本平台全部开放接口的唯一入站认证凭据，统一在密钥库签发与吊销（原 AC-1；PRD M7-2/M7-3、`docs/adr/0010`）。
- **FR-002**: 创建 PAT MUST 填写名称、有效期（默认 90 天、自创建时刻起算、允许设为永不过期）与权限范围；范围只能勾选持有人已获授权对象的子集（已订阅的资产、有权限的知识库——含我的目录知识库；平台原生工具不在其列），勾选时 MUST 联动校验；单用户 PAT 数上限 20 个。**到期行为（2026-08-23 用户裁定）**：到期即失效；MUST NOT 发送到期提醒通知（不新增通知事件类型）；PAT 列表页 MUST 呈现每个 PAT 的到期时间。**PAT 创建后全部锁定**——名称、有效期、权限范围不可编辑；需要变更时新建并删除旧的（2026-08-23 用户裁定，编辑范围矩阵见 FR-017）（原 AC-2；PRD §9.3、§9.10、J8-1）。
- **FR-003**: 令牌明文 MUST 仅在创建成功时完整显示一次；停用与删除 MUST 需二次确认——动作用语统一（2026-08-23 用户裁定）：**停用**＝临时禁用、可恢复（可重新启用）；**删除**＝终态移除、不可恢复。**MUST NOT 提供 PAT 重新生成与有效期延长**（2026-08-23 用户裁定）：泄漏应急/轮换/到期续期一律走「新建同范围 PAT → 在自有系统切换 → 删除旧 PAT」（原 AC-3/AC-4；PRD M7-2、J8-1——已移除「重新生成」表述）。
- **FR-004**: 失效 MUST 分两类来源：对象侧——某项授权失效（订阅被取消、资产被下架或删除、知识库权限被 Alice 回收）时该 PAT 对该对象的访问立即失效，PAT 本身及其对其他对象的访问不受影响；主体侧——持有人账号被 Alice 停用时其名下全部 PAT 与全部个人出站凭据（含个人模型凭据）立即失效，恢复账号后需重新签发（原令牌不复活）（原 AC-5/AC-6；PRD §9.3）。

**出站个人凭据（三类目标）**

- **FR-010**: 出站个人凭据 MUST 按人持有，目标类型三种：平台外资产调用、平台原生工具（知识导入通道）、Nexus 模型服务（个人模型凭据）（原 AC-7；PRD M7-1、§9.3）。
- **FR-011**: 平台外资产调用凭据 MUST 由平台签发、绑定用户与资产，目标限当前用户已订阅的资产；未生成、凭据失效或调用失败时调用失败并引导至密钥库申请生成，MUST NOT 回落至任何共享身份（共享身份会击穿目标服务的按人授权）；支持申请生成、停用（可逆）、删除（终态不可逆——原表述「撤销」统一为「删除」，2026-08-23 用户裁定）；MUST NOT 提供重新生成（与再次申请生成等价，2026-08-23 用户裁定同原则移除）。凭据 MUST NOT 设独立有效期——其生命周期完全跟随订阅与失效规则（订阅失效/主体侧失效/管理员停用即失效；2026-08-23 用户裁定）。平台签发的该凭据 MUST NOT 提供任何用户可编辑内容（平台签发、绑定用户与资产）（原 AC-8；PRD M7-1、§9.3、J1-5、`docs/adr/0014`）。
- **FR-012**: 平台原生工具凭据 MUST 全员可选（三类通道鉴权方式各不相同）；执行导入需知识库 Contributor 及以上权限（我的目录为创建者本人或「可编辑」分享授权用户）；导入语义见 spec 005。编辑范围：仅**凭据值**可编辑，目标通道与鉴权方式只读（2026-08-23 用户裁定，FR-017）（原 AC-9；PRD M7-1、§9.7）。
- **FR-013**: 个人模型凭据 MUST 不按调用点划分——同一条凭据适用于该用户的全部模型调用点；可配置多条（上限 5 条），列表有序、各有启用/禁用开关。编辑范围：仅**凭据值**可编辑；启用/禁用与排序为独立动作、不算编辑（2026-08-23 用户裁定，FR-017）（原 AC-10；PRD M7-1、§9.10）。
- **FR-014**: 保存个人模型凭据后 MUST 自动执行一次全量可用性检测（对当前全部模型各执行一次测试调用，单模型检测超时 10 秒）并保存「模型可用性列表」快照；此后可手动刷新、无定时自动检测；平台新增模型对存量快照为「未检测」、按不可用处理并提示可重新检测（原 AC-11；PRD M7-1、§9.3、§9.10）。
- **FR-017**: 凭据编辑范围 MUST 遵循不可变优先矩阵（2026-08-23 用户裁定）：PAT 创建后全部锁定；平台外资产调用凭据无可编辑内容；导入通道与 Nexus 模型凭据仅可编辑凭据值。**编辑凭据值保存后 MUST 自动重检一次**：模型凭据全量重建可用性快照（同 FR-014），导入通道凭据自动真实鉴权探测一次（同 FR-015）——更新＝保存语义，快照与探测结果永远对应当前值。
- **FR-015**: 密文字段 MUST 默认掩码显示、可切换明文（切换动作留痕）；个人出站凭据 MUST 支持一键探测（探测超时 10 秒）；探测口径 MUST 为**真实鉴权**——以配置凭据对目标发起真实认证调用，认证通过才算探测可用（与 spec 003 裁定同构，2026-08-23 用户裁定；真实认证调用的具体设计待架构/开发确认，watchlist #58）（原 AC-15；PRD M7-1/M7-4、§9.10）。
- **FR-016**: 配置交互 MUST 为单页配置（资源选择器 + 动态认证表单同屏；认证表单按目标声明的鉴权方式动态生成，已声明字段只读；带参跳转进入时选择器折叠为只读摘要）；从 MCP 详情页、订阅者中心、Agent 详情页跳转凭据配置时 MUST 带入目标资产信息（Owner 跳转该资产的资产控制台凭据配置、订阅者跳转密钥库个人凭据配置），保存或签发后自动返回来源页面（原 AC-14；PRD M7-1/M7-4、J8-3）。

**模型类调用解析**

- **FR-020**: 模型类调用 MUST 按触发人解析、个人凭据优先、平台默认凭据兜底——触发人枚举：Chat 会话的会话用户、知识库构建的操作人、检索的发起者（含 PAT 检索接口持有人）、准入测评裁判模型归执行发布的 Owner（联动 spec 004 FR-012）；按序取触发人名下第一条「启用中且快照标记该模型可用」的个人模型凭据，无候选则使用平台默认凭据（原 AC-12/AC-21；PRD §9.3、`docs/adr/0016`）。
- **FR-021**: 个人凭据真实调用发生鉴权/权限类失败时，MUST 本次调用改用平台默认凭据、快照中相应模型（令牌失效时为全部模型）置不可用并通知本人（spec 009 FR-032）；瞬时故障 MUST NOT 改写快照、不发通知（原 AC-13；PRD §9.3）。
- **FR-022**: 适用域边界 MUST 显式成立：模型类资源是平台自有资源，回落平台默认凭据不击穿任何第三方按人授权；平台外资产调用仍一律不回落——两条规则互不适用（PRD §9.3、§13.9）。

**凭据解析总则与审计**

- **FR-030**: 平台内资产调用 MUST 由平台以资产级服务凭据发起并传递当前用户身份上下文（供资产内部处理用户级数据权限），订阅者零配置（原 AC-19；PRD §9.3、J2-2、`docs/adr/0014`；凭据配置侧见 spec 003 FR-009）。
- **FR-031**: 平台外资产调用 MUST 先校验持有人已订阅目标资产，再使用平台为持有人签发的个人出站凭据发起调用（原 AC-20；PRD §9.3、M7-3）。
- **FR-032**: 管理员按资产维度停用出站调用后，该资产的全部出站凭据解析（资产级服务凭据与全部个人出站凭据）MUST 一并禁用，平台网关不再为该资产发起出站调用——**优先于一切解析规则**；恢复需平台管理员手动解除（停用语义见 spec 008）（原 AC-22；PRD §9.3、`docs/adr/0009`）。
- **FR-033**: 每次调用 MUST 审计记录实际使用的凭据主体，粒度为**三元组**：凭据 ID + 凭据类型（资产级服务凭据/个人出站凭据/平台资源凭据）+ 持有人账号（资产级服务凭据记资产 ID 与资产名）——可精确归因到条（2026-08-23 用户裁定）；审计与调用日志留存 3 年（自产生时刻起算）（原 AC-23；PRD §9.3、§9.8、US-121）。
- **FR-034**: 资产级服务凭据的通道归属 MUST 为：鉴权声明属版本类、密钥值走轻发布通道（豁免门控与测评、发布留痕、通知全体负责人且仅含变更事实——2026-08-23 裁定；spec 004 FR-016/FR-018）；质量门控要求「已配置且探测可用」（spec 003 FR-022④）——本 spec 只引用，不重复定义（原 AC-16/AC-17/AC-18 的归属更新；PRD §9.3、`docs/adr/0014` 第十轮补注）。

**开放接口清单**

- **FR-040**: P0 开放接口 MUST 共四类：资产调用（外部系统调用已订阅的 Agent 与 MCP）、读取知识库元数据、检索知识库、更新知识库内容；全部以 PAT 为唯一入站认证（原 AC-24；PRD M7-3）。
- **FR-041**: 知识库三类接口的权限要求 MUST 为：读取元数据与检索需持有人具备该库知识库 Consumer 及以上权限；更新知识库内容需知识库 Owner 或知识库 Contributor 权限；我的目录的知识库默认仅创建者本人调用——「可查看」分享授权可调用读取与检索、「可编辑」还可调用更新（知识侧语义见 spec 005）（PRD M7-3、J4-6）。
- **FR-042**: 平台原生工具 MUST NOT 出现在开放接口之列（P0 不开放经 PAT 调用）（原 AC-25；PRD M7-3、`docs/adr/0015`）。

### Key Entities

- **PAT（个人访问令牌）**: 唯一入站凭据。关键属性：名称、有效期（默认 90 天自创建时刻起算，可永不过期）、权限范围（持有人已授权对象的子集）、状态（启用/停用）、创建时刻；单用户上限 20 个；明文仅创建时可见一次。
- **个人出站凭据（Outbound Personal Credential）**: 按人持有的外部资源凭据。关键属性：目标类型（平台外资产调用/平台原生工具/Nexus 模型服务）、目标对象、状态（启用/停用/已删除——停用可逆、删除终态不可逆，2026-08-23 用户裁定）、有序列表位置（模型凭据）。无独立有效期——生命周期跟随订阅与失效规则（2026-08-23 用户裁定）。
- **模型可用性列表（可用性快照）**: 个人模型凭据的可用模型快照。关键属性：每模型的可用标记（含「未检测」）、检测时间；保存凭据时全量检测产生，仅鉴权类失败改写，支持手动刷新。
- **凭据解析结果（隐式）**: 一次调用实际使用的凭据主体，记录为三元组（凭据 ID + 类型 + 持有人账号；资产级服务凭据记资产 ID 与资产名）——写入审计与调用日志，留存 3 年（2026-08-23 用户裁定粒度）。
- **资产级服务凭据**: 资产属性，不在密钥库（实体定义见 spec 003；通道归属见 spec 004 FR-016）。

## Success Criteria

### Measurable Outcomes

- **SC-001**: PAT 勾选越权对象（未授权或非子集）的阻断率 100%；平台原生工具出现在可选范围的次数为 0。
- **SC-002**: 平台外资产调用在未生成/凭据失效/调用失败时 100% 失败并引导申请，0 次回落至共享身份。
- **SC-003**: 鉴权/权限类失败 100% 触发回落平台默认凭据 + 快照改写 + 通知本人；瞬时故障 0 次改写快照、0 次通知。
- **SC-004**: 主体侧失效（账号被 Alice 停用）后，名下全部 PAT 与个人出站凭据 100% 立即失效；恢复后 0 个原令牌复活。
- **SC-005**: 对象侧失效后该 PAT 对该对象访问 100% 立即失效，对其他对象 0 影响。
- **SC-006**: 令牌明文 100% 仅创建时显示一次；PAT 管理界面 0 次出现「重新生成」与「有效期延长」入口。
- **SC-007**: 每次调用 100% 记录实际凭据主体三元组（凭据 ID + 类型 + 持有人账号）；管理员停用出站后该资产任何凭据主体的调用 100% 失败。
- **SC-008**: 个人模型凭据保存后 100% 触发全量可用性检测（单模型超时 10 秒）；平台新增模型对存量快照 100% 按「未检测/不可用」处理。
- **SC-009**: 单用户 PAT 超过 20 个、个人模型凭据超过 5 条的创建 100% 被阻断。

## Assumptions

- 平台全部凭据以企业 Key Vault 为底层加密存储（PRD §13.10 #2 已确认）；用户只与平台交互。
- 资产级服务凭据的配置与通道语义定义处在 spec 003/004；平台资源凭据的维护在 spec 008（管理后台平台资源注册表与模型设置）；本 spec 承载用户侧两个管理面与全局解析规则。
- 模型类资源全部经 Nexus 供给，不存在非 Nexus 供给的模型服务（PRD §13.10 #16 已确认）。
- 凭据解析的实现归属 mgmt-service（hub ADR-005）；Python 侧经 grc-ai-sdk 调用（hub ADR-003）。
- Alice 作为唯一授权权威提供订阅/权限判定与账号停用事件；权限回收与账号停用即时生效。

## Non-Goals / Boundaries

- **资产级服务凭据的管理界面**：资产属性，创建向导与资产控制台承载（spec 003），不在密钥库（`docs/adr/0014`）。
- **平台资源凭据**：管理后台平台资源注册表与模型设置承载（spec 008）。
- **经 PAT 调用平台原生工具**：P0 不开放（PRD §12.4、`docs/adr/0015`）。
- **凭据轮换的自动化策略**（定时轮换、过期前提醒）：P0 不提供，过期与失效靠显式动作与失效规则。
- **监控中心的 PAT 管理面**（PAT 详情与停用）：P1（PRD M10）。
