## 背景与目标

提供统一的对话入口。默认对话对象是平台 Chat agent-runtime（界面展示名 Chat）——平台自有的知识问答智能体，**当前交付范围支持文本输入，以及 Base64 图像输入 + 文本输出的图像识别能力**；仍可挂载知识库检索（带引用证据与图片/插图）。当前范围不含图像生成、OCR 工作流、音频/视频；P0 不调用平台原生工具（平台原生 MCP），也不调用已上架资产。用户订阅资产 Agent 后可经详情页「去使用」或对话工作台的资产 Agent 选择器进入该资产的**Agent 调试台**——调试台不是完整 chat：页面只读展示 Agent 原始 JSON 与基础信息；用户在下方 JSON 编辑器填写或粘贴请求，提交后在右侧查看原始 JSON 响应；平台网关代理透传；调试记录用户侧不持久化、不可挂载知识库。P1 预留 Chat 调用已订阅 MCP 资产工具的能力，但不进入当前对话工作台闭环。一切经平台流转的对话统一经过平台网关的护栏检测。

## Clarifications

### Session 2026-09-21（Chat 首触体验与首次提问引导裁定）

- Q: 空 Chat 会话首次进入时，AI 是否应直接「说话」？ → A: 应展示**助手欢迎卡片**——视觉上可呈现为 Chat 的主动问候与能力说明，但它由首触模板提供，不调用模型；MUST NOT 生成 Turn、进入历史会话、参与会话标题生成、产生真实模型调用或真实业务调用记录。
- Q: 首触区应传达哪些能力与边界？ → A: 明确展示当前 P0 可用入口（直接业务问答、挂载知识库并带来源引用、Base64 图像输入与文本输出的图像识别），并 MUST NOT 承诺 Agent/MCP 调用、图像生成、OCR 工作流或音视频（用户裁定）。
- Q: starter 入口点击后的行为？ → A: 首触区提供至少 3 个可执行入口；文本 starter 点击后**填入输入框但不自动发送**，知识库与图片 starter 分别打开挂载与图片选择入口；用户确认后的最终请求进入与手工输入一致的权限、护栏与网关链路（用户裁定）。
- Q: 首触区推荐图像识别时，默认模型是否必须可处理图像？ → A: 必须——空 Chat 会话默认模型 MUST 为 vision-capable；仍允许用户切换非 vision 模型并确认发起接收 Provider 4xx 的图像请求，但首触入口 MUST NOT 通过默认路径制造必然失败的图像调用（用户裁定）。

### Session 2026-09-21（Agent 调试台定位裁定）

- Q: 资产 Agent 使用面的产品形态？ → A: 定位为**Agent 调试台而非完整 chat**——页面展示 Agent 基础信息及只读 Agent Card 原始 JSON；用户通过 JSON 编辑器提交请求，并在右侧查看原始 JSON 响应（用户指令裁定）。
- Q: 调试记录持久化？ → A: 用户侧**不持久化**——不进入历史会话列表，不适用 90 天留存、500 上限、搜索、筛选、删除等会话管理规则，页面刷新或离开后调试内容不可恢复；平台侧合规留存与审计日志口径不变（护栏与审计在网关执行）（用户裁定）。
- Q: Agent 调试台左侧只读展示的「Agent 原有 JSON」应是哪一种？ → A: **Agent Card 原始 JSON**——展示资产发布时拉取并固化的 Agent Card / 能力声明原始 JSON；不展示完整在架接入配置 JSON、鉴权元数据、凭据明文、Health Check 地址与探测详情、护栏策略模板细节（2026-09-21 用户裁定）。
- Q: 输入与输出的交互形态？ → A: 用户通过**JSON 编辑器**填写或粘贴 JSON 请求体；提交后在右侧查看原始 JSON 响应；不使用纯文本输入、动态表单或 Chat 消息渲染（2026-09-21 用户裁定）。
- Q: 多轮上下文是否保留？ → A: 保留——FR-021 的 contextId 模型不变，Agent 调试台支持多轮调试，多轮上下文仍由资产自行维护（用户裁定）。
- Q: Agent 调试台平台侧会话 ID（contextId 承载）的生命周期？ → A: **每次进入 Agent 调试台生成新的平台侧会话 ID**，页面刷新、离开或切换资产即失效并新建——与用户侧不持久化自洽（2026-09-21 裁定，FR-021 与 Debug Turn 实体同步）。
- Q: JSON 响应操作语义？ → A: 提供复制原始 JSON 与重新生成；**重新生成＝以同一 JSON 请求重新调用资产并替换本轮 JSON 响应**；调试台无知识库检索语义，仅重跑资产调用（2026-09-21 裁定，US4 场景 5b 同步）。
- Q: Agent 调试台用户缺少、失效或尚未颁发个人凭据时，应该怎样处理？ → A: **阻断并引导配置**——禁止调用；静态凭据未配置或失效时展示「前往配置凭据」入口；动态凭据处于颁发中或颁发失败时展示对应状态与处理指引；不得回退到平台或共享身份（2026-09-21 用户裁定）。
- Q: 资产 Owner 或 Deputy 没有订阅记录时，是否可以直接进入该资产的 Agent 调试台？ → A: **可直接进入且用个人凭据**——Owner / Deputy 无需订阅即可进入自己资产的 Agent 调试台，但发起调用仍要求当前用户个人凭据可用，适用与订阅用户相同的护栏、审计与凭据不可用阻断规则（2026-09-21 用户裁定）。
- Q: 资产被删除后，用户在「我的资产」抽屉及相关 Agent 调试台入口中应看到什么？ → A: **完全移除**——资产删除后从「我的资产」抽屉、详情入口及 Agent 调试台入口完全移除；下架资产才保留置灰不可进入的条目，二者必须区分（2026-09-21 用户裁定）。
- Q: Chat 命中知识库时，引用证据应展示到什么粒度？ → A: 在「回答依据」中展示每条命中的**具体 Chunk 正文**，并同时展示其排序位次、相似度、所属知识库与来源文档；用户无需仅凭来源元信息跳转原文才可核验命中内容（2026-09-21 用户指令裁定）。
- 连带修订：历史会话管理（US5、FR-028~FR-032）收窄为**仅适用 Chat 会话**；FR-032 的「失效场景只读回看」对资产调试失效，改为 Agent 调试台拒绝新调用并按原因展示对应文案；FR-028 的「按 Agent 筛选」随会话列表仅含 Chat 会话而移除；原「透传会话与 Chat 会话适用同一套持久化与管理规则」（2026-08-21 裁定）**superseded**。

### Session 2026-09-15

- Q: Chat 多模态当前到底支持什么？ → A: **提升为当前交付范围**，但只支持图像识别：输入可含 Base64 图片，输出仍是文本；不做图像生成、不做 OCR 工作流、不做音视频；SDK 不负责文件存储/检索/压缩/转换（用户批准）。
- Q: 图像输入的格式与限制？ → A: **仅 Base64**；首版仅接受 JPEG/PNG/WebP；单次最多 4 张、单张解码后最大 10 MiB、总计最大 20 MiB；默认 `detail=auto`，可选 `low/high`；拒绝 SVG/GIF；多模态请求默认超时 120 秒且可配置（用户批准）。
- Q: Chat 选模型/选凭据与旧“自动平台兜底横幅”还成立吗？ → A: **不再以 SDK 自动选个人凭据/自动回落平台凭据为现行口径**。业务层/调用方先决定模型与 `credentialId`，SDK 只负责统一调用；若模型不支持 vision，由 Provider 4xx 直接返回；2026-08-23 的“自动兜底横幅”口径转为历史 superseded 记录（用户批准）。
- Q: Chat 图像输入与 parser 的 `MULTIMODAL` 概念冲突怎么处理？ → A: **vision-capable chat model 走 ChatPort；文档解析继续是 `DOCUMENT_PARSE`**。历史 `MULTIMODAL -> parser` 映射保留一版 deprecated 兼容，再于 1.0 移除；现有 Postman 文件只证明 GPT-5.5 文本接口 / API version，不证明图像兼容，需补真实 Nexus Base64 图片 PoC（用户批准）。

### Session 2026-08-21

- Q: 单会话可挂载知识库数上限？ → A: 5 个（PRD §9.10 参数基线审定——用户确认）。
- Q: 多库挂载时检索结果如何归并？ → A: 每个挂载知识库各取相似度最高的前 5 条切片；跨库按相似度归并后取前 10 条，按切片去重（PRD §9.10 参数基线审定——用户确认）。
- Q: 会话与对话对象的绑定关系？ → A: Chat 会话固定绑定 Chat；该资产的 Agent 调试台页面固定绑定单一资产（2026-09-21 Agent 调试台定位裁定修正——原「会话固定绑定唯一对话对象、透传会话与 Chat 会话适用同一套持久化与管理规则」口径 superseded）。
- Q: 输入侧护栏命中的处置？ → A: 直接拦截并拒答，响应回传命中的护栏类型，页面展示命中类型与处置结果（与输出侧提示一致）；临时文件内容视同用户输入、随 P1 上传功能生效（PRD §9.5——用户确认）。
- Q: 模型选择与深度分析开关在资产侧是否提供？ → A: 不提供——仅 Chat 会话提供模型选择器与深度分析开关；Agent 调试台不提供，资产 Agent 的模型由资产自身决定，会话能力以资产返回为准（用户确认）。
- Q: 「重新生成」的语义与旧回答去向？ → A: 按当前知识库状态重新检索并重跑模型，旧回答被直接替换、不保留历史版本（与无快照语义自洽——用户裁定）。
- Q: 单用户会话数上限与达上限后的处置？ → A: 上限 500 个（PRD §9.10 参数基线审定）；达上限时「新建会话」入口禁用并提示已达上限，引导用户删除旧会话后恢复；不自动清理任何会话（会话是用户工作记录，静默清理造成无感知数据丢失——用户裁定）。
- Q: 会话标题如何生成？ → A: 首轮问答完成后由模型生成摘要标题；生成失败时兜底取首条提问截断；支持手动重命名，重命名后不再被自动覆盖（用户裁定）。
- Q: 我的资产抽屉两区的默认排序？ → A: 已订阅区按最近使用时间倒序（无使用记录按订阅时间），收藏区按收藏时间倒序；两区均可切换按名称排序（PRD §7 M1-15——用户确认）。
- Q: Chat 侧生成失败（模型/检索/网络）时失败轮次是否落库？ → A: 展示明确错误提示与重试入口；失败轮次的回答不写入会话历史，用户消息保留可直接重发（失败回答无消费价值，落库会污染历史与上下文——用户裁定）。

### Session 2026-08-22

- Q: 透传会话的多轮上下文谁维护？ → A: 平台网关在每轮透传请求中携带当前消息与平台侧会话 ID，多轮上下文由资产自行维护，平台不向资产透传历史消息（对齐 A2A 协议的 `contextId` 模型；避免每轮向资产全量暴露用户对话历史——用户裁定）。
- Q: 前一条回答仍在生成时能否发送下一条？ → A: 不能——生成期间发送入口禁用并提示「正在生成中」，用户可经「停止生成」主动中止后立即发送；新消息不自动中止当前生成；Chat 会话与 Agent 调试台行为一致（防止同会话轮次交错破坏资产侧上下文连续性——用户裁定）。
- Q: 订阅失效（退订/被 Owner 取消）与出站停用后，历史会话如何处理？ → A: 2026-09-21 Agent 调试台定位裁定修正——调试记录用户侧不持久化，无历史调试记录可回看；失效场景统一为 Agent 调试台拒绝新调用并按原因展示对应文案（原「只读回看」口径 superseded）。
- Q: 透传会话是否要求资产支持流式输出？ → A: 不要求——平台缓冲资产完整响应，经输出侧护栏检测通过后直接完整呈现；资产以普通请求-响应即可接入，准入门控不含流式能力校验（2026-08-24 输出侧护栏机制修订取代原按段回放口径）。
- Q: 用户删除会话后对话原文的去向？ → A: 软删除——用户侧立即不可见且不可恢复；脱敏/敏感字段遮蔽后的对话内容按 PRD §9.8 继续留存至 90 天期满（自最后一条消息起算）再清除，删除不影响审计日志 3 年留存（与资产/知识库软删除终态模式一致；若合规裁定收窄为只留元数据，语义不变、留存范围随动——用户裁定）。

## User Scenarios & Testing

### User Story 1 — 与 Chat 的基础对话与图像识别 (Priority: P1)

普通用户登录后直接进入对话工作台，默认与平台 Chat agent-runtime（Chat）对话：欢迎页/消息流主界面、模型选择、深度分析开关、思考过程展示、复制与重新生成、常驻免责声明，以及**图像输入、文本输出**的首版识别能力。

**Why this priority**: Chat 是平台的默认对话对象与第一触点；图像识别已升级为当前交付范围的一部分，无此则当前版本的多模态 Chat 不成立。

**Independent Test**: 不选择任何资产发起纯文本与图像对话，验证主界面两种形态、模型下拉仅含对话类与多模态类、图像类型/数量/大小限制、深度分析与思考过程、复制/重新生成与免责声明均符合规格；纯文本调用保持兼容。

**Acceptance Scenarios**:

1. **Given** 用户进入对话工作台且未选择资产, **When** 发起对话, **Then** 对话对象为 Chat——Chat 不是资产，不上架、不可订阅、无 Owner、恒可用。
2. **Given** Chat 会话, **When** 使用其能力, **Then** P0 仅可使用模型对话与挂载知识库检索两项；Chat 不调用平台原生工具（平台原生 MCP），不调用已上架资产；既有接口中的工具调用承载仅作兼容保留并为 P1 Chat 调用已订阅 MCP 资产工具能力预留。
3. **Given** 新会话无消息, **When** 打开对话页, **Then** 展示欢迎页与输入框；有消息时展示消息流与底部固定输入区；Enter 发送、Shift+Enter 换行。
4. **Given** Chat 会话, **When** 打开模型选择下拉, **Then** 仅展示对话类与多模态类模型（向量化模型与重排序模型不出现）；Chat 绑定平台默认护栏策略模板，提示词与实现随平台部署定义、P0 无配置入口。
5. **Given** Chat 会话, **When** 开启深度分析, **Then** 模型执行更多推理步骤，思考过程默认展开，以可折叠的有序步骤列表展示。
6. **Given** Chat 会话附带图片输入, **When** 用户提交请求, **Then** 仅接受 Base64 编码的 JPEG/PNG/WebP；单次最多 4 张，单张解码后 ≤ 10 MiB，总计 ≤ 20 MiB；`detail` 默认 `auto`，可选 `low/high`；系统内部按 OpenAI-compatible content parts + data URI 序列化，回答仍为文本。
7. **Given** Chat 会话附带图片输入, **When** 图片为 SVG/GIF、超过数量/大小上限、或 Base64 不合法, **Then** 请求在进入 Provider 前被拒绝，并返回明确错误提示；系统不负责外部 URL 抓取、文件存储、压缩或格式转换。
8. **Given** 一条已生成的回答, **When** 用户点击重新生成, **Then** 系统按当前知识库状态重新检索并重跑模型，旧回答被直接替换、不保留历史版本；复制全文随时可用。
9. **Given** 任意会话页, **When** 查看输入区下方, **Then** 常驻展示 AI 生成内容免责提示与平台级用户协议链接。

### User Story 1a — Chat 首触体验与首次提问引导 (Priority: P1)

新用户或从新建入口进入空 Chat 会话的用户，可在不阅读帮助文档、不打开其他模块的前提下理解 Chat 当前能完成什么，并可直接从自然输入、知识库挂载或图像识别入口开始第一次有效提问。

**Why this priority**: Chat 是平台的「门面」；首次进入能否快速理解能力边界并完成第一次尝试，直接决定用户是否继续探索工具链、资产订阅与治理功能。

**Independent Test**: 打开一个全新的 Chat 会话，验证助手欢迎卡片、能力边界、三个 starter 入口、默认 vision 模型、无模型 Turn 与首次发送后的正常消息流；分别点击文本、知识库和图像 starter，确认其行为与原有权限/护栏链一致。

**Acceptance Scenarios**:

1. **Given** 用户打开空 Chat 会话, **When** 页面就绪, **Then** 展示助手欢迎卡片与首触区；卡片可显示用户显示名，显示名不可用时回退为通用称呼；首触区明确提供直接业务问答、知识库带来源引用、Base64 图像识别三类入口。
2. **Given** 空 Chat 会话尚未发送真实输入, **When** 用户仅查看欢迎卡片或首触区, **Then** 平台不调用模型，不生成会话 Turn、不写入历史会话、不触发标题生成，也不产生真实业务调用记录。
3. **Given** 首触区, **When** 用户点击文本 starter, **Then** 对应提示词被填入输入框但不自动发送；点击知识库 starter 时打开挂载面板；点击图片 starter 时打开图片选择入口；用户确认后的请求进入与手工输入一致的权限、输入侧护栏、网关与输出侧护栏链。
4. **Given** 新建空 Chat 会话, **When** 查看模型选择状态, **Then** 当前默认模型具备 vision 能力；若用户手动切换到非 vision 模型并发起图像请求，Provider 4xx 仍直接返回（见 FR-009e），但默认首触路径不得导向必然失败。
5. **Given** 首触区, **When** 用户查看任一入口或说明, **Then** 不展示 Agent 调试台调用、MCP 调用、图像生成、OCR 工作流或音视频能力承诺；这些内容不进入当前 Chat 首触闭环。

### User Story 2 — 知识库挂载与检索 (Priority: P1)

普通用户在 Chat 会话中挂载有权限且「可用」的知识库（可精确到单文档），提问后获得带引用来源与检索证据的回答，图片与图表类证据内嵌渲染。

**Why this priority**: 知识库检索是 Chat 区别于裸模型的唯一能力，是平台知识价值的出口。

**Independent Test**: 在 Chat 会话挂载一个「可用」知识库并提问，验证可选范围、挂载上限、归并口径、引用证据（含具体命中 Chunk 正文）与内嵌渲染；中途停用该库，验证下一轮检索立即失效。

**Acceptance Scenarios**:

1. **Given** Chat 会话, **When** 打开知识库挂载面板, **Then** 可按目录树浏览、按名称搜索、按知识库多选、按文档单选；可选范围为状态「可用」的以下知识库（以 spec 005 FR-049 为定义处）：公共目录中——①用户持有知识库 Consumer 及以上有效权限的库；②用户为该库创建者且享有知识库创建角色内含读取语义的库；③可见范围为「公开可用」的库（全体登录用户隐含 Consumer 读取语义）；以及当前用户本人创建且状态「可用」的我的目录知识库；草稿与已停用的库不出现。
2. **Given** Chat 会话已挂载 5 个知识库, **When** 尝试挂载第 6 个, **Then** 被阻断并提示「超过知识库挂载上限，建议减少选择的知识库」。
3. **Given** 会话挂载了多个知识库, **When** 用户提问, **Then** 检索归并口径为：每个挂载知识库各取相似度最高的前 5 条切片，跨库按相似度归并后取前 10 条，按切片去重。
4. **Given** 回答已生成, **When** 查看回答末尾并展开「回答依据」, **Then** 展示引用来源标签；每条命中切片均展示具体 Chunk 正文、排序位次、相似度分值、所属知识库与来源文档，并可打开原文；命中的图片/插图/图表类证据内嵌渲染并标注来源文档。
5. **Given** 会话挂载的知识库被停用、被软删除、回「草稿」或用户权限被回收, **When** 发起下一轮检索, **Then** 按检索时刻的知识库状态与权限判定——立即不可检索/无内容/被拒绝；进行中的会话与新会话一视同仁，不设会话级快照。
6. **Given** Agent 调试台, **When** 查看页面, **Then** 不提供知识库挂载能力。

### User Story 3 — 流式输出与护栏 (Priority: P1)

Chat 会话与 Agent 调试台统一经过输出侧护栏：上游流式响应采用重叠滑动窗口检测，非流式响应采用全文缓冲检测并在通过后直接完整呈现；输入侧命中直接拒答；可随时中止生成；护栏命中展示类型与处置结果。

**Why this priority**: 护栏是平台安全基线的运行时执行点（宪法级约束），流式回放与中止决定对话可用体感。

**Independent Test**: 分别构造输入命中、输出命中、中止生成三种场景，验证拦截/占位/回放行为与提示文案。

**Acceptance Scenarios**:

1. **Given** 用户发送的消息命中输入侧护栏, **When** 提交, **Then** 直接拦截并拒答，响应回传命中的护栏类型，页面展示命中类型与处置结果（与输出侧提示一致）。
2. **Given** 上游提供流式响应, **When** 输出内容持续到达, **Then** 平台按重叠滑动窗口执行输出侧护栏检测，窗口通过才释放其可下发内容；任一窗口命中时立即终止上游、瞬时撤回全部已下发内容（含已通过窗口的前缀）并原位展示「该回答因命中安全护栏已被撤回」（含护栏类型）——终态零字留存、命中轮次不落库（2026-08-24 用户裁定）。
3. **Given** 上游仅提供非流式响应, **When** 完整回答返回, **Then** 平台缓冲全文并执行输出侧护栏检测，通过后直接完整呈现（不假流式）；命中则全文不呈现并展示同一提醒。
3b. **Given** 回答正在生成或回放, **When** 用户点击停止生成, **Then** 平台停止读取后续内容，未释放的已生成内容按当前路径完成检测；未通过按命中规则处置，通过则可保留已下发部分。
4. **Given** 回答生成期间, **When** 用户尝试发送新消息, **Then** 发送入口禁用并提示「正在生成中」；新消息不自动中止当前生成；用户可主动「停止生成」后立即发送；Chat 会话与 Agent 调试台行为一致。
5. **Given** 护栏命中（输入或输出侧）, **When** 页面展示, **Then** 可见命中的护栏类型与处置结果。

### User Story 4 — Agent 调试台 (Priority: P2)

用户订阅资产 Agent 后，或作为该资产的 Owner / Deputy，经详情页「去使用」或对话工作台的资产 Agent 选择器进入该资产的**Agent 调试台**：页面展示 Agent 基础信息及只读原始 JSON；用户在下方 JSON 编辑器填写或粘贴请求，提交后在右侧查看原始 JSON 响应。平台网关代理透传，护栏、凭据解析、审计在网关执行；Chat 不在场、不可挂载知识库；调试记录用户侧不持久化。

**Why this priority**: 调试台是订阅价值的专业验证入口——用户直接查看 Agent 原始 JSON 并以 JSON 请求/响应验证其真实行为，而非获得一个完整 chat 产品；依赖订阅链路（spec 002）存在，故列为第二优先级切片。

**Independent Test**: 订阅一个已发布 Agent 后经「去使用」进入调试台，完成一轮 JSON 调用，验证网关透传、身份上下文传递、Agent 原始 JSON 与基础信息只读展示、JSON 编辑器输入、右侧原始 JSON 输出、无挂载能力、刷新后调试内容不保留。

**Acceptance Scenarios**:

1. **Given** 用户已订阅某资产 Agent，或为该资产的 Owner / Deputy, **When** 经详情页「去使用」或选择器进入, **Then** 进入该资产的 Agent 调试台，平台网关代理透传（护栏、凭据解析、审计在网关执行）；Chat 不在场、不可挂载知识库；页面展示当前 Agent 基础信息与只读原始 JSON。Owner / Deputy 无需订阅即可进入，但调用仍要求当前用户个人凭据可用。
2. **Given** Agent 调试台页面, **When** 查看 Agent 信息区, **Then** 展示该 Agent 的基础信息及只读原始 JSON；不提供编辑入口；不展示鉴权元数据、凭据明文、Health Check 探测详情与护栏策略模板细节。
3. **Given** Agent 调试台进行中, **When** 平台发起资产调用, **Then** 使用当前用户的个人凭据发起（2026-08-24 模型裁定），并在请求中传递当前用户身份上下文（供资产内部处理用户级数据权限）。
4. **Given** Agent 调试台多轮调用, **When** 每轮请求发出, **Then** 平台携带当前 JSON 请求与平台侧会话 ID；多轮上下文由资产自行维护，平台不向资产透传历史消息。
5. **Given** 用户在 JSON 编辑器中提交合法 JSON 请求, **When** 调用完成, **Then** 页面右侧展示资产返回的原始 JSON 响应；请求与响应不按 Chat 消息样式渲染。
5b. **Given** 一轮 JSON 调用已完成, **When** 用户操作该轮输出, **Then** 可复制原始 JSON；重新生成＝以同一 JSON 请求重新调用资产并替换本轮 JSON 响应（调试台无知识库检索语义，仅重跑资产调用）。
6. **Given** 资产 Agent 仅支持普通请求-响应（非流式）, **When** 响应返回, **Then** 平台缓冲完整响应，经输出侧护栏检测通过后在右侧展示原始 JSON 响应；准入门控不含流式能力校验。
7. **Given** Agent 调试台页面, **When** 查看交互区, **Then** 展示 JSON 编辑器与原始 JSON 响应区；不展示模型选择器与深度分析开关（模型由资产自身决定）。
8. **Given** 用户在 Agent 调试台, **When** 刷新页面、离开或通过选择器切换资产, **Then** 进入该资产的独立 Agent 调试台页面，不带入其他资产的调试内容；调试记录用户侧不持久化——不进入历史会话列表，页面刷新或离开后调试内容不可恢复（平台侧合规留存与审计日志口径不变）。
9. **Given** 资产已下架、订阅失效（退订或被 Owner 取消）、出站调用被停用，或当前用户个人凭据不可用, **When** 用户在 Agent 调试台发起调用, **Then** 调用被拒并按原因展示对应文案；静态凭据未配置或失效时提供「前往配置凭据」入口，动态凭据颁发中或颁发失败时展示对应状态与处理指引，不得回退到平台或共享身份（见 FR-032 与 FR-035）。

### User Story 5 — 历史会话管理（仅 Chat 会话） (Priority: P2)

Chat 会话服务端持久化 90 天，支持搜索、打开恢复、删除与新建；单用户上限 500 个；会话标题自动生成可重命名；删除为软删除。Agent 调试台的调试记录不适用本 story（用户侧不持久化，见 US4/FR-019）。

**Why this priority**: 历史会话是工作记录的留存与复访能力，依赖对话主链路先行。

**Independent Test**: 构造多会话环境，验证 90 天持久化口径、搜索、上限阻断、标题生成与重命名、删除软语义。

**Acceptance Scenarios**:

1. **Given** 用户的 Chat 历史会话, **When** 查看列表, **Then** 会话服务端持久化 90 天（自最后一条消息起算）；支持按会话标题与首条提问搜索、打开恢复、删除、新建。
2. **Given** 用户已有 500 个会话, **When** 尝试新建, **Then** 「新建会话」入口禁用并提示已达上限，引导删除旧会话后恢复；平台不自动清理任何会话。
3. **Given** 新会话完成首轮问答, **When** 生成会话标题, **Then** 由模型生成摘要标题；生成失败时兜底取首条提问截断；用户可手动重命名，重命名后不再被自动覆盖。
4. **Given** 用户删除某会话, **When** 删除生效, **Then** 会话在用户侧立即不可见且不可恢复（软删除）；脱敏/敏感字段遮蔽后的对话内容按 PRD §9.8 留存至 90 天期满再清除，删除不影响审计日志 3 年留存。

### User Story 6 — 我的资产抽屉与不可用提示 (Priority: P2)

对话工作台提供「我的资产」抽屉（已订阅/收藏两区，含排序与点击语义）；资产或订阅、个人凭据不可用时按对应原因展示文案；已删除资产完全移除；Chat 侧生成失败展示错误与重试入口。

**Why this priority**: 抽屉是回到工作的快捷入口，不可用提示是异常体验的底线；均为增强层而非核心链路。

**Independent Test**: 构造已订阅、收藏、已下架、订阅失效、出站停用、个人凭据不可用、服务异常和已删除资产条目，验证抽屉分区、排序、点击去向、置灰、移除与文案。

**Acceptance Scenarios**:

1. **Given** 用户打开「我的资产」抽屉, **When** 浏览, **Then** 分已订阅与收藏两区；已订阅区默认按最近使用时间倒序（无使用记录按订阅时间），收藏区默认按收藏时间倒序，两区均可切换按名称排序。
2. **Given** 抽屉条目, **When** 点击, **Then** 已订阅的 Agent 直接进入其 Agent 调试台；MCP 与未订阅资产进入其详情页；已下架资产条目置灰不可进入 Agent 调试台；已删除资产不出现在抽屉或任何 Agent 调试台入口。
3. **Given** 资产、订阅或当前用户个人凭据不可用, **When** 用户尝试使用, **Then** 按原因展示五类文案之一：已被下架 / 订阅已失效 / 出站调用已被平台停用 / 个人凭据不可用 / 服务暂时不可用；服务暂时不可用文案附资产名称与负责人。个人凭据不可用时，静态凭据提供「前往配置凭据」入口，动态凭据展示颁发中或颁发失败状态与处理指引，不得回退到平台或共享身份。
4. **Given** Chat 会话中生成失败（模型服务或检索服务失败、网络中断等）, **When** 失败发生, **Then** 展示明确错误提示与重试入口；失败轮次的回答不写入会话历史，用户消息保留可直接重发。

### Edge Cases

- 回答生成期间发送新消息？——发送入口禁用并提示「正在生成中」，可主动中止后立即发送（FR-027）。
- 同一会话挂载的知识库中途被停用或权限被回收？——下一轮检索即不可检索/被拒绝，无会话级快照（FR-016）。
- 资产 Agent 服务超时或返回错误？——经配置的重试后仍失败时提示「该资产服务暂时不可用」并展示资产名称与负责人（FR-036）。
- 图像输入为 SVG/GIF、超过 4 张、单张超过 10 MiB、总计超过 20 MiB 或 Base64 非法？——在进入 Provider 前即阻断并提示明确原因（FR-009b）。
- 用户给不支持 vision 的 Chat 模型发送图片？——SDK 不预判能力，由业务配置与调用方决定是否允许；若仍发出请求，Provider 4xx 直接返回（FR-009e）。
- 会话数达 500 上限后新建？——入口禁用并提示，引导删除旧会话；不自动清理（FR-030）。
- 会话标题模型生成失败？——兜底取首条提问截断（FR-031）。
- 资产不支持流式输出？——平台缓冲完整响应并完成全文检测后直接完整呈现（不假流式），接入不受阻（FR-022/FR-023，2026-08-24 口径）。
- 用户在 90 天留存期内删除会话？——软删除，用户侧不可见，原文留存至期满（FR-031）。
- Agent 调试台刷新或离开后想恢复之前的调试内容？——不可恢复，调试记录用户侧不持久化（FR-019）；平台侧合规留存与审计日志不受影响。
- 已下架/订阅失效/出站停用资产，或个人凭据未配置、失效、颁发中或颁发失败时，在 Agent 调试台发起调用？——调用被拒；静态凭据提供「前往配置凭据」入口，动态凭据展示对应状态与处理指引，不得回退到平台或共享身份（FR-032/FR-035）。
- 资产被删除后？——从「我的资产」抽屉、详情入口及 Agent 调试台入口完全移除；下架资产才保留置灰不可进入的条目（FR-034a）。

## Requirements

### Functional Requirements

**Chat 对话对象**

- **FR-001**: 系统 MUST 在用户未选择资产时将对话对象默认为平台 Chat agent-runtime（Chat）；Chat 不是资产——不上架、不可订阅、无 Owner、恒可用（原 AC-1）。
- **FR-002**: Chat 的 P0 能力 MUST 有且仅有模型对话与挂载知识库检索两项；P0 不调用平台原生工具（平台原生 MCP），不调用已上架资产；`tool_call` SSE 事件与消息模型中的 `toolCalls` 字段仅作既有契约兼容保留，并为 P1 Chat 调用已订阅 MCP 资产工具能力预留，不构成 P0 Chat 功能承诺（原 AC-2）。
- **FR-003**: Chat MUST 绑定平台默认护栏策略模板；其提示词与实现随平台部署定义，P0 不提供配置入口（原 AC-3/AC-4）。

**对话主界面与基础能力**

- **FR-004**: 对话主界面 MUST 在无消息时展示欢迎页与输入框、有消息时展示消息流与底部固定输入区；Enter 发送、Shift+Enter 换行（原 AC-17b）。
- **FR-004a**: 空 Chat 会话 MUST 展示助手欢迎卡片；卡片可呈现为 Chat 主动问候并可展示用户显示名（显示名不可用时回退为通用称呼）；它 MUST 在真实用户发送前即达，不得依赖模型调用（2026-09-21 用户裁定）。
- **FR-004b**: 首触区 MUST 明确展示三类当前 P0 能力入口：直接业务问答、挂载知识库并带来源引用、Base64 图像输入与文本输出的图像识别；MUST NOT 承诺 Agent/MCP 调用、图像生成、OCR 工作流或音视频（2026-09-21 用户裁定）。
- **FR-004c**: 首触区 MUST 提供至少 3 个可执行 starter 入口；文本 starter 点击后 MUST 填入输入框但不自动发送，知识库 starter MUST 打开挂载面板，图像 starter MUST 打开图片选择入口；确认后的最终请求 MUST 进入与手工输入一致的权限、输入侧护栏、网关与输出侧护栏链（2026-09-21 用户裁定）。
- **FR-004d**: 欢迎卡片与首触区 MUST NOT 生成 Turn、进入历史会话、参与会话标题生成、触发真实资产/模型调用或产生业务用量；页面访问范围之外的护栏与合规审计语义不变（2026-09-21 用户裁定）。
- **FR-005**: 模型选择 MUST 仅在 Chat 会话提供，下拉列表仅展示对话类与多模态类模型（向量化模型与重排序模型不出现）；Agent 调试台不展示模型选择器，资产 Agent 的模型由资产自身决定（原 AC-3/AC-17）。
- **FR-005a**: 新建空 Chat 会话的默认模型 MUST 具备 vision 能力，使首触图像识别路径默认可用；用户切换到非 vision 模型后发送图像时，Provider 4xx MUST 直接返回且不构成默认首触路径（2026-09-21 用户裁定）。
- **FR-006**: 深度分析开关 MUST 仅在 Chat 会话提供；开启后模型执行更多推理步骤，思考过程默认展开（原 AC-18）。
- **FR-007**: 思考过程 MUST 以可折叠的有序步骤列表展示（原 AC-19）。
- **FR-008**: 回答操作 MUST 含复制全文与重新生成；重新生成按当前知识库状态重新检索并重跑模型，旧回答被直接替换、不保留历史版本（原 AC-20）。
- **FR-009**: 输入区下方 MUST 常驻展示 AI 生成内容免责提示与平台级用户协议链接（原 AC-21）。
- **FR-009a**: Chat 当前交付范围 MUST 支持**图像输入、文本输出**的图像识别能力；不含图像生成、OCR 工作流、音频/视频（2026-09-15 用户批准）。
- **FR-009b**: Chat 图像输入 MUST 仅接受 Base64，不支持外部 URL 抓取；首版仅接受 JPEG/PNG/WebP，单次最多 4 张，单张解码后最大 10 MiB、总计最大 20 MiB；SVG/GIF MUST 被拒绝。SDK 与 Chat 业务链路 MUST NOT 承担文件存储、检索、压缩或格式转换职责（2026-09-15 用户批准）。
- **FR-009c**: Chat 图像输入的 `detail` 参数 MUST 默认 `auto`，可选 `low/high`；多模态请求默认超时 MUST 为 120 秒，且允许调用方配置覆盖（2026-09-15 用户批准）。
- **FR-009d**: SDK / Chat 调用链 MUST 将图像输入内部序列化为 OpenAI-compatible content parts 与 data URI；纯文本请求 MUST 保持向后兼容。引入图像输入后，流式输出与既有 tool-calling 承载语义 MUST 保持兼容并纳入测试（2026-09-15 用户批准）。
- **FR-009e**: SDK MUST NOT 自行判定模型是否支持 vision；该决策归业务配置与调用方。若对不支持 vision 的模型发送图片，Provider 4xx MUST 直接传播。vision-capable chat model MUST 使用 ChatPort；Document Parse MUST 保持独立 `DOCUMENT_PARSE` 概念。历史 `MULTIMODAL -> parser` 映射 MUST 走一版 deprecated 兼容，再于 1.0 移除（2026-09-15 用户批准）。

**知识库挂载与检索（仅 Chat 会话）**

- **FR-010**: 仅 Chat 会话 MUST 可挂载知识库；Agent 调试台不可挂载（原 AC-5）。
- **FR-011**: 可挂载范围 MUST 为状态「可用」的以下知识库（定义处以 spec 005 FR-049 为准）：公共目录中——①用户持有知识库 Consumer 及以上有效权限的库；②用户为该库创建者且享有知识库创建角色内含读取语义的库（spec 005 FR-013c）；③可见范围为「公开可用」的库（全体登录用户隐含 Consumer 读取语义，spec 005 FR-011）；以及当前用户本人创建且状态「可用」的我的目录知识库；草稿与已停用的库不出现在挂载列表（原 AC-6；知识库角色申请与生效语义见 spec 005 FR-059/FR-060；2026-09-21 按 spec 005 FR-049 口径补齐裁定）。
- **FR-012**: 挂载面板 MUST 支持按目录树浏览、按名称搜索、按知识库多选、按文档单选；单会话挂载知识库数上限 5 个，超限阻断并提示「超过知识库挂载上限，建议减少选择的知识库」（原 AC-7）。
- **FR-013**: 检索归并口径 MUST 为：每个挂载知识库各取相似度最高的前 5 条切片，跨库按相似度归并后取前 10 条，按切片去重（原 AC-8b；去重粒度对齐 PRD §9.10 审定基线）。
- **FR-014**: 回答末尾 MUST 展示引用来源标签；展开「回答依据」后，每条命中切片 MUST 展示具体 Chunk 正文、排序位次、相似度分值、所属知识库与来源文档，并可打开原文（原 AC-8；2026-09-21 用户裁定）。
- **FR-015**: 命中的图片/插图/图表类证据 MUST 在回答中内嵌渲染并标注来源文档（原 AC-9）。
- **FR-016**: 知识库检索 MUST 不设会话级快照：检索行为由检索时刻的知识库状态与权限决定——库被停用或软删除后立即不可检索、回「草稿」后无可检索内容、权限被回收后检索即被拒绝；进行中的会话与新会话一视同仁。既有契约中的 `snapshotAt` 字段仅作兼容保留，不作为检索授权、知识库状态或可检索范围的判断依据；P0 可返回空值或挂载记录时间（原 AC-10；关联 watchlist #31）。

**Agent 调试台**

- **FR-017**: 持有资产有效订阅的用户，以及该资产的 Owner / Deputy，MUST 可经资产详情页「去使用」或对话工作台的资产 Agent 选择器进入该资产的 Agent 调试台；Owner / Deputy 无需订阅即可进入，但发起调用仍要求当前用户个人凭据可用。平台网关代理透传，护栏、凭据解析、审计在网关执行（原 AC-11；2026-09-21 用户裁定）。
- **FR-018**: Agent 调试台中 Chat MUST 不在场、不可挂载知识库；页面 MUST 展示当前 Agent 的基础信息（原 AC-12）。
- **FR-019**: Agent 调试台页面 MUST 固定绑定单一资产，进入时确定、不可中途变更；通过选择器切换资产即进入该资产的独立调试台页面，MUST NOT 带入其他资产的调试内容。调试记录 MUST NOT 在用户侧持久化：不进入历史会话列表，不适用 90 天留存、500 上限、搜索、筛选、删除等会话管理规则（FR-028~FR-032 仅适用 Chat 会话），页面刷新或离开后调试内容不可恢复；平台侧合规留存与审计日志口径不变（原 AC-12b；2026-09-21 用户裁定）。
- **FR-019b**: Agent 调试台 MUST 只读展示该资产发布时拉取并固化的 **Agent Card 原始 JSON** 及基础信息；MUST NOT 提供编辑入口；MUST NOT 展示完整在架接入配置 JSON、鉴权元数据、凭据明文、Health Check 地址与探测详情、护栏策略模板细节（2026-09-21 用户裁定）。
- **FR-019c**: Agent 调试台 MUST 提供 JSON 编辑器，用户可填写或粘贴 JSON 请求体并发起调用；调用完成后 MUST 在右侧展示资产返回的原始 JSON 响应。请求与响应 MUST NOT 按 Chat 消息样式渲染（2026-09-21 用户裁定）。
- **FR-019d**: Agent Card 原始 JSON MUST 取当前在架版本所固化的能力声明；进入调试台时读取一次，页面驻留期间不要求实时刷新，重新进入时重新读取。具体接口投影、字段脱敏与订阅者可见范围在 plan / 契约阶段确认（2026-09-21 用户裁定）。
- **FR-020**: Agent 调试台调用 MUST 为平台内资产调用：平台以**当前用户的个人凭据**发起调用（2026-08-24 凭据模型裁定——旧资产凭据模型取消，见 spec 007 FR-030），并传递当前用户身份上下文（供资产内部处理用户级数据权限）（原 AC-13）。
- **FR-021**: 平台网关 MUST 在每轮调试请求中携带当前 JSON 请求与平台侧会话 ID；多轮上下文由资产自行维护，平台不向资产透传历史消息（对齐 A2A 协议的 contextId 模型；原 AC-13b）。平台侧会话 ID 的生命周期 MUST 为：每次进入 Agent 调试台时生成新 ID，页面刷新、离开或切换资产即失效并新建（2026-09-21 裁定）。
- **FR-022**: Agent 调试台 MUST NOT 要求资产支持流式输出：资产以普通请求-响应即可接入，准入门控不含流式能力校验。上游资产提供非流式响应时，平台 MUST 缓冲完整响应并完成全文检测后在右侧展示原始 JSON 响应；提供流式响应时，平台 MUST 采用 FR-023 的重叠滑动窗口检测（原 AC-13c；2026-08-24 用户裁定采纳机制基线并修正非流式直出）。

**流式输出与护栏**

- **FR-023**: 输出侧护栏 MUST 按上游响应形态执行：流式响应采用重叠滑动窗口检测，每个窗口通过后才释放其可下发内容；任一窗口命中时，MUST 立即终止上游生成与后续输出、**瞬时撤回全部已下发内容（含此前已通过窗口的前缀）**，原位展示「该回答因命中安全护栏已被撤回」（含命中的护栏类型）——终态全文零字留存，命中轮次的回答不落库，历史回看中该轮显示同一占位文案（仅适用 Chat 会话，Agent 调试台无历史回看）。非流式响应采用全文缓冲检测，通过后直接完整呈现（不假流式），命中则全文不呈现并展示同一提醒。窗口参数与检测引擎选型 MUST 不在 spec 定义（挂 watchlist #1/#50 留 plan 阶段）（原 AC-14；2026-08-24 用户裁定——机制采纳 Zhang 基线、命中语义坚持全文零字留存；处置语义与 spec 006 FR-042/FR-043 一致）。
- **FR-024**: 输入侧护栏命中 MUST 直接拦截并拒答，响应回传命中的护栏类型，页面展示命中类型与处置结果（与输出侧提示一致）；临时文件内容视同用户输入、随 P1 上传功能生效（原 AC-14b）。
- **FR-025**: 中止生成时 MUST 停止读取上游后续内容；对尚未释放的已生成内容按当前路径完成检测（流式完成当前窗口、非流式完成已有内容）；检测未通过 MUST 按 FR-023 命中规则处置（撤回全部已下发内容并展示占位提醒），通过则可保留已下发部分（原 AC-15；2026-08-24 用户裁定口径）。
- **FR-026**: 回答生成期间 MUST 禁用发送入口并提示「正在生成中」；用户可经「停止生成」主动中止后立即发送；新消息不自动中止当前生成；Chat 会话与 Agent 调试台行为一致（原 AC-15b）。
- **FR-027**: 护栏命中时页面 MUST 展示命中的护栏类型与处置结果（原 AC-16）。

**回答渲染**

- **FR-027b**: 回答中的结构化内容 MUST 基于 Markdown 及扩展语法渲染（2026-08-25 用户裁定）：表格支持横向滑动查看；代码块支持语法高亮、行号与一键复制；Mermaid 流程图与数学公式经 Markdown 扩展插件渲染。
- **FR-027c**: 流式输出过程 MUST 控制内容渲染刷新频率以避免屏幕闪烁，且 MUST NOT 强制滚动跟随最新输出（不打断用户阅读已生成部分）；长回答 MUST 支持分段或折叠展示（2026-08-25 用户裁定；刷新频率值与分段阈值为前端实现参数，不进 spec）。

**历史会话（仅 Chat 会话）**

- **FR-028**: Chat 会话 MUST 服务端持久化 90 天（自最后一条消息起算）；单用户会话数上限 500 个；支持按会话标题与首条提问搜索、打开恢复、删除、新建（原 AC-22；2026-09-21 收窄——Agent 调试台调试记录不适用；原「按 Agent 筛选」随会话列表仅含 Chat 会话移除）。
- **FR-029**: 会话数达上限时 MUST 禁用「新建会话」入口并提示已达上限，引导用户删除旧会话后恢复；平台不自动清理任何会话（原 AC-22b）。
- **FR-030**: 会话标题 MUST 在首轮问答完成后由模型生成摘要标题，标题生成应使用快速小模型（考虑响应速度）；生成失败时兜底取首条提问截断；支持手动重命名，重命名后不再被自动覆盖（原 AC-22c）。
- **FR-031**: 会话删除 MUST 为软删除：用户侧立即不可见且不可恢复；脱敏/敏感字段遮蔽后的对话内容按 PRD §9.8 继续留存至 90 天期满（自最后一条消息起算）再清除；删除不影响审计日志 3 年留存（原 AC-22d；若合规裁定收窄为只留元数据，语义不变、留存范围随动）。
- **FR-032**: 三类失效场景（资产已下架、订阅失效（用户退订或被 Owner 取消）、出站调用被平台停用）下，Agent 调试台 MUST 拒绝新调用并按原因展示对应文案；个人凭据不可用时的阻断与引导见 FR-035（原 AC-23；2026-09-21 用户裁定——调试记录用户侧不持久化，原「历史会话只读回看」口径对资产会话失效）。

**我的资产抽屉与不可用提示**

- **FR-033**: 「我的资产」抽屉 MUST 分已订阅与收藏两区：已订阅区默认按最近使用时间倒序（无使用记录按订阅时间），收藏区默认按收藏时间倒序，两区均可切换按名称排序；点击语义为已订阅 Agent 进 Agent 调试台、MCP 与未订阅资产进详情页（原 AC-24）。
- **FR-034**: 已下架资产条目 MUST 置灰不可进入 Agent 调试台（原 AC-25）。
- **FR-034a**: 已删除资产 MUST 从「我的资产」抽屉、详情入口及 Agent 调试台入口完全移除；删除终态 MUST NOT 复用已下架资产的置灰可见语义（2026-09-21 用户裁定）。
- **FR-035**: 资产或当前用户个人凭据不可用提示 MUST 覆盖四类文案：已被下架、出站调用已被平台停用、个人凭据不可用、服务暂时不可用（附资产名称与负责人）。个人凭据不可用时，静态凭据未配置或失效 MUST 提供「前往配置凭据」入口；动态凭据颁发中或颁发失败 MUST 展示对应状态与处理指引；MUST NOT 回退到平台或共享身份（原 AC-26；2026-09-21 用户裁定）。
- **FR-036**: Chat 侧生成失败（模型服务或检索服务失败、网络中断等）MUST 展示明确错误提示与重试入口；失败轮次的回答不写入会话历史，用户消息保留可直接重发（原 AC-26b）。

### Key Entities

- **首触指引（First-Run Guidance）**: 空 Chat 会话中的用户体验对象。关键属性：助手欢迎文案、能力边界说明、starter 入口（文本/知识库/图像）、用户显示名（可为空并回退通用称呼）。生命周期仅覆盖空会话状态；不是 Turn，不参与历史会话、标题生成或用量统计。
- **会话（Session）**: 平台侧持久化的 Chat 对话记录（仅 Chat 会话；2026-09-21 收窄——Agent 调试记录非 Session 实体）。关键属性：对话对象（Chat）、标题（模型生成可重命名）、消息序列、最后消息时刻（90 天留存起算点）、挂载知识库集合（上限 5 库）、软删除标记。单用户上限 500 个。
- **轮次（Turn）**: Chat 会话中的一轮问答。关键属性：用户消息、回答全文、引用证据集合、护栏处置结果（通过/拦截/占位）、生成状态。失败轮次的回答不落库，用户消息保留。
- **调试轮次（Debug Turn）**: Agent 调试台中的一轮调用，**用户侧不持久化**（页面刷新或离开后不可恢复）。关键属性：JSON 请求体、原始 JSON 响应、护栏处置结果、平台侧会话 ID（contextId 承载，多轮上下文由资产自维护；每次进入 Agent 调试台生成，刷新/离开/切换资产即失效并新建）。
- **引用证据（Citation）**: 回答附带的检索证据。关键属性：命中 Chunk 正文、切片排序位次、相似度分值、所属知识库、来源文档；图片/图表类证据内嵌渲染。
- **挂载（Mount）**: Chat 会话与知识库（精确到文档）的关联。不设快照，每次检索按当时状态与权限判定。
- **我的资产条目（Asset Entry）**: 抽屉中的资产条目。关键属性：分区（已订阅/收藏）、最近使用时间、收藏时间、在架状态、出站停用标记。

## 界面与交互细节（2026-09-22 追加，纯增量）

> 注：本节为 2026-09-22 用户指令追加的纯增量内容，不改动本文件任何既有条目——US / FR / SC / Edge Cases / Assumptions / Non-Goals / Open Questions 原文与编号均保持原样；作用是把既有 FR 落到用户可见界面上，便于设计交付与验收对齐。

**条目级别**: 本节条目默认 SHOULD 级；重述既有 MUST 处不改变其效力。

**标记约定**: 「（缺口）」表示对标其他平台对话产品后识别出的缺失细节，「（候选）」表示体验优化备选，「（待确认）」表示需用户裁定后方可转 FR；三者均不属于需求，汇总见「细节缺口汇总」与「体验优化候选」。

**不约束**: 视觉参数（色板、间距、字号、圆角、动效时长、图标库）归设计稿与前端规范，不入 spec。

**参考平台**: 见「其他平台设计参考对照」；仅作样式参考，不构成依赖、不要求像素级对齐，冲突时一律以既有 FR 为准。

### 空会话首触（对齐 US1a / FR-004a~FR-004d）

- **空态布局**: 消息区 SHOULD 为垂直居中的三段式——问候、能力说明、starter 入口组；输入区位置与常规态一致，发送首条消息后不发生布局跳动。
- **问候语**: SHOULD 与界面语言一致，可含用户显示名；显示名缺失时 MUST 回退为通用称呼（FR-004a）。
- **能力说明**: SHOULD 不超过 3 行并与三类入口一一对应；MUST NOT 出现 Agent 调试台、MCP、图像生成、OCR 工作流或音视频表述（FR-004b）。
- **starter 形态**: SHOULD 为 3~4 个卡片式入口（图标加标题加一句副标题），窄屏换行；文本 starter 点击后 MUST 填入输入框并聚焦、不自动发送，知识库与图像 starter MUST 打开对应面板（FR-004c）。
- **starter 可用性**: 卡片点击后 SHOULD 保持可见以支持连续尝试，SHOULD 可键盘 Tab 聚焦、Enter 触发；图标 MUST NOT 作为唯一表意手段，须有文字标签。
- **首触区退出**: 首条真实消息发送成功后，首触区随空态一并消失；是否提供「引导回放 / 常驻帮助入口」为待裁定项（缺口、待确认）。
- **禁止模拟**: MUST NOT 出现「模型正在输入」类占位动画，SHOULD NOT 用打字机效果模拟回答，避免用户误认为已发生模型调用（FR-004d）。

### 对话主界面与输入区（对齐 US1 / FR-004、FR-008、FR-009、FR-027b、FR-027c）

**消息流**

- **角色区分**: SHOULD 沿用主流约定——用户消息右对齐、助手消息左对齐；助手正文 SHOULD 限宽（约 72%~80%）且不加气泡边框（阅读型排版），用户消息用浅色气泡。
- **回答操作行**: 复制与重新生成（FR-008）SHOULD 在回答完成后出现——桌面 hover 显现、触屏常驻；生成中该位置 MUST 显示「停止生成」（FR-025 / FR-026）。
- **首 token 前等待态**: SHOULD 有明确指示（光标或轻量动效加「正在生成…」）；MUST NOT 使用百分比进度条，模型无法给出准确进度（缺口）。
- **时间信息**: SHOULD 按时间分组显示轻量时间信息，MUST NOT 逐条展示完整日期时间造成阅读噪声（缺口）。

**输入区**

- **自适应与快捷键**: 输入框 SHOULD 多行自适应高度（约 1~8 行后内部滚动）；Enter 发送、Shift+Enter 换行（FR-004）。
- **生成中状态**: 输入框左侧为附件（图片）入口、右侧为发送与停止按钮；生成中发送按钮 MUST 变为「停止生成」且保持可点击，输入框可继续编辑但发送禁用并提示「正在生成中」（FR-026）。
- **常驻声明**: 输入区下方 MUST 常驻展示 AI 生成内容免责提示与平台级用户协议链接，且不遮挡输入（FR-009）。
- **输入上限**: 超长输入 SHOULD 有上限并在接近上限时就地提示；口径与数值为参数基线项（缺口、待确认）。
- **草稿保留**: 未发送草稿 SHOULD 在会话内切换、刷新或误关闭后保留（缺口、待确认）。
- **快捷键集**: 停止生成、新建会话、搜索会话等快捷键为候选增强项（候选）。

**渲染与长内容**

- **结构化渲染**: 表格横向滑动、代码块（语法高亮加行号加一键复制）、Mermaid 与数学公式渲染（FR-027b）；复制成功 SHOULD 给出轻量反馈（按钮态变化或 toast）（缺口）。
- **滚动行为**: 流式期间 MUST NOT 强制滚动跟随最新输出（FR-027c）；用户上滚离开底部后 SHOULD 出现「回到最新」浮动按钮（缺口）。
- **长回答折叠**: 超长回答 SHOULD 提供分段或折叠入口，折叠态须有明确展开入口与内容摘要；MUST NOT 自动折叠用户尚未浏览的内容（FR-027c）。

### 思考过程与深度分析（对齐 FR-006、FR-007）

- **开关位置**: 深度分析开关 SHOULD 与模型选择器同区、开关态可辨；开启后思考过程默认展开（FR-006）。
- **思考面板**: 思考过程 SHOULD 为独立可折叠面板，标题含「思考过程」、折叠后保留一行摘要；视觉层级 SHOULD 弱于回答正文，不得与正文混淆（FR-007）。
- **阶段提示**: 生成中 SHOULD 分阶段提示当前动作——「正在深度分析…」到「正在生成回答…」，挂载知识库时另有「正在检索知识库…」（缺口）。
- **耗时展示**: 思考耗时与步骤数展示为候选增强项（候选）。

### 知识库挂载与引用（对齐 US2 / FR-010~FR-016）

**挂载**

- **入口形态**: SHOULD 位于输入区工具条，以「知识库」按钮加已挂载计数（如「知识库 2/5」）呈现并展开为面板。
- **面板能力**: SHOULD 支持目录树浏览、名称搜索、按知识库多选、按文档单选（FR-012）；已选项 SHOULD 在面板顶部以 chips 回显并可在会话内单独移除。
- **范围与上限**: 达 5 个上限时未选项 MUST 禁用并展示 FR-012 定稿文案；可选范围与权限 MUST 严格按 FR-011 与 FR-016，MUST NOT 以置灰占位方式展示不可用或无权限知识库，避免用户误判为已挂载但检索不到。

**引用与回答依据**

- **来源标签**: 回答末尾 MUST 展示引用来源标签（FR-014）；SHOULD 采用正文内联角标加末尾来源列表的双向对应范式（缺口）。
- **依据明细**: 「回答依据」SHOULD 默认折叠，展开后每条命中 MUST 展示具体 Chunk 正文、排序位次、相似度、所属知识库与来源文档，并可打开原文（FR-014）。
- **双向定位**: 角标与来源条目互相定位（点角标跳到对应来源并高亮、来源条目可回跳正文位置）为待裁定增强项（缺口、候选）。
- **相似度格式**: 分值的展示格式（0~1 或百分比、小数位）为待确认项（缺口、待确认）；SHOULD NOT 在分值旁给出「可信 / 不可信」主观结论。
- **图片证据**: 图片、插图与图表类证据 MUST 内嵌渲染并标注来源文档（FR-015）；SHOULD 支持点击放大。
- **零命中呈现**: 知识库零命中时的呈现为待确认项（缺口、待确认）；SHOULD 区分有检索依据与无检索依据（回答由模型通用知识生成）两种形态，避免用户误读为已引用来源。
- **复制含来源**: 复制回答时 SHOULD 保留来源列表为候选增强项（缺口、候选）。

### 图像输入（对齐 FR-009a~FR-009e）

- **录入方式**: 附件入口 SHOULD 支持文件选择、粘贴截图与拖拽；截图是高频路径，粘贴为待确认项（缺口、待确认）。
- **选中呈现**: 选中的图片 SHOULD 以缩略图 chip 附于输入框上方（文件名与尺寸加删除按钮）；达 4 张时 MUST 禁用新增并提示上限。
- **校验时机**: 校验 MUST 在进入 Provider 前完成（FR-009b）；不合规项 SHOULD 就地标错并给出一句话原因（类型不支持 / 单张超 10 MiB / 总计超 20 MiB / Base64 非法），MUST NOT 静默丢弃。
- **拒绝原因**: SVG 与 GIF 被拒绝时 MUST 给出明确原因，MUST NOT 仅依赖文件选择器的类型过滤兜底。
- **参数收纳**: `detail`（默认 `auto`，可选 `low/high`，FR-009c）SHOULD 收纳于高级或模型设置，MUST NOT 出现在首触主路径（待确认）。
- **结果对照**: 图像识别类回答回显所依据的图片缩略图为候选增强项（候选）。
- **无障碍**: 缩略图 MUST 有替代文本，删除操作 MUST 键盘可达。

### 生成中、流式与护栏提示（对齐 US3 / FR-023~FR-027）

- **输出侧命中**: 已下发内容 MUST 瞬时全部消失并原位替换为占位块（弱化底色加图标加「该回答因命中安全护栏已被撤回」加护栏类型）；占位块 MUST NOT 提供展开或回看入口，MUST NOT 残留任何前文痕迹；历史回看中该轮 MUST 显示同一占位文案（FR-023）。
- **输入侧命中**: SHOULD 以会话内系统提示呈现——用户消息保留并紧随一条拦截说明（含护栏类型与处置结果）；MUST NOT 用模态弹窗打断整页（FR-024；缺口）。
- **停止生成**: 停止后已下发部分 SHOULD 标记「已停止生成」；未通过检测 MUST 按命中规则撤回；按钮点击后 MUST 立即恢复可发送态（FR-025 / FR-026）。
- **流式中断**: 已下发一部分后连接中断的呈现为待裁定项（缺口、待确认）——既有条目已定义护栏命中（FR-023）、停止生成（FR-025）与生成失败（FR-036），但未定义流式中断时已下发内容的处置；SHOULD 明确为保留已下发内容并就地标记「生成中断」加重试入口，或整轮不呈现，并与 FR-036 的落库口径保持一致。
- **离开后返回**: 生成期间离开会话再返回时生成是否继续、返回后是否续看结果（缺口、候选、待确认）。
- **长等待反馈**: 多模态请求默认 120 秒超时（FR-009c），等待期 SHOULD 给出可感知反馈，超时后 MUST 按 FR-036 呈现明确结果（缺口、候选）。

### 历史会话列表（对齐 US5 / FR-028~FR-031）

- **列表形态**: SHOULD 位于侧栏或抽屉，按最后消息时间倒序并可按时间分组（今天、昨天、更早）；条目 hover SHOULD 呈现重命名与删除，删除 MUST 二次确认并使用轻量 popconfirm 而非系统原生 confirm。
- **新建入口**: SHOULD 常驻列表顶部；标题生成完成前 SHOULD 以「新会话」等占位呈现，生成后自动替换（FR-030；缺口）。
- **搜索**: SHOULD 位于列表顶部，按会话标题与首条提问命中（FR-028）；无结果 SHOULD 给空态提示，命中词 SHOULD 高亮（缺口）。
- **用量可见性**: 会话数接近上限时 SHOULD 展示用量（如「498/500」）；达上限时 MUST 禁用「新建会话」并展示 FR-029 文案（缺口）。
- **窄屏收敛**: SHOULD 以抽屉形态收起列表，选中会话后自动收起（缺口）。
- **范围自洽**: MUST NOT 把 FR-028~FR-032 的会话管理能力延伸到 Agent 调试台。

### 我的资产抽屉与错误态（对齐 US6 / FR-033~FR-036）

- **抽屉形态**: SHOULD 分已订阅与收藏两区并支持排序切换（FR-033）；条目 SHOULD 以徽标呈现状态（已订阅、收藏、已下架），已下架 MUST 置灰且点击说明原因（FR-034）；已删除资产 MUST NOT 出现在任何入口（FR-034a）。
- **抽屉空态**: SHOULD 给出引导（如前往资产市场探索），MUST NOT 呈现空白面板（缺口）。
- **失败轮次**: SHOULD 就地以错误块呈现——用户消息保留、错误提示与重试按钮（FR-036）；重试 MUST 复用同一用户消息、不重复插入用户气泡。
- **错误文案**: SHOULD 采用现象加原因加可执行动作的结构，并与 FR-035 已定稿文案保持同一口径；是否展示请求 ID 或追踪标识以便支持定位为待确认项（缺口、待确认）。
- **入口阻断**: 资产不可用（FR-032 / FR-035）SHOULD 在入口处即阻断并说明原因，MUST NOT 让用户先进入再失败。

### Agent 调试台（对齐 US4 / FR-017~FR-022）

- **区隔标识**: 顶栏 SHOULD 展示资产图标、名称、「Agent 调试台」标识与平台侧会话 ID（每次进入新建，FR-021）；MUST NOT 出现 Chat 的模型选择器、深度分析开关与知识库挂载，避免用户误认为处于 Chat 会话（FR-005 / FR-018）。
- **布局**: 宽屏 SHOULD 左右分栏——左侧为只读 Agent Card 原始 JSON（可折叠、可复制、语法高亮），右侧为上（JSON 请求编辑器）下（原始 JSON 响应区）；窄屏 SHOULD 纵向堆叠并以请求与响应标签页切换（缺口）。
- **JSON 编辑器**: SHOULD 具备语法高亮、行号、括号匹配、格式化与错误定位；提交前 MUST 完成 JSON 合法性校验，非法时 MUST 阻断且不发起调用（FR-019c；缺口）。
- **响应区**: SHOULD 只读、可折叠、可复制全文，并提供 Pretty 与 Raw 切换与单字段复制（缺口）；超长响应 SHOULD 默认折叠（缺口）。
- **只读脱敏**: 被排除字段 MUST 整体不渲染，MUST NOT 以星号掩码或「已隐藏」等占位暴露字段名（FR-019b）。
- **轮次操作**: MUST 提供复制原始 JSON 与重新生成；MUST NOT 提供点赞、点踩或追问建议等 Chat 型操作（FR-019c 裁定）。
- **空态**: SHOULD 给出「粘贴或填写 JSON 请求后提交」引导与可一键填入的示例请求骨架；请求编辑器 SHOULD 默认携带上一轮请求以便迭代修改（缺口、候选）。
- **同页多轮**: 同页多轮结果采用逐轮堆叠保留还是仅最新一轮替换为待确认项（缺口、待确认）——既有条目已定义多轮上下文由资产维护（FR-021）与调试记录用户侧不持久化（FR-019），建议明确为逐轮堆叠（含轮次序号、请求摘要与响应折叠），刷新后整体丢失。
- **调用中状态**: SHOULD 有等待态与「已用时」提示，超时与失败 MUST 按 FR-036 口径呈现（缺口）。

### 跨页通则

- **四态齐备**: 每个可交互面 SHOULD 覆盖加载、空、错误与禁用四态；禁用态 SHOULD 就近说明原因（文案或 tooltip）。
- **文案口径**: 已定稿文案（FR-012 挂载超限、FR-023 撤回提醒）MUST 原样使用；其余文案 SHOULD 采用现象加原因加可执行动作的结构（例：「图片超过 10 MiB，请压缩后重试」）。
- **一致性**: Chat 与 Agent 调试台 SHOULD 共用同一套基础视觉语言与基础组件（按钮、输入、空态、toast），交互集按各自定位区分（调试台无 Chat 型操作）。
- **无障碍**: 键盘可达、焦点可见、图标配文字替代；流式输出的助手消息 SHOULD 提供对屏幕阅读器友好的播报方式（如节流的 live region），MUST NOT 逐字播报（缺口）。
- **国际化**: spec 只约束语义与状态，不固定界面文案措辞（已定稿文案除外）；日期与数字格式 SHOULD 随界面语言（缺口、待确认）。
- **响应式**: SHOULD 定义窄屏与移动端的布局收敛规则（侧栏收纳、分栏堆叠、输入区安全区）；本 spec 约束收敛行为，不约束具体断点值（缺口）。
- **深色模式**: 为待确认候选（候选、待确认）。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户登录后无需任何前置配置即可与 Chat 发起首轮对话（US-1）。
- **SC-002**: 输入侧护栏命中的消息 100% 被拦截拒答，且 100% 展示命中的护栏类型与处置结果。
- **SC-003**: 输出侧护栏命中的回答终态 0 字留存：非流式命中 0 字呈现；流式命中时命中窗口及其后 0 字下发、此前已下发的前缀 100% 被瞬时撤回，且 100% 展示护栏命中提醒（含护栏类型）、命中轮次 0 落库（2026-08-24 用户裁定口径）。
- **SC-004**: 知识库状态或权限变更后，自下一轮检索起 100% 按最新状态判定，无快照残留（含进行中会话）。
- **SC-005**: 会话数达 500 上限时新建入口 100% 被阻断并提示；不发生任何静默自动清理。
- **SC-006**: 五类资产、订阅或个人凭据不可用场景（已下架/订阅失效/出站停用/个人凭据不可用/服务不可用）100% 展示对应文案；个人凭据不可用时，静态凭据 100% 提供「前往配置凭据」入口，动态凭据 100% 展示对应状态与处理指引，且 0 次回退到平台或共享身份；服务不可用文案附资产名称与负责人。
- **SC-007**: 挂载知识库的问答 100% 附带引用来源信息（具体命中 Chunk 正文、排序位次、相似度、所属知识库、来源文档），可从证据打开原文。
- **SC-008**: 生成失败轮次的回答 0 落库，对应用户消息 100% 保留并可直接重发（适用 Chat 会话；Agent 调试台轮次本不落库）。
- **SC-009**: 删除 Chat 会话后用户侧 100% 不可见且不可恢复；留存与审计口径符合 PRD §9.8。
- **SC-010**: 合法图像输入（Base64 JPEG/PNG/WebP、≤4 张、10 MiB/张、20 MiB 总量）100% 被接受并按 data URI 路径序列化；SVG/GIF、超限或非法 Base64 100% 在进入 Provider 前被拒绝。
- **SC-011**: 图像输入接入后，纯文本调用兼容率 100%；流式输出与既有 tool-calling 承载语义 0 回归。
- **SC-012**: Agent 调试台 100% 只读展示当前在架版本固化的 Agent Card 原始 JSON 与基础信息；用户可 100% 通过 JSON 编辑器提交请求，并在右侧查看原始 JSON 响应；调试记录 0 进入历史会话列表，刷新后 0 可恢复（2026-09-21 用户裁定口径；取值口径见 FR-019d）。
- **SC-013**: 已删除资产 100% 从「我的资产」抽屉、详情入口及 Agent 调试台入口移除；已下架资产与已删除资产的展示语义 0 混淆。
- **SC-014**: 新建空 Chat 会话 100% 展示助手欢迎卡片与至少 3 个 starter 入口；welcome 与 starter 在用户确认前 0 次模型/真实资产调用、0 Turn、0 次进入历史会话、0 次参与标题生成（2026-09-21 首触裁定）。
- **SC-015**: starter 引导 100% 只覆盖当前 P0 能力，且经 starter 发起的最终请求 100% 进入与手工输入一致的权限与护栏链；新建空会话默认模型 100% 为 vision-capable。

## Non-Goals / Boundaries

- **个性化首触推荐与模型生成开场白**：当前首触区使用可审核模板与固定 starter 集合；不基于历史会话或由模型实时生成开场白，不产生真实模型调用 Turn（2026-09-21 用户裁定）。
- **Agent 调试台不是完整 chat**：不提供历史会话管理、会话标题、搜索/筛选/删除等会话生命周期能力；不提供模型选择器、深度分析开关、知识库挂载、普通文本输入或动态表单（2026-09-21 用户裁定）。
- **临时文件上传**（P1）：文件参与当前会话、不入知识库、会话结束即失效；文件内容视同用户输入纳入输入侧护栏（检测时机随 §13.10 第 6 项 P1 展开）。
- **图像生成 / OCR 工作流 / 音频视频**：不在当前 Chat 多模态范围内；当前只支持图像输入、文本输出。
- **外部 URL 拉图 / 图片持久化 / 压缩转换**：不在当前 Chat 多模态范围内；文件生命周期由业务或文件服务负责。
- **建议追问**（P1）：回答下方追问建议，点击即发送。
- **对话记忆**（P1）：用户偏好记录与应用，含总开关与按 Agent 筛选查看。
- **引用阅读面板**（P1）：选中引用后侧栏联动展示关联文档。
- **P0 中 MCP 资产不是对话对象**：对话工作台内不可调用 MCP 资产；MCP 资产消费方式为资产 Agent 服务端自行接入或外部系统经 PAT 调用；P1 预留 Chat 调用已订阅 MCP 资产工具的能力。
- **平台原生工具仅作知识库外部导入通道**：不属于 P0 对话能力，也不属于 P1 MCP 资产调用预留范围（导入语义见 spec 005，维护语义见 spec 008）。
