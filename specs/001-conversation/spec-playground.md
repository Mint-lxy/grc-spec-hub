## 背景与目标

提供统一的对话入口。默认对话对象是平台 Chat agent-runtime（界面展示名 Chat）——平台自有的知识问答智能体，**当前交付范围支持文本输入，以及 Base64 图像输入 + 文本输出的图像识别能力**；仍可挂载知识库检索（带引用证据与图片/插图）。当前范围不含图像生成、OCR 工作流、音频/视频；P0 不调用平台原生工具（平台原生 MCP），也不调用已上架资产。用户订阅资产 Agent 后可经详情页「去使用」或对话工作台的资产 Agent 选择器进入该资产的**实验台**——实验台不是完整 chat：页面只读呈现该资产的能力声明（输入输出结构）与关键接入参数，试验区可发起多轮调用（平台网关代理透传），每轮实验可查看输入与输出（渲染消息 + 可展开原始报文）；实验记录用户侧不持久化、不可挂载知识库。P1 预留 Chat 调用已订阅 MCP 资产工具的能力，但不进入当前对话工作台闭环。一切经平台流转的对话统一经过平台网关的护栏检测。

## Clarifications

### Session 2026-09-21（实验台定位裁定）

- Q: 资产 Agent 会话的产品形态？ → A: 定位为**实验台而非完整 chat**——页面只读呈现资产参数，试验区可发起调用并查看每轮输入与输出；US4 与 FR-017~022 同步改写（用户指令裁定）。
- Q: 实验记录持久化？ → A: 用户侧**不持久化**——不进入历史会话列表，不适用 90 天留存、500 上限、搜索、筛选、删除等会话管理规则，页面刷新或离开后实验内容不可恢复；平台侧合规留存与审计日志口径不变（护栏与审计在网关执行）（用户裁定）。
- Q: 实验台展示的「参数」范围？ → A: 能力声明的**输入输出结构**（以 spec 003 FR-010 的 Agent Card 拉取只读镜像为信息源）+ 关键接入参数（协议、超时/重试）；不提供编辑入口；鉴权元数据与护栏策略模板细节不向实验台展示（用户裁定）。
- Q: 输入输出可视的粒度？ → A: 渲染后的消息 + 可展开的**平台发往资产的请求原始报文**与**资产返回的响应原始报文**两级（用户裁定）。
- Q: 多轮上下文是否保留？ → A: 保留——FR-021 的 contextId 模型不变，实验台支持多轮调试，多轮上下文仍由资产自行维护（用户裁定）。
- Q: 实验台平台侧会话 ID（contextId 承载）的生命周期？ → A: **每次进入实验台生成新的平台侧会话 ID**，页面刷新、离开或切换资产即失效并新建——与用户侧不持久化自洽：刷新后用户已看不到历史轮次，延续 contextId 会让资产在用户不可见的上下文上续跑（2026-09-21 裁定，FR-021 与 Bench Turn 实体同步）。
- Q: 实验台的回答操作（复制/重新生成）语义？ → A: 提供复制全文与重新生成；**重新生成＝以同一输入重新调用资产并替换本轮输出**——与 Chat 的替换语义一致，避免两套交互；实验台无知识库检索语义，仅重跑资产调用（2026-09-21 裁定，US4 场景 5b 同步）。
- Q: PRD 层偏离（J1「切换到专属透传会话」、M1-14/US-14「会话内容是用户自己的数据」均按 chat 会话表述）如何处理？ → A: 以本次实验台定位裁定为准，两处 PRD 表述登记为**待订正偏离**（建议另行登记 watchlist/PRD 订正项），不构成 spec 阻塞（2026-09-21 裁定）。
- Q: 实验台轮次是否纳入 PRD §9.8 的 90 天脱敏留存？ → A: **挂起待合规/BA 正式裁定**——FR-019 维持「平台侧合规留存与审计日志口径不变」的现有表述，Open Question 保留，裁定后回写（2026-09-21 用户裁定挂起）。
- Q: 实验台展示的这些参数到底怎么取？ → A: **新增 FR-019d 作字段级声明**——信息源唯一为管理服务资产详情只读接口（`getMarketplaceAsset`）；版本类字段（协议、服务地址、能力声明）取**当前在架版本**，热改类字段（超时、重试）取**当前即时生效值**；进入实验台时读取一次，MUST NOT 取未发布修订、草稿数据或本地缓存；鉴权元数据、凭据明文、Health Check 地址与护栏模板细节不展示（2026-09-21 用户指令裁定）。
- 连带修订：历史会话管理（US5、FR-028~FR-032）收窄为**仅适用 Chat 会话**；FR-032 的「失效场景只读回看」对资产会话失效，改为实验台拒绝新调用并按原因展示对应文案；FR-028 的「按 Agent 筛选」随会话列表仅含 Chat 会话而移除；原「透传会话与 Chat 会话适用同一套持久化与管理规则」（2026-08-21 裁定）**superseded**。

### Session 2026-09-15

- Q: Chat 多模态当前到底支持什么？ → A: **提升为当前交付范围**，但只支持图像识别：输入可含 Base64 图片，输出仍是文本；不做图像生成、不做 OCR 工作流、不做音视频；SDK 不负责文件存储/检索/压缩/转换（用户批准）。
- Q: 图像输入的格式与限制？ → A: **仅 Base64**；首版仅接受 JPEG/PNG/WebP；单次最多 4 张、单张解码后最大 10 MiB、总计最大 20 MiB；默认 `detail=auto`，可选 `low/high`；拒绝 SVG/GIF；多模态请求默认超时 120 秒且可配置（用户批准）。
- Q: Chat 选模型/选凭据与旧“自动平台兜底横幅”还成立吗？ → A: **不再以 SDK 自动选个人凭据/自动回落平台凭据为现行口径**。业务层/调用方先决定模型与 `credentialId`，SDK 只负责统一调用；若模型不支持 vision，由 Provider 4xx 直接返回；2026-08-23 的“自动兜底横幅”口径转为历史 superseded 记录（用户批准）。
- Q: Chat 图像输入与 parser 的 `MULTIMODAL` 概念冲突怎么处理？ → A: **vision-capable chat model 走 ChatPort；文档解析继续是 `DOCUMENT_PARSE`**。历史 `MULTIMODAL -> parser` 映射保留一版 deprecated 兼容，再于 1.0 移除；现有 Postman 文件只证明 GPT-5.5 文本接口 / API version，不证明图像兼容，需补真实 Nexus Base64 图片 PoC（用户批准）。

### Session 2026-08-21

- Q: 单会话可挂载知识库数上限？ → A: 5 个（PRD §9.10 参数基线审定——用户确认）。
- Q: 多库挂载时检索结果如何归并？ → A: 每个挂载知识库各取相似度最高的前 5 条切片；跨库按相似度归并后取前 10 条，按切片去重（PRD §9.10 参数基线审定——用户确认）。
- Q: 会话与对话对象的绑定关系？ → A: Chat 会话固定绑定 Chat；资产 Agent 的实验台页面固定绑定单一资产（2026-09-21 实验台定位裁定修正——原「会话固定绑定唯一对话对象、透传会话与 Chat 会话适用同一套持久化与管理规则」口径 superseded）。
- Q: 输入侧护栏命中的处置？ → A: 直接拦截并拒答，响应回传命中的护栏类型，页面展示命中类型与处置结果（与输出侧提示一致）；临时文件内容视同用户输入、随 P1 上传功能生效（PRD §9.5——用户确认）。
- Q: 模型选择与深度分析开关在资产侧是否提供？ → A: 不提供——仅 Chat 会话提供模型选择器与深度分析开关；实验台不提供，资产 Agent 的模型由资产自身决定，会话能力以资产返回为准（PRD §7 M1-2、旅程 J1——用户确认）。
- Q: 「重新生成」的语义与旧回答去向？ → A: 按当前知识库状态重新检索并重跑模型，旧回答被直接替换、不保留历史版本（与无快照语义自洽——用户裁定）。
- Q: 单用户会话数上限与达上限后的处置？ → A: 上限 500 个（PRD §9.10 参数基线审定）；达上限时「新建会话」入口禁用并提示已达上限，引导用户删除旧会话后恢复；不自动清理任何会话（会话是用户工作记录，静默清理造成无感知数据丢失——用户裁定）。
- Q: 会话标题如何生成？ → A: 首轮问答完成后由模型生成摘要标题；生成失败时兜底取首条提问截断；支持手动重命名，重命名后不再被自动覆盖（用户裁定）。
- Q: 我的资产抽屉两区的默认排序？ → A: 已订阅区按最近使用时间倒序（无使用记录按订阅时间），收藏区按收藏时间倒序；两区均可切换按名称排序（PRD §7 M1-15——用户确认）。
- Q: Chat 侧生成失败（模型/检索/网络）时失败轮次是否落库？ → A: 展示明确错误提示与重试入口；失败轮次的回答不写入会话历史，用户消息保留可直接重发（失败回答无消费价值，落库会污染历史与上下文——用户裁定）。

### Session 2026-08-22

- Q: 透传会话的多轮上下文谁维护？ → A: 平台网关在每轮透传请求中携带当前消息与平台侧会话 ID，多轮上下文由资产自行维护，平台不向资产透传历史消息（对齐 A2A 协议的 `contextId` 模型；避免每轮向资产全量暴露用户对话历史——用户裁定；2026-09-21 实验台定位裁定确认保留）。

- Q: 透传会话是否要求资产支持流式输出？ → A: 不要求——平台缓冲资产完整响应，经输出侧护栏检测通过后直接完整呈现；资产以普通请求-响应即可接入，准入门控不含流式能力校验（2026-08-24 输出侧护栏机制修订取代原按段回放口径）。
- Q: 用户删除会话后对话原文的去向？ → A: 软删除——用户侧立即不可见且不可恢复；脱敏/敏感字段遮蔽后的对话内容按 PRD §9.8 继续留存至 90 天期满（自最后一条消息起算）再清除，删除不影响审计日志 3 年留存（与资产/知识库软删除终态模式一致；若合规裁定收窄为只留元数据，语义不变、留存范围随动——用户裁定）。

## User Scenarios & Testing

### User Story 1 — 与 Chat 的基础对话与图像识别 (Priority: P1)

普通用户登录后直接进入对话工作台，默认与平台 Chat agent-runtime（Chat）对话：欢迎页/消息流主界面、模型选择、深度分析开关、思考过程展示、复制与重新生成、常驻免责声明，以及**图像输入、文本输出**的首版识别能力。

**Why this priority**: Chat 是平台的默认对话对象与第一触点；图像识别已升级为当前交付范围的一部分，无此则当前版本的多模态 Chat 不成立。

**Independent Test**: 不选择任何资产发起纯文本与图像对话，验证主界面两种形态、模型下拉仅含对话类与多模态类、图像类型/数量/大小限制、深度分析与思考过程、复制/重新生成与免责声明均符合规格；纯文本调用保持兼容。

**Acceptance Scenarios**:

1. **Given** 用户进入对话工作台且未选择资产, **When** 发起对话, **Then** 对话对象为 Chat——Chat 不是资产，不上架、不可订阅、无 Owner、恒可用。
2. **Given** Chat 会话, **When** 使用其能力, **Then** P0 仅可使用模型对话与挂载知识库检索两项；Chat 不调用平台原生工具（平台原生 MCP），不调用已上架资产；既有接口中的工具调用承载仅作兼容保留并为 P1 Chat 调用已订阅 MCP 资产工具能力预留。
3. **Given** 新会话无消息, **When** 打开对话页, **Then** 展示欢迎页与输入框；有消息时展示消息流与底部固定输入区；Enter 发送、Shift+Enter 换行。
4. **Given** Chat 会话, **When** 打开模型选择下拉, **Then** 仅展示对话类与多模态类模型（向量化模型与重排序模型不出现）；Chat 绑定平台默认护栏策略模板，提示词与实现随平台部署定义、P0 无配置入口。
5. **Given** Chat 会话, **When** 开启深度分析, **Then** 模型执行更多推理步骤，思考过程默认展开，以可折叠的有序步骤列表展示。
6. **Given** Chat 会话附带图片输入, **When** 用户提交请求, **Then** 仅接受 Base64 编码的 JPEG/PNG/WebP；单次最多 4 张，单张解码后 ≤ 10 MiB，总计 ≤ 20 MiB；`detail` 默认 `auto`，可选 `low/high`；系统内部按 OpenAI-compatible content parts + data URI 序列化，回答仍为文本。
7. **Given** Chat 会话附带图片输入, **When** 图片为 SVG/GIF、超过数量/大小上限、或 Base64 不合法, **Then** 请求在进入 Provider 前被拒绝，并返回明确错误提示；系统不负责外部 URL 抓取、文件存储、压缩或格式转换。
8. **Given** 一条已生成的回答, **When** 用户点击重新生成, **Then** 系统按当前知识库状态重新检索并重跑模型，旧回答被直接替换、不保留历史版本；复制全文随时可用。
9. **Given** 任意会话页, **When** 查看输入区下方, **Then** 常驻展示 AI 生成内容免责提示与平台级用户协议链接。

### User Story 2 — 知识库挂载与检索 (Priority: P1)

普通用户在 Chat 会话中挂载有权限且「可用」的知识库（可精确到单文档），提问后获得带引用来源与检索证据的回答，图片与图表类证据内嵌渲染。

**Why this priority**: 知识库检索是 Chat 区别于裸模型的唯一能力，是平台知识价值的出口。

**Independent Test**: 在 Chat 会话挂载一个「可用」知识库并提问，验证可选范围、挂载上限、归并口径、引用证据与内嵌渲染；中途停用该库，验证下一轮检索立即失效。

**Acceptance Scenarios**:

1. **Given** Chat 会话, **When** 打开知识库挂载面板, **Then** 可按目录树浏览、按名称搜索、按知识库多选、按文档单选；可选范围为状态「可用」的以下知识库（以 spec 005 FR-049 为定义处）：公共目录中——①用户持有知识库 Consumer 及以上有效权限的库；②用户为该库创建者且享有知识库创建角色内含读取语义的库；③可见范围为「公开可用」的库（全体登录用户隐含 Consumer 读取语义）；以及当前用户本人创建且状态「可用」的我的目录知识库；草稿与已停用的库不出现。
2. **Given** Chat 会话已挂载 5 个知识库, **When** 尝试挂载第 6 个, **Then** 被阻断并提示「超过知识库挂载上限，建议减少选择的知识库」。
3. **Given** 会话挂载了多个知识库, **When** 用户提问, **Then** 检索归并口径为：每个挂载知识库各取相似度最高的前 5 条切片，跨库按相似度归并后取前 10 条，按切片去重。
4. **Given** 回答已生成, **When** 查看回答末尾, **Then** 展示引用来源标签；展开可见命中切片的排序位次、相似度分值、所属知识库与来源文档，可打开原文；命中的图片/插图/图表类证据内嵌渲染并标注来源文档。
5. **Given** 会话挂载的知识库被停用、被软删除、回「草稿」或用户权限被回收, **When** 发起下一轮检索, **Then** 按检索时刻的知识库状态与权限判定——立即不可检索/无内容/被拒绝；进行中的会话与新会话一视同仁，不设会话级快照。
6. **Given** 资产 Agent 实验台, **When** 查看页面, **Then** 不提供知识库挂载能力。

### User Story 3 — 流式输出与护栏 (Priority: P1)

Chat 会话与实验台统一经过输出侧护栏：上游流式响应采用重叠滑动窗口检测，非流式响应采用全文缓冲检测并在通过后直接完整呈现；输入侧命中直接拒答；可随时中止生成；护栏命中展示类型与处置结果。

**Why this priority**: 护栏是平台安全基线的运行时执行点（宪法级约束），流式回放与中止决定对话可用体感。

**Independent Test**: 分别构造输入命中、输出命中、中止生成三种场景，验证拦截/占位/回放行为与提示文案。

**Acceptance Scenarios**:

1. **Given** 用户发送的消息命中输入侧护栏, **When** 提交, **Then** 直接拦截并拒答，响应回传命中的护栏类型，页面展示命中类型与处置结果（与输出侧提示一致）。
2. **Given** 上游提供流式响应, **When** 输出内容持续到达, **Then** 平台按重叠滑动窗口执行输出侧护栏检测，窗口通过才释放其可下发内容；任一窗口命中时立即终止上游、瞬时撤回全部已下发内容（含已通过窗口的前缀）并原位展示「该回答因命中安全护栏已被撤回」（含护栏类型）——终态零字留存、命中轮次不落库（2026-08-24 用户裁定）。
3. **Given** 上游仅提供非流式响应, **When** 完整回答返回, **Then** 平台缓冲全文并执行输出侧护栏检测，通过后直接完整呈现（不假流式）；命中则全文不呈现并展示同一提醒。
3b. **Given** 回答正在生成或回放, **When** 用户点击停止生成, **Then** 平台停止读取后续内容，未释放的已生成内容按当前路径完成检测；未通过按命中规则处置，通过则可保留已下发部分。
4. **Given** 回答生成期间, **When** 用户尝试发送新消息, **Then** 发送入口禁用并提示「正在生成中」；新消息不自动中止当前生成；用户可主动「停止生成」后立即发送；Chat 会话与实验台行为一致。
5. **Given** 护栏命中（输入或输出侧）, **When** 页面展示, **Then** 可见命中的护栏类型与处置结果。

### User Story 4 — 资产 Agent 实验台 (Priority: P2)

用户订阅资产 Agent 后，经详情页「去使用」或对话工作台的资产 Agent 选择器进入该资产的**实验台**：页面顶部展示资产名称，只读呈现该资产的参数（能力声明的输入输出结构 + 关键接入参数），试验区可发起多轮调用（平台网关代理透传，护栏、凭据解析、审计在网关执行），每轮实验可查看输入与输出；Chat 不在场、不可挂载知识库；实验记录用户侧不持久化。

**Why this priority**: 实验台是订阅价值的兑现路径——用户用它验证资产 Agent 的真实行为（看得到参数、看得到输入输出），而非获得一个完整 chat 产品；依赖订阅链路（spec 002）存在，故列为第二优先级切片。

**Independent Test**: 订阅一个已发布 Agent 后经「去使用」进入实验台，完成一轮调用，验证网关透传、身份上下文传递、资产名与参数只读呈现、每轮输入输出可查看、无挂载能力、刷新后实验内容不保留。

**Acceptance Scenarios**:

1. **Given** 用户已订阅某资产 Agent, **When** 经详情页「去使用」或选择器进入, **Then** 进入该资产的实验台，平台网关代理透传（护栏、凭据解析、审计在网关执行）；Chat 不在场、不可挂载知识库；页面顶部展示当前实验的资产名称。
2. **Given** 实验台页面, **When** 查看资产信息区, **Then** 只读展示该资产的参数：能力声明的输入输出结构（以 spec 003 FR-010 的 Agent Card 拉取只读镜像为信息源）与关键接入参数（协议、服务地址、超时/重试）；取值口径（信息源、版本口径、读取时机、脱敏边界）见 FR-019d；不提供编辑入口；不展示鉴权元数据与护栏策略模板细节。
3. **Given** 实验台进行中, **When** 平台发起资产调用, **Then** 使用当前用户的个人凭据发起（2026-08-24 模型裁定），并在请求中传递当前用户身份上下文（供资产内部处理用户级数据权限）。
4. **Given** 实验台多轮调用, **When** 每轮请求发出, **Then** 平台携带当前消息与平台侧会话 ID；多轮上下文由资产自行维护，平台不向资产透传历史消息。
5. **Given** 一轮实验已完成, **When** 查看该轮, **Then** 展示渲染后的输入消息与输出消息，且可展开查看平台发往资产的请求原始报文与资产返回的响应原始报文。
5b. **Given** 一轮实验已完成, **When** 用户操作该轮输出, **Then** 可复制全文；重新生成＝以同一输入重新调用资产并替换本轮输出（与 Chat 替换语义一致；实验台无知识库检索语义，仅重跑资产调用）。
6. **Given** 资产 Agent 仅支持普通请求-响应（非流式）, **When** 回答返回, **Then** 平台缓冲完整响应，经输出侧护栏检测通过后直接完整呈现；准入门控不含流式能力校验。
7. **Given** 实验台页面, **When** 查看交互区, **Then** 不展示模型选择器与深度分析开关（模型由资产自身决定，会话能力以资产返回为准）。
8. **Given** 用户在实验台, **When** 刷新页面、离开或通过选择器切换资产, **Then** 进入该资产的独立实验台页面，不带入其他资产的实验内容；实验记录用户侧不持久化——不进入历史会话列表，页面刷新或离开后实验内容不可恢复（平台侧合规留存与审计日志口径不变）。
9. **Given** 资产已下架、订阅失效（退订或被 Owner 取消）或出站调用被停用, **When** 用户在实验台发起调用, **Then** 调用被拒并按原因展示对应文案（与 FR-035 三类提示一一对应）。

### User Story 5 — 历史会话管理（仅 Chat 会话） (Priority: P2)

Chat 会话服务端持久化 90 天，支持搜索、打开恢复、删除与新建；单用户上限 500 个；会话标题自动生成可重命名；删除为软删除。实验台的实验记录不适用本 story（用户侧不持久化，见 US4/FR-019）。

**Why this priority**: 历史会话是工作记录的留存与复访能力，依赖对话主链路先行。

**Independent Test**: 构造多会话环境，验证 90 天持久化口径、搜索、上限阻断、标题生成与重命名、删除软语义。

**Acceptance Scenarios**:

1. **Given** 用户的 Chat 历史会话, **When** 查看列表, **Then** 会话服务端持久化 90 天（自最后一条消息起算）；支持按会话标题与首条提问搜索、打开恢复、删除、新建。
2. **Given** 用户已有 500 个会话, **When** 尝试新建, **Then** 「新建会话」入口禁用并提示已达上限，引导删除旧会话后恢复；平台不自动清理任何会话。
3. **Given** 新会话完成首轮问答, **When** 生成会话标题, **Then** 由模型生成摘要标题；生成失败时兜底取首条提问截断；用户可手动重命名，重命名后不再被自动覆盖。
4. **Given** 用户删除某会话, **When** 删除生效, **Then** 会话在用户侧立即不可见且不可恢复（软删除）；脱敏/敏感字段遮蔽后的对话内容按 PRD §9.8 留存至 90 天期满再清除，删除不影响审计日志 3 年留存。

### User Story 6 — 我的资产抽屉与不可用提示 (Priority: P2)

对话工作台提供「我的资产」抽屉（已订阅/收藏两区，含排序与点击语义）；资产不可用时按三类原因展示对应文案；Chat 侧生成失败展示错误与重试入口。

**Why this priority**: 抽屉是回到工作的快捷入口，不可用提示是异常体验的底线；均为增强层而非核心链路。

**Independent Test**: 构造已订阅/收藏/已下架/出站停用/服务异常五类资产条目，验证抽屉分区、排序、点击去向、置灰与文案。

**Acceptance Scenarios**:

1. **Given** 用户打开「我的资产」抽屉, **When** 浏览, **Then** 分已订阅与收藏两区；已订阅区默认按最近使用时间倒序（无使用记录按订阅时间），收藏区默认按收藏时间倒序，两区均可切换按名称排序。
2. **Given** 抽屉条目, **When** 点击, **Then** 已订阅的 Agent 直接进入其实验台；MCP 与未订阅资产进入其详情页；已下架资产条目置灰不可进入实验台。
3. **Given** 资产不可用, **When** 用户尝试使用, **Then** 按原因展示三类文案之一：已被下架 / 出站调用已被平台停用 / 服务暂时不可用（附资产名称与负责人）。
4. **Given** Chat 会话中生成失败（模型服务或检索服务失败、网络中断等）, **When** 失败发生, **Then** 展示明确错误提示与重试入口；失败轮次的回答不写入会话历史，用户消息保留可直接重发。

### Edge Cases

- 回答生成期间发送新消息？——发送入口禁用并提示「正在生成中」，可主动中止后立即发送（FR-026）。
- 同一会话挂载的知识库中途被停用或权限被回收？——下一轮检索即不可检索/被拒绝，无会话级快照（FR-016）。
- 资产 Agent 服务超时或返回错误？——经配置的重试后仍失败时提示「该资产服务暂时不可用」并展示资产名称与负责人（FR-035）。
- 图像输入为 SVG/GIF、超过 4 张、单张超过 10 MiB、总计超过 20 MiB 或 Base64 非法？——在进入 Provider 前即阻断并提示明确原因（FR-009b）。
- 用户给不支持 vision 的 Chat 模型发送图片？——SDK 不预判能力，由业务配置与调用方决定是否允许；若仍发出请求，Provider 4xx 直接返回（FR-009e）。
- 会话数达 500 上限后新建？——入口禁用并提示，引导删除旧会话；不自动清理（FR-029）。
- 会话标题模型生成失败？——兜底取首条提问截断（FR-030）。
- 资产不支持流式输出？——平台缓冲完整响应并完成全文检测后直接完整呈现（不假流式），接入不受阻（FR-022/FR-023，2026-08-24 口径）。
- 用户在 90 天留存期内删除会话？——软删除，用户侧不可见，原文留存至期满（FR-031）。
- 实验台刷新或离开后想恢复之前的实验内容？——不可恢复，实验记录用户侧不持久化（FR-019）；平台侧合规留存与审计日志不受影响。
- 已下架/订阅失效/出站停用资产的实验台中发起调用？——被拒并按原因提示（FR-032/FR-035）。

## Requirements

### Functional Requirements

**Chat 对话对象**

- **FR-001**: 系统 MUST 在用户未选择资产时将对话对象默认为平台 Chat agent-runtime（Chat）；Chat 不是资产——不上架、不可订阅、无 Owner、恒可用（原 AC-1）。
- **FR-002**: Chat 的 P0 能力 MUST 有且仅有模型对话与挂载知识库检索两项；P0 不调用平台原生工具（平台原生 MCP），不调用已上架资产；`tool_call` SSE 事件与消息模型中的 `toolCalls` 字段仅作既有契约兼容保留，并为 P1 Chat 调用已订阅 MCP 资产工具能力预留，不构成 P0 Chat 功能承诺（原 AC-2）。
- **FR-003**: Chat MUST 绑定平台默认护栏策略模板；其提示词与实现随平台部署定义，P0 不提供配置入口（原 AC-3/AC-4）。

**对话主界面与基础能力**

- **FR-004**: 对话主界面 MUST 在无消息时展示欢迎页与输入框、有消息时展示消息流与底部固定输入区；Enter 发送、Shift+Enter 换行（原 AC-17b）。
- **FR-005**: 模型选择 MUST 仅在 Chat 会话提供，下拉列表仅展示对话类与多模态类模型（向量化模型与重排序模型不出现）；实验台不展示模型选择器，资产 Agent 的模型由资产自身决定（原 AC-3/AC-17）。
- **FR-006**: 深度分析开关 MUST 仅在 Chat 会话提供；开启后模型执行更多推理步骤，思考过程默认展开（原 AC-18）。
- **FR-007**: 思考过程 MUST 以可折叠的有序步骤列表展示（原 AC-19）。
- **FR-008**: 回答操作 MUST 含复制全文与重新生成；重新生成按当前知识库状态重新检索并重跑模型，旧回答被直接替换、不保留历史版本（原 AC-20）。
- **FR-009**: 输入区下方 MUST 常驻展示 AI 生成内容免责提示与平台级用户协议链接（原 AC-21）。
- **FR-009a**: Chat 当前交付范围 MUST 支持**图像输入、文本输出**的图像识别能力；不含图像生成、OCR 工作流、音频/视频（2026-09-15 用户批准）。
- **FR-009b**: Chat 图像输入 MUST 仅接受 Base64，不支持外部 URL 抓取；首版仅接受 JPEG/PNG/WebP，单次最多 4 张，单张解码后最大 10 MiB、总计最大 20 MiB；SVG/GIF MUST 被拒绝。SDK 与 Chat 业务链路 MUST NOT 承担文件存储、检索、压缩或格式转换职责（2026-09-15 用户批准）。
- **FR-009c**: Chat 图像输入的 `detail` 参数 MUST 默认 `auto`，可选 `low/high`；多模态请求默认超时 MUST 为 120 秒，且允许调用方配置覆盖（2026-09-15 用户批准）。
- **FR-009d**: SDK / Chat 调用链 MUST 将图像输入内部序列化为 OpenAI-compatible content parts 与 data URI；纯文本请求 MUST 保持向后兼容。引入图像输入后，流式输出与既有 tool-calling 承载语义 MUST 保持兼容并纳入测试（2026-09-15 用户批准）。
- **FR-009e**: SDK MUST NOT 自行判定模型是否支持 vision；该决策归业务配置与调用方。若对不支持 vision 的模型发送图片，Provider 4xx MUST 直接传播。vision-capable chat model MUST 使用 ChatPort；Document Parse MUST 保持独立 `DOCUMENT_PARSE` 概念。历史 `MULTIMODAL -> parser` 映射 MUST 走一版 deprecated 兼容，再于 1.0 移除（2026-09-15 用户批准）。

**知识库挂载与检索（仅 Chat 会话）**

- **FR-010**: 仅 Chat 会话 MUST 可挂载知识库；资产 Agent 实验台不可挂载（原 AC-5）。
- **FR-011**: 可挂载范围 MUST 为状态「可用」的以下知识库（定义处以 spec 005 FR-049 为准）：公共目录中——①用户持有知识库 Consumer 及以上有效权限的库；②用户为该库创建者且享有知识库创建角色内含读取语义的库（spec 005 FR-013c）；③可见范围为「公开可用」的库（全体登录用户隐含 Consumer 读取语义，spec 005 FR-011）；以及当前用户本人创建且状态「可用」的我的目录知识库；草稿与已停用的库不出现在挂载列表（原 AC-6；知识库角色申请与生效语义见 spec 005 FR-059/FR-060；2026-09-21 按 spec 005 FR-049 口径补齐裁定）。
- **FR-012**: 挂载面板 MUST 支持按目录树浏览、按名称搜索、按知识库多选、按文档单选；单会话挂载知识库数上限 5 个，超限阻断并提示「超过知识库挂载上限，建议减少选择的知识库」（原 AC-7）。
- **FR-013**: 检索归并口径 MUST 为：每个挂载知识库各取相似度最高的前 5 条切片，跨库按相似度归并后取前 10 条，按切片去重（原 AC-8b；去重粒度对齐 PRD §9.10 审定基线）。
- **FR-014**: 回答末尾 MUST 展示引用来源标签；展开可见命中切片的排序位次、相似度分值、所属知识库与来源文档，并可打开原文（原 AC-8）。
- **FR-015**: 命中的图片/插图/图表类证据 MUST 在回答中内嵌渲染并标注来源文档（原 AC-9）。
- **FR-016**: 知识库检索 MUST 不设会话级快照：检索行为由检索时刻的知识库状态与权限决定——库被停用或软删除后立即不可检索、回「草稿」后无可检索内容、权限被回收后检索即被拒绝；进行中的会话与新会话一视同仁。既有契约中的 `snapshotAt` 字段仅作兼容保留，不作为检索授权、知识库状态或可检索范围的判断依据；P0 可返回空值或挂载记录时间（原 AC-10；关联 watchlist #31）。

**资产 Agent 实验台**

- **FR-017**: 用户 MUST 可经资产详情页「去使用」或对话工作台的资产 Agent 选择器进入该资产的实验台；平台网关代理透传，护栏、凭据解析、审计在网关执行（原 AC-11；2026-09-21 实验台定位裁定）。
- **FR-018**: 实验台中 Chat MUST 不在场、不可挂载知识库；页面顶部 MUST 展示当前实验的资产名称（原 AC-12）。
- **FR-019**: 实验台页面 MUST 固定绑定单一资产，进入时确定、不可中途变更；通过选择器切换资产即进入该资产的独立实验台页面，MUST NOT 带入其他资产的实验内容。实验记录 MUST NOT 在用户侧持久化：不进入历史会话列表，不适用 90 天留存、500 上限、搜索、筛选、删除等会话管理规则（FR-028~FR-032 仅适用 Chat 会话），页面刷新或离开后实验内容不可恢复；平台侧合规留存与审计日志口径不变（护栏与审计在网关执行）（原 AC-12b；2026-09-21 用户裁定——取代原「透传会话与 Chat 会话适用同一套持久化与管理规则」口径）。
- **FR-019b**: 实验台 MUST 只读展示该资产的参数：能力声明的**输入输出结构**（以 spec 003 FR-010 的 Agent Card 拉取只读镜像为信息源）与关键接入参数（协议、服务地址、超时/重试）；取值口径见 FR-019d；MUST NOT 提供编辑入口；鉴权元数据与护栏策略模板细节 MUST NOT 向实验台展示（2026-09-21 用户裁定；服务地址于 2026-09-21 取值口径声明时纳入展示范围——与资产详情页 `endpointUrl` 的投影口径一致）。
- **FR-019c**: 实验台每轮实验 MUST 支持查看输入与输出：展示渲染后的输入消息与输出消息，且 MUST 可展开查看平台发往资产的请求原始报文与资产返回的响应原始报文（2026-09-21 用户裁定）。
- **FR-019d**: 实验台展示参数的**取值口径** MUST 为：
  1. **信息源唯一**：MUST 经管理服务资产详情只读接口（`GET /mgmt/marketplace/assets/{assetId}`，operationId `getMarketplaceAsset`）读取；MUST NOT 由前端直连资产服务读取，MUST NOT 取自创建向导草稿数据、未发布修订或任何本地缓存/浏览器存储。
  2. **字段映射**：协议 ← `protocolType`（Agent 恒为 A2A 的单值只读字段，spec 003 澄清裁定）；服务地址 ← `endpointUrl`；超时/重试 ← 接入配置的超时与重试字段（字段命名口径见 `MarketplaceAssetHealthProbeRequest` 的 `timeoutSeconds`/`retryCount`，取值域见 spec 003 FR-007：超时默认 30 秒、可配 5–120 秒，重试默认 1 次、可配 0–3 次）；输入输出结构 ← `manifestSnapshot`/`capabilityConfig`/`interfaceConfig`（spec 003 FR-010 只读镜像）。
  3. **版本口径**：版本类字段（协议、服务地址、能力声明——spec 004 FR-016）MUST 取**当前在架版本**（`currentVersionId`/`currentVersionNo` 对应版本）的值，MUST NOT 取未发布修订（spec 004 FR-014：修订期间全部流量仍走在架版本）；热改类字段（超时、重试——spec 004 FR-016）MUST 取**当前即时生效值**，MUST NOT 取版本快照（热改不进入版本，取快照会与实际调用不一致）。
  4. **展示与执行同源**：每轮调用由平台网关按**调用时刻的生效配置**执行；参数展示 MUST 与网关执行取自同一信息源的同一口径，MUST NOT 出现「展示值取版本快照、执行值取热改即时值」（或反向）的错位。
  5. **读取时机**：MUST 在进入实验台时读取一次（与 FR-021 平台侧会话 ID 生成同一时点）；页面驻留期间平台侧配置变更 MUST NOT 要求实时刷新展示（不引入实时订阅/推送），重新进入实验台即重新读取。
  6. **脱敏与边界**：MUST NOT 展示鉴权配置（`authConfig`，即凭据元数据）、凭据明文、Health Check 地址与探测详情、护栏策略模板细节；接口 MUST NOT 返回凭据明文（`MarketplaceAssetDetail` 按当前用户关系投影）。
  7. **不可读/不可用时**：资产无可用在架版本或读取失败时，实验台 MUST NOT 展示参数区内容，并按 FR-032/FR-035 展示对应不可用文案（与调用被拒口径一致）。

  （2026-09-21 用户指令裁定——「只读呈现参数」必须先解决「从哪取、取哪个版本、什么时候取」，否则展示值与实际执行值可能错位；字段级语义的单一权威仍归 spec 003 FR-007/FR-010 与 spec 004 FR-016，本条只声明实验台侧的取数与展示口径，不重定义字段语义。契约影响：复用 mgmt-service `getMarketplaceAsset`，无新增端点；`accessConfig` 字段显式化见 Open Questions。）
- **FR-020**: 实验台调用 MUST 为平台内资产调用：平台以**当前用户的个人凭据**发起调用（2026-08-24 凭据模型裁定——旧资产凭据模型取消，见 spec 007 FR-030），并传递当前用户身份上下文（供资产内部处理用户级数据权限）（原 AC-13）。
- **FR-021**: 平台网关 MUST 在每轮透传请求中携带当前消息与平台侧会话 ID；多轮对话上下文由资产自行维护，平台不向资产透传历史消息（对齐 A2A 协议的 contextId 模型；原 AC-13b；契约影响：`grc-agent-service.yaml` 透传接口需含会话 ID 字段；2026-09-21 实验台定位裁定确认保留多轮调试）。平台侧会话 ID 的生命周期 MUST 为：每次进入实验台时生成新 ID，页面刷新、离开或切换资产即失效并新建（2026-09-21 裁定——与用户侧不持久化自洽，刷新后历史轮次用户不可见，延续 contextId 会让资产在用户不可见的上下文上续跑）。
- **FR-022**: 实验台 MUST NOT 要求资产支持流式输出：资产以普通请求-响应即可接入，准入门控不含流式能力校验。上游资产提供非流式响应时，平台 MUST 缓冲完整响应并完成全文检测后直接完整呈现（不做按段回放式的假流式）；提供流式响应时，平台 MUST 采用 FR-023 的重叠滑动窗口检测（原 AC-13c；2026-08-24 用户裁定采纳机制基线并修正非流式直出）。

**流式输出与护栏**

- **FR-023**: 输出侧护栏 MUST 按上游响应形态执行：流式响应采用重叠滑动窗口检测，每个窗口通过后才释放其可下发内容；任一窗口命中时，MUST 立即终止上游生成与后续输出、**瞬时撤回全部已下发内容（含此前已通过窗口的前缀）**，原位展示「该回答因命中安全护栏已被撤回」（含命中的护栏类型）——终态全文零字留存，命中轮次的回答不落库，历史回看中该轮显示同一占位文案（仅适用 Chat 会话，实验台无历史回看）。非流式响应采用全文缓冲检测，通过后直接完整呈现（不假流式），命中则全文不呈现并展示同一提醒。窗口参数与检测引擎选型 MUST 不在 spec 定义（挂 watchlist #1/#50 留 plan 阶段）（原 AC-14；2026-08-24 用户裁定——机制采纳 Zhang 基线、命中语义坚持全文零字留存；处置语义与 spec 006 FR-042/FR-043 一致）。
- **FR-024**: 输入侧护栏命中 MUST 直接拦截并拒答，响应回传命中的护栏类型，页面展示命中类型与处置结果（与输出侧提示一致）；临时文件内容视同用户输入、随 P1 上传功能生效（原 AC-14b）。
- **FR-025**: 中止生成时 MUST 停止读取上游后续内容；对尚未释放的已生成内容按当前路径完成检测（流式完成当前窗口、非流式完成已有内容）；检测未通过 MUST 按 FR-023 命中规则处置（撤回全部已下发内容并展示占位提醒），通过则可保留已下发部分（原 AC-15；2026-08-24 用户裁定口径）。
- **FR-026**: 回答生成期间 MUST 禁用发送入口并提示「正在生成中」；用户可经「停止生成」主动中止后立即发送；新消息不自动中止当前生成；Chat 会话与实验台行为一致（原 AC-15b）。
- **FR-027**: 护栏命中时页面 MUST 展示命中的护栏类型与处置结果（原 AC-16）。

**回答渲染**

- **FR-027b**: 回答中的结构化内容 MUST 基于 Markdown 及扩展语法渲染（2026-08-25 用户裁定）：表格支持横向滑动查看；代码块支持语法高亮、行号与一键复制；Mermaid 流程图与数学公式经 Markdown 扩展插件渲染。
- **FR-027c**: 流式输出过程 MUST 控制内容渲染刷新频率以避免屏幕闪烁，且 MUST NOT 强制滚动跟随最新输出（不打断用户阅读已生成部分）；长回答 MUST 支持分段或折叠展示（2026-08-25 用户裁定；刷新频率值与分段阈值为前端实现参数，不进 spec）。

**历史会话（仅 Chat 会话）**

- **FR-028**: Chat 会话 MUST 服务端持久化 90 天（自最后一条消息起算）；单用户会话数上限 500 个；支持按会话标题与首条提问搜索、打开恢复、删除、新建（原 AC-22；2026-09-21 收窄——实验台实验记录不适用；原「按 Agent 筛选」随会话列表仅含 Chat 会话移除）。
- **FR-029**: 会话数达上限时 MUST 禁用「新建会话」入口并提示已达上限，引导用户删除旧会话后恢复；平台不自动清理任何会话（原 AC-22b）。
- **FR-030**: 会话标题 MUST 在首轮问答完成后由模型生成摘要标题，标题生成应使用快速小模型（考虑响应速度）；生成失败时兜底取首条提问截断；支持手动重命名，重命名后不再被自动覆盖（原 AC-22c）。
- **FR-031**: 会话删除 MUST 为软删除：用户侧立即不可见且不可恢复；脱敏/敏感字段遮蔽后的对话内容按 PRD §9.8 继续留存至 90 天期满（自最后一条消息起算）再清除；删除不影响审计日志 3 年留存（原 AC-22d；若合规裁定收窄为只留元数据，语义不变、留存范围随动）。
- **FR-032**: 三类失效场景（资产已下架、订阅失效（用户退订或被 Owner 取消）、出站调用被平台停用）下，实验台 MUST 拒绝新调用并按原因展示对应文案（与 FR-035 三类提示一一对应）（原 AC-23；2026-09-21 用户裁定——实验记录用户侧不持久化，原「历史会话只读回看」口径对资产会话失效）。

**我的资产抽屉与不可用提示**

- **FR-033**: 「我的资产」抽屉 MUST 分已订阅与收藏两区：已订阅区默认按最近使用时间倒序（无使用记录按订阅时间），收藏区默认按收藏时间倒序，两区均可切换按名称排序；点击语义为已订阅 Agent 进实验台、MCP 与未订阅资产进详情页（原 AC-24）。
- **FR-034**: 已下架资产条目 MUST 置灰不可进入实验台（原 AC-25）。
- **FR-035**: 资产不可用提示 MUST 覆盖三类文案：已被下架、出站调用已被平台停用、服务暂时不可用（附资产名称与负责人）（原 AC-26）。
- **FR-036**: Chat 侧生成失败（模型服务或检索服务失败、网络中断等）MUST 展示明确错误提示与重试入口；失败轮次的回答不写入会话历史，用户消息保留可直接重发（原 AC-26b）。

### Key Entities

- **会话（Session）**: 平台侧持久化的 Chat 对话记录（仅 Chat 会话；2026-09-21 收窄——实验台实验记录非 Session 实体）。关键属性：对话对象（Chat）、标题（模型生成可重命名）、消息序列、最后消息时刻（90 天留存起算点）、挂载知识库集合（上限 5 库）、软删除标记。单用户上限 500 个。
- **轮次（Turn）**: Chat 会话中的一轮问答。关键属性：用户消息、回答全文、引用证据集合、护栏处置结果（通过/拦截/占位）、生成状态。失败轮次的回答不落库，用户消息保留。
- **实验轮次（Bench Turn）**: 实验台中的一轮调用，**用户侧不持久化**（页面刷新或离开后不可恢复）。关键属性：输入消息（含可展开的请求原始报文）、输出消息（含可展开的响应原始报文）、护栏处置结果、平台侧会话 ID（contextId 承载，多轮上下文由资产自维护；每次进入实验台生成，刷新/离开/切换资产即失效并新建）。
- **引用证据（Citation）**: 回答附带的检索证据。关键属性：命中切片排序位次、相似度分值、所属知识库、来源文档；图片/图表类证据内嵌渲染。
- **挂载（Mount）**: Chat 会话与知识库（精确到文档）的关联。不设快照，每次检索按当时状态与权限判定。
- **我的资产条目（Asset Entry）**: 抽屉中的资产条目。关键属性：分区（已订阅/收藏）、最近使用时间、收藏时间、在架状态、出站停用标记。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户登录后无需任何前置配置即可与 Chat 发起首轮对话（US-1）。
- **SC-002**: 输入侧护栏命中的消息 100% 被拦截拒答，且 100% 展示命中的护栏类型与处置结果。
- **SC-003**: 输出侧护栏命中的回答终态 0 字留存：非流式命中 0 字呈现；流式命中时命中窗口及其后 0 字下发、此前已下发的前缀 100% 被瞬时撤回，且 100% 展示护栏命中提醒（含护栏类型）、命中轮次 0 落库（2026-08-24 用户裁定口径）。

## Non-Goals / Boundaries

- **实验台不是完整 chat**：不提供历史会话管理、会话标题、搜索/筛选/删除等会话生命周期能力；不提供模型选择器、深度分析开关、知识库挂载（2026-09-21 用户裁定）。
- **临时文件上传**（P1）：文件参与当前会话、不入知识库、会话结束即失效；文件内容视同用户输入纳入输入侧护栏（检测时机随 §13.10 第 6 项 P1 展开）。
- **图像生成 / OCR 工作流 / 音频视频**：不在当前 Chat 多模态范围内；当前只支持图像输入、文本输出。
- **外部 URL 拉图 / 图片持久化 / 压缩转换**：不在当前 Chat 多模态范围内；文件生命周期由业务或文件服务负责。
- **建议追问**（P1）：回答下方追问建议，点击即发送。
- **对话记忆**（P1）：用户偏好记录与应用，含总开关与按 Agent 筛选查看。
- **引用阅读面板**（P1）：选中引用后侧栏联动展示关联文档。
- **P0 中 MCP 资产不是对话对象**：对话工作台内不可调用 MCP 资产；MCP 资产消费方式为资产 Agent 服务端自行接入或外部系统经 PAT 调用；P1 预留 Chat 调用已订阅 MCP 资产工具的能力。
- **平台原生工具仅作知识库外部导入通道**：不属于 P0 对话能力，也不属于 P1 MCP 资产调用预留范围（导入语义见 spec 005，维护语义见 spec 008）。
