# Spec 001 — 对话工作台

**Feature Branch**: `clarify/001-conversation`（本文件为既有 AC 格式 spec 的 spec-kit 风格重写，内容等价迁移并纳入 2026-08-21 与 2026-08-22 两轮澄清裁定；原 AC 编号对照见文末附录）

**Created**: 2026-08-13（初版，随 specs/001–009 拆解）；2026-08-22（spec-kit 风格重写）

**Status**: Reviewed

**PRD 来源（v1.2）**: §7 M1（功能清单）、§6 J1.5–J1.6（用户旅程）、§8.1 US1–US20、§9.5/§9.8/§9.10

**Input**: 统一对话入口：默认对话对象为平台 Chat agent-runtime（Chat，能力仅模型对话与知识库检索）；订阅资产 Agent 后经详情页「去使用」或选择器进入透传会话；流式输出与护栏；历史会话管理；我的资产抽屉；资产不可用提示。一切经平台流转的对话统一经过平台网关的护栏检测。

---

## 背景与目标

提供统一的对话入口。默认对话对象是平台 Chat agent-runtime（界面展示名 Chat）——平台自有的知识问答智能体，P0 能力仅模型对话与知识库检索（带引用证据与图片/插图）；P0 不调用平台原生工具（平台原生 MCP），也不调用已上架资产。用户订阅资产 Agent 后可经详情页「去使用」或对话工作台的资产 Agent 选择器进入透传会话（不可挂载知识库）。P1 预留 Chat 调用已订阅 MCP 资产工具的能力，但不进入 P0 对话工作台闭环。一切经平台流转的对话统一经过平台网关的护栏检测。

## Clarifications

### Session 2026-08-21

- Q: 单会话可挂载知识库数上限？ → A: 5 个（PRD §9.10 参数基线审定——用户确认）。
- Q: 多库挂载时检索结果如何归并？ → A: 每个挂载知识库各取相似度最高的前 5 条切片；跨库按相似度归并后取前 10 条，按切片去重（PRD §9.10 参数基线审定——用户确认）。
- Q: 会话与对话对象的绑定关系？ → A: 会话固定绑定唯一对话对象（Chat 或某一资产 Agent），创建时确定、不可中途变更；资产 Agent 选择器切换资产即新建/切换到该资产的会话；透传会话与 Chat 会话适用同一套持久化与管理规则（旅程 J1「切换到专属透传会话」——用户裁定）。
- Q: 输入侧护栏命中的处置？ → A: 直接拦截并拒答，响应回传命中的护栏类型，页面展示命中类型与处置结果（与输出侧提示一致）；临时文件内容视同用户输入、随 P1 上传功能生效（PRD §9.5——用户确认）。
- Q: 模型选择与深度分析开关在透传会话是否提供？ → A: 不提供——仅 Chat 会话提供模型选择器与深度分析开关；资产 Agent 会话的模型由资产自身决定，会话能力以资产返回为准（PRD §7 M1-2、旅程 J1——用户确认）。
- Q: 「重新生成」的语义与旧回答去向？ → A: 按当前知识库状态重新检索并重跑模型，旧回答被直接替换、不保留历史版本（与无快照语义自洽——用户裁定）。
- Q: 单用户会话数上限与达上限后的处置？ → A: 上限 500 个（PRD §9.10 参数基线审定）；达上限时「新建会话」入口禁用并提示已达上限，引导用户删除旧会话后恢复；不自动清理任何会话（会话是用户工作记录，静默清理造成无感知数据丢失——用户裁定）。
- Q: 会话标题如何生成？ → A: 首轮问答完成后由模型生成摘要标题；生成失败时兜底取首条提问截断；支持手动重命名，重命名后不再被自动覆盖（用户裁定）。
- Q: 我的资产抽屉两区的默认排序？ → A: 已订阅区按最近使用时间倒序（无使用记录按订阅时间），收藏区按收藏时间倒序；两区均可切换按名称排序（PRD §7 M1-15——用户确认）。
- Q: Chat 侧生成失败（模型/检索/网络）时失败轮次是否落库？ → A: 展示明确错误提示与重试入口；失败轮次的回答不写入会话历史，用户消息保留可直接重发（失败回答无消费价值，落库会污染历史与上下文——用户裁定）。

### Session 2026-08-22

- Q: 透传会话的多轮上下文谁维护？ → A: 平台网关在每轮透传请求中携带当前消息与平台侧会话 ID，多轮上下文由资产自行维护，平台不向资产透传历史消息（对齐 A2A 协议的 `contextId` 模型；避免每轮向资产全量暴露用户对话历史——用户裁定）。
- Q: 前一条回答仍在生成时能否发送下一条？ → A: 不能——生成期间发送入口禁用并提示「正在生成中」，用户可经「停止生成」主动中止后立即发送；新消息不自动中止当前生成；两类会话行为一致（防止同会话轮次交错破坏资产侧上下文连续性——用户裁定）。
- Q: 订阅失效（退订/被 Owner 取消）与出站停用后，历史会话如何处理？ → A: 与已下架一致——三类失效场景统一只读回看、发送被拒并按原因展示对应文案（依据 PRD M1-14/US-14「会话内容是用户自己的数据」——用户裁定）。
- Q: 透传会话是否要求资产支持流式输出？ → A: 不要求——平台缓冲资产完整响应，经输出侧护栏检测通过后按段回放；资产以普通请求-响应即可接入，准入门控不含流式能力校验（与全文缓冲检测语义自洽，降低接入门槛——用户裁定）。
- Q: 用户删除会话后对话原文的去向？ → A: 软删除——用户侧立即不可见且不可恢复；脱敏/敏感字段遮蔽后的对话内容按 PRD §9.8 继续留存至 90 天期满（自最后一条消息起算）再清除，删除不影响审计日志 3 年留存（与资产/知识库软删除终态模式一致；若合规裁定收窄为只留元数据，语义不变、留存范围随动——用户裁定）。

## User Scenarios & Testing

### User Story 1 — 与 Chat 的基础对话 (Priority: P1)

普通用户登录后直接进入对话工作台，默认与平台 Chat agent-runtime（Chat）对话：欢迎页/消息流主界面、模型选择、深度分析开关、思考过程展示、复制与重新生成、常驻免责声明。

**Why this priority**: Chat 是平台的默认对话对象与第一触点，无此则平台无最小可用价值。

**Independent Test**: 不选择任何资产发起对话，验证主界面两种形态、模型下拉仅含对话类与多模态类、深度分析与思考过程、复制/重新生成与免责声明均符合规格。

**Acceptance Scenarios**:

1. **Given** 用户进入对话工作台且未选择资产, **When** 发起对话, **Then** 对话对象为 Chat——Chat 不是资产，不上架、不可订阅、无 Owner、恒可用。
2. **Given** Chat 会话, **When** 使用其能力, **Then** P0 仅可使用模型对话与挂载知识库检索两项；Chat 不调用平台原生工具（平台原生 MCP），不调用已上架资产；既有接口中的工具调用承载仅作兼容保留并为 P1 Chat 调用已订阅 MCP 资产工具能力预留。
3. **Given** 新会话无消息, **When** 打开对话页, **Then** 展示欢迎页与输入框；有消息时展示消息流与底部固定输入区；Enter 发送、Shift+Enter 换行。
4. **Given** Chat 会话, **When** 打开模型选择下拉, **Then** 仅展示对话类与多模态类模型（向量化模型与重排序模型不出现）；Chat 绑定平台默认护栏策略模板，提示词与实现随平台部署定义、P0 无配置入口。
5. **Given** Chat 会话, **When** 开启深度分析, **Then** 模型执行更多推理步骤，思考过程默认展开，以可折叠的有序步骤列表展示。
6. **Given** 一条已生成的回答, **When** 用户点击重新生成, **Then** 系统按当前知识库状态重新检索并重跑模型，旧回答被直接替换、不保留历史版本；复制全文随时可用。
7. **Given** 任意会话页, **When** 查看输入区下方, **Then** 常驻展示 AI 生成内容免责提示与平台级用户协议链接。

### User Story 2 — 知识库挂载与检索 (Priority: P1)

普通用户在 Chat 会话中挂载有权限且「可用」的知识库（可精确到单文档），提问后获得带引用来源与检索证据的回答，图片与图表类证据内嵌渲染。

**Why this priority**: 知识库检索是 Chat 区别于裸模型的唯一能力，是平台知识价值的出口。

**Independent Test**: 在 Chat 会话挂载一个「可用」知识库并提问，验证可选范围、挂载上限、归并口径、引用证据与内嵌渲染；中途停用该库，验证下一轮检索立即失效。

**Acceptance Scenarios**:

1. **Given** Chat 会话, **When** 打开知识库挂载面板, **Then** 可按目录树浏览、按名称搜索、按知识库多选、按文档单选；可选范围为状态「可用」且用户持有知识库 Consumer 及以上权限的知识库，以及我的目录下状态「可用」的知识库（含本人创建与获得可查看/可编辑分享授权的）；草稿与已停用的库不出现。
2. **Given** Chat 会话已挂载 5 个知识库, **When** 尝试挂载第 6 个, **Then** 被阻断并提示「超过知识库挂载上限，建议减少选择的知识库」。
3. **Given** 会话挂载了多个知识库, **When** 用户提问, **Then** 检索归并口径为：每个挂载知识库各取相似度最高的前 5 条切片，跨库按相似度归并后取前 10 条，按切片去重。
4. **Given** 回答已生成, **When** 查看回答末尾, **Then** 展示引用来源标签；展开可见命中切片的排序位次、相似度分值、所属知识库与来源文档，可打开原文；命中的图片/插图/图表类证据内嵌渲染并标注来源文档。
5. **Given** 会话挂载的知识库被停用、被软删除、回「草稿」或用户权限被回收, **When** 发起下一轮检索, **Then** 按检索时刻的知识库状态与权限判定——立即不可检索/无内容/被拒绝；进行中的会话与新会话一视同仁，不设会话级快照。
6. **Given** 资产 Agent 透传会话, **When** 查看挂载面板, **Then** 不提供知识库挂载能力。

### User Story 3 — 流式输出与护栏 (Priority: P1)

两类会话的回答统一先经输出侧护栏全文检测再按段回放；输入侧命中直接拒答；可随时中止生成；护栏命中展示类型与处置结果。

**Why this priority**: 护栏是平台安全基线的运行时执行点（宪法级约束），流式回放与中止决定对话可用体感。

**Independent Test**: 分别构造输入命中、输出命中、中止生成三种场景，验证拦截/占位/回放行为与提示文案。

**Acceptance Scenarios**:

1. **Given** 用户发送的消息命中输入侧护栏, **When** 提交, **Then** 直接拦截并拒答，响应回传命中的护栏类型，页面展示命中类型与处置结果（与输出侧提示一致）。
2. **Given** 模型已生成回答全文, **When** 输出侧护栏检测通过, **Then** 回答按段回放；若命中则全文不下发。
3. **Given** 回答正在回放, **When** 用户点击停止生成, **Then** 对已生成部分执行输出侧检测，通过后回放保留，命中则以「已拦截」占位文本替代。
4. **Given** 回答生成期间, **When** 用户尝试发送新消息, **Then** 发送入口禁用并提示「正在生成中」；新消息不自动中止当前生成；用户可主动「停止生成」后立即发送；Chat 会话与透传会话行为一致。
5. **Given** 护栏命中（输入或输出侧）, **When** 页面展示, **Then** 可见命中的护栏类型与处置结果。

### User Story 4 — 资产 Agent 透传会话 (Priority: P2)

用户订阅资产 Agent 后，经详情页「去使用」或对话工作台的资产 Agent 选择器进入该资产的透传会话：平台网关代理透传（护栏、凭据解析、审计在网关执行），Chat 不在场、不可挂载知识库，页面顶部展示资产名称。

**Why this priority**: 透传会话是订阅价值的兑现路径，依赖订阅链路（spec 002）存在，故列为第二优先级切片。

**Independent Test**: 订阅一个已发布 Agent 后经「去使用」进入会话，完成一轮问答，验证网关透传、身份上下文传递、资产名展示与无挂载能力。

**Acceptance Scenarios**:

1. **Given** 用户已订阅某资产 Agent, **When** 经详情页「去使用」或选择器进入, **Then** 进入该资产的透传会话，平台网关代理透传（护栏、凭据解析、审计在网关执行）；Chat 不在场、不可挂载知识库；页面顶部展示当前对话的资产名称。
2. **Given** 透传会话进行中, **When** 平台发起资产调用, **Then** 使用资产级服务凭据发起，并在请求中传递当前用户身份上下文（供资产内部处理用户级数据权限）；订阅者无需配置个人出站凭据。
3. **Given** 透传会话多轮对话, **When** 每轮请求发出, **Then** 平台携带当前消息与平台侧会话 ID；多轮上下文由资产自行维护，平台不向资产透传历史消息。
4. **Given** 资产 Agent 仅支持普通请求-响应（非流式）, **When** 回答返回, **Then** 平台缓冲完整响应，经输出侧护栏检测通过后按段回放；准入门控不含流式能力校验。
5. **Given** 用户在某透传会话中, **When** 通过选择器切换资产, **Then** 新建/切换到该资产的专属会话；会话固定绑定唯一对话对象，创建时确定、不可中途变更；Chat 与资产会话相互切换时不带入前序对话历史记录，须新建会话且用户可感知新建了会话；透传会话与 Chat 会话适用同一套持久化与管理规则（90 天、500 上限、搜索、筛选、删除）。
6. **Given** 透传会话, **When** 查看对话页, **Then** 不展示模型选择器与深度分析开关（模型由资产自身决定，会话能力以资产返回为准）。

### User Story 5 — 历史会话管理 (Priority: P2)

会话服务端持久化 90 天，支持搜索、筛选、打开恢复、删除与新建；单用户上限 500 个；会话标题自动生成可重命名；删除为软删除；三类失效场景历史会话只读回看。

**Why this priority**: 历史会话是工作记录的留存与复访能力，依赖对话主链路先行。

**Independent Test**: 构造多会话环境，验证 90 天持久化口径、搜索/筛选、上限阻断、标题生成与重命名、删除软语义及三类失效场景的只读回看。

**Acceptance Scenarios**:

1. **Given** 用户的历史会话, **When** 查看列表, **Then** 会话服务端持久化 90 天（自最后一条消息起算）；支持按会话标题与首条提问搜索、按 Agent 筛选、打开恢复、删除、新建。
2. **Given** 用户已有 500 个会话, **When** 尝试新建, **Then** 「新建会话」入口禁用并提示已达上限，引导删除旧会话后恢复；平台不自动清理任何会话。
3. **Given** 新会话完成首轮问答, **When** 生成会话标题, **Then** 由模型生成摘要标题；生成失败时兜底取首条提问截断；用户可手动重命名，重命名后不再被自动覆盖。
4. **Given** 用户删除某会话, **When** 删除生效, **Then** 会话在用户侧立即不可见且不可恢复（软删除）；脱敏/敏感字段遮蔽后的对话内容按 PRD §9.8 留存至 90 天期满再清除，删除不影响审计日志 3 年留存。
5. **Given** 资产已下架、订阅失效（退订或被 Owner 取消）或出站调用被停用, **When** 用户打开相关历史会话, **Then** 可只读回看；发送新消息被拒并按原因展示对应文案（与不可用提示一一对应）。

### User Story 6 — 我的资产抽屉与不可用提示 (Priority: P2)

对话工作台提供「我的资产」抽屉（已订阅/收藏两区，含排序与点击语义）；资产不可用时按三类原因展示对应文案；Chat 侧生成失败展示错误与重试入口。

**Why this priority**: 抽屉是回到工作的快捷入口，不可用提示是异常体验的底线；均为增强层而非核心链路。

**Independent Test**: 构造已订阅/收藏/已下架/出站停用/服务异常五类资产条目，验证抽屉分区、排序、点击去向、置灰与文案。

**Acceptance Scenarios**:

1. **Given** 用户打开「我的资产」抽屉, **When** 浏览, **Then** 分已订阅与收藏两区；已订阅区默认按最近使用时间倒序（无使用记录按订阅时间），收藏区默认按收藏时间倒序，两区均可切换按名称排序。
2. **Given** 抽屉条目, **When** 点击, **Then** 已订阅的 Agent 直接进入其对话页；MCP 与未订阅资产进入其详情页；已下架资产条目置灰不可进入对话。
3. **Given** 资产不可用, **When** 用户尝试使用, **Then** 按原因展示三类文案之一：已被下架 / 出站调用已被平台停用 / 服务暂时不可用（附资产名称与负责人）。
4. **Given** Chat 会话中生成失败（模型服务或检索服务失败、网络中断等）, **When** 失败发生, **Then** 展示明确错误提示与重试入口；失败轮次的回答不写入会话历史，用户消息保留可直接重发。

---

### Edge Cases

- 回答生成期间发送新消息？——发送入口禁用并提示「正在生成中」，可主动中止后立即发送（FR-027）。
- 同一会话挂载的知识库中途被停用或权限被回收？——下一轮检索即不可检索/被拒绝，无会话级快照（FR-016）。
- 资产 Agent 服务超时或返回错误？——经配置的重试后仍失败时提示「该资产服务暂时不可用」并展示资产名称与负责人（FR-036）。
- 会话数达 500 上限后新建？——入口禁用并提示，引导删除旧会话；不自动清理（FR-030）。
- 会话标题模型生成失败？——兜底取首条提问截断（FR-031）。
- 资产不支持流式输出？——平台缓冲完整响应后按段回放，接入不受阻（FR-023）。
- 用户在 90 天留存期内删除会话？——软删除，用户侧不可见，原文留存至期满（FR-032）。
- 已下架/订阅失效/出站停用资产的会话中发送新消息？——被拒并按原因提示；只读回看不受影响（FR-032）。

## Requirements

### Functional Requirements

**Chat 对话对象**

- **FR-001**: 系统 MUST 在用户未选择资产时将对话对象默认为平台 Chat agent-runtime（Chat）；Chat 不是资产——不上架、不可订阅、无 Owner、恒可用（原 AC-1）。
- **FR-002**: Chat 的 P0 能力 MUST 有且仅有模型对话与挂载知识库检索两项；P0 不调用平台原生工具（平台原生 MCP），不调用已上架资产；`tool_call` SSE 事件与消息模型中的 `toolCalls` 字段仅作既有契约兼容保留，并为 P1 Chat 调用已订阅 MCP 资产工具能力预留，不构成 P0 Chat 功能承诺（原 AC-2）。
- **FR-003**: Chat MUST 绑定平台默认护栏策略模板；其提示词与实现随平台部署定义，P0 不提供配置入口（原 AC-3/AC-4）。

**对话主界面与基础能力**

- **FR-004**: 对话主界面 MUST 在无消息时展示欢迎页与输入框、有消息时展示消息流与底部固定输入区；Enter 发送、Shift+Enter 换行（原 AC-17b）。
- **FR-005**: 模型选择 MUST 仅在 Chat 会话提供，下拉列表仅展示对话类与多模态类模型（向量化模型与重排序模型不出现）；资产 Agent 会话不展示模型选择器，模型由资产自身决定（原 AC-3/AC-17）。
- **FR-006**: 深度分析开关 MUST 仅在 Chat 会话提供；开启后模型执行更多推理步骤，思考过程默认展开（原 AC-18）。
- **FR-007**: 思考过程 MUST 以可折叠的有序步骤列表展示（原 AC-19）。
- **FR-008**: 回答操作 MUST 含复制全文与重新生成；重新生成按当前知识库状态重新检索并重跑模型，旧回答被直接替换、不保留历史版本（原 AC-20）。
- **FR-009**: 输入区下方 MUST 常驻展示 AI 生成内容免责提示与平台级用户协议链接（原 AC-21）。

**知识库挂载与检索（仅 Chat 会话）**

- **FR-010**: 仅 Chat 会话 MUST 可挂载知识库；资产 Agent 透传会话不可挂载（原 AC-5）。
- **FR-011**: 可挂载范围 MUST 为：状态「可用」且用户持有知识库 Consumer 及以上权限的知识库，以及我的目录下状态「可用」的知识库（含本人创建与获得可查看/可编辑分享授权的）；草稿与已停用的库不出现在挂载列表（原 AC-6）。
- **FR-012**: 挂载面板 MUST 支持按目录树浏览、按名称搜索、按知识库多选、按文档单选；单会话挂载知识库数上限 5 个，超限阻断并提示「超过知识库挂载上限，建议减少选择的知识库」（原 AC-7）。
- **FR-013**: 检索归并口径 MUST 为：每个挂载知识库各取相似度最高的前 5 条切片，跨库按相似度归并后取前 10 条，按切片去重（原 AC-8b；去重粒度对齐 PRD §9.10 审定基线）。
- **FR-014**: 回答末尾 MUST 展示引用来源标签；展开可见命中切片的排序位次、相似度分值、所属知识库与来源文档，并可打开原文（原 AC-8）。
- **FR-015**: 命中的图片/插图/图表类证据 MUST 在回答中内嵌渲染并标注来源文档（原 AC-9）。
- **FR-016**: 知识库检索 MUST 不设会话级快照：检索行为由检索时刻的知识库状态与权限决定——库被停用或软删除后立即不可检索、回「草稿」后无可检索内容、权限被回收后检索即被拒绝；进行中的会话与新会话一视同仁。既有契约中的 `snapshotAt` 字段仅作兼容保留，不作为检索授权、知识库状态或可检索范围的判断依据；P0 可返回空值或挂载记录时间（原 AC-10；关联 watchlist #31）。

**资产 Agent 透传会话**

- **FR-017**: 用户 MUST 可经资产详情页「去使用」或对话工作台的资产 Agent 选择器进入透传会话；平台网关代理透传，护栏、凭据解析、审计在网关执行（原 AC-11）。
- **FR-018**: 透传会话中 Chat MUST 不在场、不可挂载知识库；页面顶部 MUST 展示当前对话的资产名称（原 AC-12）。
- **FR-019**: 会话 MUST 固定绑定唯一对话对象（Chat 或某一资产 Agent），创建时确定、不可中途变更；选择器切换资产即新建/切换到该资产的会话；Chat 与资产会话相互切换时 MUST NOT 带入前序对话历史记录，须新建会话且用户可感知新建了会话；透传会话与 Chat 会话适用同一套持久化与管理规则（原 AC-12b）。
- **FR-020**: 透传会话 MUST 为平台内资产调用：平台以资产级服务凭据发起调用，并传递当前用户身份上下文（供资产内部处理用户级数据权限）；订阅者无需配置个人出站凭据（原 AC-13）。
- **FR-021**: 平台网关 MUST 在每轮透传请求中携带当前消息与平台侧会话 ID；多轮对话上下文由资产自行维护，平台不向资产透传历史消息（对齐 A2A 协议的 contextId 模型；原 AC-13b；契约影响：`grc-agent-service.yaml` 透传接口需含会话 ID 字段）。
- **FR-022**: 透传会话 MUST NOT 要求资产支持流式输出：平台缓冲资产完整响应，经输出侧护栏检测通过后按段回放；资产以普通请求-响应即可接入，准入门控不含流式能力校验（原 AC-13c）。

**流式输出与护栏**

- **FR-023**: 回答全文 MUST 先经输出侧护栏检测，通过后按段回放；命中则全文不下发（原 AC-14）。
- **FR-024**: 输入侧护栏命中 MUST 直接拦截并拒答，响应回传命中的护栏类型，页面展示命中类型与处置结果（与输出侧提示一致）；临时文件内容视同用户输入、随 P1 上传功能生效（原 AC-14b）。
- **FR-025**: 中止生成时 MUST 对已生成部分同样先检测后回放；命中则以「已拦截」占位文本替代（原 AC-15）。
- **FR-026**: 回答生成期间 MUST 禁用发送入口并提示「正在生成中」；用户可经「停止生成」主动中止后立即发送；新消息不自动中止当前生成；Chat 会话与透传会话行为一致（原 AC-15b）。
- **FR-027**: 护栏命中时页面 MUST 展示命中的护栏类型与处置结果（原 AC-16）。

**历史会话**

- **FR-028**: 会话 MUST 服务端持久化 90 天（自最后一条消息起算）；单用户会话数上限 500 个；支持按会话标题与首条提问搜索、按 Agent 筛选、打开恢复、删除、新建（原 AC-22）。
- **FR-029**: 会话数达上限时 MUST 禁用「新建会话」入口并提示已达上限，引导用户删除旧会话后恢复；平台不自动清理任何会话（原 AC-22b）。
- **FR-030**: 会话标题 MUST 在首轮问答完成后由模型生成摘要标题，标题生成应使用快速小模型（考虑响应速度）；生成失败时兜底取首条提问截断；支持手动重命名，重命名后不再被自动覆盖（原 AC-22c）。
- **FR-031**: 会话删除 MUST 为软删除：用户侧立即不可见且不可恢复；脱敏/敏感字段遮蔽后的对话内容按 PRD §9.8 继续留存至 90 天期满（自最后一条消息起算）再清除；删除不影响审计日志 3 年留存（原 AC-22d；若合规裁定收窄为只留元数据，语义不变、留存范围随动）。
- **FR-032**: 三类失效场景（资产已下架、订阅失效（用户退订或被 Owner 取消）、出站调用被平台停用）下历史会话 MUST 统一可打开只读回看；发送新消息被拒并按原因展示对应文案（原 AC-23，与 FR-035 三类提示一一对应）。

**我的资产抽屉与不可用提示**

- **FR-033**: 「我的资产」抽屉 MUST 分已订阅与收藏两区：已订阅区默认按最近使用时间倒序（无使用记录按订阅时间），收藏区默认按收藏时间倒序，两区均可切换按名称排序；点击语义为已订阅 Agent 进对话页、MCP 与未订阅资产进详情页（原 AC-24）。
- **FR-034**: 已下架资产条目 MUST 置灰不可进入对话（原 AC-25）。
- **FR-035**: 资产不可用提示 MUST 覆盖三类文案：已被下架、出站调用已被平台停用、服务暂时不可用（附资产名称与负责人）（原 AC-26）。
- **FR-036**: Chat 侧生成失败（模型服务或检索服务失败、网络中断等）MUST 展示明确错误提示与重试入口；失败轮次的回答不写入会话历史，用户消息保留可直接重发（原 AC-26b）。

### Key Entities

- **会话（Session）**: 平台侧持久化的对话记录。关键属性：对话对象（Chat 或某一资产 Agent，创建时绑定不可变更）、标题（模型生成可重命名）、消息序列、最后消息时刻（90 天留存起算点）、挂载知识库集合（仅 Chat 会话，上限 5 库）、软删除标记。单用户上限 500 个。
- **轮次（Turn）**: 一轮问答。关键属性：用户消息、回答全文、引用证据集合、护栏处置结果（通过/拦截/占位）、生成状态。失败轮次的回答不落库，用户消息保留。
- **引用证据（Citation）**: 回答附带的检索证据。关键属性：命中切片排序位次、相似度分值、所属知识库、来源文档；图片/图表类证据内嵌渲染。
- **挂载（Mount）**: Chat 会话与知识库（精确到文档）的关联。不设快照，每次检索按当时状态与权限判定。
- **我的资产条目（Asset Entry）**: 抽屉中的资产条目。关键属性：分区（已订阅/收藏）、最近使用时间、收藏时间、在架状态、出站停用标记。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户登录后无需任何前置配置即可与 Chat 发起首轮对话（US-1）。
- **SC-002**: 输入侧护栏命中的消息 100% 被拦截拒答，且 100% 展示命中的护栏类型与处置结果。
- **SC-003**: 输出侧护栏命中的回答 0 字下发（全文不下发或以「已拦截」占位替代）。
- **SC-004**: 知识库状态或权限变更后，自下一轮检索起 100% 按最新状态判定，无快照残留（含进行中会话）。
- **SC-005**: 会话数达 500 上限时新建入口 100% 被阻断并提示；不发生任何静默自动清理。
- **SC-006**: 三类资产不可用场景（已下架/出站停用/服务不可用）100% 展示对应文案，服务不可用文案附资产名称与负责人。
- **SC-007**: 挂载知识库的问答 100% 附带引用来源信息（排序位次、相似度、所属知识库、来源文档），可从证据打开原文。
- **SC-008**: 生成失败轮次的回答 0 落库，对应用户消息 100% 保留并可直接重发。
- **SC-009**: 删除会话后用户侧 100% 不可见且不可恢复；留存与审计口径符合 PRD §9.8。

## Assumptions

- 模型类资源全部经 Nexus 供给（PRD §13.10 #16 已确认）；模型调用凭据按触发人解析——个人模型凭据优先、平台默认兜底（ADR-0016）。
- Alice 作为唯一授权权威可正常提供知识库权限判定；权限回收即时生效。
- 平台网关统一执行护栏检测、凭据解析与审计（ADR-0015）。
- ADR-007（A2A 协议统一）当前为 Proposed；若 Accept，透传接口形态按 A2A 落地，FR-021 的上下文归属语义不变（watchlist #45）。
- 单会话挂载上限（5）、归并口径（5/10）、会话数上限（500）等数值为 §9.10 参数基线审定值，后续基线调整时同步更新。

## Non-Goals / Boundaries

- **临时文件上传**（P1）：文件参与当前会话、不入知识库、会话结束即失效；文件内容视同用户输入纳入输入侧护栏（检测时机随 §13.10 第 6 项 P1 展开）。
- **建议追问**（P1）：回答下方追问建议，点击即发送。
- **对话记忆**（P1）：用户偏好记录与应用，含总开关与按 Agent 筛选查看。
- **引用阅读面板**（P1）：选中引用后侧栏联动展示关联文档。
- **P0 中 MCP 资产不是对话对象**：对话工作台内不可调用 MCP 资产；MCP 资产消费方式为资产 Agent 服务端自行接入或外部系统经 PAT 调用；P1 预留 Chat 调用已订阅 MCP 资产工具的能力。
- **平台原生工具仅作知识库外部导入通道**：不属于 P0 对话能力，也不属于 P1 MCP 资产调用预留范围（导入语义见 spec 005，维护语义见 spec 008）。
