## 平台与资产

| 术语 | 定义 | 备注 / 不是什么 |
|------|------|-----------------|
| AI Foundation Platform | 本产品的正式名称，奔驰中国面向企业 AI 资产的统一平台。中文语境可写「平台」 | 不是：AI Agent Portal（已废弃的旧称）、Agent 门户、AI 门户 |
| Marketplace | 平台内资产发现与订阅的模块，员工在此浏览、评估并申请使用他人发布的资产 | 不是：共创智能集市、集市、应用商店、资产市场 |
| 资产（Asset） | 可在 Marketplace 上架并通过订阅获得使用授权的对象，当前仅 Agent 与 MCP 两类。资产的唯一身份恒为资产 ID（订阅、PAT 范围勾选、调用、通知归因均按 ID）；资产名称全平台唯一——创建与基础信息热改时校验，重名阻断并提示，软删除后名称即释放、可被新资产重新使用 | 不是：应用、产品、对象、能力 |
| Agent | 可对话或可调用的智能体资产。按接入方式分为高代码 Agent（Owner 自建服务，通过 A2A 协议接入）与低代码 Agent（在 Dify 中编排，平台登记治理信息） | 不是：智能体（与 Agent 混用时）、机器人、助手 |
| MCP | Model Context Protocol 工具服务，向 Agent 或对话提供可调用的工具能力 | 不是：工具、插件、Tool Server |
| 知识库 | 文档经解析、切片、向量化后形成的可检索集合，归属于知识目录。三态：草稿、可用、已停用——首份文档完成向量化即自动转可用；只有可用状态才能被挂载与检索；「可用」时删除最后一份已向量化文档回「草稿」，「已停用」不因文档删除改变状态（离开只能由知识库 Owner 显式操作）。检索不设会话级快照：停用与软删除后立即不可检索、回「草稿」后无可检索内容、权限回收后检索即被拒绝，进行中的会话与新会话一视同仁。「已停用」仅收敛消费面（挂载、检索、开放接口），维护侧操作不受限。不是资产——不上架、不可订阅；公共知识库访问由 Alice 决定，我的目录的平台内分享授权由平台管理且不写入 Alice。创建后不可在既有目录之间移动、不可复制（子树内下沉分层除外，控制链与 Alice 角色不变）。知识库 Owner 可重命名与删除（系统软删除，「可用」须先停用） | 不是：知识资产、文档库、语料库 |
| 知识库就绪度 | 知识库详情页的构建完成度展示指标，计算为「已向量化文档数 / 未删除文档数」，以百分比展示；未删除文档数为零时展示 0%。它只是展示指标，不改变知识库状态机 | 不是：健康分、质量分 |
| Skill | 可被多个 Agent 复用的原子能力。不是资产，不上架不订阅。当前版本不提供 | 不是：技能资产、工具 |
| 公共目录 | 全企业共享的知识目录树，其中的目录权限与知识库授权以 Alice 为唯一权威。平台管理员仅负责冷启动时创建一级目录并指定一级目录控制角色与知识库创建角色 | 不是：共享目录、企业目录 |
| 我的目录 | 当前用户的私人知识空间，与公共目录并列的根节点，其中的知识库默认不经 Alice 授权、仅本人可见可用；创建者可分享原知识库（被分享者不获得副本，在自己的「我的知识库 > 分享给我的」子分区看到）。分享授权为平台内授权，不调用 Alice，分「可查看」（对应知识库 Consumer 读取语义）与「可编辑」（对应知识库 Contributor 读写语义）两级：可随时撤销（无需二次确认）、即时生效、不发通知，授予、撤销与失效均审计留痕；单库分享人数设上限（数值随 PRD §9.10 审定）。被分享者账号被 Alice 停用时其分享授权立即失效；创建者账号被停用时其我的目录知识库随之软删除、全部分享授权同步失效 | 不是：个人空间、私有目录 |
| 孤儿资产 | 全部 Owner 与 Deputy 账号均被 Alice 停用的资产。平台不做自动处置（资产保持运行），但订阅入口关闭并提示；治理中心只读总览对其显著标记；平台管理员可为其补员（指定新 Owner，留痕并通知新 Owner），补员后一切 Owner 职能与订阅入口恢复 | 不是：无主资产、僵尸资产 |
| 平台 Chat agent-runtime | 平台自有的知识问答（RAG）智能体，对话工作台不选择资产时的对话对象；界面展示名为 Chat（介绍语：平台原生知识对话智能体，提供与知识库的交互问答能力）。它不是资产：不上架、不可订阅、无 Owner、恒可用；绑定平台默认护栏策略模板；用户可为其选择对话模型；提示词与实现随平台部署定义（P0 不提供配置入口）。P0 能力面有且仅有两项：模型对话；检索用户挂载的、本人具备知识库 Consumer 权限的「可用」知识库，给出带引用证据与图片/插图的回答。P0 中它不调用平台原生工具（平台原生 MCP），也不调用任何已上架资产；使用资产 Agent 须经详情页「去使用」或对话工作台资产 Agent 选择器显式选择，进入该资产的透传会话（此时 Chat 不在场）。P1 预留 Chat 调用已订阅 MCP 资产工具的能力，该预留不等同于调用平台原生工具 | 不是：裸对话、直接与模型对话、系统助手 |
| 平台原生工具 | 平台自有并由平台管理员维护的 MCP 服务，当前实例为 Confluence MCP、SharePoint/OneDrive MCP、OSS（S3/Blob）MCP，三者鉴权方式各不相同。免订阅、全员可用、不上 Marketplace、无 Owner；不绑护栏模板（导入结果进入知识库后由输出侧检测覆盖），不适用质量门控与发布准入测评。仅作为知识库的外部导入通道，不属于 P0 Chat 的对话能力，也不属于 P1 Chat 调用已订阅 MCP 资产工具的预留范围；导入使用操作人个人出站凭据（执行导入需知识库 Contributor 及以上权限；我的目录中允许创建者本人或获得「可编辑」分享授权的用户执行导入）。P0 不开放经 PAT 调用平台原生工具——外部系统可直连来源系统，经平台中转无增量价值 | 不是：系统工具、内置插件 |
| MCP 资产 | 上架到 Marketplace、拥有 Owner、可被订阅的 MCP 类型资产。不同于平台原生工具：平台原生工具免订阅且只作为知识导入通道；MCP 资产受资产生命周期、订阅、凭据、审计与质量门控约束。P0 中 MCP 资产不作为对话对象，不提供「去使用」；P1 预留 Chat 调用已订阅 MCP 资产工具的能力 | 不是：平台原生工具、系统工具、内置插件 |
| 平台资源 | 平台在默认资源之外提供、需经平台管理员登记与授权的实例与云服务（Azure Document Intelligence 服务、Azure AI Search 服务——两者随 P1 管线组件启用，Milvus 与 PGVector 向量数据库实例）。不是资产——不上架、不可订阅、无 Owner。分两型：实例类（带连接信息与凭据，注册表承载）与模型类（不带连接信息、带凭据，模型清单承载，调用一律经 Nexus 网关）。可用范围三种：默认可用（全员；每类向量数据库至少一个默认实例且恒存在）、授权可用（按资源逐人分配；平台内部配置、不经 Alice、即时生效留痕、不发通知、回收不影响存量知识库）、平台内部（Nexus 令牌，不出现在任何用户选择器）。用户侧选择器只展示默认实例与本人已获授权实例。模型类凭据解析为个人优先、平台默认兜底：按触发人解析，依「模型可用性列表」快照选择（快照由配置时全量检测产生，仅鉴权类失败改写），无候选或不可用则用平台默认凭据（依据 docs/adr/0016） | 不是：平台资源资产、资源资产 |

## 角色

| 术语 | 定义 | 备注 / 不是什么 |
|------|------|-----------------|
| Owner | 资产的创建者与维护者，负责配置订阅申请表单、审批订阅申请、维护资产版本。一个资产允许多个 Owner；发布资产时必须设置多于一位 Owner 或 Deputy，以覆盖离职与休假；该冗余对「已发布」资产持续生效，收缩负责人名单不得破坏它。对资产而言 Owner 与 Provider 是同一概念，文档统一使用 Owner | 不是：Provider、提供方、创作者（指角色时） |
| Deputy | 资产的共同负责人，享有与 Owner 相同的管理权限。发布资产时若 Owner 仅一人，必须至少增设一名 Deputy 方可上架 | 不是：副 Owner、备份负责人 |
| 订阅审批人链 | Owner 为资产配置的订阅审批结构，由多级组成，每级可有多个审批人。申请提交后各级同时收到待办，级间无先后依赖；每级至少一人通过即该级通过，全部级通过则申请通过。仅适用于 Agent 与 MCP 资产；知识库与目录的权限审批是单级审批。申请提交时锁定审批链快照。某级无有效审批人时自动回落由任一 Owner 或 Deputy 审批（标注回落）；审批链可关闭，关闭后申请进入全体 Owner 与 Deputy 待办，任一处理即可。禁止自审：各级审批人计算时排除申请人本人，该级因此无有效审批人时同样回落 Owner 或 Deputy。任一审批人驳回即整单驳回，其余各级未处理待办立即清除；驳回理由必填、建议补充项选填 | 不是：审批流、审批流水线、逐级审批 |
| 知识库 Owner / 知识库 Contributor / 知识库 Consumer | Alice 授予的三种知识库级权限角色，分别对应管理整个知识库、增删知识库内文档、检索使用知识库。三者必须带「知识库」前缀书写，不得简称为 Owner。公共目录建库时创建者须同时指定知识库 Owner 与知识库 Deputy（可为创建者本人），平台据此调用 Alice 创建三种维护角色并将知识库 Owner 角色授予指定的 Owner 与 Deputy；知识库创建角色持有人不自动获得这些维护角色。三种维护角色的后续授予与回收由知识库 Owner 或知识库 Deputy 单级审批；两者全部失效时由上级目录控制角色补员 | — |
| 知识库 Deputy | 公共目录知识库的冗余负责人，建库时由创建者随知识库 Owner 一并指定；获授知识库 Owner 角色，权限与知识库 Owner 等同（与资产侧 Deputy 同构）。仅适用于公共目录；我的目录的管控动作恒由创建者本人执行 | 不是：库主、编辑者、只读用户 |
| 目录控制角色 | 知识目录级权限角色，可管理该目录（新增、重命名、删除子目录）。角色由平台在创建目录时调用 Alice 接口创建于 Alice 中，Alice 是存储与真相来源。父级目录的控制角色自动拥有其全部子级目录的控制权限。一级目录的控制角色由平台管理员冷启动指定，其余层级的授予与回收由上级目录控制角色审批维护 | 不是：目录管理员、目录 Owner |
| 知识库创建角色 | 知识目录级权限角色，可在该目录下创建知识库，但不自动获得知识库维护权限。角色由平台调用 Alice 接口创建于 Alice 中，授予与回收随目录控制角色同一套审批链路 | 不是：建库权限、创建者 |

## 治理机制

| 术语 | 定义 | 备注 / 不是什么 |
|------|------|-----------------|
| Alice | 奔驰的企业权限系统，是账号、角色、公共知识目录与公共知识库授权的唯一权威来源。本平台展示其授权结果并提供申请入口，不自行决策或审批此类授权；公共知识目录与公共知识库相关角色由平台在相应对象创建时调用 Alice 接口发起创建，平台是发起方，Alice 是存储与真相来源。我的目录的平台内分享授权为例外，由平台管理且不写入 Alice | 不是：权限系统、IAM、审批系统 |
| 护栏（Guardrail） | 平台提供的内容安全检测能力原子（如个人身份信息检测、有害内容检测、提示词注入检测、违禁词检测）。护栏不直接绑定 Agent，只能被组合进护栏策略模板；组合时逐条配置灵敏度与作用侧。命中的唯一处置是拦截，响应中回传命中的护栏类型 | 不是：检测器、过滤器、规则 |
| 灵敏度 | 护栏在模板中的判定强度，取值 0 至 100，数值越高越容易命中。它是护栏行为的唯一旋钮，平台不再区分置信度分档 | 不是：阈值、置信度 |
| 作用侧 | 一条护栏在模板中生效的位置：输入侧（用户提问进入模型前）、输出侧（模型回答返回用户前）或双侧。由平台管理员逐护栏配置 | 不是：检测方向、生效范围 |
| 护栏策略模板 | 由平台管理员配置的一组护栏及其灵敏度的组合，可启用或停用。Owner 创建 Agent 时必须从启用状态的模板中选择恰好一个；模板条目明细（护栏、灵敏度、作用侧）对 Owner 只读可见，上架后可在资产控制台改绑其他启用模板（即时生效）。模板是配置，不是执行点——检测统一在平台网关上对经由平台流转的对话执行，任一会话恰好适用一个模板；输出侧检测针对完整回答（网关缓冲全文、检测通过后按段回放，命中则全文不下发） | 不是：护栏策略、策略、防护方案 |
| 平台默认护栏策略模板 | 平台管理员指定的一个启用状态模板，适用于平台 Chat agent-runtime 的会话（即对话工作台中未选择任何资产 Agent 的会话）。全局唯一，且恒须存在：当前默认模板不可直接停用，须先指定另一启用模板为新默认 | 不是：兜底策略、默认策略 |
| 测评模板 | 测评中心里可复用的测评配置（裁判模型、指标、执行参数、数据集）。模板名全局唯一 | 不是：测评方案、评测模板 |
| 发布准入测评模板 | 一类特殊的测评模板，由平台管理员维护且全局固定唯一，内含提示词注入、意图偏离、内容安全三类测评问题集。Agent 上架前必须执行该模板；仅管理员可修改其问题集 | 不是：发布前测评、准入测评、上架测评 |
| 质量门控（Quality Gate） | 资产上架前的静态自动检查集，为硬阻断，按资产类型参数化（Agent 七项、MCP 六项，均含负责人冗余校验；Agent 第七项为「护栏策略模板已绑定且当前处于启用状态」）。与发布准入测评模板是两个独立关卡：质量门控检查配置是否完备，准入测评检查行为是否安全。门控结果为上架时点快照——上架后的热改类配置变更不触发重跑、不影响在架可见性；模板被管理员停用不影响存量在架 Agent，仅在下一次门控重跑（首发／新版本发布／重新上架）时强制确证 | 不是：准入检查、上架检查 |
| 下架 | Owner 或 Deputy 将已发布资产撤出 Marketplace的动作，资产转入「已下架」，全部订阅随之失效且为终态——重新上架不恢复订阅（申请人自行重新申请）。下架时需弹窗二次确认（轻量提醒，不引入审批或他人环节）并必填下架原因；原因随业务记录永久留痕，并随下架通知发给订阅者。下架时该资产全部「待审批」订阅申请一并自动转为「已取消」并通知申请人（审批人待办同步清除）。下架状态由平台运行时自动感知：一切经平台流向该资产的调用（资产会话透传与 PAT 开放接口调用）失败并收到「该资产已被下架」的明确提示；它与「出站调用已被平台停用」「资产服务暂时不可用」并列为三类资产不可用文案。平台不做意图路由，下架资产的各入口（详情页「去使用」、抽屉条目）同步置灰拦截。应急场景同样由 Owner 侧执行下架；平台管理员不改变资产状态。重新上架 = 一次新版本发布（修订为空时按当前在架配置发起空载荷版本发布），不单独发送「资产重新上架」通知，由发布流程的资产发布通知覆盖。发布进行中的资产不可下架（须先中止发布），确保紧急处置与迭代不互相静默覆盖 | 不是：应急隐藏、应急停用、封禁、kill switch |
| 资产删除 | Owner 或 Deputy 将资产彻底撤出平台的动作，需二次确认，转入「已删除」终态。适用于「草稿」「待发布」「待测评」与「已下架」；「已发布」资产须先下架方可删除（与知识库「可用态须先停用」同构）。删除为系统软删除：资产对全部用户不可见（含负责人与平台管理员），退出创作者中心、治理中心与已下架占位页，并清理该资产的资产级服务凭据；删除动作与操作人永久留痕。业务记录（订阅记录、条款确认、审批留痕、发布记录、下架原因）继续永久保留——留痕的是记录，不是资产条目 | 不是：硬删除、注销、归档（指本动作时） |
| 强治理变更 | 影响已订阅方调用契约的资产变更，例如接口的输入或输出参数增删、鉴权方式变更。由 Owner 在发布新版本时显式申报，申报时必填影响说明与迁移指引；平台在新版本上架替换的同一时刻通知全部订阅者（附申报内容）并留痕——通知与替换同时发生，订阅者无缓冲窗口。平台不自行检测 | 不是：重大变更、破坏性变更 |
| 热改类配置与版本类配置 | 已发布资产配置的三分法，分类原则：字段是否进入调用契约或需要质量门控／发布准入测评验证。热改类——订阅申请表单、订阅审批人链、负责人名单、护栏策略模板改绑、基础信息（资产名称、业务标签、简介、能力标签、适用场景）、超时与重试——在资产控制台即时生效，不进入版本轨道，变更审计留痕、不通知订阅者（写入需版本校验，避免并发击穿负责人冗余等约束）；版本类——服务地址、Health Check、鉴权声明（鉴权模式、鉴权方式与参数名、动态模式的授权申请接口地址与令牌回写字段）、能力声明、MCP 托管方式——仅能经未发布修订以新版本变更，重跑质量门控与发布准入测评。鉴权的粒度分界：声明进契约（版本类），密钥值是凭证（轻发布）。使用条款与资产级服务凭据的密钥值走轻发布（见「使用条款」词条）：豁免门控与测评，密钥轮换与泄露处置不被验证流程拖住，但经发布动作生效并留痕。通知受众按载荷区分：条款升版通知存量订阅者与待审批申请人（附新版条款）；密钥值轮换仅通知全体负责人（仅含变更事实、不含密钥本身、不通知订阅者——密钥值是平台与资产的契约而非订阅者与资产的契约，2026-08-23 收窄裁定；发布前强制探测可用）——密钥值于 2026-08-23 自热改类移入该通道（部分调整 v0.9 裁决） | 不是：热更新（单独出现时） |
| 资产版本与未发布修订 | 资产任一时刻只有一个活版本对外服务，订阅记录不绑定版本，新版本上架整体替换、全体订阅者自动跟随。未发布修订是资产的可选数据属性（不是状态机节点）：「已发布」与「已下架」状态均可携带。修订载荷仅限版本类配置与使用条款；热改类配置只能经资产控制台即时通道生效，不进入修订——一个字段恰有一条变更通道。发布（含重新上架）= 消费修订：纯条款修订走轻发布（豁免质量门控与发布准入测评），含版本类字段的修订重跑质量门控与发布准入测评（MCP 仅质量门控）后生效，版本号递增并写入发布记录。下架不触碰未发布修订；已下架资产可编辑修订后重新上架，修订为空时按当前在架配置发起空载荷版本发布。发布并发全互斥：同一资产任一时刻至多一次发布进行中（版本发布与轻发布互斥，重复发起阻断并提示当前发布进度）；中止发布即取消进行中的准入测评任务（已产生的部分结果不落库、详情页不展示）。测评任务在发起时刻锁定模板快照（问题集与三类阈值），执行与判定不受模板后续修改影响 | 不是：草稿轨道（状态机节点含义时）、多版本共存 |

## 授权与凭据

| 凭据体系（四类凭据总览） | 平台全部凭据的无歧义划分（2026-08-23 补齐）：PAT（入站：外部系统 → 平台开放接口的唯一入站凭据，平台签发，范围为持有人已授权对象的子集，创建后全部锁定，不支持重新生成与有效期延长）；个人出站凭据（出站：平台 → 外部资源，三类目标——平台外资产调用／平台原生工具导入通道／Nexus 模型服务；平台外调用类由平台签发绑定用户与资产、无可编辑内容，另两类仅凭据值可编辑、保存后自动重检/探测）；资产级服务凭据（出站：平台 → 资产服务，资产属性、每资产一份、不在密钥库、订阅者不可见，鉴权声明属版本类、密钥值走轻发布通道）；平台资源凭据（平台内部：Nexus 令牌与实例类资源连接凭据，管理员维护，不兜底用户资产调用、不出现给用户） | 不是：凭据中心、Vault（指本体系时）；四类两两不混用——PAT 不是资产服务凭据；个人出站凭据不是 PAT（方向相反）；平台资源凭据不兜底用户调用 |

| 术语 | 定义 | 备注 / 不是什么 |
|------|------|-----------------|
| 静态凭据 | 资产 Owner 提供的固定不变鉴权凭据，例如固定 API Key 或 Bearer Token。它属于资产级服务凭据的一种形态，用于平台内资产调用 | 不是：固定令牌（单独出现时） |
| 动态凭据 | 资产 Owner 提供的外部鉴权服务端点，平台调用该端点动态获取调用资产所需令牌。它属于资产级服务凭据的一种形态，用于平台内资产调用。配置时的一键测试为真实鉴权——以配置的密钥真实调用该端点并成功换取令牌，方算探测可用（与静态凭据密钥值探测强度对齐） | 不是：自动模式、动态令牌（指该机制时） |
| 平台内资产调用 | 用户在平台内使用已订阅资产的调用方式，例如资产详情页「去使用」或对话工作台资产 Agent 选择器进入的透传会话。平台使用资产级服务凭据完成认证，并在请求中传递当前用户身份上下文，供资产内部处理用户级数据权限；订阅者无需配置个人出站凭据 | 不是：按人鉴权资产（指该场景时）、共享身份调用 |
| 平台外资产调用 | 外部系统经平台开放接口调用已订阅资产的调用方式。外部系统使用 PAT 作为入站认证；平台校验持有人已订阅目标资产后，使用平台为持有人签发、绑定用户与资产的个人出站凭据调用资产。未生成、凭据失效或调用失败时不回落至任何共享身份 | 不是：按人鉴权资产（指资产属性时）、共享身份回落 |
| 订阅（Subscription） | 使用者向资产 Owner 申请资产使用授权的过程与记录，含申请信息、使用条款确认与 Owner 侧审批。订阅约束的是"人使用资产"，与认证凭据无关。Owner 与 Deputy 对自有资产免订阅可用（订阅是消费方准入机制，不适用于负责人）。同一申请人对同一资产至多一条在途（待审批）申请，在途期间订阅入口对其禁用。「被驳回」与「已取消」均为终态，「重新申请」一律新建记录（以原申请内容预填），原记录连同驳回理由永久保留；「已取消」记录取消来源（主动退订／Owner 取消／资产下架／资产删除／账号失效） | 不是：授权、开通、Access |
| 使用条款（Terms of Use） | Owner 为资产设定的使用约束文本，是资产的独立必填配置，自带版本号，与订阅申请表单定义分开维护。订阅者必须显式勾选同意后方可提交订阅申请，平台记录条款版本、确认人与确认时间。条款变更走轻发布：修改进入未发布修订，Owner 执行发布后生效——条款版本递增、通知存量订阅者与该资产的待审批申请人（附新版条款）、发布记录留痕；豁免质量门控与发布准入测评（行为与接入配置未变，无检测对象）；不阻断存量订阅者继续使用、不要求重新确认，新订阅按当前版本签署 | 不是：Terms、协议、条款 |
| 平台级用户协议 | 平台管理员维护的全平台统一使用协议，规定平台本身的责任边界，常驻于对话工作台免责声明处。与资产级使用条款是两个相互独立的文档。P0 内容随部署发布，后台编辑功能入 P1 | 不是：用户协议（与使用条款混用时） |
| 密钥库 | 平台统一管理用户侧调用凭据的模块，分入站与出站两个管理面：入站为 PAT（外部系统调用本平台开放接口的唯一入站凭据）；出站为个人出站凭据——按人持有的外部资源凭据，目标类型三种：平台外资产调用（平台签发，未生成即调用失败并引导申请，不回落任何共享身份）、知识库的三个外部导入通道（操作人个人凭据，目标为对应的平台原生工具）、Nexus 模型服务（即个人模型凭据：不按调用点划分，同一条凭据适用于持有人的全部模型调用点，其可用模型由该凭据在 Nexus 的权限决定，可配置多条以覆盖不同模型；模型类调用按触发人解析、个人凭据优先、无可用个人凭据时使用平台默认凭据，见「平台资源」词条与 docs/adr/0016）。资产级服务凭据不在密钥库管理——它是资产属性：每资产一份，由 Owner 在创建向导鉴权配置步与资产控制台配置，用于平台内资产调用（鉴权声明属版本类、密钥值走轻发布通道——豁免门控与测评、发布留痕并通知全体负责人，通知仅含变更事实、不含密钥值本身）。平台资源凭据也不在密钥库管理——实例类资源凭据与平台内部 Nexus 令牌由平台管理员在平台资源注册表维护，模型类平台默认凭据在模型设置中维护。PAT 开放接口调用资产时，平台先校验持有人已订阅该资产，再使用平台为持有人签发的个人出站凭据发起平台外资产调用。持有人账号被 Alice 停用时，其名下全部 PAT 与个人出站凭据立即失效（主体侧失效）。底层存储委托给企业 Key Vault，用户只与密钥库交互 | 不是：Vault、凭据中心、Key Vault（指本平台模块时） |
| PAT（Personal Access Token，个人访问令牌） | 外部系统调用本平台开放接口时使用的唯一入站认证凭据，统一在密钥库签发与吊销。PAT 只是认证方式，其可勾选的对象范围是持有人已获授权对象（已订阅资产、有权限知识库）的子集，不能扩张权限；平台原生工具不在可勾选范围内。失效有两类来源：对象侧（订阅取消、资产下架或删除、知识库权限被回收，仅该对象的访问失效）与主体侧（持有人账号被 Alice 停用，其名下全部 PAT 立即失效）。管理动作语义统一（2026-08-23 裁定）：停用＝可逆临时禁用（可重新启用），删除＝终态移除不可恢复——凭据语境的「撤销」统一写「删除」 | 不是：API Token、访问令牌（指入站场景时） |
| Nexus | 奔驰的企业模型网关，平台通过它调用各家大语言模型；平台全部模型类资源（对话、多模态、向量化、重排序）均经 Nexus 供给，不存在非 Nexus 供给的模型服务。访问 Nexus 所需的令牌分两种：平台统一令牌属平台资源凭据（平台管理员在平台资源注册表维护），个人令牌属密钥库的个人出站凭据（目标类型「Nexus 模型服务」，不按调用点划分，可配置多条以覆盖不同模型的权限） | 不是：模型网关（首次出现时需并列写明） |
| Dify | 企业内部署的低代码 Agent 编排平台。低代码 Agent 在 Dify 中编排，由本平台登记治理信息后上架 | 不是：低代码平台（首次出现时需并列写明） |
