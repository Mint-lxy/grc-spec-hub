## 原型 Chat 历史种子：localStorage 锁死旧 seed 的修复（2026-09-21）

- 用户截图反馈：浏览器（`file://` 直开）仍展示 seed5 中文 user 文案——v3 英文化只改了 `makeSeed5` 等函数定义，但浏览器 localStorage 里仍存着 v3 之前注入的旧 seed5 对象。
- 根因：`seedSessions()` 用「`!sessions.some(x => x.id === s.id)`」逻辑，旧 id 已存在就**跳过重写**——localStorage 一旦落盘就再也读不到代码里的新版本。
- 修复：在 `marketplace - agent.html` 引入版本号 `CHAT_SEED_REV`（常量 `"5"`），并在 mismatch 分支改为「按 id 集丢弃并**重建**全部种子会话」——把 seed1 抽出为 `makeSeed1(now)`，与 makeSeed4..makeSeed12 一并走 `makers.map(fn => fn(now))`。
  - 用户自建的会话（id 不在种子集）保留不动。
  - 升级路径与首次 fallback 共用 `buildSeeds()`，避免再次写两份种子清单。
- 教训（记入 MEMORY 候选）：**任何「代码模板 + localStorage/IndexedDB 注入种子」模式必须配一个版本号**，且 mismatch 时**重建**（而不是 dedup-skip），否则 localStorage 一旦落盘旧版本就锁死，编辑器改源码也救不回。
